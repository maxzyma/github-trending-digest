**主线二：Agent Skills 从"多装几个"走到"装了有没有用"。** 今天榜上 4 个技能项目分属三种角色。stitch-skills 是 Google Labs 给 Stitch 设计工具配的官方技能库，Claude-BugHunter 和 claude-trading-skills 是安全和投资两个垂直领域的社区技能包，NVIDIA 的 SkillEvaluator 则是评测框架：同一个任务分别在装技能和不装技能时让 Agent 跑一遍，比较结果差多少（项目称为 Skill Lift），并检查不同技能的描述是否重叠、让 Agent 选错。前三个回答"有哪些技能可装"，SkillEvaluator 回答"装了以后 Agent 是否真的变好"。团队如果已经在维护内部技能库，可以拿它给技能做回归测试。

**主线三：表格、文档和界面成了 Agent 的新入口。** Univer 是可嵌入的表格和文档 SDK，11-14 发布 v1.5.0，日增从昨天的 +495 翻倍到 +988，今天登上榜首；项目把自己定位成给人和 Agent 共用的办公组件，编辑、计算和文件处理都可以嵌进自己的产品。AG-UI 是规定 Agent 后端和前端界面之间如何传消息、工具调用和状态的开放协议，昨天快照日增只有 +9，今天回到 +355，11-15 合入了一批 Go SDK 的事件解码修复（#3179、#3184 等）。做产品的团队可以把两者放在一起看：AG-UI 管 Agent 怎么把过程推到界面上，Univer 提供表格和文档这类用户每天在用的界面本身。

### [NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator) — NEW ⭐ 1,746（+122）| Python | 信源：中

**它是什么**: NVIDIA 开源的"Agent 技能体检工具"。Agent Skills 是装给 Claude Code、Codex 这类编码 Agent 的说明书加脚本，告诉它某类任务怎么做。SkillEvaluator 分三层检查一个技能：第一层看格式、安全和兼容性，给 0–100 的质量分；第二层看这个技能和已装的其他技能是否内容重叠、会不会让 Agent 选错；第三层把 Agent 放进沙箱，同一组任务装技能跑一遍、不装再跑一遍，比较成绩差多少，项目称这个差值为 Skill Lift。

**解决什么问题**: 技能越装越多以后，团队很难回答"这个技能到底有没有让 Agent 变好"，也难发现两个技能描述太像、互相抢活。以前只能靠人工试用和感觉，SkillEvaluator 把这件事变成可重复跑的评测，可以放进 CI，技能改一版就对比一次。

**谁在用、怎么用**（来自 Issues/X）:
- 安装前门禁: Nous Research 在 X 上表示，其 Hermes Agent 安装技能时会调用它做检查，并据此改进了自家 11 个技能。
- 云平台接入: Google 工程师 kweinmeister 提交 #140（11 条评论，已合并关闭），为第三层评测加入 Claude Code on Agent Platform 支持，并在 X 上分享了 12 个场景、72 次对照实验的结果。
- 官方数据: @NVIDIAAI 称用它测了 300 多个技能（官方自述，未独立核实）。

**社区怎么评价**:
- 正面: 发版节奏稳定（11-06 v0.8.0、11-13 v0.9.0），外部报告的安全扫描误报（#31）、关键词误匹配（#30）都已修复；v0.9.0 新增评测预算控制和技能版本对比。
- 负面: #61 直接质疑"这个工具给出的数字是否有意义"，从 08-21 开到 11-13 才随指标文档补齐关闭；讨论中提到评分缺少人工标注校准，只跑少量用例时置信区间很宽。#69、#136 报告第三层在 Docker 或本地模式下跑不起来。
- 健康度: 1,746 星、234 个 fork，subscribers 只有 3；33 位贡献者，但两位 NVIDIA 维护者约占全部 542 个提交的八成。2026-06-24 建仓，open 的 10 个 issue、22 个 PR。HN、Reddit 未找到讨论，X 上的声量主要来自官方和 KOL。

**风险与争议**:
- **stability**: Skill Lift 等指标还没有独立验证，用例少时结论不可靠（#61），适合看趋势，不宜当成绝对分数。
- **dependency**: 基础检查不需要密钥，但模型打分、重叠检测的向量计算和部分第三层评测默认调用 NVIDIA Build 接口，需要 `NVIDIA_API_KEY` 并受限流约束。
- **cost**: 第三层要反复跑真实 Agent 和沙箱，模型调用费用随用例数成倍增长；v0.9.0 才加入 token 和费用预算控制。
- **bus_factor**: 两位维护者贡献约八成提交。

**技术备注**: Python，Apache-2.0，已发布到 PyPI。第三层基于 Harbor 沙箱运行，需要 Docker；安全扫描集成 SkillSpector、Gitleaks，Semgrep 可选。属于 NVIDIA Verified Skills 流水线的一部分。

### [ggml-org/ggml](https://github.com/ggml-org/ggml) — NEW ⭐ 15,933（+43）| C++ | 信源：弱

知名老项目首入 tracker。

2022 年建仓的机器学习张量库，MIT 许可，是 llama.cpp 和 whisper.cpp 共用的底层计算库，主要开发在 llama.cpp 仓进行，再同步到这里。11-13 发布 1.0.0：删掉已弃用的公共 API 和旧的 `DIAG_MASK` 算子（RPC 协议同步升级，会拒绝不兼容的旧节点），新增可配置的 YaRN 截断和 FP8 支持；性能侧包括 CUDA/Metal 的少行量化矩阵乘与 MoE 融合、Vulkan 预填充阶段的 FlashAttention、SYCL 设备端 MoE 调度，以及新的 WebGPU 内核和更多高通 Hexagon 算子。今天日增只有 +43，上榜时间紧跟 1.0 发布，推断与版本发布带来的关注有关。直接链接 ggml 的下游项目升级前要检查是否调用了被删接口。

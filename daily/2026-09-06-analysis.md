三者放在一起看，今天的"新供给"其实没有新技术方向：一个是已知作者的 skill 外溢、一个是目录站、一个是复制快照。**skill 盘的扩张越来越靠周边与派生，而不是新的核心能力。**

**主线三：agent 运行时这条线今天在"活着且在改"，与 skill 盘的停更式上行形成对照。** `hermes-agent`（↑3，#4）今天有新提交（MCP server 与内置工具同名时的列表视图修复）；`opencode`（↑7，#8）昨天合并 #47306 加 GitLab reasoning 变体、v1.18.29 是四天内的第三个版本；`magnitude`（↓5 但 +674，三日累计 +1,279）昨天加了首次运行的 Pi 引导流程、今天补 contributing 文档；回榜的 `ruvnet/ruflo`（RE，#9）9 月 5 日一天推了五个提交，全部出自作者 ruvnet 本人，提交前缀是 `dream(memory)` / `dream(performance)` 并引用 #3168、#3183——这是把 agent 自动生成的改动直接进主干的写法，与它在本 tracker 5 月首录时的"品牌覆盖 claude-flow → ruflo、hype 大于 substance"的判断放在一起，值得继续观察。反过来，skill 盘头部三席的最近提交分别是链接检查排除项（`mattpocock/skills`，9-04）、dependabot 升级（`ECC`，9-03）、Trendshift 徽章排版（`ponytail`，9-04），`humanizer` 已 18 天无提交仍在 #11。**同一张榜上，运行时项目的 star 在跟着代码走，skill 包的 star 在跟着转发走。**

**主线四：榜单解读提醒 — 今天有两个数字最容易被误读。** 一是 `FckSignups` 的 441 open issues：不是 441 个 bug，是收录申请队列；二是 `WorldFlowAI/everything-claude-code` 的 2,379 ⭐：它同名、同 README、同 star 徽章（徽章还指向上游仓），Trending 页面上与上游只差一个 owner 名，误认成官方仓的概率很高。另有一个反向提醒：`hermes-agent` 的 40,079 open 里只有 13,498 条是 issue、其余是 PR，昨天已提过一次，今天仍是全榜最高，继续按拆分后的口径读。

## 如何理解今天的热度信号

今天要分开看的是三种"数字看起来像一回事、其实不是"的情况：

**第一种：issue 数不等于 bug 数。** `FckSignups` 的 441 open issues 半数以上是网站表单自动开出的收录申请，`hermes-agent` 的 40,079 open 里三分之二是 PR。两者都需要拆开口径再读——前者读的是"审核吞吐跟不上投稿"，后者读的是"PR 队列的规模"，都不是"未解决缺陷数"。

**第二种：同名不等于同一个项目。** `WorldFlowAI/everything-claude-code` 与 `affaan-m/ECC` 在 Trending 页面上只差一个 owner 名，README 与徽章完全一致。GitHub 的 `fork` 标记为 false 意味着它不会在页面上显示 "forked from"，只有对比 commit sha 才能看出它是复制快照。**看到与知名项目同名的低 star 仓，先对 sha，再看最后推送日。**

**第三种：KOL 背书是真实的，但它解释的是"今天为什么上榜"，不是"值不值得装"。** `humanlayer/skills` 的上榜可以直接追到 Matt Pocock 的一条评价，作者本人也是 12-factor agents 的作者——这两点都是真实的信誉信号。但仓库本身 12 次提交、三周无更新、安装命令 bug 挂了五个月，**信誉在作者身上，维护不在仓库里**。对 skill 类项目，"谁写的"和"现在有没有人管"是两个独立的问题，今天这个样本把两者分得很开。

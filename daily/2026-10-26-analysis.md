## NEW 首次上榜

### [JetBrains/thinkrail](https://github.com/JetBrains/thinkrail) — NEW ⭐ 1,812（+51）| TypeScript | 信源：中

**它是什么**: JetBrains 孵化器里的开源 IDE，专门给开源命令行编程 Agent “pi” 套一个图形界面。可以装成桌面应用，也可以用命令行启动后在浏览器里打开。不用注册新账号，登录 JetBrains AI 或沿用 pi 自己的鉴权即可。

**解决什么问题**: 在终端里用编程 Agent，同时跑几个任务容易互相改乱代码，过程也只能翻终端日志。ThinkRail 给每个任务开一个独立的 git worktree，多个 Agent 并行工作不碰你自己的工作目录；编辑器、终端、diff 审阅都在一个窗口里，审阅意见可以直接发回给 Agent。项目意图写在 `SPEC.md` 里，Agent 会读取并维护，换会话不丢上下文。

**谁在用、怎么用**（来自 Issues/HN）:
- 个人开发者用 pi 并行开发几个分支，在同一界面审 diff、开 PR；HN 帖（50233294）里有人说“正是我缺的 pi 图形界面”，也有人认为 worktree 并行比 JetBrains 现有 IDE 的 AI 集成顺手。
- 有外部用户请求上架 Windows 包管理器 winget（#477）；社区出现了让它托管 Claude Code 的 fork，以及把 WebView 移植到 Avalonia 的实验（HN 49992698）。
- 目前没找到团队或企业落地的案例。

**社区怎么评价**:
- 正面: worktree 隔离加集中审阅的工作流被认为实用；JetBrains 出品让人对长期维护有一定预期。
- 负面: HN 上有人指出 README 和官网明显由 AI 撰写；Agent 直接在本机运行，没有容器或沙箱；JetBrains 同时有 Air 和 ThinkRail 两条 Agent 产品线，方向显得分散。issue 里有 macOS 睡眠唤醒后终端卡死（#428，已关）、标题栏不符合原生风格（#346）、工作区不能自定义名称（#420）。
- 健康度: 1,812 星、7 个 subscribers（约 259:1），105 fork，open issue 与 PR 合计 203 个。仓库建于 2026-07-08，今天仍有推送。提交集中在两位核心成员，最新版本是 v0.3.0-nightly.6（10-25），尚无正式版。

**风险与争议**:
- **stability**: 只有 nightly 版本；macOS 桌面版只支持 Apple Silicon，Linux 要求 Ubuntu 24.04 以上。
- **dependency**: 只支持 pi 一个 Agent，接其他 Agent 要靠社区 fork。
- **bus_factor**: 提交集中在两人，孵化器项目能否长期投入取决于 JetBrains 的产品取舍。
- **安全隔离**: Agent 在本机直接执行命令，没有沙箱，需要使用者自己控制权限。

**技术备注**: TypeScript，Apache-2.0。基于 git worktree 隔离任务，支持 Skills 与 MCP；桌面版和浏览器版共用一套前端。

**它是什么**: 开源、可自托管的部署平台，定位是 Vercel、Heroku、Netlify 的替代品。装在自己的服务器上后，可以一键部署静态站、数据库、全栈应用和 360 多个现成服务。

**近况**: 2021-01 开源，64,446 星、5,790 fork，open issue 与 PR 合计 363 个。版本节奏很密，10-21 连发 v4.3.24 和 v4.4.7，10-23 发布 v4.5.0：新增 Gitea 私有仓库部署（#12234）、按服务器自动打安全补丁（beta）、集群监控页（#11867、#12162）、应用和数据库的文件浏览器（#11518）、passkey 登录（#12154）和维护模式页（#12112）。星数与 subscribers 比约 330:1，作为大型成熟项目属于正常范围。

**风险与争议**:

### [AgriciDaniel/claude-seo](https://github.com/AgriciDaniel/claude-seo) — NEW ⭐ 20,959（+197）| Python | 信源：中

**它是什么**: 装进 Claude Code 的 SEO 审计工具包。给它一个网址，它会派出多个子 Agent 分别检查网站的技术 SEO、内容可信度（E-E-A-T）、结构化数据、在 AI 搜索里的可见度（GEO/AEO、llms.txt）、外链、本地 SEO、电商和多语言设置，最后汇总成按优先级排好的修复清单，可导出 PDF 或 Excel。

**解决什么问题**: 过去做一次完整 SEO 体检，要么请代理商按项目收费，要么订阅每月几百美元的 SEO SaaS，再人工整理报告。claude-seo 想让 SEO 顾问或站长在自己的 Claude Code 里直接跑出诊断，再按需接入付费数据源补充排名和外链数据。

**谁在用、怎么用**（来自 Issues/X/评测文章）:
- 外部贡献者在补电商场景，例如 Shopify 全站爬取的 PR（#302）。
- 有用户在接 DataForSEO 数据时发现上游 MCP 服务已升到 v3，仓库里 16 个文件引用的工具名已失效、成本表不准（#319）；也有人提出 Firecrawl 抓取层返回 500 时需要多供应商切换（#316）。
- README 把目标用户定为做周度客户审计的 SEO 代理商、首次沟通现场出诊断的自由顾问，以及自查的本地商家和电商站点；作者自报用它运营的网站 12 周获得 10.8K 次 Search Console 点击，属于自述数据，未独立核实。

**社区怎么评价**:
- 正面: 多篇 Claude 技能合集文章把它列为覆盖最全的 SEO 技能包；X 上有法语开发者推荐（@CamilleRoux）。
- 负面: 合集文章同时提到 DataForSEO 要付费、部分功能需要自己补齐；历史 issue 里有不能渲染单页应用（#11）、GEO 子 Agent 写进文档却没接入审计（#17）等问题，均已关闭。
- 健康度: 20,959 星、161 subscribers（约 130:1），2,959 fork，open issue 与 PR 合计 52 个。仓库建于 2026-02-07，作者一人 348 次提交，第二名 13 次。大约两周一个版本，最新 v2.5.0（10-22）。HN 只有作者自己发的 Show HN（1 分、0 评论），Reddit 没有找到专门讨论。

**风险与争议**:
- **cost**: 完整审计会让 5 个子 Agent 跑 Opus，明显消耗 Claude 套餐额度；DataForSEO、Firecrawl 等扩展都要自带付费账号。
- **dependency**: 依赖第三方 MCP 与抓取 API，上游改版就会失效（#319、#316）。
- **bus_factor**: 维护几乎全靠作者一人。
- **vanity**: 热度主要来自 X 转发和合集文章，HN、Reddit 没有独立讨论，星数需要谨慎解读。
- **商业导流**: README 推广作者的付费社区，会员可提前拿到新功能版本；公开版本身是 MIT 免费。

**技术备注**: Python + Claude Code 技能 / 子 Agent 结构，26 个子技能、19 个子 Agent，9 个可选扩展接实时 SEO 数据。MIT 许可。

## 本日主线

**主线一：榜单地图 — 今天没有单一霸榜项目，16 项摊成六个互不相干的方向。** 可分六组：

- **AI agent 垂直落地**（3 项，最大盘）—— `melgarafael/DeskcommCRM`（NEW，#2，1,821 ⭐，+504）、`jihe520/MathModelAgent`（NEW，#6，5,138 ⭐）、`alsk1992/CloddsBot`（↓4，#8，2,519 ⭐）。三个项目分别做 WhatsApp 卖货、数学建模竞赛论文、跨市场自动交易，共同点是不再卖"agent 框架"，而是直接交付某一行的成品工作流。
- **安全与网络对抗**（4 项）—— `SnailSploit/Claude-Red`（NEW，#13，3,618 ⭐）、`vxcontrol/pentagi`（RE，#16，23,467 ⭐）、`p1neappleXpress/OpenFlux`（NEW，#11，1,409 ⭐，+355）、`Flowseal/zapret-discord-youtube`（RE，#5，33,212 ⭐）。前两项是"把渗透测试交给 LLM"，后两项是反封锁工具。
- **成熟老项目首入 / 回流**（3 项）—— `Sonarr/Sonarr`（NEW 首入 tracker，2011 年建仓，15,932 ⭐）、`yuliskov/SmartTube`（NEW 首入 tracker，2020 年建仓，33,225 ⭐）、`armory3d/armorpaint`（↓2，#12，4,918 ⭐）。自托管媒体与创作工具这条老线今天集中冒头。
- **AI 编码基础设施**（3 项）—— `max-sixty/worktrunk`（NEW，#15，7,248 ⭐）、`asgeirtj/system_prompts_leaks`（RE，#3，65,438 ⭐）、`Shubhamsaboo/awesome-llm-apps`（RE，#10，137,643 ⭐）。
- **模型发布**（1 项）—— `multimodal-art-projection/YuE`（NEW，#14，7,309 ⭐），YuE2 于 9 月 9 日发布。
- **消费端工具**（2 项）—— `bilawalsidhu/gods-eye-view`（↑1 榜首，29,996 ⭐，+2,265）、`nab138/iloader`（NEW，#4，3,092 ⭐）。

对照 9 月 11 日（上一个被 tracker 记录的榜单日）：那天是「本地跑大模型」三条路线同框，今天这条线整体消失，换成了垂直 agent 和安全两块。榜单换血率很高——16 项里 13 项是 9-11 榜上没有的。

**主线二：YuE2 把音乐生成的中间层打开了，但权重许可同时往回退。** YuE v1 是黑箱的 lyrics-to-song，YuE2 在中间插了一层可读可编辑的 ABC 乐谱（团队称 symbolic planning）：模型先写旋律和和弦，人或 agent 可以在渲染成音频前改和声、改曲式，再交给声学模型渲染 48kHz 成品。官方 demo 演示了 9 轮对话 14 个版本，把一首中文流行改成加萨克斯 solo 的英文爵士。HN 讨论 105 分 / 101 评论，是今天榜上唯一有百评级外部讨论的项目。需要同时看清的是许可：仓库徽章写 Apache-2.0，但那只覆盖代码和文档，**模型权重按仓内单独的 `MODEL_LICENSE` 走 CC BY-NC 4.0**——而 v1 当年正是应社区要求才从 NC 改到 Apache。想商用的人别只看 GitHub 页面上那个徽章。

**主线三：Claude Skills 生态长出了攻击性安全技能包。** `Claude-Red` 把 78 个 `SKILL.md` 按 23 个攻击面分类打包，克隆进 `~/.claude/skills/` 后由对话触发自动加载；同日 `pentagi`（自主渗透测试 agent）回归榜单。这条线的技术形态值得注意——它不含工具代码，纯粹是提示词方法论库，分发成本近乎为零，`Claude-Red` 已被第三方 skill 注册表自动摄取转发（其 issue #4）。合规姿态上它写了明确的授权使用声明并点名 CFAA 和英国计算机滥用法，但 issue #6 里维护者面对"Claude 不肯扫描"的抱怨，公开建议用户去研究 LLM 越狱与上下文构造——声明与实操之间有明显落差。

**主线四：榜单解读提醒 — 今天有三个项目的 stars/subscribers 比都在 100:1 以上，但结论完全相反，这个比值单独用不了。** `worktrunk` 453:1，看着最吓人，但它有 3,168 个已合并 PR、617 个 issue、每周一个 release，HN 上甚至出现了多个"某工具是 worktrunk 的极简替代"的对标贴——CLI 工具装了就用，几乎没人点 watch，低 watch 是品类特征。`iloader` 124:1，单版本下载 75.5 万次，Homebrew / AUR / Fedora COPR 三个社区自发打包。反过来 `Claude-Red` 110:1，12 个 open issue **全部零评论**，HN 和 Reddit 均无讨论，传播主要吃"Claude Skills"话题红利。判据不是比值本身，是比值背后能不能找到下载量、fork 改造、分散的 issue 提出者这类使用痕迹。

### [melgarafael/DeskcommCRM](https://github.com/melgarafael/DeskcommCRM) — NEW ⭐ 1,821（+504）| TypeScript | 信源：中

**它是什么**: 一套自己装在服务器上的客户管理系统，专门给"靠聊天卖货"的小生意用。接上自己的 WhatsApp 号之后，AI 客服负责接待、判断这个客人值不值得跟进、按销售漏斗一步步推，谈到关键处再转人工。对标 Kommo、Octadesk、Intercom 这类订阅制 SaaS。

**解决什么问题**: 以前巴西的电商、诊所、房产中介要么手工在 WhatsApp 里翻聊天记录，要么按月付费给 SaaS 且数据在别人手里。DeskcommCRM 给了第三条路：一条命令在 VPS 上拉起 CRM + WAHA（非官方 WhatsApp 通道）+ 数据库，数据留在自己机器上，AI 接待能力自带。

**谁在用、怎么用**（来自 Issues）:
- 巴西中小商家自部署：项目与主机商 HostGator 合作提供 `hostgator-setup-kit/install.sh`，扫码接入自己的 WhatsApp 号即可开张。issue 区全部是葡萄牙语，提问者几乎都在描述自己 VPS 上的具体故障。
- 缺陷报告非常具体，说明确实跑在生产上：issue #667 报告"连接新 WhatsApp"必然失败，根因是 session 名 69 字符超过 WAHA 的 54 字符上限；#715 报告 install.sh 在 root crontab 为空时挂死。

**社区怎么评价**:
- 正面: issue / PR 讨论密度很高（PR #680 有 272 条评论），外部贡献者 jmpo、JowaniOrantes、maugarciasa 持续提 PR，维护者修复响应在天级。554 forks 对应 1,821 stars（30% fork:star），搜索结果里几乎全是个人 fork，是自部署而非刷量的形态。
- 负面: #670 指出 install.sh 强制要求填真实 AI key，与官方 `docs/deploy-selfhost` 里"可选"的承诺矛盾；#754 报告 `fn_decrypt_oauth` 持续有 10–30% 调用失败；#752 报告删联系人失败时会破坏消息与会话历史，既无事务也无审计；#472 指出 CHANGELOG 里写的 v1.11.1 实际不存在。
- 健康度: stars/subscribers = 130:1；122 个 open items 里含 40 个 open PR；维护者 melgarafael 提交 3,494 次，第二名 88 次；仓龄仅 4.5 个月，近四周提交 163 / 767 / 530 / 247，三天内从 v1.18.0 发到 v1.19.0。
- 外部足迹: HN、X、Reddit 均检索不到讨论。这更像"单一语种社区内部真实使用 + 外部零曝光"，不是通常意义的热度虚高。

**风险与争议**:
- **bus_factor**: 97% 的提交来自一个人，第二贡献者相差 40 倍。
- **stability**: 安装脚本和核心连接路径都有高频致命 bug，版本号与 CHANGELOG 对不上。
- **dependency**: 强绑 WAHA 这条非官方 WhatsApp 通道和 HostGator 一家主机商，上游封号或改协议即全线不可用。
- **privacy**: 宣称符合巴西 LGPD，但 issue #701 显示匿名化之后自动跟进流程仍在继续跑。

**技术备注**: TypeScript，MIT 许可，Docker 部署，多租户，声称 MCP-ready。

### [nab138/iloader](https://github.com/nab138/iloader) — NEW ⭐ 3,092（+209）| TypeScript | 信源：中

**它是什么**: 桌面端（Windows / macOS / Linux）一键把 SideStore 装进 iPhone 或 iPad 的安装器。插上设备、登录 Apple ID，它自动完成签名证书申请、pairing 文件生成与放置——这几步原本要手动串起好几个命令行工具。

**解决什么问题**: 想在非越狱 iPhone 上装 App Store 之外的应用，路径一直是 AltStore / SideStore，但把 SideStore 本身装上去就是第一道劝退关。iloader 是这一层的安装器，不是 AltStore 的替代品；SideStore 官方文档已把它列为推荐安装方式。竞品是 Dadoum 的 Sideloader 和老牌 Impactor，README 明确说参考了前者对 Apple 私有开发者接口的实现。

**谁在用、怎么用**（来自 Issues / 社区打包）:
- 普通 iOS 用户装第三方应用：v2.3.1 单版本 75.5 万次下载，v2.3.3 发布三天 8.2 万次。
- 社区自发分发：Homebrew cask、AUR、Fedora COPR 三处都有非官方打包，winget 也有打包请求（microsoft/winget-pkgs #376168）。用户主动搬运是很强的采用信号。

**社区怎么评价**:
- 正面: SideStore 官方文档背书 + 三个发行版打包渠道；十个月内处理了 611 条 issue（368 已关闭），发版极频繁，八月到九月已从 v2.2.10 推进到 v2.3.3。
- 负面: issue #583（49 条评论）是最严重的一条——免费 Apple ID 在 iOS 26.5.2 / 26.6 / 27 beta 上普遍触发 `0xe8008024`「provisioning profile is banned」，多设备同时中招，有开发者反馈已联系 Apple 开发者支持但无回复无解法。#709（21 条）是 Apple GSA 认证接口返回 429 限流。#509 的 iOS 27 兼容性仍未闭环。
- 健康度: stars/subscribers = 124:1，但 75 万下载量直接推翻了空心化判断。254 个 open issue 的构成几乎全是用户求助工单（Apple ID 登录失败 #681–#688、签名错误 #716、设备额度用尽 #715、Developer Services 403 #713、pairing file 缺失 #723），是单人维护对海量用户的必然堆积，不是弃坑。作者提交 304 次，第二名 33 次，占比约 78%。

**风险与争议**:
- **compliance**: 核心机制是拿免费 Apple ID 的开发者证书给非 App Store 应用签名，游走在 Apple 开发者协议边缘。#583 已实测出 Apple 主动封禁 provisioning profile。
- **dependency**: 全链路依赖 Apple 未公开的私有接口（gsa.apple.com、Developer Services），#709 的 429 限流和 #713 的 403 已是预演。
- **stability**: iOS 大版本更新常导致整体失效，修复节奏被动跟随 Apple。
- **bus_factor**: 单人主导 78% 提交。

**技术备注**: TypeScript，MIT 许可（名称与 Logo 单独保留），跨三平台桌面客户端。

**它是什么**: 俄语区的反封锁代理工具。README 自称"网络协议栈研究工具"，那是免责措辞；实质是 Go 写的用户态 TCP 隧道加 SOCKS5 客户端，配合自建 VPS 出口节点。

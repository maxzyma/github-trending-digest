### [openinterpreter/openinterpreter](https://github.com/openinterpreter/openinterpreter) — NEW ⭐ 65,516（+299）| Rust | 信源：中

**它是什么**: 知名开源项目 Open Interpreter 的官方组织重写版。老版是让你「在终端里用自然语言驱动写代码、跑命令」的 Python 工具；新版把整仓改写成 Rust，并直接 fork 自 OpenAI 的 Codex CLI，主打「用一套 agent 外壳把便宜/本地模型的能力榨到最好」。

**解决什么问题**: 强模型（如 GPT/Claude 旗舰）调用成本高，而便宜或本地开源模型单独用时能力弱、不稳。openinterpreter 想用统一的 agent harness（沙箱执行、工具调用、skill 编排）补齐低成本模型的短板，让终端里的「自然语言→执行代码」在不烧钱的前提下可用。

**谁在用、怎么用**（来自 Issues/官方）:
- 场景 1: 终端内自然语言驱动写码/执行，配 native 沙箱（macOS/Linux Landlock/Windows），并能作为 ACP agent 接入编辑器、用 QA skill 驱动浏览器与原生 App 测试。
- 场景 2: 接本地/开源模型仍是长期痛点——历史 issue #964（OogaBooga endpoint 兼容，28 评论）、#1371（llama-3.1 70B 卡死）、#1220（ollama llama3:70b 跑不起）显示低成本模型适配稳定性差。

**社区怎么评价**:
- 正面: 老版有深厚口碑（2023 年 HN 117 分 / 58 评论），Rust 重写发布获 InfoQ 等行业媒体报道。
- 负面: 重写本身在 HN/X/Reddit 无独立社区讨论；仅有行业评论在探讨「AI 辅助重写他人开源项目」的伦理/许可问题。
- 健康度: 65,516 stars / subscribers 463（≈142:1，属知名老仓历史积累，非短期虚高），open issues 274，昨日仍活跃 push；贡献榜几乎全是 OpenAI Codex 团队账号（因 fork 自 openai/codex），原作者 KillianLucas 仅 175 提交。

**风险与争议**:
- **dependency**: 本质是 OpenAI Codex CLI 的 fork，技术路线与命运高度绑定上游。
- **stability**: 仍是 v0.0.x 早期版本，历史 issue 显示低成本/本地模型适配脆弱。
- **bus_factor**: 原作者贡献占比极低，主力是外部 OpenAI 工程师，长期治理归属不清晰。
- **重写身份争议**: 官方主仓从 Python 原创转为 Codex fork，引出许可与「是否还是同一个项目」的讨论。

**技术备注**: Rust 重写，fork 自 openai/codex；native 沙箱（Linux Landlock / macOS / Windows），支持 ACP agent 接入与 skill/QA 驱动。原 Python 版转为社区维护 fork（endolith/open-interpreter）。

### [YimMenu/YimMenuV2](https://github.com/YimMenu/YimMenuV2) — NEW ⭐ 1,429（+38）| C++ | 信源：中

**它是什么**: 面向《GTA 5: Enhanced》的实验性 mod / 作弊菜单（cheat menu）。玩家把它以 DLL 形式注入游戏，在游戏内弹出一个功能面板，用来改载具、单刷抢劫任务、修改金钱/解锁等。

**解决什么问题**: 想在 GTA5 里做单机改造、载具编辑、任务单刷或自定义体验的玩家，原本要手动改内存或拼零散工具。YimMenuV2 把这些能力打包成一个可注入的菜单。但它当前不解决联机场景——GTA5 Enhanced 切到 BattlEye 内核级反作弊后，本菜单没有 bypass。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 玩家 disable BattlEye 后注入 YimMenuV2.dll，配合 FSL 把存档改道本地磁盘做进度隔离，用于载具编辑器、Heist 单刷、金钱/解锁。功能请求活跃：#125 Solo Heist（42 评论）、#440 保存改装载具（29）、#29 Lua API（30），说明有真实深度使用者。
- 场景 2: 反作弊是核心痛点——#930「take me out of the game battleye」（48 评论，最热）、#532「开 BE 后卡在佩里科岛任务」（33 评论）：本次上榜正因 Enhanced 切到 BattlEye 后暂无 bypass。

**社区怎么评价**:
- 正面: Issue 区活跃（多个 30+ 评论热帖），30 位贡献者、最近 commit 2026-07-11，维护高度活跃。
- 负面: 官方 README 明说公开房会因 heartbeat failure 被合法房主踢出；无 BattlEye bypass。
- 健康度: 1,429 stars / subscribers 66（≈21.6:1，作弊工具属正常），open issues 238（活跃 bug 堆积，非空心），forks 355，仓龄 2023-08 至今，GPL-2.0 未归档。

**风险与争议**:
- **compliance**: GTA5 作弊菜单，违反 Rockstar ToS。
- **privacy**: GTA Online 使用有明确账号封禁风险，BattlEye 为内核级反作弊。
- **stability**: 官方标注 experimental，无 BattlEye bypass，公开房会被踢/卡任务。

**技术备注**: C++ 编写，DLL 注入式 mod 菜单，GPL-2.0；社区共识为仅建议用于 Story Mode / 私服，联机使用封号风险高。

## 如何理解今天的热度信号

- **skills 生态多形态化是真信号，但短龄单仓仍需 grounding**: 工程（mattpocock/skills）、设计（hallmark）、营销（marketingskills）、护栏（dcg）同日成簇，反映「把职能经验固化成 skill」的方向确实在扩散；但其中 hallmark 等短龄仓 subscribers 偏低，选型/引用前应看 forks 与真实 issue。
- **知名老仓的高 ratio 与收藏型仓的高 ratio 都不等于虚高**: openinterpreter（142:1）是 2023 年老仓历史 star 积累，awesome-llm-apps / exercises-dataset / maths-cs-ai-compendium 是收藏/数据/教材型仓，subscribers 偏低是结构性正常，不宜按 100:1 阈值单独判虚高。
- **真正需要谨慎的是合规与有效性**: YimMenu 是明确违反 ToS 的作弊工具、有封号风险；HKUDS 的交易/tutoring agent 是学术团队真实产出，但实盘与教学效果缺第三方验证——这两类的热度都应与合规边界和效果证据分开来读。

### [amadeusprotocol/node](https://github.com/amadeusprotocol/node) — NEW ⭐ 4,578（+1,397）| Rust/Elixir | 信源：中

**它是什么**: 一条加密货币公链的节点软件。这条链叫 AMA Protocol，代币是 $AMA，它的核心卖点是"挖矿别浪费算力"——传统比特币式挖矿让矿机反复算无意义的哈希，AMA 想让矿工改去算 AI 里最常用的矩阵乘法（MatMul），顺手把算力变成"有用的 AI 计算"。它同时自称是"给 agent 用的隐私 Layer 1"，区块 500ms、WASM 智能合约、BLS12-381 签名。注意这个仓库的 GitHub **description 是空的**，语言标签写 Rust，但实际代码是 Rust（约 675KB，做性能敏感的 NIF）+ Elixir/Erlang（约 495KB，节点主体 `amadeusd`，OTP 应用名 `:ama`）的混合体，只读仓库首页无法判断它是什么。

**解决什么问题**: 它想解决的是"有用工作量证明"（PoUW）这个老问题：PoW 的安全性来自烧电，但烧掉的算力对世界没有产出。把哈希换成矩阵乘法，理论上能让同一份电既保护网络又产出 AI 算力。但 PoUW 最难的一环是**验证**——矩阵乘法算一次便宜、验一次同样贵，没法像哈希那样"算难验易"，而公开的 DOCS.md 与官方文档里没有给出这个问题的方案，只在参数表里写了 "UPoW: MatMul"。也就是说，它宣称解决的问题和它公开展示的设计之间，还有一段没有填上的距离。

**谁在用、怎么用**（来自 Issues/官方文档）:
- 场景 1: **跑验证节点挖 $AMA**。README 的主体内容是 Ubuntu 24.04 上 podman 构建、systemd 自动更新、以及为跑满 1Gbps UDP 而调 `net.core.wmem_max` 等内核参数——面向的是矿工/节点运营者，不是应用开发者。
- 场景 2: **写 WASM 智能合约**。`contract_samples/` 下有 AssemblyScript 和 Rust 两套样例（如 counter.wasm），配 `Testnet.deploy` / `Testnet.call` 的 REPL 调用路径；#14/#15/#17 是围绕 Rust 合约 SDK 的讨论。
- 场景 3: **技术性讨论确实存在但极少**。#11（21 条评论）讨论挖矿难度调整，维护者要求提出者给出理由后有实质来回，是全仓唯一有工程含量的长讨论；#8 由核心开发提出 ANR 流量退避。
- 场景 4: **生产采用无任何证据**。官方文档自述是实验性协议，官方 X 账号自己在警告"未授权任何交易所上线 $AMA"，说明当前围绕它的活动主要在投机侧。

**社区怎么评价**:
- 正面: 参数表和文档结构是齐的（区块时间、epoch、签名方案、序列化格式都写明），钱包扩展、TypeScript SDK、区块浏览器、Discord 一整套外围设施都已搭起来；#11 这类难度调参讨论说明确有真实矿工在跑节点。
- 负面: 8-18 至 8-19 两天集中涌入的 #28（正文 "Hxhdhjd"）、#29（正文 "Node"）、#30（空正文）、#31（"给我任务"）不是技术反馈，是刷贡献痕迹；HN 与 Reddit 均零讨论；X 上基本只有官方号 @ama_protocol 自推；媒体侧只有 2025-09-25 一篇 GlobeNewswire 新闻稿被十余个站点转载，**零独立技术评测、零第三方审计**；团队匿名，只自称"前大厂工程师"。
- 健康度: 4,578 ⭐ / 15 subscribers（≈305:1）/ 85 forks / 9 open issues，2024-03-07 建仓（2.4 年）。vans163 一人 684 commits，其余 4 人合计 7 commits——**单人占 ≈99%**。近 40 次提交的信息基本都是 `harden`、`fix stats` 这类一行短句，无法从提交历史读出演进脉络。今日 +1,397 相当于它历史总 star 的 30%。

**风险与争议**:
- **vanity**: 这是今天证据链最完整的一例——官网挂 "Airdrop is Live" 与 amahub 任务体系，star 暴涨时间线与 #28~#31 那批灌水 issue 精确吻合，同时 HN/Reddit 零讨论、无第三方评测。单日 +1,397 而 watcher 仅 15 人，是"任务换 star"而非采用曲线的典型形状。
- **compliance**: **仓库无 LICENSE 文件**。法律上这等于保留全部权利——任何人都无权使用、复制或分发这份代码，而它是一条要求第三方运营节点的公链。README 只有免责声明与 OFAC 提示。
- **bus_factor**: 一条公链的 99% 代码由单一匿名开发者维护，其余贡献者合计 7 次提交。共识层出问题时没有第二个人能接。
- **stability**: 官方文档自述"实验性协议，功能可能变更或永不实现"；无第三方安全审计；PoUW 的验证方案未在公开材料中给出。
- **cost**: 节点运营需要按 README 调内核 UDP 缓冲到 256MB 量级并跑满 1Gbps，加上 MatMul 挖矿本身的算力成本，参与门槛与电费风险由节点运营者独担；同时官方已警告存在冒名交易平台。

**技术备注**: Elixir/Erlang（OTP 应用 `:ama`，节点二进制 `amadeusd`）+ Rust NIF 混合，GitHub 语言标签为 Rust；无 license；2024-03-07 建仓。协议参数：500ms 出块、100,000 块一个 epoch、10 亿 AMA 上限、BLS12-381 签名、WASM 合约、排序 Merkle 树证明、自研 VecPak 序列化。外围有 Chrome 钱包扩展、TypeScript SDK 与区块浏览器。

### [marceloprates/prettymaps](https://github.com/marceloprates/prettymaps) — NEW ⭐ 13,160（+63）| Python | 信源：强

**它是什么**: 一行 Python 代码把任意地址画成一张海报级城市地图。你给它 "Barcelona" 或一组经纬度，它自动从 OpenStreetMap 拉取建筑轮廓、水系、绿地和街道网络，用 matplotlib 渲染成可打印、可裱框的艺术图。有 Streamlit 在线版（prettymaps.streamlit.app），不写代码的人也能直接用。这是 2021 年建仓的知名长尾项目，今天首次进入本 tracker。

**解决什么问题**: 做这类地图海报以前是一条手工流水线：先从 OSM 导出数据，再进 QGIS 筛图层，最后进 Illustrator 调配色和排版，一张图几个小时。prettymaps 把这条链压成 `prettymaps.plot("城市名")` 加一个 preset 主题，几十秒出 SVG/PNG。它解决的不是分析问题而是**表达问题**——让不懂 GIS 工具链的人也能产出好看的地理图像。

**谁在用、怎么用**（来自 Issues/PR/HN/第三方教程）:
- 场景 1: **城市海报与礼品图**。这是最主流用法，README 自带 r/prettymaps 版块，X 上的传播基本都是作品展示型。
- 场景 2: **运动轨迹出图**。PR #145（贡献者 postmaxin）刚加入 GPX/KML 轨迹支持，可以把跑步、骑行的实际路线叠在城市底图上——这是一个明确的新刚需场景，也是它最近一轮传播的可能源头。
- 场景 3: **教学与数据可视化入门材料**。CodeCut 等站点有完整第三方教程，Console 期刊做过作者访谈；PR #144 把教程从 Jupyter notebook 换成 marimo 并配了静态文档。
- 场景 4: **容器化批量出图**。PR #148 把 opencv-python 换成 headless 版，正是为了修容器部署。

**社区怎么评价**:
- 正面: HN 口碑是全榜最硬的一档——2021-08 首帖 **982 分 / 74 条评论**，2022-07 的 "Pretty maps in Python" 又拿 301 分，连衍生重写版 prettymapp（chrieke）2023 年都拿了 324 分。审美质量本身获得广泛认可，第三方教程和媒体访谈都留有独立足迹。
- 负面: 几何异常类老 issue 长期未闭环——#51 水体渲染错位、#27 shapely TopologyException、#61/#8 铁路图层报错，多为 2021 年遗留。#150（2026-08-01）是 "Overpass API max retries exceeded"，反映对上游公共 API 的脆弱依赖。
- 健康度: 13,160 ⭐ / 87 subscribers（≈151:1，成熟长尾项目的结构性比值，不构成 vanity 证据）/ 659 forks / open issues 仅 14。贡献者高度集中：marceloprates 228 commits，第二名 chrieke 仅 11。维护是**脉冲式**的——2025-08 之后沉寂近一年，2026-07-27 至 08-07 集中活跃（PR #143~#152），之后再无动作；正式版本仍停在 2025-03 的 v1.4.2，PyPI 也停在同一版本。今日 +63 是全榜倒数第二，属温和回流而非爆发。
- 为什么今天回榜: 无新版本发布，最可能是 7 月底到 8 月初那批 PR（尤其 GPX/KML 轨迹功能与 marimo 文档翻新）引发的二次传播，叠加长尾项目常见的社交转帖回流。

**风险与争议**:
- **compliance**: AGPL-3.0，网络分发场景有传染性——想拿它做 SaaS 出图服务需要开源。**更需要注意的是**：PyPI 元数据此前长期误标为 MIT，直到 2026-08 的 PR #152 才修正；在那之前按 MIT 引入这个库的项目存在合规隐患，值得回查。作者另明确禁止用于 NFT 售卖（此前曾被 AeternaCivitas/geoartnft 盗用且不署名）。
- **bus_factor**: 单人主导（228 : 11），2025 年几乎全年停更，2026 年也只有一段两周的集中提交。
- **dependency**: 重度依赖 osmnx + Overpass API 这套公共基础设施，#150 就是 Overpass 限流导致的直接失败；osmnx 2.0 的破坏性变更需要固定 `osmnx<2.0`。上游一动，出图就断。
- **stability**: 水体、铁路图层的几何异常与 TopologyException 属长期未修的已知缺陷，批量出图时需要人工挑片。

**技术备注**: Python，AGPL-3.0，2021-03-05 建仓；技术栈是 osmnx（拉 OSM 数据）+ shapely（几何运算）+ matplotlib（渲染），输出 SVG/PNG；提供 preset 主题机制与 Streamlit 在线版；正式版本 v1.4.2（2025-03），最后 push 2026-07-30。

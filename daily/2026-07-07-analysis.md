## NEW 项目

### [karakeep-app/karakeep](https://github.com/karakeep-app/karakeep) — NEW ⭐ 26,917（+199）| TypeScript | 信源：强

**它是什么**: 一个自托管的"什么都能收藏"应用。你把链接、笔记、图片、PDF、YouTube 视频丢进去，它自动用 AI（可接 OpenAI 或本地 Ollama）打标签、做全文搜索，还会把网页归档下来防止链接失效。前身是 2023 年发布的 Hoarder，2025 年更名 Karakeep。

**解决什么问题**: Pocket、Raindrop、Omnivore 这类"稍后读/书签"服务好用但托管在别人服务器上，隐私和长期可用性都不在自己手里（Omnivore 已关停就是前车之鉴）。karakeep 把整套书签/read-it-later 搬到自己的服务器，Docker 一键部署，数据和 AI 打标都能留在本地。

**谁在用、怎么用**（来自 Issues/Reddit）:
- 自托管数字囤积者：保存链接/笔记/图片/PDF/YouTube，配 RSS 自动收藏、全文搜索、链接归档；有用户在 14 年老 Mac mini 上跑 25,000+ 书签无压力。
- 真实痛点：#414 登录页归档不干净（绕过 cookie/GDPR banner，63 评，老大难）、#2344 0.30 版内存泄漏 RAM 持续增长（54 评）、#1166 请求为 puppeteer 提供 VNC 客户端以登录网站后归档（39 评）。

**社区怎么评价**:
- 正面: Reddit r/selfhosted 高频推荐，定位为 Pocket/Raindrop/Omnivore 自托管替代；常与 Linkwarden 对比——karakeep 更快、AI 更强，Linkwarden 归档更彻底。多篇独立评测（XDA 等）。
- 负面: HN 讨论零散无高分主帖；默认点开跳源站而非本地归档；非技术用户 Docker 部署仍有门槛。
- 健康度: 26,917 ⭐ / 75 subscribers（≈359:1，成熟自托管应用结构性偏高，forks 1,320、约 176 贡献者佐证真实使用，非空心化）；open issues 659，2024-02 创建约 2.5 年，2026-07-06 仍每日推送。

**风险与争议**:
- **stability**: 0.30 版内存泄漏（#2344），登录态页面归档不干净（#414）。
- **compliance**: AGPL-3.0 + 新增付费 Cloud（$4/月），需留意 open-core 走向。
- **privacy**: 自托管本身利于隐私，但接第三方 AI 打标（OpenAI）时内容会外发。

**技术备注**: TypeScript；Docker 部署，AI 打标支持 OpenAI/本地 Ollama，全文搜索 + RSS 自动收藏 + 网页归档。

### [bradautomates/claude-video](https://github.com/bradautomates/claude-video) — NEW ⭐ 4,282（+427）| Python | 信源：中

**它是什么**: 一个让 Claude"看"视频的 Claude Code skill。你敲 `/watch <链接或路径> "问题"`，它自动取字幕、按需下载视频、抽取关键帧、做带时间戳的转录，再把帧图 + 文字一起交给 Claude 回答。支持 YouTube/TikTok/Loom/X 和本地文件。

**解决什么问题**: Claude 本身不能直接看视频。以前你要自己截图、扒字幕、手动喂给它。claude-video 把"下载→抽帧→转录→喂给模型"打包成一条命令，让 Claude 能分析录屏 bug、定位复现帧、总结指定时间段。

**谁在用、怎么用**（来自 Issues/X）:
- 视频视觉反馈：定位录屏 bug 的复现帧、用 `--start/--end` 分析指定时间段、给视频画面反馈。
- 概念被认可但原仓 grounding 薄：已出现多个衍生/竞品仓（Newuxtreme/watch-video-skill、pheistman/claude-watch 等），但原仓 issue 几乎无实质讨论——唯一有评论的 #31 是 fork 广告。

**社区怎么评价**:
- 正面: 作者 Brad Bonanno（AI 自动化 YouTuber）配套视频引流，被 Paradigm CTO、Agentic 创始人等 star。
- 负面: HN 无讨论；Reddit 无实质线程；X 以作者自我推广为主，未见独立开发者反馈；近 7 天各渠道"无提及"。
- 健康度: 4,282 ⭐ / 30 subscribers（≈143:1）；forks 607（比值偏高，多为一次性）；open issues 34 但讨论稀薄；2026-04-24 创建仅约 2.5 个月，contributors 仅作者 1 人。

**风险与争议**:
- **vanity**: 热度（4.3K 星 + YouTube 引流）与真实社区 grounding（HN/Reddit/X 独立反馈、issue 讨论）严重不匹配，传播由作者内容营销驱动。
- **cost**: token 成本被帧主导——每帧即一张图，长视频图像 token 快速累积（README 自承）。
- **dependency**: 强依赖 yt-dlp + ffmpeg 外部二进制，无字幕时依赖 Groq/OpenAI Whisper API。
- **bus_factor**: 单一作者，v0.1.3 早期版本，长视频覆盖稀疏需重跑。

**技术备注**: Python；`/watch` 命令，字幕优先 + 场景感知/关键帧抽帧 + 时间戳转录，帧图与转录一起交给 Claude。

## 如何理解今天的热度信号

今日"值得放心点开"与"需谨慎解读"的分野比较清晰：

- **成熟供给回流是真信号**：firecrawl/zvec/agent-skills（RE）+ karakeep/awesome（首入）都有多年维护史、活跃 issue、外部独立讨论。karakeep 359:1、awesome 58:1 这类比值要么属自托管应用结构性偏高、要么本就健康，不能与短龄爆款一刀切。
- **短龄内容营销驱动的需甄别**：claude-video（143:1、2.5 个月龄、单人、YouTube 引流、HN/Reddit 零讨论）是今日最典型的"热度与社区足迹落差"样本；claude-skills、taste-skill 的短龄高比值信号也未消。
- **作者光环项目要组合看**：CodexBar（346:1）、gastown 比值高源于知名作者高传播，但 forks/issue/PR 显示真实使用，非空心化。

结论不变：Trending 单日增量与 stars/subscribers 比值都只是"注意力"指标，判断"是否值得采用"要看 issue 真实度、外部独立讨论、仓龄与维护结构的组合。

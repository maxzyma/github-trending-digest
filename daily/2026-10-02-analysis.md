## 首次上榜项目

### [tile-ai/tilelang](https://github.com/tile-ai/tilelang) — NEW ⭐ 8,521（+163）| Python | 信源：强

**它是什么**: 一门专门用来写"算子"的编程语言。算子是 AI 模型里最底层的计算单元（矩阵乘法、注意力计算等），决定模型在显卡上跑多快。传统上要用 CUDA 手写，门槛很高；TileLang 让工程师用接近 Python 的写法描述计算，再由编译器生成针对 NVIDIA、AMD、华为昇腾等硬件优化过的代码。

**解决什么问题**: 新模型结构（新的注意力机制、MoE 路由、低精度量化）往往需要专门的高性能算子，手写 CUDA 动辄上千行、只有少数专家能维护。TileLang 的论文称约 70 行代码即可达到 FlashMLA 98% 的性能，把"写一个快算子"从专家活变成普通算法工程师也能做的事，并且同一份代码可以移植到不同硬件。

**谁在用、怎么用**（来自 Issues/X/技术报告）:
- DeepSeek：据 DeepSeek-V4 技术报告，V4 用 TileLang 融合算子替换了大部分细粒度 PyTorch 算子，训练和推理都在用；V3.2-Exp 发布时官方账号推荐用 TileLang 做研究原型。9 月底开源的昇腾版编程栈同样基于 TileLang（HN 10-02 有转载帖，5 分 0 评论）。
- SGLang：DeepSeek-V4 首日支持接入了 TileLang 实现的 mHC 算子，RL 训练中也用到 TileLang 注意力算子。
- vLLM：有人提议回退到 TileLang 参考算子（vllm#30644），被标记为不计划实施，说明主流推理框架尚未全面依赖它。

**社区怎么评价**:
- 正面: 采用证据来自一线模型厂商和推理框架，而不是 star 数；X 上有研究者评价其"正在获得关注"。
- 负面: #3301 一次提交了 49 个可复现的正确性 bug（仍 open）；#2314 `cudaDeviceReset` 符号缺失（16 评论）；新卡兼容反复出问题，如 #1871 RTX 5060 Ti / Blackwell 编译失败、#1787 B200 上矩阵乘性能下降；#290 动态 shape 下结果错误。
- 健康度: 8,521 stars / 45 subscribers（约 189:1），对基础设施库不宜单凭比例判断；约 218 名贡献者，但头号维护者提交数是第二名的 9 倍以上；最新版 v0.1.15（9-30），大约每月一版；open issues + PR 共 396。

**风险与争议**:
- **stability**: 正确性 bug 批量出现、Blackwell 消费级显卡兼容差，版本号仍在 0.1.x。
- **bus_factor**: 提交高度集中在单一核心维护者。
- **榜单时点**: 本次上榜大概率由 DeepSeek 昇腾开源新闻带动，单日 +163 不代表采用速度的变化。

**技术备注**: Python 前端 + 基于 TVM 的编译栈，支持 NVIDIA / AMD / 昇腾等后端，MIT 许可（API 显示 NOASSERTION，LICENSE 文件为 MIT）；论文 arXiv 2504.17577。

### [pablostanley/yoinks](https://github.com/pablostanley/yoinks) — NEW ⭐ 2,897（+361）| TypeScript | 信源：中

**它是什么**: 在终端里下载网络视频的小工具。粘贴一个 YouTube、Instagram、TikTok 等平台的链接，选清晰度或只要音频，就能保存到本地。作者是设计师 Pablo Stanley，这是他的第一个终端界面（TUI）作品。

**解决什么问题**: 普通用户下载视频通常要去满是广告和可疑跳转的下载网站；开发者则直接用 `yt-dlp` 命令行，但参数多、不直观。yoinks 在 `yt-dlp` 外面包了一层好看的交互界面，主打"没有可疑广告"。

**谁在用、怎么用**（来自 GitHub Issues/X）:
- 在终端下载单个视频或提取 mp3；#34 用户表示喜欢这个工具，同时要求自定义下载路径。
- 有人仿照它做了桌面版衍生项目；也有用户问能否在 Android 的 Termux 上运行（#39）。
- 尚不支持播放列表和批量下载，`--best`、`--mp3` 等脚本参数仍在 roadmap。

**社区怎么评价**:
- 正面: 界面和上手体验受到认可，npm 近 30 天下载约 5,400 次。
- 负面: #8（评论最多）YouTube 报"Requested format is not available"或 403，需手动 `yt-dlp --update`；#29 无法粘贴；#32 下载的视频在 QuickTime 里只有声音没有画面。X 上唯一可见的独立评价是质疑"这只是 CLI 工具的 TUI 包装"。
- 健康度: 2026-07-16 创建，最后推送 2026-07-17；只有作者一名贡献者；修复 QuickTime 兼容（#40）、支持指定目录（#35）等外部 PR 均未合并。HN、Reddit 均无讨论。

**风险与争议**:
- **compliance**: 本质是视频平台下载器，与 YouTube 等平台服务条款冲突，下载内容的版权责任在用户。
- **dependency**: 功能完全依赖 `yt-dlp`，平台一改接口就失效，#8 即是例子。
- **bus_factor**: 单人维护，近三个月无提交，外部 PR 积压。
- **vanity**: 9 月下旬的二次走红主要来自作者知名度和聚合号转发，没有对应的新版本或技术讨论。
- **仿冒仓**: 已出现同名仓库以"Windows 本地运行"为卖点分发，下载时需确认来源是 `pablostanley/yoinks`。

**技术备注**: TypeScript / Node 终端界面，底层调用 `yt-dlp` 与 `ffmpeg`，MIT。

### [Friedrich-M/UniMate](https://github.com/Friedrich-M/UniMate) — NEW ⭐ 1,625（+217）| Python | 信源：中

**它是什么**: 一个让 3D 角色"动起来"的 AI 模型。给它一个已经装好骨骼的 3D 模型（人、狗、鸟、鱼、虫子、蛇，甚至带关节的物体）和一句文字描述，它就生成对应的动作动画。是 SIGGRAPH Asia 2026 论文的官方代码，作者来自普林斯顿、UC Berkeley、MIT、南洋理工。

**解决什么问题**: 以往的动作生成模型大多只认一种骨架（通常是人形），换一种动物就要重新收集数据、重新训练。UniMate 用一个统一模型覆盖不同结构的骨架，游戏和 3D 内容团队不必为每种角色单独做动作模型。

**谁在用、怎么用**（来自 GitHub Issues/X）:
- 游戏角色动画：#4 中作者确认模型权重和生成的动作可以商用（MIT），提问者计划用于游戏角色。
- 自定义骨架：#8（14 评论）中用户给自己的四足模型生成动作，出现"四足角色被生成为直立姿态"的问题，作者无法复现，9-30 关闭。
- 复现与再训练：#2（19 评论）社区要求放出权重，9-27 已在 HuggingFace 发布预览版；#6（16 评论，9-30 关闭）有用户无法复现 demo 和论文效果，作者随后补发了处理非训练分布骨架的预处理脚本。

**社区怎么评价**:
- 正面: 作者回复及时，issue 讨论质量高；代码、数据集（UniML3D）、训练推理脚本和预览权重分批放出，开放程度在 SIGGRAPH 论文仓里算完整。
- 负面: 复现难度和四足朝向问题在多个 issue 中反复出现；搭配自动绑骨工具时兼容性弱（#26 仍 open）。
- 健康度: 1,625 stars / 42 subscribers（约 39:1），比例正常；只有作者一名代码贡献者；X 上主要是作者和合作者自推，HN、Reddit 无讨论。

**风险与争议**:
- **stability**: 权重是预览版，复现效果和非人形骨架的姿态问题尚未稳定解决。
- **bus_factor**: 单一维护者，学术项目在论文发表后维护周期不确定。
- **dependency**: 训练用到的部分动物动作数据来自商业资产包，无法再分发，完整复现训练需另行购买。

**技术备注**: PyTorch，权重托管在 HuggingFace，论文 arXiv 2609.05415，MIT。

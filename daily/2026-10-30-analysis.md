## 新上榜项目

### [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot) — NEW ⭐ 7,528（+1,199）| TypeScript | 信源：中

**它是什么**: 一个桌面聊天应用，界面像 Telegram。联系人列表里每个"联系人"都是一个 AI 助手，你给它发消息派活，它在自己的电脑上完成。这台电脑可以是云端 Linux 桌面、本地隔离虚拟机，也可以在你明确开启后直接是你自己的 Mac 或 Ubuntu。

**解决什么问题**: xAI 的 Grok Bot 提供了"一组 bot 当聊天联系人"的用法，但它是闭源云服务，只能用 Grok 模型，需要付费订阅。OpenMausBot 把同样的形态做成开源版：每个助手可以选不同模型，底层调用你本机已装好的 `claude`、`codex` 或 `grok` 命令行，数据存在本地 `~/.openmausbot`，敏感操作会弹出审批卡片。它还通过 Composio 接入 500 多个应用，也能经 USB 操作 Android 手机。

**谁在用、怎么用**（来自 Issues/X）:
- 场景 1: 已有 Claude Code 或 Codex 订阅的开发者，用多个助手各管一台虚拟机跑浏览、点击、手机自动化等任务；社区在推进多机电脑池（#508）等功能。
- 场景 2: 多语言用户在实际使用移动端和桌面端，例如日本用户报告 iOS 上日文假名输入消失或被误发送（#1334），中文用户在补全简体中文翻译，目前缺 1,280 个词条（#1880）。
- 场景 3: X 上一位提过两个 PR 的独立贡献者称它是"目前最接近 Grok Bot 的开源项目"，但也提到早期因没有 iOS 版卸载过。

**社区怎么评价**:
- 正面: 迭代很快，上线约 80 天发了 91 个版本，10-30 发布 v0.1.134；除作者外有几位贡献者提交了数百次；提供签名公证的 macOS 安装包、Windows 和 Ubuntu 安装包以及 iOS 客户端。
- 负面: Ubuntu Wayland 下控制主机仍未开启（#345）；部分高讨论度 PR 积压较久，如 #1126（9 月提交、45 条评论）仍未合并；一篇第三方评测认为它不如 Grok Bot 顺滑。
- 健康度: 7,528 stars / 19 subscribers ≈ 396:1；1,119 forks；550 个 open 项中 196 个是 PR；作者 milind-soni 提交 4,212 次，占前几名贡献者的约七成；2026-08-11 创建。HN 只有一条 1 分、零评论的帖子，Reddit 无讨论；X 上以作者和 KOL 借 Grok Bot 话题推广为主，独立使用反馈很少。

**风险与争议**:
- **privacy**: 开启主机控制后，助手可以直接操作你的电脑和手机，并通过 Composio 获得第三方应用授权，权限范围很大，公司电脑上使用前需评估。
- **dependency**: 依赖 Claude、Codex、Grok 命令行及各自订阅，云桌面依赖 Composio 和赞助方服务。
- **vanity**: 星数与关注者比例偏高，传播主要靠 KOL 借热点，HN 和 Reddit 上没有讨论；大量 fork 和外部 PR 说明有真实开发者参与，热度需要谨慎解读。
- **bus_factor**: 提交高度集中在作者一人。
- **compliance**: README 大量使用 Grok Bot、Meta Muse 等他方产品名做对比宣传；项目声明没有发行代币，市面上同名代币与其无关。

**技术备注**: TypeScript + React 19 + Electron，Apache-2.0 许可；可用 `npm i -g openmausbot` 安装，本地在 127.0.0.1 起一个调度服务管理各助手进程。

### [CopilotKit/OpenBot](https://github.com/CopilotKit/OpenBot) — NEW ⭐ 8,184（+247）| TypeScript | 信源：中

**它是什么**: CopilotKit 团队做的"AI 同事"平台，公司可以把它装在自己的服务器上。每个 AI 同事有独立的容器、Chromium 浏览器、登录状态和文件目录，你像给同事派活一样交代任务。它对网页、文件和 MCP 工具的每一次操作都先经过一道网关，按策略放行或拦下并记录在案；碰到不该独自完成的事，就交给人接手，处理完再交回去。

**解决什么问题**: 企业想用 Grok Bot 这类"带电脑的 Agent"，又不愿把数据和操作交给托管服务。OpenBot 用 Docker Compose 部署在企业自己的环境里，数据存在自己的 PostgreSQL，模型自选。Agent 本身可替换：任何支持 AG-UI 协议的 Agent 都能接入。AG-UI（Agent-User Interaction Protocol）是 CopilotKit 发起的开放协议，规定 Agent 和前端界面之间如何传递消息、状态和工具调用，LangGraph、Mastra、CrewAI 等框架写的 Agent 可以按它接入。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 场景 1: 仓库自带的示例按企业场景配置同事，默认有"通用助理"和"知识库问答"两个，另有风险分析示例，覆盖报销审核、会议纪要转待办、工单分诊。未找到外部团队公开的生产案例。
- 场景 2: 有用户接入电商和第三方工具时踩到策略误判和集成问题：给 Shopify 订单写备注被当成"动钱"操作拦下，退款反而放行（#890）；Composio 插件发错了认证 header（#817）。
- 场景 3: 多同事协作仍有缺口，一个同事记住的事实被误报为另一个同事也记得（#714），内置同事无法转交任务（#399）。

**社区怎么评价**:
- 正面: 团队开发活跃，累计 706 个 PR，46 位贡献者，10-29 仍有提交；审批网关和审计记录直接回应企业对"Agent 能动手"的安全顾虑。
- 负面: README 自标 Beta；10-12 发布 v0.2.0 后 18 天没有新版本；外部用户提交的 issue 较少，大部分讨论来自团队成员。
- 健康度: 8,184 stars / 33 subscribers ≈ 248:1；1,048 forks；52 个 open 项（33 issue、19 PR）；第一贡献者约占 27%，前三名约占一半；2026-08-17 创建。HN 只有一条 8 月的 Show HN（12 分、1 条评论），X 上以 CopilotKit 官方和联合创始人推广为主，Reddit 无讨论。

**风险与争议**:
- **dependency**: 服务端启动需要 CopilotKit Intelligence 的 key，会话和记忆都存在 Intelligence 里；免费开发者计划可在本机 Docker 里运行，生产用量和价格需另行确认。
- **stability**: 仍是 Beta，安全策略有误判（#890），多同事记忆和交接有已知问题（#714、#399）。
- **cost**: 每个同事常驻一个 Chromium 实例，加上自备模型的 token 费用，同事数量多时资源开销明显。
- **vanity**: 星数与关注者比例偏高，HN 和 Reddit 讨论很少，传播以官方推广为主，热度需要谨慎解读。
- **同名混淆**: 与同榜的 nightly-labs/openbot 只是撞名，后者是本地桌面应用、非商业许可，两者代码和定位无关，搜索和安装时注意区分。

**技术备注**: TypeScript，MIT 许可；Docker Compose + PostgreSQL + Bun 1.4 以上部署，模型密钥自备。

## 首次上榜项目

### [xtool-org/xtool](https://github.com/xtool-org/xtool) — NEW ⭐ 9,466（+1,198）| Swift | 信源：中

**它是什么**: 一个命令行工具，让开发者不用 Mac 也能做 iOS 应用。在 Linux 或 Windows 上写好 Swift 代码后，xtool 负责编译、用 Apple 账号签名，再把应用装到连接的 iPhone 上，完成原本必须在 Mac 上用 Xcode 才能走完的流程。

**解决什么问题**: 开发 iOS 应用通常必须买 Mac，因为 Apple 官方的编译、签名、安装工具只在 macOS 上运行。只有 Linux 或 Windows 电脑的开发者以前只能借 Mac、租云端 Mac，或者改用 Flutter、React Native 并把最终打包交给 Mac。xtool 把构建、签名、安装这几步搬到了其他系统上。它仍然需要从 Xcode 安装包里取出 iOS SDK，所以替代的是 Xcode 的构建流程，不是 Apple 的整套开发环境。

**谁在用、怎么用**（来自 Issues/HN）:
- Linux 下的 iOS 开发：用户在 VS Code 加 SourceKit-LSP 里写 Swift 包管理器项目，用 `xtool dev` 构建并装到真机。#302 让 SourceKit-LSP 拿到真实源码路径，#293 修复 SwiftBuild 链接时的 Swift 运行时搜索路径，均为 10 月社区贡献者提交的 PR，尚未合并。
- 离线和受限网络环境：#319 提交离线构建 SDK 的支持，允许使用本地工具集。
- 跨框架需求：#28 请求支持 Compose Multiplatform、Flutter、React Native 构建，10 条评论，2025-05 开到现在，说明目前只覆盖 Swift 包管理器项目。

**社区怎么评价**:
- 正面: HN 讨论扎实。2025-05-11 的"Build iOS Apps on Linux and Windows"（指向 Swift 论坛发布帖）拿到 269 分，2025-05-17 的"XTool – Cross-platform Xcode replacement"拿到 195 分、66 条评论。Linux 用户反响积极，有人认为比基于 VS Code 的 Sweetpad 开发体验更好。
- 负面: HN 评论指出"Xcode 替代"的说法夸大，仍需 Xcode 提供 SDK 和工具链；有人引用 Apple 许可协议，质疑在非 Apple 硬件上构建并上架是否合规。#19 报告 `xtool dev` 卡在连接设备这一步，21 条评论，2025-05 开到现在未关闭。
- 健康度: 星数与 subscribers 比约 225:1，对 2024-11 建仓的开发者工具偏高，但有两次高分 HN 讨论和持续的社区 PR，不足以说明热度失真。open issue 和 PR 93 个，MIT 许可。核心作者 kabiroberai 有 405 次提交，其余贡献者各 1 到 2 次。发版频繁：9-21 的 1.20.0 与 1.20.1、10-05 的 1.21.0、10-14 的 1.22.2。X 和 Reddit 未检索到相关讨论。

**风险与争议**:
- **compliance**: Apple 的 SDK 和 Xcode 许可协议对在非 Apple 硬件上构建应用有限制，自用与上架 App Store 的边界存在争议，商业团队采用前需要自行评估。
- **dependency**: 依赖从 Xcode 提取的 SDK 和 Apple ID 或开发者账号签名；1.22.2 需要伪装成 Pixel 7 设备才能恢复 Apple ID 登录，Apple 再调整认证就可能再次失效。
- **stability**: 没有模拟器和调试器，#19 设备连接问题长期未解决；1.20.0 换用 SwiftBuild 后作者提示还会有兼容问题。
- **bus_factor**: 几乎全部提交来自一名维护者。

**技术备注**: Swift 实现，MIT 许可；底层用 SwiftPM 和 SwiftBuild，附带可编程调用 Apple 开发者服务的 XKit 库；Windows 通过 WSL 使用。今天上榜可能与当天 1.22.2 修复登录有关，未找到明确的外部传播事件。

**主线三：OpenAI 的 Codex 插件生态正在换仓，两个仓同日在榜，装错的风险就摆在榜单上。** `openai/skills`（#3，↑8，26,534 ⭐）README 第一段已经是加粗的弃用告示，明确指向 `openai/plugins`；而 `openai/plugins`（#16，RE，5,818 ⭐，时隔 59 天）正是那个继任仓。旧仓排名比新仓高 13 位、star 数是新仓的 4.6 倍，这是典型的"惯性排名"——Trending 反映的是当下的 star 流入，而 star 流入又跟着搜索结果和转发链走，两者都还停在旧仓上。新仓昨天的提交是 `Add Qodo to curated marketplaces`，旧仓昨天的提交是 `Update skill installer post-install guidance`，说明官方还在给旧仓打迁移引导补丁，而不是已经切干净。要给 Codex 装 skill 的读者，认 `openai/plugins`。

**主线四：榜单解读提醒 — 今日 16 项里 3 项超过 100 天没有推送，其中一个有 21 万星。** `multica-ai/andrej-karpathy-skills` 最后推送 2026-04-20（142 天前），211,484 ⭐；`The-Swarm-Corporation/AutoHedge` 最后推送 2026-05-11（121 天前），今日仍 +494 并跳升 6 位；`MoonTechLab/LunaTV` 最后推送 2026-05-28，且早在 2025 年 10 月就公告无限期停更。另一组要一起看的数字是 stars/subscribers 比：`camofox-browser` 376:1、`hyperframes` 365:1、`diagram-design` 326:1、`markitdown` 318:1、`i-have-adhd` 301:1。这个比值本身不能判定任何事情——`markitdown` 是微软维护、635 个 open issue 的成熟工具库，高比值只说明它被大量当作"书签"收藏。判断要看比值与其他信号的组合：`i-have-adhd` 的高比值有 HN 324 分 256 评论的真实讨论托底，而 `AutoHedge` 的日增翻倍则找不到任何对应的社区事件。看今日榜单时，把"最后推送日期"和"有没有对应的公开讨论"放在排名前面看。

## 首次上榜项目

### [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) — NEW ⭐ 30,662（+656）| Python | 信源：强

**它是什么**: 给编程 AI 助手装的一份"说话方式"补丁。核心是一份 140 行的规则文件，写了 10 条要求：第一行直接给下一步动作、多步任务用编号、给具体分钟数而不是"一会儿"、列表最多 5 条、不要开场白也不要"希望有帮助"这类收尾。README 里放了同一个答案的前后对照——原本三段铺垫里埋着的结论，变成"先跑 `npm install jsonwebtoken@latest`，然后改 `src/auth.ts:42`"。规则借鉴自临床读物《The Adult ADHD Tool Kit》，但作者在标语里就写明"不需要真有 ADHD 诊断"。

**解决什么问题**: 装之前，你问 agent 一个问题，答案埋在客套和铺垫下面，得滚屏找；装之后，答案在第一行。它不给 agent 新增任何能力，只压缩你读答案要花的时间。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 日常写码时让 agent 少绕弯子，是 HN 讨论里最常见的用法；但最高赞评论给出的是更省事的替代——"我现在直接在 prompt 里打一句 'I have adhd' 就够了，不用装这个仓"。
- 把 10 条规则 fork 下来改成团队自己的输出规范。这也是仓内 `evals/` 与 `tests/` 目录存在的原因——作者试图让"输出规范"变成可回归测试的东西。
- 跨平台安装：仓内同时提供 `plugin.json`、`gemini-extension.json`、`qwen-extension.json`、`kimi.plugin.json`、`opencode.json`，覆盖 Claude Code、Gemini、Qwen、Kimi、opencode。但 issue #91 与 #119 反映 Codex 与 Hermes 上的安装说明是错的，照做没反应。

**社区怎么评价**:
- 正面: 2026-09-08 上 HN 首页（[item 49610631](https://news.ycombinator.com/item?id=49610631)），324 分、256 评论，是本仓最硬的社区证据。主流态度是"认同问题、质疑形式"。仓内 issue 讨论质量高于同类 skill 仓——#99 有人跑了 A/B 实验，质疑规则 8（"错误要就事论事"）会诱导 agent 乱归因。
- 负面: HN 上被两条独立高赞反复追问的是同一件事——**61 个文件、9,223 行，就为了一份 140 行的 md**（本地 clone 实测：`git ls-files` 61 项、总行数 9,223，`skills/i-have-adhd/SKILL.md` 140 行）。另一类批评是"为什么这是 skill 而不是 CLAUDE.md 或 output-styles"，以及实用层面的"Claude 只能保持几轮简洁，之后又变啰嗦"。还有一条来自 ADHD 患者的抵触：没这病的人拿这个当梗，观感不好。
- 健康度: 30,662 ⭐ / 102 watchers = **301:1**，比值很高；open issues 33，forks 1,864，最后推送 2026-09-08，活跃。贡献者集中但不是单人仓——作者 ayghri 104 次提交，第二名 15 次，另有 10 余名外部贡献者提 PR 和翻译（README 已 7 语种）。仓龄不足 4 个月（创建于 2026-05-13）。

**风险与争议**:
- **vanity**: 301:1 的 stars/watchers 比、KOL 转发主导的 X 传播路径、4 个月仓龄换 3 万星，与"核心内容只有 140 行"之间存在明显落差。但与今日其他高比值项目不同，它有 HN 324 分的真实讨论托底，不能简单归为空心。
- **未验证收益**: issue #4 是最早也最核心的一条——"有人测过这会不会降低模型表现吗？"输出变短可能损失推理质量。该 issue 开了四个月，至今没有 benchmark 结论。仓内有 `evals/` 目录，但没有对外发布的对照数据。
- **stability**: 规则 9"列表最多 5 条"被模型照字面执行，把本该完整的列表截断（#96）；`SKILL.md` 的 metadata 嵌套结构会让严格解析器加载失败（#93）；多平台安装文档失效（#91、#119）。
- **提示注入面**: 仓内 `AGENTS.md` 有一节 "AI Agora discussions"，把 [issue #127](https://github.com/ayghri/i-have-adhd/issues/127) 指定为"agent 可以发言的共享论坛"。逐字读该节，它的写法是**收窄权限**（"agent 只能在带 `AI Agora` 标签的 issue 下评论""不得评论非自己创建的 PR""标签本身不授权任何仓库修改"），不是命令 agent 去发帖。但它仍然构成一个事实：任何 clone 该仓并读 `AGENTS.md` 的 agent，都会读到一条指向特定 issue 的行为指引。把第三方仓的 `AGENTS.md` 交给自己的 agent 阅读，这一层的边界值得读者自己划。

**技术备注**: 主语言 Python（脚本与 eval 部分），实际交付物是 markdown。Skill 正本在 `skills/i-have-adhd/SKILL.md`，Cursor 副本在 `.cursor/skills/` 下需手工保持同步。仓内含 `hooks/`、`extensions/`、`tests/`、`evals/` 与 5 套平台清单文件，这也是"9,223 行"的来源。

### [viarotel-org/escrcpy](https://github.com/viarotel-org/escrcpy) — NEW ⭐ 11,413（+178）| JavaScript | 信源：中

**它是什么**: 把安卓手机屏幕投到电脑上、用电脑键鼠直接操作手机的图形化工具。底层是命令行工具 scrcpy，Escrcpy 用 Electron 给它套了一个人人会用的界面，跨 Windows/macOS/Linux，Apache-2.0。属于成熟老项目首次进入本 tracker（创建于 2023-09-15），不是新项目。

**解决什么问题**: 原版 scrcpy 只有命令行，参数几十个。Escrcpy 把连接（USB / Wi-Fi / 局域网自动发现）、多设备管理、录屏截屏、文件传输、键鼠映射都变成点选。3.0 之后又加了 MCP + 视觉识别的自动化——用自然语言批量控制多台设备，按画面内容触发脚本而不是按固定坐标。

**谁在用、怎么用**（来自 Issues/发布记录）:
- 多设备同时操作是主力场景，issue 区大量围绕多台手机的连接与同步。
- 3.0 起的 MCP 能力把它从"投屏工具"推向"agent 可驱动的手机自动化层"——issue #614 是用户主动提的 MCP 支持诉求，已在 3.0 落地。
- 功能诉求集中在 #419（Logcat）、#229（剪贴板同步模式）、#569（把手机当电脑麦克风）。

**社区怎么评价**:
- 正面: 版本驱动明显——9 月 1 日发布 v3.2.0（内嵌投屏体验重做、置顶/全屏、键鼠映射更稳、官方 Linux ARM64 构建、修 Windows 启动与音频转发），8 月 3 日的 v3.0.8 引入 MCP 自动化架构，中文技术站 8 月起集中报道。今天上榜大概率是这条路径的延迟效应。
- 负面: #627"3.0.8 内存泄露、无法正常使用"10 条评论，是当前最热且带 bug 标签；#636（9-08）"新版本突然无法投屏"，说明 3.x 稳定性仍在收敛。
- 健康度: 11,413 ⭐ / 57 watchers = 200:1，对面向普通用户的桌面工具属正常区间（大量人收藏当工具书用），单看这个比值不足以判 vanity。forks 795，open issues 21，近 8 周持续有提交。但贡献者极度集中：viarotel 一人 1,344 次提交，第二名仅 5 次。issue 多为中文，用户盘偏国内。

**风险与争议**:
- **bus_factor**: 99% 提交来自单一作者，无第二维护者，提交呈脉冲式（多周为 0）。
- **stability**: 3.x 系列连续出现内存泄露（#627）与投屏失效回归（#636）。
- **dependency**: 完全依赖上游 scrcpy 与 ADB，上游 4.0 升级已带来适配工作量；AI 自动化能力还额外依赖 AutoGLM 与外部模型 API。
- **社区足迹偏中文**: HN 零讨论，Reddit 无实质专帖（上游 scrcpy 有独立社区但未见 Escrcpy 讨论）。英文侧 grounding 弱，热度主要来自中文软件推荐站与 GitHub 本身。

**技术备注**: Electron + Vue，Apache-2.0。发行版覆盖 Windows / macOS / Linux（3.2.0 起含官方 Linux ARM64）。

## 如何理解今天的热度信号

今天有两组数字值得单独拎出来，因为它们直接影响读榜方式。

**第一组：排名和日增今天大面积脱钩。** `hyperframes` 日增 +2,627（全榜最高）排 #5，`markitdown` +2,047 排 #9，而 `openai/skills` +490 排 #3、`diagram-design` +710 排 #2。日增涨了 5~7 倍的三个项目（hyperframes、camofox、context-mode）排名全部下滑，其中 context-mode 掉 10 位。Trending 的排序不是日增排序，把它当热度排行读会得到相反的结论。

**第二组：stars/subscribers 比要和别的信号一起看，单独用会误判。** 今日比值最高的五个是 camofox 376:1、hyperframes 365:1、diagram-design 326:1、markitdown 318:1、i-have-adhd 301:1。但这五个的性质完全不同：`markitdown` 是微软维护、635 个 open issue 的成熟库，高比值只说明大量人收藏当书签；`i-have-adhd` 的高比值背后有 HN 324 分 256 评论；而 `AutoHedge` 的比值只有 130:1，看着"健康"，实际是 121 天没推送、日增却翻倍且无任何公开讨论对应。**比值本身不是判据，比值与社区足迹的落差才是。**

**一条实操建议**：今天有三个项目（andrej-karpathy-skills、AutoHedge、LunaTV）超过 100 天没有推送，其中一个有 21 万星。看到高星项目时先看 `pushed_at`，再看有没有对应的 HN/issue 活动，最后才看排名。

### [GoogleChrome/modern-web-guidance-src](https://github.com/GoogleChrome/modern-web-guidance-src) — NEW ⭐ 1,808（+159）| TypeScript | 信源：强

**它是什么**: 一套给 AI 编码助手看的"现代 Web 写法手册"。Claude Code、Codex 这类 Agent 写网页前先查它，就知道某个效果浏览器是否已经原生支持、哪些浏览器能用、不支持时怎么降级。上榜的是源码仓，放指南的编写、校准和评测代码；用户实际安装的是分发仓 `GoogleChrome/modern-web-guidance`（5,140 星）。

**解决什么问题**: 模型学到的前端写法停在几年前。让它做一个悬浮卡片或弹出层，它多半会写一段 JavaScript，而浏览器现在用几行 HTML 和 CSS 就能做到。这套指南覆盖 250 个 Web 平台特性，README 称由 Chrome、Edge、Firefox 和 MDN 团队共同维护。维护者在 HN 上说明，默认只推荐已在主流浏览器普遍可用的特性，其余的必须带降级方案。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 写前端前检索指南: 在 Claude Code、Codex 里装成技能，Agent 写 UI 前先取对应条目。X 上有日本开发者分享了装进 Codex 的用法。
- 扫描存量代码: 用 `legacy-scan` 找出项目里可以换成原生能力的旧写法。
- 共建指南: #2111 讨论怎样做浏览器和真机测试，#1415 提议补充以用户体验为中心的指南和评测。

**社区怎么评价**:
- 正面: Show HN 帖 423 分、141 条评论（11-10）。认可的声音集中在"渐进增强本来就该这样做"。
- 负面: HN 上有人担心它在推 Chrome 独有或实验性的特性，也有人说在提示词里写一句"用现代 JS/CSS"就能拿到大部分效果。仓库内 #849 在问推广很早期的特性会不会有害，#2372 指出 `hovercard.md` 里的选择器会让浏览器在每次 DOM 变更时重算整个文档的样式。无障碍专家 Adrian Roselli 写过一篇批评文章，建议不要依赖这套指南。
- 健康度: 1,808 星、32 subscribers，比值约 56:1。302 个 open issue、62 个 open PR，今天仍有提交。提交集中在 Google 员工，前三位合计 900 多次。

**风险与争议**:
- **dependency**: 指南的取向由浏览器厂商主导，接入前先在 AGENTS.md 或 CLAUDE.md 里写明自己项目的浏览器支持范围。
- **cost**: HN 上有一位用户反馈在自己的代码库上跑一次约 5 美元，token 开销需要自己测。
- **privacy**: CLI 默认开启遥测，可用 `DISABLE_TELEMETRY=1` 关闭。
- **bus_factor**: 提交集中在少数 Google 员工，外部贡献者占比低。

**技术备注**: TypeScript，Apache-2.0。安装用 `npx modern-web-guidance@latest install`，也可以不安装直接运行 `search`、`retrieve`、`legacy-scan`。Reddit 本次未能检索。

### [shadcn/improve](https://github.com/shadcn/improve) — NEW ⭐ 10,936（+361）| Markdown | 信源：中

**它是什么**: shadcn/ui 作者写的一个 Agent 技能。你让最强的模型通读代码库，挑出值得改的问题，为每个问题写一份可以独立执行的计划文件，放在 `plans/` 目录下。它自己不改源码，README 的说法是"计划就是产品"。

**解决什么问题**: 最强的模型贵，额度也有限，把它用在逐行改代码上不划算。improve 把工作拆成两段：贵的模型负责判断"改什么、怎么验证、什么时候该停"，便宜的模型照着计划执行。计划里带代码摘录、验证命令和停止条件，按"最弱的执行者也能照做"来写。

**谁在用、怎么用**（来自 Issues/X）:
- 批量产出计划: shadcn 本人在 X 上的用法是趁高端模型可用时集中生成计划，之后交给便宜模型执行。
- 提 PR 前自查: 用 `/improve branch` 只审当前分支的改动。
- 改造执行环境: #2 建议把执行用的临时 worktree 放在工作区内，避免反复弹出授权提示。作者回复欢迎 PR，另一位用户说已在本地这样改。

**社区怎么评价**:
- 正面: X 上传播广，midudev、vikingmute 等开发者账号做过介绍；Emil Kowalski 的 `/improve-animations` 和 Ibelick 的 `improve-ui` 两个技能注明受它启发。
- 负面: #30（11-11）指出执行阶段的范围检查只看未暂存的改动，执行者已经提交的越界修改查不出来。#20 提出"先读执行者的 diff，再运行它的代码"，这个 PR 从 7 月挂到现在。
- 健康度: 10,936 星、29 subscribers，比值约 377:1。18 个 open 项里 12 个是 PR。主要提交集中在 6 月，最近一次是 9-12，此后两个月没有更新。HN 上没有找到讨论。

**风险与争议**:
- **vanity**: 星数和 subscribers、issue 数量、HN 讨论不成比例，热度主要来自作者和 X 上的开发者账号，独立使用反馈少。
- **bus_factor**: shadcn 提交 18 次，其余 4 位贡献者各 1 到 2 次；两个月没有提交，PR 持续积压。
- **stability**: 执行流程的范围检查和安全检查有公开未修的缺口（#30、#20），让它自动执行前先人工看 diff。

**技术备注**: 纯 Markdown 技能，没有代码，带 Claude 插件市场清单。安装用 `npx skills add shadcn/improve`，MIT 许可。Reddit 本次未能检索。

### [openai/codex-security](https://github.com/openai/codex-security) — NEW ⭐ 11,784（+52）| TypeScript | 信源：强

**它是什么**: OpenAI 官方的代码安全扫描工具。在仓库里运行 `cs scan .`，Codex 会通读代码找漏洞，验证每个候选漏洞是否成立，生成补丁并复核修复。除了命令行，它还提供 TypeScript SDK 和 GitHub Action。

**解决什么问题**: 传统扫描器按规则匹配，误报多，报出来的问题还要人去确认。Codex Security 让 Agent 把"找、验证、修"三步连起来做，结果可以导出成 SARIF、JSON、CSV，或同步到 Linear、Jira、GitHub。使用需要登录 OpenAI 账号，CI 里要配置 API key，部分安全请求还要求 Trusted Access for Cyber 资格。

**谁在用、怎么用**（来自 Issues/HN）:
- 本地全仓扫描和增量扫描: 用户在 Linux、容器和 Windows 里跑全仓扫描，#20（17 条评论）报告模型跑完后扫描产物缺失。
- 接进 CI: 用 `--diff` 只扫改动部分，#251 涉及 SARIF 导出。
- 付费长时间扫描: #56 要求扫描被安全策略中止时保留已完成的部分，#25 要求在开始计费前展示扫描范围、预算含义和预期产出。

**社区怎么评价**:
- 正面: #25 的讨论里有用户提到，跑完的扫描能给出有价值的发现。7 月发布时 HN 主帖 598 分、229 条评论。
- 负面: HN 评论里有人说它本质是一组技能文件加并发的 Codex 会话，有人说它默认用最高档模型、不理会用户的模型设置，也有人说安全护栏拦得太多。issue 里最集中的抱怨是花了钱和时间却拿不到报告（#20、#56、#25）。
- 健康度: 11,784 星、40 subscribers，比值约 295:1。138 个 open 项里 104 个是 PR。11-10 同日发布 npm 0.9.0、0.9.1 和 Action 0.9.1，今天仍有提交。提交集中在一位 OpenAI 员工（1,245 次）。

**风险与争议**:
- **cost**: 扫描按 token 计费，成本难以预估，#25 要求付费前先展示范围和预算。
- **stability**: 扫描产物缺失（#20）和策略中止后工作丢失（#56）两个问题从 7 月开到现在。
- **dependency**: 绑定 OpenAI 账号和模型，部分能力有资格门槛。

**技术备注**: TypeScript，Apache-2.0。`npm install --global @openai/codex-security`，需要 Node 22.13 以上和 Python 3.10 以上。X 上以官方和转述帖为主，Reddit 本次未能检索。

**主线二：验收与证据成为卖点 — 榜首 `e2e` 把 agent 测试做成"缓存回放"。** `tester-army/e2e` 10-01 正式发布，允许在同一个 TypeScript 测试里混用 Playwright 式的确定性断言和自然语言的 `agent.act()` / `agent.assert()`，Web 和 iOS/Android 共用一套 API。它的关键设计是：agent 步骤一旦被后续断言验证通过，下次运行直接回放录下的动作、不再调用模型，应用变了才重新调用。这正面回应了 agent 测试最常被诟病的两点，即结果不稳定和每次跑都要花钱。同一天，`impeccable` 合入首屏检查和被遮挡文本检测的修复（#938、#918），`ponytail` 给 review / audit 的发现加上编号（#523），`pstack-claude` 的卖点也是"复现、调查、修改、拿证据验收"的固定流程。skill 层的竞争点正在从"让 agent 写得更多"转向"让 agent 证明自己写对了"。

**主线三：跨宿主分发的成本显形 — 同一套工作流要在 Cursor、Claude Code、Codex 之间搬运。** `pstack-claude` 把 Cursor 员工 Lauren Tan（@poteto）放在 `cursor/plugins` 里的 pstack 移植到 Claude Code、Codex、Pi、OpenCode、Gemini 等宿主，README 写明原版署名，但不是官方维护，issue 区最常见的诉求就是跟进上游（#21、#173）。反方向的例子是 `text-to-cad` 10-03 新增 Cursor 插件（#520）、`marketingskills` v2.11.16 新增 Codex 插件。代价也在今天暴露：`ponytail` v4.11.0 的发版说明承认，v4.10.2 起 `plugin.json` 的一行改动让 Codex、VS Code 和 Qwen 只把它当作 skill 包加载，hooks 没注册，规则根本没送到模型，建议 Codex 用户立即升级。多宿主覆盖已经成为 skill 包的标配，但每多一个宿主就多一套加载方式需要验证。

### [tester-army/e2e](https://github.com/tester-army/e2e) — NEW ⭐ 3,170（+345）| TypeScript | 信源：中

**它是什么**: 一个自动化测试框架，用来检查网站和手机 App 的功能是不是正常。写测试时可以像传统工具那样精确地写"点这个按钮、检查这段文字"，也可以直接用一句话告诉 AI "去完成注册流程""确认购物车里有两件商品"，由 AI 自己操作页面。出自 YC 投资的测试公司 TesterArmy。

**解决什么问题**: 以前写端到端测试，要么用 Playwright、Cypress 一行行写定位器，页面一改测试就坏；要么用 AI 代理去点，但每次运行结果可能不同，还要为每次调用付模型费用。`e2e` 的折中是：AI 第一次走通并通过断言后，把它的操作录下来，之后直接回放，不再调模型，页面变了才让 AI 重新走一遍。手机端则由同一套 API 驱动，可以替代 Maestro 这类专门的移动测试工具。

**谁在用、怎么用**（来自 Issues/HN/X）:
- PR 预览环境回归：母公司 Launch HN（48586299，132 分、69 评）中有用户用它验证每个 PR 的预览环境。
- 替代手写移动测试：X 上有早期用户表示已用它替换手写的 Maestro 流程；外部用户反馈 Android 上持续刷新的界面每次读取要 20–40 秒（#841，未关闭）。
- 提交前探索：`e2e explore` 用于提交 PR 前做一次性的探索式测试。

**社区怎么评价**:
- 正面: 作者发布帖约 110 万浏览，Vercel CEO Guillermo Rauch 转发称赞；缓存回放被认为是对 LLM 测试成本和不确定性的务实处理。
- 负面: HN 上有人嫌 flaky、估算约 0.3 美元/测试、质疑 LLM 的非确定性，也有人认为 LLM 已经让直接写 Playwright 足够容易；测试从业者 davert 在 X 上指出探索式 agent 测试和带 AI 自愈的脚本回归是两回事。框架本身的两个 HN 帖子几乎无人讨论（1 分、3 分）。
- 健康度: 3,170 ⭐ / 8 subscribers（约 396:1）/ 120 forks / 46 open（真实 issue 12 个，其余为 PR），历史 113 个 issue、698 个 PR，开发很活跃。7-22 建仓，10-04 仍有推送。okwasniewski 一人 520 次提交，下一位人类贡献者只有 9 次。

**风险与争议**:
- **stability**: 尚未 1.0，API 仍在变，#822 移除了 Playwright trace 录制，#648 带 breaking 标记；移动端仍有性能问题（#841）。
- **cost**: agent 步骤调用用户自付的 LLM；可选的托管浏览器（Kernel）和模拟器（Expo EAS）是付费服务。
- **dependency**: 开源框架同时是 TesterArmy 商业平台的获客入口，长期路线受公司策略影响。
- **bus_factor**: 核心提交几乎全部来自一位维护者。
- **vanity**: 程度较轻。比例偏高、仓库很新，热度主要来自作者和 KOL 传播，独立社区讨论少；但 issue/PR 数量显示是真实在开发的项目。

**技术备注**: TypeScript，Apache-2.0；移动端由 agent-device 驱动；模型自带（API Key、订阅或本地模型），支持 Vercel AI Gateway。

### [michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude) — NEW ⭐ 1,154（+232）| JavaScript | 信源：中

**它是什么**: 一个"搬运版"的 AI 编程工作流。原版 pstack 是 Cursor 员工 Lauren Tan 为 Cursor 写的插件，包含 20 多个 skill 和约 22 个固定流程（playbook）。这个仓库把它改写成 Claude Code、Codex、Pi、OpenCode、Gemini 等其他 AI 编程工具能用的版本。

**解决什么问题**: 让 AI 修 bug 或做功能时，它常常直接动手改代码，跳过复现和验证。pstack 的做法是把一句需求拆成"复现问题、调查原因、委派修改、拿证据验收"几个固定步骤，核心入口是 `/poteto-mode`。原版只在 Cursor 里能用，这个移植让其他工具的用户也能用上同一套流程；它还额外加了一个自动路由 hook，遇到大任务时自动进入 poteto-mode。

**谁在用、怎么用**（来自 Issues/X）:
- 跟进上游：最常见的诉求是同步原版新版本（#21、#23、#173）。
- 多运行时扩展：有人希望用 Grok CLI 做子 worker（#105），有人在扩展 Pi、Copilot 运行时（#146、#164）。
- 实际故障：Windows 上 Codex 的 SessionStart hook 失效（#171 报告，#172 修复）。
- 长任务迁移：X 用户 @robinebers 提到在 Claude 里跑"一个 fork"做 3–4 小时的中等规模迁移，但未点名是本仓。

**社区怎么评价**:
- 正面: 署名规范（附 `LICENSE-cursor-team-kit` 和 `NOTICE.md`），在 `tools/forks.json` 里声明了与原版的差异；发版密集，10-04 一天发出 v0.9.65 ~ v0.9.67。
- 负面: HN、Reddit 均无本仓讨论，原版在 HN 也只有两个 1–2 分的帖子；另有 open-pstack、potetos-for-everyone 等竞争移植。
- 健康度: 1,154 ⭐ / 3 subscribers（约 385:1）/ 129 forks / 6 open（5 个为 PR）。5-26 建仓，10-04 仍有推送。11 位贡献者，作者一人约 151 次提交，第二名 5 次。

**风险与争议**:
- **dependency**: 内容完全依赖上游 pstack 演进，同步滞后已多次被提出（#21、#173）；非官方移植，Cursor 不维护。
- **bus_factor**: 作者一人约占 151/168 次提交。
- **stability**: 版本仍在 0.9.x，一天多版；在 Prime Agent、OpenCode、Gemini CLI 上的子代理委派尚未经过验证。
- **cost**: 编排多模型、开子代理，长任务 token 开销大。
- **vanity**: 比例偏高、社区讨论薄，热度主要借原版 pstack 的名气。

**技术备注**: JavaScript，MIT；原版位于 `cursor/plugins` 的 pstack 目录；以插件/skill 形式安装到各宿主。

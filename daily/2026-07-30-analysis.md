### [deepfakes/faceswap](https://github.com/deepfakes/faceswap) — NEW ⭐ 56,317（+166）| Python | 信源：中

**它是什么**: 一个在自己机器上跑的开源换脸工具。给它两个人的素材，它训练一个神经网络，然后把视频或图片里 A 的脸换成 B 的脸；带图形界面，流程是"提取人脸 → 训练 → 转换"三步。它是 "deepfake" 这个词的源头级项目——2017 年 12 月 Reddit 那次事件之后由社区接手重写，官网与论坛在 faceswap.dev。

**解决什么问题**: 换脸原本是影视级 VFX 流程，需要专业团队和工时。它把整条流程做成消费级 GPU 上可跑的开箱工具。项目自身的伦理立场写在 README 里且相当明确：禁止不当内容、禁止未经同意换脸、禁止隐瞒使用痕迹，并主张"技术公开才能推动伪造检测研究"——即把自己定位为研究与检测对抗的公开基线，而不是产品。

## 如何理解今天的热度信号

今天最值得记的一条方法论不是"比值多高算虚高"，而是**比值必须和项目年龄、用户构成一起读**。同一张榜上，2013 年的 snipe-it 是 43:1、2017 年的 faceswap 是 37:1，而 open-code-review 297:1、airi 269:1、superpowers 265:1、MediaCrawler 250:1、FlashKDA 249:1、openwork 243:1。差异主要来自两件事：老工具的用户会 watch 发版通知（因为要跟安全补丁），新工具的用户只 star 收藏；组织仓库（FlashKDA 4 个 subscribers）和 skill 合集（superpowers）天然订阅稀薄。所以单看比值只能提问，不能定案——今天最有说服力的健康信号来自另外三项：有没有真实 release、`pushed_at` 是不是本周、有没有作者以外的独立外部讨论。

按这三条，今日最经得起检验的是 **GeoLibre**（7-29 发 v2.4.0 + 抓取时刻仍在提交 + HN 301 分）、**jcode**（今日双发版 + 实时提交）、**open-code-review**（v1.8.0 + 7-29 仍在合 PR）；**openwork** 三项齐备但要注意实际许可是 open-core 而非纯 MIT，且非 macOS 平台的安装路径有实测失败。

最需要谨慎的是三类。第一类是**高增量掩盖的零代码活动**：awesome-systematic-trading 今日 +945，停更 18 个月未 archive；maderix/ANE 停更 4.7 个月且作者明确声明不再维护。第二类是**触发源不可定位**：snipe-it、faceswap、ANE 今日上榜都找不到 7 月的事件锚点，本文给出的推断（安全公告、监管新闻、ANEForge 话题外溢）都只是弱相关，读者不必把"上了 trending"读成"发生了什么事"。第三类是**热度来自话题、不来自仓库**：FlashKDA 自身在 HN 只有 2 分 0 评，真正的 301 分讨论属于 Kimi Linear 这个话题——它值得看，但要按"3.3 个月仓龄、仅 forward、无 backward、需 SM90+ 硬件"的实际成熟度评估，而不是按 HN 热度评估。

最后一条只针对今天两个 NEW 老项目：**它们的风险不在热度，而在部署面**。snipe-it 是 AGPL-3.0 且近两月发了 5 条安全公告（含 1 条 high，集中在多公司隔离的权限模型），自建实例必须紧跟升级；faceswap 的代码许可（GPL）不豁免生成内容的法律责任，TAKE IT DOWN Act、州级合成媒体法与 EU AI Act Art.50 约束的是产出物。这两项都不是"该不该 star"的问题，是"上生产前该做什么"的问题。

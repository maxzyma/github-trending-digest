- **模型与推理基础设施**（3 项）—— `Comfy-Org/ComfyUI`（↓1，#5，+1,206）扩散模型节点式工作流，`shiyu-coder/Kronos`（↓2，#14）金融 K 线基础模型，`vllm-project/vllm`（NEW，#15，94,457 ⭐）大模型推理与服务引擎

和 10-20 相比，12 项中留下 7 项。`akitaonrails/ai-memory`、`HKUDS/CLI-Anything`、`anthropics/claude-code`、`withmarbleapp/os-taxonomy`、`Kruk2/jasna` 离榜。补进来的 8 项里有 7 项是技能或插件包，另一项是 vLLM。昨天榜上没有一个插件目录，今天这一组成了最大盘，换手几乎都发生在这个方向。

**主线二：技能包分化 — 一边比收录数量，一边把单项工作流程做深。** 7 个技能项目大致分两类。

- **目录型**：agency-agents 按岗位收录角色 Agent，wshobson/agents 是插件市场，AAS 收录 2,600+ 技能并新做了 CLI、本地 MCP 和 Workbench 来检索、挑选和校验技能组合。卖点是“装一次就有一大套”。
- **流程型**：security-audit-skill 把安全审计拆成多个阶段，每条发现要独立复核并输出机器可读结果；Ponytail 10-08 发布 v5，规则重写、长度减半，要求 Agent 改代码前先列出改动会波及的调用方、测试和配置，并新增整库审计 `/ponytail-audit`；Graphify 10-20 发布 v0.9.93，修复技能读文件只读到一部分时内容被静默丢失的问题。卖点是“把一件事做对”。

两类项目有个共同点：都不再只绑定 Claude Code。wshobson/agents 的描述列出 Claude Code、Codex、Cursor、OpenCode、GitHub Copilot、Google Antigravity 和 Pi 七个宿主，AAS 和 Ponytail 也都在扩展宿主接入。对读者来说，挑技能包时更值得看的是它在自己用的 Agent 上是否真正生效，而不是收录了多少条。

**主线三：推理基础设施 — vLLM 首入 tracker，ComfyUI 跟进新图像模型。** vLLM 10-18 发布 v0.32.0，含 363 位贡献者的 814 个提交。重点是低精度 KV cache 覆盖更多显卡（NVFP4 支持 SM8x/SM90/SM12x，GLM-5.x 在 SM100 上默认 FP8 KV cache），以及新的 `/v1/systemone` 结构化决策接口。ComfyUI 10-21 合入 Fibo 2.0 支持（#17240）和 Bria 的 FIBO 2.0 合作方节点，日增 1,206，连续两天破千。Kronos 连续第二天在榜，代码仍停在 4-13。

**主线四：榜单解读提醒 — 回榜的技能包热度来自持续传播，代码变化不一定同步。** security-audit-skill 最近一次提交是 9-14，10-08 上次在榜后 13 天又涨了 8,259 星，今天日增排第二。几个短龄技能项目的星数与 subscribers 比偏高：Ponytail 约 427:1，Graphify 约 323:1，security-audit-skill 约 254:1；Orca 约 693:1，open issue 已到 4,376。opencode（约 259:1）和 vLLM（约 155:1）这类大型成熟项目的比值属于结构性偏高，不能单凭比值下结论。技能包能否在自己的项目里起作用，要看 issue 区的真实反馈和自己试用的结果。

## NEW 首次上榜

### [wshobson/agents](https://github.com/wshobson/agents) — NEW ⭐ 41,274（+93）| Python | 信源：中

**它是什么**: 一个给编程 Agent 用的“插件超市”。里面是现成的子 Agent、技能和斜杠命令，按用途打包成插件，比如 Python 开发、代码评审、测试、安全扫描、基础设施。README 目前列出 94 个插件、202 个 Agent、185 个技能和 105 个命令。用户在 Claude Code 里执行 `/plugin marketplace add wshobson/agents` 后，可以只装需要的那几个插件。

**解决什么问题**: 以前想让编程 Agent 具备某方面的专门能力，要自己写提示词和配置，或者到处找零散的分享。这个仓库把常用角色和流程整理成可以按需安装的插件。10-04 起 README 写明同一套 Markdown 源文件可以用于 Claude Code、Codex CLI、Cursor、OpenCode、Google Antigravity、GitHub Copilot 和 Pi 七种工具（#749、#751、#752），换工具不用重写。

**谁在用、怎么用**（来自 Issues/PR/X）:
- 按需装插件：通过插件市场命令只装某几个领域的插件，X 上多以“必装资源清单”的形式被推荐。
- 外部贡献者修内容：#676 为插件集加一致性检查（70 条评论），#720 修复技能引用丢失，#771 拆分 8 个过大的技能；10-15 合入一批修复（#765–#776），涉及 Copilot、CORS、Turborepo 2、Cypress/Playwright API 等过时示例。
- 曾踩的坑：#500 报告 30 个 Agent 重名导致运行时冲突，#736 插件加载失败，均已关闭。

**社区怎么评价**:
- 正面: 外部贡献者在持续做质量修复，open issue 很少，当前待处理的多是新 PR 和技能提案。
- 负面: 历史上重名 Agent 内容不一致、示例代码过时的问题较多，仍在批量修；X 上有一条西语帖误称它是 Anthropic 官方发布，回复中已有人纠正（原帖未打开核实）。
- 健康度: 318 subscribers，星数与 subscribers 比约 130:1，对已有 15 个月的大仓库不算异常；4,393 fork；open issue 2。提交高度集中：作者 376 次，第二名真人贡献者 10 次，其余主要是 dependabot 等机器人。HN 只有 2025-07-31 一帖（2 分、0 评论），Reddit 未检索到讨论。

**风险与争议**:
- **bus_factor**: 单一维护者主导，第二名真人贡献者只有 10 次提交。
- **stability**: 插件内容质量参差，重名冲突和过时示例是反复出现的问题类型，用前需在自己的项目里试。
- **vanity**: 关注度主要来自清单式转发，HN、Reddit 几乎没有讨论；但 fork 数和外部修复 PR 说明有真实使用，需谨慎解读而非直接判定。

**技术备注**: 内容以 Markdown 为主，配套 Python 校验脚本；MIT 许可，没有发布 Release，直接跟随主分支。本次上榜没有新版本这类事件，可能与多工具通用定位和清单式传播有关，属推断。

### [sickn33/agentic-awesome-skills](https://github.com/sickn33/agentic-awesome-skills) — NEW ⭐ 48,120（+83）| Python | 信源：中

**它是什么**: 一个超大号的“Agent 技能合集”，原名 `antigravity-awesome-skills`（旧地址会自动跳转，npm 包名仍沿用旧名）。它收录了 2,600 多个技能，每个技能是一份 `SKILL.md` 说明加可选脚本，教编程 Agent 做某类事，比如写 Playwright 测试、做架构评审。现在仓库还附带一个叫 AAS Core 的本地工具，有命令行、本地 MCP 服务和图形界面 Workbench，用来搜目录、挑技能、检查装在一起的技能会不会冲突。

**解决什么问题**: 各家编程 Agent（Claude Code、Cursor、Codex CLI、Gemini CLI、Antigravity）都支持技能文件，但技能散落在各处，用户得自己找、自己装、自己判断谁和谁冲突。这个仓库把它们集中起来，按岗位打包成 bundle，一次装好；AAS Core 再把“装哪些、能不能一起用”做成可以查询和校验的步骤。

**谁在用、怎么用**（来自 Issues/PR/X/skills.sh）:
- 批量安装：skills.sh 显示累计约 55 万次安装，安装量高的有 playwright-skill、software-architecture。
- 按需挑选：X 上日本用户 @sora19ai 建议只装 Web、QA、DevOps 等专门 bundle，不要全量安装；#244 有用户不清楚 bundle 怎么用。
- 厂商投稿：不少 PR 是产品方提交自家技能，如 Beatra（#2027）、pixeltable（#2024）、Datacircle（#2026）。

**社区怎么评价**:
- 正面: 投稿活跃，PR 累计 1,743 个，以外部新技能为主；X 上被当作“一键默认技能套装”推荐。
- 负面: issue 多是安装和使用问题，#269 技能太多导致上下文溢出（13 条评论），#235 多个技能互相冲突，#315 安装报 MODULE_NOT_FOUND，#215 安装后出错。
- 健康度: 324 subscribers，星数与 subscribers 比约 149:1；7,022 fork；175 个 issue 已全部关闭，当前 0 个 open issue、6 个 open PR。提交集中：作者 1,042 次，GitHub Actions 机器人 899 次，第三名 468 次，第四名只有 36 次。HN 新旧两个名字都没有专门讨论，Reddit 未检索到讨论。

**风险与争议**:
- **compliance**: 整库标 MIT，但收录的官方技能和社区技能各有许可，部分技能是从别处 fork 来的，商用前需逐个核对来源与许可。
- **supply-chain**: 2,600+ 第三方技能主要由一位维护者加机器人审核，技能可以带可执行脚本，也可以接托管 MCP。10-20 合并的发布校验（#2022、#2023）能拒绝缺来源身份或内容漂移的版本，但不等于逐个审计过技能内容。
- **stability**: 10-18 到 10-20 连发四个版本，技能冲突和安装报错反复出现。
- **bus_factor**: 维护高度集中在作者本人。

**技术备注**: Python 为主，分发走 npm 包和 GitHub 仓库；AAS Core 提供 CLI、本地 MCP 和 Workbench，v19.12.1（10-20）。本次上榜可能与仓库从“awesome 列表”转为 AAS Core 控制平面、以及近几日密集发版有关，属推断。

### [vllm-project/vllm](https://github.com/vllm-project/vllm) — NEW ⭐ 94,457（+128）| Python | 知名老项目首入 tracker

- **它是什么**: 开源大模型推理与服务引擎，用来在自己的 GPU 上高效部署模型并提供 OpenAI 兼容接口，是很多自建推理服务的底座。
- **近期**: 10-18 发布 v0.32.0（814 个提交，363 位贡献者，其中 121 位新人）。新增 `/v1/systemone` 接口，按结构化状态回答选择、打分类问题，默认开启；新的 `hf` 工具调用与推理解析器读取模型自带的 `response_template`，带这个模板的模型不再需要专门的解析器；NVFP4 KV cache 覆盖 SM8x、SM90、SM12x，GLM-5.x 在 SM100 上默认 FP8 KV cache，PR 中的测试显示每卡 KV 内存减半、吞吐提升 2.3%–5.5%、首 token 延迟增加 7%–11%；Model Runner V2 在 ROCm 上成为默认。10-18 以来又有 194 个提交。
- **备注**: open issue 2,671，属于大型基础设施项目的正常体量。成熟项目，不做完整 grounding。

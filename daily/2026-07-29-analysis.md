## NEW 项目

### [hello245m/free-stockdb](https://github.com/hello245m/free-stockdb) — NEW ⭐ 1,339（+50）| HTML | 信源：中

**它是什么**: 一个装在自己电脑上的"A 股行情数据库"。双击一个更新程序，它把整个 A 股市场的日线、周线、月线和 1/5/15/30 分钟 K 线下载到本机文件夹；再双击另一个程序，本机就起了一个数据服务（默认 `127.0.0.1:7899`）。之后你想查行情，可以用 Python、HTTP 接口、Excel/WPS 公式、浏览器网页，甚至让 Claude/Cursor 通过 MCP 直接问它。

**解决什么问题**: 做 A 股量化研究，真正卡住人的往往不是策略，而是数据工程。逐只股票去调远程免费接口会被限频甚至封 IP，作者自述拉一遍全市场分钟线要 3-5 天。数据落到本地之后，回测和指标计算只读本机文件，速度快、可离线、可在局域网里多人共享同一份数据。它还预置了 39 个技术指标、复权因子，以及申万三级行业与约 1,200 个概念板块的映射，省掉自己拼板块归属的活。

**谁在用、怎么用**（来自 Issues/中文社区）:
- 全市场分钟线批量回测：这是项目的主场景，README 与 issue #7 的用户实测反馈更新器能跑到 30-50MB/s。
- 非编程路径取数：Excel/WPS 直接用公式拉行情，适合不写代码的研究者；#17 有用户反馈 MCP 目录文件被误删，说明 MCP 接入确有人在用。
- 跨市场与跨平台需求外溢：#20 求美股/港股、#23 求单股下载、#1 求 mac/linux（有人已尝试用 wine 跑），需求踊跃说明存在真实使用意愿，而非纯收藏。

**社区怎么评价**:
- 正面: 下载速度与"本地化"思路获认可；forks 213、issue 里持续有功能诉求，是真实使用信号。
- 负面: 数据正确性与合并停滞是主要问题——#50 报告分钟/周/月聚合 K 线的 open/close 颠倒（范围查询方向与时间映射不一致），这类缺陷会直接污染回测结论，对应修复 PR #51 至今 open；外部贡献者 im47cn 提交的 #45（HTTP 参数未 URL-decode）、#46（单线程 accept loop）两个 P0/P1 修复同样未合并。#7 中作者明确不考虑内网 http 代理支持，#49 询问在线更新无回复。
- 健康度: 1,339 ⭐ / 8 subscribers ≈ **167:1**；forks 213，open issues 5；仓龄仅 2.7 个月（2026-05-08 建仓），MIT；唯一 contributor `hello245m`（35 commits）。仓库内实际代码仅约 30KB C++（`server.cpp` / `updater.cpp`）加 Python 封装，分发物是预编译 exe；#19 问是否开源，作者答"后续可以考虑……担心开源后诞生 n 个收费版"，即核心引擎目前是闭源二进制。仅 1 个 release（测试版 0.2.1），README 仍写"即将提供 mac 和 linux 版本"。外部讨论：HN 无讨论，X 无讨论，Reddit 无讨论，中文侧仅作者自荐的 V2EX 帖（t/1229982，标题即"快速破 1000 星"）且 0 回复，知乎/掘金无第三方评测。

**风险与争议**:
- **vanity**: 167:1 的 stars/subscribers 比、2.7 个月仓龄、HN/X/Reddit 全无讨论、中文侧只有作者自荐 0 回复帖——传播热度与可验证社区足迹明显不匹配。
- **stability**: 仅 0.2.1"测试版本"，且存在分钟/周/月 K 线 open/close 颠倒这类会改变回测结论的正确性缺陷，修复 PR 未合并；仅支持 Windows。
- **compliance**: 数据来源与再分发授权未披露。`docs/DATA_SOURCE.md` 声明更新器"不内置任何数据地址"，改读 `sync_url.txt` 指向的镜像；但仓库内的 `sync_url.txt` 全是注释、无实际地址，真实镜像地址只在 Release zip 内——数据供给链在仓库之外、不可审计，而 README 免责声明把数据版权与再分发责任推给"镜像发布者与使用者"。
- **privacy**: 核心为闭源预编译 exe、无 CI 可复现构建，且会主动出网同步数据；上生产机前需自行做二进制核验与出网监控。
- **dependency**: 数据可用性完全取决于作者维护的镜像节点，镜像一停整套工具即失效。
- **bus_factor**: 单人 35 commits，三个外部修复 PR 长期未合。

**技术备注**: C++ 服务端（GitHub 语言统计为 HTML，因仓库内网页查询界面占比高）+ Python SDK，MIT，2026-05-08 建仓；本地服务默认 `127.0.0.1:7899`，提供 Python / HTTP / Excel-WPS / HTML / MCP 五种查询入口；数据经 `manifest.txt` 做 SHA-256 校验；当前仅 Windows。未 clone 进 `repos/`——分发物是仓库外的预编译二进制，源码侧可分析内容有限，API 与源码树核验已足够。

## 如何理解今天的热度信号

今天最有信息量的不是名单内容，而是**留榜结构本身**：13 项中 12 项留榜、前五名次全部冻结。这种冻结容易被读成"这批项目正在稳定获得采用"，但把增量和 `pushed_at` 并排看，结论正好相反——排名前列的稳定性主要来自话题惯性，而当天的 star 增量正集体流向代码静止的项目：claude-video 近一个月无提交、连续两天 +988/+989；awesome-systematic-trading 停更 18 个月、连续两天三位数增量。与之相对，每天在合 PR、跑 CI 的 microsoft/agent-governance-toolkit 只有 +46，andrewyng/aisuite 只有 +62。

对读者的两条实用判据没有变，今天只是更好用了：看 `pushed_at`（还有人在改吗）、找一条作者之外的独立外部讨论（除了作者和聚合站，有人评价吗）。按这两条，今日最经得起检验的是 GeoLibre（HN 301 分 + 今日仍在 push）、airi（+797 且凌晨有 push）、以及 jenkins / aisuite / superfile 这类有长期维护史的项目；最需要谨慎的仍是停更清单与传播驱动型 skill。

对今日唯一 NEW 的 free-stockdb，还要补一条只在这类工具上出现的判据：**分发物是否可审计**。它的核心是仓库外的预编译 Windows exe，数据镜像地址不在仓库、只在 Release zip 内，没有 CI 可复现构建；而它要做的事恰好是长期驻留在你机器上、持续出网同步数据。对于要跑真金白银策略的人，先解决两件事再谈用不用：一是 #50 那个 open/close 颠倒的聚合 K 线缺陷是否已修（它会直接改变回测结论），二是自己做二进制与出网行为核验。热度只有 1,339 stars，风险却和这个量级不成比例。

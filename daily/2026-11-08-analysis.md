## 新上榜项目

### [mbillow/localthings](https://github.com/mbillow/localthings) — NEW ⭐ 1,070（+186）| Python | 信源：中

**它是什么**: 一个 Home Assistant 插件。装上后，家里的三星洗衣机、烘干机、冰箱、空调、烤箱和扫地机可以在局域网内直接接受控制和上报状态，不再经过三星的 SmartThings 云和账号。

**解决什么问题**: Home Assistant 原有的 SmartThings 集成走"云推送"，每条指令和状态都要绕一圈三星服务器。三星 6 月宣布 SmartThings API 改为每月 4.99 美元的付费计划；据 localsmarthomeguide 转述，SmartThings 11-04 发帖称现有集成 12-15 后停止工作。对三星家电，SmartThings 往往是接入 Home Assistant 的唯一途径。localthings 用家电本身支持的 OCF 协议（CoAP over DTLS，X.509 客户端证书认证）在本地通信，约 2022 年以前的部分旧机型走 TCP 8888 端口的 HTTPS 接口。

**谁在用、怎么用**（来自 Issues/HA 论坛/博客）:
- 冰箱和洗烘纯本地化：HA 论坛有用户反馈在三星 Foodcenter 冰箱上拿到了原先 SmartThings 提供的全部传感器；rutg3r.com 的博文标题就是"绕开 SmartThings API 付费墙"。
- 社区扩展机型：#511 为洗衣机加程序档位自动发现，#268 给空气净化器加 AI Purify 模式，#659 请求支持 POWERbot R7040 扫地机（25 条评论）。

**社区怎么评价**:
- 正面: 外部 PR 持续扩充机型映射；讨论最热的 #435（127 条评论）在设计 PSK 与服务端认证设备的接入架构，说明贡献者在处理真实设备差异。
- 负面: #504 报告 DTLS 握手时洗衣机和烘干机短暂掉 WiFi（已关闭）；#616 多联机空调发给客厅的指令启动了餐厅那台；#177、#335 一拖二空调的子机发现不了；#300 壁挂烤箱不响应。
- 健康度: 1,070 stars、5 subscribers（约 214:1）、95 个 open issue/PR，仓库 2026-06-30 创建，11-02 发布 v0.36.0。30 多位贡献者，但作者 mbillow 一人 905 次提交。HN 只有一帖（1 分、0 评论），X、Reddit 未搜到讨论，讨论集中在 HA 社区论坛。

**风险与争议**:
- **dependency**: 认证依赖三星固件信任库里已公开的一条中间 CA 证书链（出自某 fork 的 README），三星轮换证书或改固件可能导致整体失效。
- **stability**: 设备兼容靠逐个机型的映射表补齐，#616 说明多联机场景存在控错设备的实际风险。
- **compliance**: 用公开证书链直连设备是否违反三星服务条款，目前没有定论。
- **privacy**: 添加第一台设备时仍要联系一次三星服务器，家电本身也仍连着三星云。
- **bus_factor**: 905 次提交来自同一人。

**技术备注**: Python，MIT 许可，协议层基于 `QuiteYellow/SmartThings-Local`，已进入 HACS 默认列表。

### [ranxianglei/billion-context](https://github.com/ranxianglei/billion-context) — NEW ⭐ 4,636（+191）| TypeScript | 信源：中

**它是什么**: 一个装在本机的代理程序，夹在 Claude Code、Codex、OpenCode 这类编码 Agent 和模型 API 之间。它给对话加上"压缩、展开、搜索历史"几个工具，让模型自己决定把哪段旧对话折成摘要、需要原文时再展开，从而在小窗口模型上跑很长的单个会话。

**解决什么问题**: 长会话一旦超出上下文窗口，宿主通常整段截断或做一次性摘要，细节丢失、token 开销也跟着历史长度增长。billion-context 把压缩交给模型按需进行，保留原文可回查。项目宣称支持 20 多个宿主，接入方式有原生插件、`bili <client>` 启动器和 URL 前缀三种。

**谁在用、怎么用**（来自 Issues/中文社区）:
- 提高缓存命中：#3198（50 条评论）里有用户做 A/B 对照，在 dsh 上缓存命中率从 85.6% 提到 91.2%。
- 以插件形式接入 OpenCode 2.x：#809（89 条评论）。
- 外部贡献者修适配问题：#4263（DashScope 上下文溢出识别）、#5178（151 条评论的 PR）。

**社区怎么评价**:
- 正面: Issue 区活跃，用户在提交真实运行数据和修复；作者还维护 QQ 群，三个群里两个已满。
- 负面: #2176（52 条评论）报告非推理模式下模型吐出标签、对话异常终止。一篇 CSDN 实测文章称只省 31%–54% token，比"5 倍"保守得多。
- 健康度: 4,636 stars、10 subscribers（约 463:1）、908 个 open issue/PR，仓库 2026-08-06 创建，11-07 发布 v0.1.213。8,032 次提交里作者占 3,689 次，第二名只有 50 次。HN、X、Reddit 均未搜到讨论，中文侧主要是 CSDN、头条、DEV.to 上的介绍稿，读起来接近推广文。

**风险与争议**:
- **效果宣称**: "省 5 倍 token"缺少可复现基准。仓内一份未署名的 1,500 项评测显示 LongMemEval-S 上省约 71%（约 3.5 倍），准确率从不压缩的 83.2% 降到 79.2%；"数十亿 token"出自作者自己的预印本。
- **privacy**: 多个宿主通过安装本地 CA 证书解密 HTTPS 流量（cert-MITM）接入，等于让代理看到全部模型请求。
- **stability**: 压缩不缩小宿主本地的会话文件；dsh 上消息到约 3 万条时，每轮要等几十秒。
- **bus_factor**: 作者一人主导绝大多数提交。

**技术备注**: TypeScript，MIT 许可，以 npm 包分发，向对话注入 `compress`、`decompress`、`search_context`、`acp_status` 四个工具。

### [dsx-ai-factory/nvke](https://github.com/dsx-ai-factory/nvke) — NEW ⭐ 570（+123）| Go | 信源：中

**它是什么**: NVIDIA 给 GPU 云服务商用的"自建托管 Kubernetes"。运营方在自己的裸金属 GPU 机房装上它，就能按需给客户创建、扩缩、升级彼此隔离的 Kubernetes 集群，效果类似在自家机房里搭一个 GKE 或 EKS。

**解决什么问题**: GPU 云厂商要把同一批机器轮流租给不同客户，每次换租户都得擦盘、重新认证、交付干净的集群。NVKE 把这套流程收进一个管理面：机器由 NVIDIA Infra Controller（NICo）供给，节点上线前用 TPM 和 SPIFFE/SPIRE 做身份认证，节点镜像由配套项目 NVKR 构建。它是 NVIDIA DSX OS 里的 Kubernetes 层。

**谁在用、怎么用**（来自 Issues/HN/媒体）:
- 目标用户是 NVIDIA Cloud Partner 和大型 GPU 机房运营方，在 BlueField 网络隔离之上做多租户 Kubernetes（官方文档与 HN 讨论）。
- 少量外部需求：#2097 希望 nvkectl 能配置 kubelet 的 maxPods。#2113 是尚未合并的 LaunchLayer 支持 PR，heise 报道里提到的这项支持目前还没进主线。

**社区怎么评价**:
- 正面: HN 11-06 的帖子 124 分、28 条评论，有人肯定 NVIDIA 把这套栈开源；heise 发了报道。
- 负面: HN 批评集中在"太重、不可组合、绑定单一厂商"，认为它把 Cluster API、Kamaji、gpu-operator 几件事混在一起，普通 Kubernetes 本来就能调度 GPU。已关闭的 #1181 指出 controller API 没有 TLS、每个节点都开 NodePort、缺审计，#742 指出 etcd 默认不加密。
- 健康度: 570 stars、10 subscribers（约 57:1）、182 个 open issue/PR，仓库 2026-08-04 创建，11-03 发布 v0.23.1。组织是 GitHub 认证的 NVIDIA 组织，贡献者多带 NVIDIA 后缀，属于公司团队开发；Issue 大多来自内部，X、Reddit 未搜到讨论。

**风险与争议**:
- **stability**: README 标明 Preview、不建议生产使用；默认不开 API 认证、走明文 HTTP，管理集群不能自我升级，也没有备份恢复方案。
- **dependency**: 预览阶段只支持 NICo 一种基础设施来源，强绑定 NVIDIA DSX 参考栈。
- **cost**: HN 有评论担心它日后进入 NVIDIA 软件付费订阅，目前只是猜测，没有官方信息。

**技术备注**: Go，官方文档在 docs.nvidia.com/nvke；同一组织下还有 run-ai、model-streamer、topograph 等仓库。

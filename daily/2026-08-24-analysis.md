**主线三：本地优先桌面工具持续有真实需求。** AprilNEA/OpenLogi 从第 9 升到第 5（+1,009，累计从 08-21 的 11,940 涨到 16,003），做的是 Logitech Options+ 的 Rust 原生替代——直接走 HID++ 改按键、DPI 和 SmartShift，不要账号不要遥测。同类的 basecamp/omarchy（Linux 桌面预置）、block/buzz（蓝牙 mesh 通信）、dani-garcia/vaultwarden（自托管 Bitwarden 服务端，2018 年建仓的老项目）今天一起回流。这类项目的共同点是"替掉一个装着账号体系的商业客户端"，热度不依赖 AI 叙事。

### [freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2) — NEW ⭐ 15,925（+401）| JavaScript | 信源：中

**它是什么**: 一个 GPT-Image-2 文生图提示词的案例库。作者把社区（主要是 X 上）流传的 530 多个出图案例逆向拆开，把原本一大段自然语言描述压成结构化的"提示词协议"，再归纳成 20 多套可复用模板，并额外导出成 agent skill 形式。配套有一个在线画廊站点 gpt-image2.canghe.ai，可以按风格筛选、复制完整提示词。

**解决什么问题**: 在这之前，想稳定复现一张好图，你得去 X 上一条条翻别人的截图，把散文式提示词整段抄下来试。抄来的提示词不结构化，改一个变量往往整体失效，更没法批量生成。这个库的主张是"Prompt as Code"——把提示词拆成可替换字段，让批量生成和自动化工作流能直接消费 `data/cases.json` 和 `style-library.json`。

**谁在用、怎么用**（来自 Issues/HN/中文社区）:
- 社区二次开发：issue #2 有人基于该库自建了一个可视化浏览站点并部署到 Vercel，说明数据结构确实可被外部复用。
- 内容创作者按案例编号直接取用；issue #3 的报错正是使用者发现"例 326 的提示词提到绿色服装和手指动作，示例图里都没体现"——这是真实照着提示词复现失败的反馈。
- HN 上仅有 2 条相关 Show HN 帖（2026-04-17 / 04-22），分别 2 分和 1 分、0 评论；主要传播在中文技术社区（腾讯云开发者社区、CSDN 均有拆解文）。

**社区怎么评价**:
- 正面: 中文社区把它当作 GPT-Image-2 的"实战提示词样本集"来拆解，认可其把散例整理成结构化资产的思路。
- 负面: issue #13 是一份措辞严厉的公开举报，评估者称 star 4 天内从 665 涨到 11,338、用户名格式高度统一，并称已举报到 GitHub 官方；issue #3 指出案例图文不符。
- 健康度: 15,925 ⭐ / 51 subscribers（312:1），fork 1,676，open issues 仅 12，建仓 2026-04-25（约 4 个月）。同名同类仓库至少有 5 个（EvoLinkAI、YouMind-OpenLab、gpt-image2、ZeroLu 等），赛道高度同质化。

**风险与争议**:
- **vanity**: stars 增速与 subscribers（51）、issues（12）、HN 讨论（2 帖 0 评论）严重不匹配，仓内已有公开刷星举报（#13）。
- **cost**: README 主体大篇幅是带 `aff=` 参数的 API 中转平台赞助位（APIMart、hiapi、PackyCode、PPToken），项目收益路径与"推荐你用哪家 API"绑定。
- **compliance**: 官方讨论群转为付费（¥9.90 支付宝），社区入口从开源协作变成付费墙后的私域。
- **stability**: 案例与实际出图存在不一致（#3），提示词复现率没有可核验的验证机制。

**技术备注**: 内容型仓库，主体是 `data/cases.json` + `style-library.json` + 图片资产，`agents/skills` 目录提供 agent skill 封装形式；README 有中/英/日三语版本。

### [apache/maka](https://github.com/apache/maka) — NEW ⭐ 3,012（+51）| TypeScript | 信源：强

**它是什么**: 一个跑在你自己机器上的 AI agent 工作台。它能读你的项目、在沙箱边界内执行工具，最关键的是把每一次模型消息、工具调用、工具返回、权限批准和会话如何结束，全部写成一份只追加不修改的日志。桌面界面和下一次发给模型的上下文，都只是这份日志的"视图"，而不是唯一的副本。它是目前 Apache 软件基金会孵化器里的 agent workspace 项目，由 tison 提案，原仓库 maka-agent/maka-agent 迁入 apache/maka。

**解决什么问题**: 现在多数 agent 工具把聊天记录当成记录本身——上下文一压缩，旧的工具输出就真的没了；崩溃一次，中断的那一轮往往不可恢复；出了问题也说不清"当时到底批准了什么工具、模型看到的是什么"。Maka 把这三件事反过来：压缩上下文只是"这次不发给模型"，证据仍在盘上；崩溃后可恢复并续跑被打断的 turn；权限决策本身也是可回看的事实。对需要审计 agent 行为的团队，这是把 agent 从黑盒变成可取证系统的一条具体路径。

**谁在用、怎么用**（来自 Issues/Apache 孵化器/第三方评测）:
- 桌面日常使用：Electron + React 的 Desktop 端提供流式会话、工具时间线、会话分支、检索与恢复；issue #2641（12 评论）、#2921（15 评论）分别在改 Desktop 的用量读取和 MCP 编辑器/inspector 交互。
- 终端与 CI 场景：`maka` / `maka run` 在当前项目目录里跑一次非交互 turn，和 Desktop 共享同一套 workspace 与模型连接；issue #2521（17 评论）在区分"额度用尽"和"鉴权失败"两类 provider 错误。
- Benchmark 复现：`maka eval run <spec> --out <dir>` 做声明式多臂实验，按 任务 × 重复 × 被测对象 展开；issue #3191（16 评论）在处理 eval 超时后残留进程的问题。
- 第三方记录：0.1.11（2026-08-18）合并了 375 个 PR、24 位贡献者；建仓约三个月拿到约 2,400 ⭐。

**社区怎么评价**:
- 正面: "记录即事实源"的设计被明确认可为对现有 agent 工具的取反；进入 ASF 孵化意味着有 IPMC 监督的治理与发布流程。
- 负面: 至今没有任何 Apache 正式 release——仓库和包管理器上现有的一切都不是 ASF release，未经 IPMC 投票；README 明确不推荐用预编译包，建议自行从源码构建。
- 健康度: 3,012 ⭐ / 12 subscribers，fork 309，open issues 259（issue 密度远高于同 star 段项目，说明是真实开发中的活跃仓）；DISCLAIMER-WIP 主动记录了已知问题。

**风险与争议**:
- **stability**: 明确标注 active development，磁盘数据格式、CLI 命令和实验能力都可能变；IM bot 集成仍是实验特性。
- **dependency**: 桌面端目前只支持 Apple Silicon macOS，Windows 是未签名 preview，Linux 未支持——跨平台团队短期无法统一采用。
- **compliance**: 孵化中项目，尚无 ASF 批准的源码 release；企业若要走合规采购，现在还没有可引用的正式发布物。

**技术备注**: TypeScript 单仓多包（`apps/` + `packages/`），Electron + React 桌面端，Node.js 22.19+，Runtime 的 Grep 工具依赖本机 ripgrep；Apache-2.0；内置工具限于 Read/Write/Edit/Bash/Glob/Grep，Computer Use 与 catalog skills 默认关闭。

### [anthropics/claude-plugins-community](https://github.com/anthropics/claude-plugins-community) — NEW ⭐ 1,441（+225）| 目录仓库 | 信源：中

**它是什么**: Anthropic 官方维护的 Claude Code / Claude Cowork 社区插件市场的只读镜像。它本身不是代码库，而是一份清单：`.claude-plugin/marketplace.json` 里目前登记了 2,282 个社区插件的名称、仓库地址和版本。插件提交走 clau.de/plugin-directory-submission，仓库这边由夜间同步任务把审核通过的条目刷进来。

**解决什么问题**: 在这之前，找 Claude Code 插件靠的是各种第三方 awesome 列表和口口相传，没有一个"官方认过、机器可读"的目录。有了这份 marketplace.json，客户端和第三方工具可以直接按清单安装、比对版本，而不必逐个信任来源不明的仓库。

**谁在用、怎么用**（来自 Issues）:
- 插件作者用它核对自己的条目是否上架：issue #14（9 评论）报告插件在 platform.claude.com 已显示 Published、但既没进 marketplace.json 也没出现在 claude.com/plugins。
- 提交队列积压是最集中的反馈：issue #1716 记录某插件自 2026-07-01 提交后状态一直未变。
- 同步机制本身也被社区反向工程：issue #995 指出夜间 bump sweep 的 max-bumps 上限会在遍历到 marketplace.json 尾部条目前耗尽，导致排在后面的条目长期不更新；issue #140 报告某插件 SHA 未跟随更新。
- HN 上无相关讨论。

**社区怎么评价**:
- 正面: 提供了官方口径的插件清单，2,282 条目量级已经足以作为分发和评估的基准数据源。
- 负面: 反馈几乎全部集中在"审核与同步不透明"——提交后没有状态可查、同步任务有已知偏差、尾部条目饿死。
- 健康度: 1,441 ⭐ / 12 subscribers，fork 159，open issues 39（其中相当比例是"我的插件呢"类工单），建仓 2026-03-20。仓库为只读镜像，issue 区实际承担了工单系统的角色。

**风险与争议**:
- **dependency**: 目录内容完全由 Anthropic 侧的审核与夜间同步决定，第三方工具若依赖此清单，会继承其延迟与遗漏（#995、#14）。
- **bus_factor**: 只读镜像 + 12 subscribers，社区无法通过 PR 修复条目，唯一路径是提交表单后等待。

**技术备注**: 目录型仓库，核心产物是 `.claude-plugin/marketplace.json`；仓内另有少量示例插件目录（eli5、quickdesign、testdino 等）。

## 如何理解今天的热度信号

今天 18 个项目里，star 体量最大的三个（ECC 242,966、hermes-agent 235,940、mattpocock/skills 235,652）单日增量分别只有 +427、+454、+2,447，而体量最小的 maka（3,012）和 claude-plugins-community（1,441）分别只涨 +51 和 +225。这说明 Trending 排名反映的是"相对热度动量"，不是绝对采用规模，两端都不能直接读成"多少人在用"。

判断可信度时，比 star 更有用的是这几组交叉证据：subscribers 是否跟着涨（真在追更新的人）、open issues 是否有真实工程讨论（maka 的 259 个 issue 里能看到 provider 错误分类、eval 进程回收这类具体问题）、以及仓库外是否有独立于作者的讨论。反过来，如果 star 曲线陡峭但 subscribers 停在两位数、issue 只有个位数、外部讨论只剩作者自荐帖，就应该按需要额外核实来对待——今天 awesome-gpt-image-2 属于这一类。

另外提醒一点：subscribers 比值本身不是判据。ripienaar/free-for-dev 135,097 ⭐ / 1,807 subscribers（75:1）和 vaultwarden 66,144 ⭐ / 308 subscribers（215:1）都是长期健康项目，成熟大仓的比值天然偏高。要结合仓龄、issue 质量和外部足迹一起看。

### [twostraws/SwiftUI-Agent-Skill](https://github.com/twostraws/SwiftUI-Agent-Skill) — NEW ⭐ 5,464（+65）| Markdown | 信源：中

**它是什么**: 一套给 AI 编程助手看的 SwiftUI 写作规则，名叫"SwiftUI Pro"，作者是 Hacking with Swift 的 Paul Hudson。装上之后，Claude Code、Codex、Cursor 等工具在写或审查 SwiftUI 代码时，会按这套规则检查。

**解决什么问题**: 大模型写 SwiftUI 常见三类毛病：用已经废弃的 API、按钮在 VoiceOver 下读不出名字、写出意外的性能问题。以前只能靠开发者事后逐条纠正；这个 skill 把规则拆成无障碍、API、数据流、导航、性能、本地化等 12 份参考文档，让 agent 在生成时就遵守。目标平台是 iOS 26+、Swift 6.4+。

**谁在用、怎么用**（来自 Issues/X）:
- 审查现有项目：开发者 Jeehut 在自己的 CreditsKit 项目上实际使用，评价"整体很有用"，但指出"把所有计算属性视图都拆出去"这条规则会让代码更难读（#14）；作者在 1.1.0 允许用户覆盖这条规则。
- 在 Xcode 里用：有用户希望在 Xcode 内置的 AI 助手里加载，作者随后补了文章和视频（#5）。
- 安装踩坑：用 `npx skills add` 装到了 `~/.agents/skills`，Claude Code 读不到（#9）；另有用户指出目录里重复嵌套了一层 skill 文件夹（#19，仍 open）。

**社区怎么评价**:
- 正面: 作者回复快、对规则提议会核实后再取舍（如 #20），讨论质量高；SwiftLee（Antoine van der Lee）在 X 上转发推荐。
- 负面: 部分规则偏主观，可能让 agent 过度重构（#14）；4 月到 10 月几乎没有提交，#21、#22、#24 等 PR 积压。
- 健康度: 5,464 ⭐ / 65 subscribers（约 84:1）/ 12 个 open issue 和 PR。仓库建于 2026-03-05，作者 12 次提交，其余两位贡献者共 6 次。HN 和 Reddit 未找到本仓的讨论，X 上以作者本人推广为主（3-12 自称"一周内成为 GitHub 上 star 最多的 Swift skill"）。

**风险与争议**:
- **bus_factor**: 维护集中在作者一人，外部 PR 长期未处理。
- **stability**: 目录嵌套重复、SKILL.md 版本号与发布版本不一致（#19）。
- **规则主观性**: 部分规则是作者的风格偏好，直接套用可能引发不必要的重构（#14）。

**技术备注**: 纯 Markdown（`SKILL.md` + 12 份 references），MIT 许可；支持 `npx skills add` 安装和 Claude Code 插件市场，另带 Codex 用的 `agents/openai.yaml`；调用方式为 Claude Code `/swiftui-pro`、Codex `$swiftui-pro`。

YC W23 公司 BerriAI 维护的 LLM 网关：用 OpenAI 的接口格式调用 100 多家模型服务，附带成本统计、限流、负载均衡、护栏和日志，常被团队部署成内部统一的模型代理。仓库描述现改为"Rust core with Python SDK"，仓内有 `litellm-rust` 目录，但按 GitHub 语言统计 Python 约 1.16 亿字节、Rust 约 460 万字节，主体仍是 Python。10-08 至 10-09 连续发了 v1.102.4、v1.104.2 两个正式版和 v1.105、v1.106 的预发布版。HN 上 9-11 的"Litelm: LiteLLM Without the Bloat"拿到 177 分、63 条评论，说明社区对它的体积和复杂度有不满，轻量替代品在出现。5,408 个 open issue 和 PR 也反映维护压力。今日增量仅 +95，在榜更多反映持续发版而非关注度激增。

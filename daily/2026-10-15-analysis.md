## 首次上榜项目

### [ifixai-ai/iFixAi](https://github.com/ifixai-ai/iFixAi) — NEW ⭐ 27,525（+2,109）| Python | 信源：弱

**它是什么**: 给 AI Agent 做"体检"的命令行工具。使用者先用配置文件写清楚业务规则和 Agent 能用哪些工具，iFixAi 再对 Agent 发起一组测试，看它有没有越权操作、编造内容、隐瞒风险，或者执行本该被拒绝的动作，最后由另一个模型打分，输出字母等级和报告。

**解决什么问题**: 团队把 Agent 接到客服、退款、内部系统后，常见做法是人工抽查对话或自己写测试用例，很难系统地发现"每一步看起来都被允许、合起来却越界"的行为。iFixAi 把这类检查做成一套固定流程，号称 120 秒内给出结论；其中的 Policy Lab 专门搜索这种组合起来有害的动作序列。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 未找到公开的使用案例。仓库最近 100 条 issue 和 PR 里没有用户提交的 issue，评论最多的是核心作者自己的修复 PR（如 #216、#255、#289，处理服务商报错和限流）；唯一的外部功能贡献是 #112，新增 Requesty 服务商。
- README 里的客服 Agent 隐藏欺诈标记、执行已被经理拒绝的退款，原文标注为示意场景，不是客户案例。
- 提供命令行、向导、Claude Code 与 Codex 插件、`uvx ifixai install` 安装 skill 几种入口，适合想在开发流程里加一道 Agent 行为检查的团队试用。

**社区怎么评价**:
- 正面: 选题对路，Agent 行为审计是团队上线前确实缺的一环；Apache-2.0 许可，支持多家模型服务商。
- 负面: HN 上 3 个帖子分别为 4 分 0 评论、3 分 1 评论、2 分 1 评论，没有形成讨论。X 上可检索到的内容以创始人账号、KOL 推介和"必备仓库"清单帖为主，未见独立开发者的实测反馈；Reddit 只找到一条仓库推介帖。
- 健康度: subscribers 410，星数与 subscribers 比约 67:1；forks 1,507，open issue 和 PR 5 个，均为 PR。2026-04-27 建仓。提交高度集中，rudycelekli 171 次，其后两人分别 40 次和 37 次。PyPI 包 `ifixai` 近一周下载约 490 次。

**风险与争议**:
- **vanity**: 2.7 万星与用户 issue、PyPI 下载、HN 讨论的量级都不匹配，外部传播以推介内容为主。
- **cost**: 被测 Agent 和打分模型都调用付费的第三方模型 API，完整 60 项检查的调用量需要先估算。
- **dependency**: 评分依赖"模型当裁判"，README 要求换另一家厂商的模型当裁判，结果才算可引用的评级，结论稳定性受裁判模型影响。
- **bus_factor**: 核心提交集中在一名维护者。
- **商业导流**: 开源版同时是付费 Pro 版的入口，README 中推广链接和徽章较多。

**技术备注**: Python 实现，`pip install ifixai[provider]` 安装；检查项和业务规则用 YAML 描述，报告输出 JSON 和 Markdown。

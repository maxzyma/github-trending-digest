## NEW 项目分析

### [OpenCut-app/OpenCut](https://github.com/OpenCut-app/OpenCut) — NEW ⭐ 66,588（+1,229）| TypeScript | 信源：强

**它是什么**: 一个完全开源、在浏览器里就能用的视频剪辑器，定位是「CapCut 的开源替代」。你打开网页就能剪片，不用注册、不用下载客户端，素材也不上传到别人的服务器。

**解决什么问题**: CapCut 出海版本近一年频繁引发版权条款、数据隐私、导出加水印的顾虑。以前想要「不上传素材、无水印、可自托管」的轻量剪辑，要么用笨重的桌面软件（剪映/PR），要么忍受在线工具的登录墙和水印。OpenCut 把剪辑放进浏览器本地完成，创作者、记者、教育者可以在隐私敏感场景下做轻量剪辑并无水印导出。

**谁在用、怎么用**（来自 Issues/HN）:
- 浏览器内导出重构：社区正把导出迁移到二进制渲染，PR #460 引入 WebCodecs 导出、#794 提供 FFmpeg/HTML5 回退。
- 编辑能力补全：#582 视频特效系统、#503 缩略图、#378 预览面板（字体/贴纸/特效）在重构。
- 目录站（OpenAlternative、AlternativeTo）普遍把它列为 CapCut 首选开源替代。

**社区怎么评价**:
- 正面: HN 主帖「OpenCut: the open-source CapCut alternative」447 分 / 151 评，社区认可其隐私优先与本地处理定位；PR 活跃。
- 负面: 另有「128k line PR」引发对超大 PR 治理的争议（HN 109 分 / 92 评）；导出/预览核心能力尚未稳定。
- 健康度: stars/subscribers ≈ 192:1（C 端工具 watch 天然偏低，需谨慎解读），forks 7,006（真实活跃度较强），open issues 333，贡献者约 30 人，仓龄约 1 年，维护活跃。

**风险与争议**:
- **stability**: 导出与预览核心能力在重构，桌面/移动端未成熟，非生产级，当前仅 Web 端相对可用。
- **vanity**: stars 增长快于 watch/issues，需区分「关注」与「采用」；但 forks 与 HN 双热帖提供真实 grounding，不构成空心化。

**技术备注**: TypeScript，浏览器端剪辑，导出正迁移至 WebCodecs + FFmpeg/HTML5 回退，支持自托管，桌面端建设中。

### [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) — NEW ⭐ 84,809（+1,095）| Python | 信源：中

**它是什么**: 一个给 AI 编码助手用的「知识图谱 skill」。它把一整个代码文件夹（含 SQL schema、脚本、文档甚至图片视频）解析成可查询的知识图谱，让 Claude Code、Codex、Cursor 等在检索代码前先查图谱来导航，宣称能在大型仓库里省下大量 token。

**解决什么问题**: AI 编码助手在 500+ 文件的大项目里，靠反复 Glob/Grep 全文扫描既慢又烧 token。graphify 用 tree-sitter 做 AST 本地解析，把代码结构预先建成图谱，Claude Code 通过 PreToolUse hook 在 Glob/Grep 之前先查图谱定位，理论上减少无效检索。它强调非向量、结构化（EXTRACTED/INFERRED 标注），设计思路本身是合理的。

**谁在用、怎么用**（来自 Issues）:
- 兼容性打磨：#533 讨论 Codex PreToolUse 兼容（10 评论）、#816 Clojure 支持（9 评论）、#155 tsconfig 别名解析（8 评论），说明存在真实使用者与工程反馈。
- 语言/模式扩展：#457/#191 LSP、prose 模式以 PR 形式推进。
- 二次开发：Rootly 有一例把它用于事故（incidents）图谱。

**社区怎么评价**:
- 正面: 508 个 open issues 中有真实的 bug 反馈与工程讨论，功能设计（AST 图谱、非向量）获使用者认可。
- 负面: 「最高 70x/49x 省 token」的数字来自营销博客（MindStudio/CLSkills），未经独立验证，疑似夸大。
- 健康度: stars/subscribers ≈ 283:1（远超 100:1 警戒线），仓龄仅约 102 天，贡献者高度集中（safishamsi 一人 800 提交，第二名仅 21 次），open issues 508，forks 8,348。

**风险与争议**:
- **vanity**: 283:1 超高比值 + 102 天新仓 + HN/X/Reddit 零有机热度 + 大量 SEO 营销博文堆砌「省 70x」话术，传播路径明显强于独立社区技术验证，星标有机性存疑。
- **bus_factor**: 单人贡献 800 提交、第二名仅 21 次，典型单核维护。
- **cost**: 「省 token」收益数字来自营销来源、未经独立复现，不宜直接采信。

**技术备注**: Python，tree-sitter AST 本地解析，非向量知识图谱，通过 PreToolUse hook 接入 Claude Code/Codex/Cursor/OpenCode/Gemini CLI。

## 如何理解今天的热度信号

今天两条线的可信度差异明显。消费级开源工具（OpenCut、Win11Debloat）和官方仓（spec-kit）有真实 forks、issues、HN 讨论或官方背书支撑；而部分短龄「skill / agent 工具包」（graphify 最典型）呈现「star 增长快于社区足迹」的组合——高 stars/subscribers 比值 + 短仓龄 + 单核维护 + 外部独立讨论稀薄 + 营销博文堆砌。判断这类项目时，应把 stars 视为「关注度」而非「采用度」，优先看 forks、真实 issue 讨论和独立第三方评测。对超大成熟仓（awesome-llm-apps、spec-kit、Win11Debloat），高比值多为该类项目的结构性特征，不应据此判定 vanity。

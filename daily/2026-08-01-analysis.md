## 本日主线

**主线一：周六榜单由"agent 生产链条 + 教程清单仓 + 自托管替代品"三块拼成，agent 侧占一半。** 12 个项目里，直接服务 AI agent 工作流的有 6 个：`zhaoxuya520/reverse-skill`（#1，安全逆向技能路由包）、`different-ai/openwork`（#2，Claude Cowork 的开源替代）、`mvanhorn/last30days-skill`（#3，跨平台调研技能）、`github/copilot-sdk`（#6，官方 agent SDK）、`agavra/tuicr`（#8，审 agent diff 的终端 code review）、`1jehuang/jcode`（#12，Rust 编码 agent CLI）。教程与清单仓占 2 个（AI-For-Beginners #5、awesome-systematic-trading #4），自托管 SaaS 替代占 2 个（chatwoot #7、kaneo #9），硬件与本地媒体工具各 1 个（ESP32-Bit-Pirate #10、faceswap #11）。周六是低发布日，榜单主要由前一周的发布余波和搜索流量推动，这也解释了为什么 star 增量第一名是一个 11 天没提交过代码的教程仓。

**主线二：agent 链条上"写"和"审"同时在榜，评审侧的工具正在补位。** `jcode`（+527，Rust 编码 agent CLI）和 `openwork`（+806，全榜第二高日增）代表产出端；`tuicr` 代表消费端——它从 #13 升到 #8，日增从前一天的 +190 翻到 +335，是全榜排名上升幅度最大的项目之一。tuicr 做的事很直白：把 GitHub 网页版 PR 的审查体验搬进终端，让人不必为 agent 的每一轮迭代开一个 PR。当写代码的速度被 agent 拉高之后，瓶颈会移到"看"，这条主线值得连续观察。

**主线三：agent skill 包按垂直领域分叉，安全方向登顶。** `reverse-skill`（+335，NEW #1）把逆向、渗透、CTF 的"选工具—装环境—记证据—出报告"固化成路由规则，是本 tracker 收录的第一个安全垂类 skill 包；`last30days-skill`（+658，↑4）走的是另一条路——跨 Reddit/X/YouTube/HN/Polymarket 做主题调研。两者共同解决的是"通用 coding agent 不知道该调哪个工具"，差别在于前者收敛到一个专业领域的工具链，后者收敛到一类信息任务。通用 skill 合集不再是这个赛道唯一的形态。

**主线四：自托管替代品今天出现"成熟仓 + 新仓"同框，可以直接对照着看。** `chatwoot`（2019 年建仓，35,406⭐，284 subscribers，1,318 open issues）和 `usekaneo/kaneo`（2024-12 建仓，6,212⭐，28 subscribers，86 open issues）都属"把云 SaaS 搬回自己服务器"这一类，但成熟度差了一个数量级。chatwoot 今日只涨 35 星，属算法周期性回流；kaneo 是首次进入本 tracker，7 月末连发三个版本后上榜。对读者的实际意义是：同一个需求下，愿意接受多少缺陷密度换取更轻的部署，这两个项目正好是两端。

**主线五：榜单解读提醒 — 今日 star 增量前两名与代码活动完全脱钩。** `microsoft/AI-For-Beginners` 日增 +1,592 是全榜第一，但仓库最后一次 push 停在 2026-07-21，已 11 天无提交；`awesome-systematic-trading` 日增 +763 排第三，最后一次 push 是 **2025-01-22**，整整 18 个月没有更新，却已连续 5 天在榜。这不是造假，而是教程仓/清单仓的固有特征——它们的热度由外部推荐、课程季和搜索流量驱动，与仓库是否在开发无关。读这两行时不要把 star 增速理解成项目在活跃演进。

### [zhaoxuya520/reverse-skill](https://github.com/zhaoxuya520/reverse-skill) — NEW ⭐ 13,663（+335）| PowerShell | 信源：中

**它是什么**: 给 AI 编码客户端（Claude Code / Cursor / Cline / Kiro）装的一套"安全工作流路由包"。你把一个 APK、一个二进制、一段加密 JS 或一道 CTF 题丢给 AI，它替 AI 决定该用 jadx 还是 IDA、自动把需要的工具链和 MCP 服务拉起来，并强制这次分析走一遍授权确认、证据链记录、时间线和报告输出。

**解决什么问题**: 在此之前，让 AI 参与逆向或渗透工作有两个卡点：AI 不知道该调哪个工具，只能凭猜测拼命令；以及整个过程没有取证记录，做完了拿不出可交付的报告。reverse-skill 把"选工具 — 装环境 — 记证据 — 出报告"固化成路由规则，AI 只需判断案件类型。

**谁在用、怎么用**（来自 Issues/HN）:
- 场景 1: 真实使用者在 issue #26、#30 主动要求扩展工具支持（JEB Pro、Reqable MCP），作者已修复合入——说明有人在真实案件里踩到了工具缺口。
- 场景 2: issue #21 的讨论主题是"AI 说没有授权就不肯干活怎么办"，作者的回复是"用国产模型或 grok""要授权你直接给他就行"。这条线索比功能请求更能说明它实际的使用姿势。

**社区怎么评价**:
- 正面: 工具路由和自举确实省事，issue 区诉求具体，forks 2,028 达 star 的 15%，不是纯收藏型仓库。
- 负面: issue #32 是一份第三方安全审计报告，指出 `quick-setup.sh` 里存在 `eval` 导致的 root 命令注入、`frida-run.ps1` 的 Python 注入、`.burp-mcp-token` 全局可读；#40 是 case-init 路径穿越；#35 是 CI 里的 PR 标题 shell 注入。这些问题在本日前后集中修复，但一个安全工具的早期代码没过安全评审本身就是个信号。
- 健康度: stars/subscribers = 13,663/60 ≈ 228:1；仓库 2026-05-13 创建，仅 80 天，均速约 170 star/天；open issues 仅 12；contributors 9 人，作者一人占约 70% 提交。

**风险与争议**:
- **compliance**: 授权门禁写在文档层，但社区里的实际讨论方向是如何绕过模型的安全对齐。工具本身面向授权渗透，使用姿势不一定跟着走。
- **stability**: 脚本按需从网络自举工具链，早期没有 sha256 pin（issue #39），供应链面暴露；#38/#39 报 macOS/Kali bootstrap 失败。
- **vanity**: 228:1 的 stars/subscribers 比、80 天仓龄、HN 提交只有 2 分 0 评论、无独立中文测评——传播速度快于社区足迹的积累。但 15% 的 fork 率和 issue 区的具体工具诉求说明它不是空壳，属"传播极快、grounding 薄"。
- **bus_factor**: 作者占约 70% 提交。

**技术备注**: 主体是 PowerShell 脚本 + SKILL.md 路由规则，MIT；内嵌调用的 Pentest Swarm 为 AGPL-3.0，仅通过 CLI/MCP 调用。

**解决什么问题**: 卡在"Jira / Plane 太重、Trello 又必须上云"中间的那部分团队——想自己掌控数据、不想为一堆用不上的功能按人头付费。kaneo 的取舍写在 slogan 里："All you need. Nothing you don't."

**技术备注**: TypeScript，MIT，Docker Compose + PostgreSQL；社区在推 SQLite 单容器方案（#1278）。

### [geo-tp/ESP32-Bit-Pirate](https://github.com/geo-tp/ESP32-Bit-Pirate) — NEW ⭐ 5,298（+83）| C++ | 信源：强

**它是什么**: 一个刷进 ESP32-S3 开发板的固件，把一块十几美元的通用板子变成"什么协议都会说"的硬件调试工具。刷完之后，你可以用 USB 串口终端或者直接在浏览器里打开一个网页 CLI，去读写 I²C、SPI、UART、1-Wire、JTAG、CAN 总线，嗅探 Wi-Fi 与蓝牙，收发红外和 Sub-GHz 射频，读 RFID/NFC 卡，或者把板子当 USB 键盘用。

**解决什么问题**: 以前排查或探索一块陌生硬件，需要凑齐一堆专用设备——串口转接板、逻辑分析仪、JTAG 调试器、射频收发器、Flipper Zero 之类的多合一玩具，每样几十到几百美元，各有各的软件。ESP32-Bit-Pirate 把这些能力压到一块通用开发板上，而且访问入口是浏览器，不用装驱动和厂商工具链。它的参照系是经典的开源硬件工具 Bus Pirate，但用现成的 ESP32 生态把成本和获取门槛压到了另一个量级。

**谁在用、怎么用**（来自 Issues/HN）:
- 场景 1: 真的有大量人在真板子上刷——issue #103（28 条评论，全仓最热）是 ESP32-S3 N16R8 变体刷完起不来、报 `esp_ota_ops: not found otadata`，讨论一路延伸到通用 S3 DevKit；#140 请求支持 Heltec WiFi LoRa 32 V3。硬件变体适配是这个项目最真实的使用证据。
- 场景 2: 社区开始围绕它做配套硬件——issue #53（15 条评论）里有人在设计一块开源的 IO 缓冲板，给 ESP32-S3 devkit 加可调 IO 电压，并在动手前先来讨论引脚复用方案。这是"工具被当基础设施用"的信号。
- 场景 3: 远程使用需求（#21 请求 Telnet 接入），说明有人把它当常驻在目标设备旁边的探针，而不是手持工具。

**社区怎么评价**:
- 正面: HN 2026-06-05 的主帖拿到 211 分 / 46 条评论，是本日榜上外部讨论最扎实的项目；发版节奏稳定（v1.4 2026-02、v1.5 2026-03、v1.6 2026-06）；外部贡献者有实质投入——AndreiVladescu 75 次提交、fdufnews 41 次（并主导了 pioarduino 构建迁移 PR #153）；MIT 许可。
- 负面: 命名争议未了结。项目原名 ESP32-**Bus**-Pirate，issue #7 有人指出直接沿用既有开源硬件项目 Bus Pirate 的名字不合适，要求改名；仓库后来确实改成了 Bit-Pirate（旧路径仍重定向），但 issue #7 至今仍开着，未正式收尾。此外硬件变体兼容性碎片化，特定 flash/PSRAM 组合刷不起来的问题长期存在。
- 健康度: stars/subscribers = 5,298/55 ≈ 96:1，是本日榜上比值最健康的短龄项目之一；forks 424（8%）；open issues 仅 30；2025-07-05 建仓，13 个月；主作者 geo-tp 1,287 次提交，占约 90%。

**风险与争议**:
- **命名争议**: 与既有开源硬件项目 Bus Pirate 的名称冲突已改名缓解，但 issue #7 未关闭，长期定名仍有变数。
- **compliance**: 典型双用途工具——RFID/NFC 读取、Sub-GHz 收发、蓝牙嗅探等能力在部分司法辖区对持有或使用有限制，用于非授权目标存在法律风险。
- **stability**: ESP32-S3 板卡变体众多，刷写失败与外设不工作的报告集中（#103），不是所有标称兼容的板子都能开箱可用。
- **bus_factor**: 主作者占约 90% 提交。

**技术备注**: C++ / Arduino-ESP32，MIT；构建已从 PlatformIO 迁到 pioarduino（PR #153，2026-07-27）；提供 Web CLI（`geo-tp.github.io/ESP32-Bit-Pirate/web-tools/`）与 USB 串口两种入口，CI/CD 已能产出合并固件产物。

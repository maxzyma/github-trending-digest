和昨天最大的差别是 skill 盘从 7 项缩到 4 项，`anthropics/claude-plugins-official`、`addyosmani/agent-skills`、`ComposioHQ/awesome-claude-skills`、`calesthio/OpenMontage` 全部掉榜；`archify` 也从守了三天的 #1 掉到 #4（尽管单日仍进 3,722 ⭐，是全榜最大增量）。腾出来的位置被两类东西填上：一类是和 AI 完全无关的 iOS 设备工具链，另一类是靠发版回来的老工程项目。榜首换成 `OpenMAIC`（↑4），这是清华 MAIC 团队的多智能体课堂，也是今天唯一一个连续两天进前五的应用型项目。

**主线二：iOS 虚拟化和 IPA 工具同框，是今天最实的一条新线。** `Lakr233/vphone-cli`（NEW，#3）在 Apple Silicon Mac 上用苹果自家 Virtualization.framework 启真实 iOS 26 固件——不是 Xcode 模拟器，是能跑 Frida、能抓包、有完整文件系统的虚拟真机，定位是按实例收费的 Corellium 的免费替代。它 8 月 28 日在 HN 拿到 406 分 / 111 条评论（item 49485267，标题 "Boot a Virtual iPhone via Apple's Virtualization.framework"，链接直指仓库），是今天全榜 grounding 最扎实的新项目之一。同组的 `majd/ipatool`（NEW，#8）是 2021 年就有的 App Store IPA 下载 CLI，8 月 28 日发了 v2.4.0——两者同日进榜不是巧合：虚拟机需要装 App，而 App 得先能下下来。这条线的读者价值很直接：做 iOS 安全研究、越狱开发或移动端 CI 自动化的人，今天有了一套可以拼起来的开源工具链。

**主线三：一只 $399 的鸭子把 sim2real 配方开源了。** `pollen-robotics/microduck_rl`（NEW，#12）是今天榜上最小的项目——810 ⭐、3 个 subscribers——但它背后是 Hugging Face 2025 年 4 月收购的 Pollen Robotics 推出的 Microduck 双足机器人（25cm、800g、$399）。这个仓开源的是过去各家当私货的完整 sim2real 训练配方：BAM 执行器建模、域随机化、齿轮回差模拟、奖励函数经验，基于 mjlab + MuJoCo Warp，4096 并行环境下 1–2 小时能出可用步态，导出 ONNX 刷进真机。HN 主帖 774 分 / 247 条评论（8 月 27 日），TechCrunch、Axios、Engadget、heise 都有独立报道。它和榜上其他项目最大的不同是：热度背后有一件可以下单购买的实物，138 个 fork 里有相当一部分是在真机上跑失败后提 PR 的人（#12 加 AMD ROCm、#13 修 Windows wandb 凭据路径、#2 修 aarch64 CUDA 源）。

**主线四：榜单解读提醒 — 今天至少有一个项目的 star 曲线是被悬赏买出来的。** `corsairdev/corsair`（NEW，#14）的 337 个"open issues"实际是 200 issue + 137 PR，而这些 PR 几乎清一色是集成插件 scaffold。原因在官网可以直接查到：`corsair.dev/oss` 页面挂着 "$30,000+ AI credits to earn"，规则是"认领一个 integration issue → 提 PR → 合并后 1 point = $1 AI credits"。这解释了为什么它 star 从几个月前的三位数涨到 10,969、fork 526，而 subscribers 只有 18（609:1），HN 和 Reddit 零讨论。这不是说项目没价值（npm 上月 19.7k 下载是真实的），而是说今天这个位次读的是运营活动的强度，不是采用度。

### [Lakr233/vphone-cli](https://github.com/Lakr233/vphone-cli) — NEW ⭐ 9,661（+361）| Swift | 信源：强

**它是什么**: 在 Apple 芯片的 Mac 上开一台"真的 iPhone"。不是 Xcode 里那个模拟器（模拟器跑的是 Mac 版程序），而是拿苹果官方固件包（IPSW）在虚拟机里真正把 iOS 26 启起来，有完整文件系统、有 root、能 SSH 进去。一条命令走完下载固件、打补丁、DFU 刷机、首次开机的全流程，还能像虚拟机一样克隆、导出、导入。

**解决什么问题**: 做 iOS 安全研究和越狱开发的人过去只有两个选择——买一堆真机来刷（砖了就废），或者用 Corellium 这类按实例收费的商业云平台。vphone-cli 把这件事变成本机上免费、可快照、可批量的操作，装完 10 分钟就能有一台可丢弃的实验机。它提供 5 档补丁强度，从 `less`（4 处补丁，保留 iOS 防护）到 `jb`（113 处，自动装 Sileo + TrollStore）到 `exp`（141 处，含反虚拟机检测研究补丁）。

**谁在用、怎么用**（来自 Issues/HN/X）:
- iOS 安全研究与逆向：虚拟机内可跑 Frida、可配 Burp 抓包，HN 讨论里研究者反馈"10 分钟搭出可用 iPhone VM"（HN item 49485267，406 分 / 111 评论）。
- 越狱开发调试：#265「Patchless Variant」37 条评论、#422「处理 iBSS 时 SIGBUS 崩溃」17 条，都是在真实调试链路上的技术追问，且已修复关闭。
- 批量自动化测试：APFS clone + 快照 + `--json` 输出，适合接 CI。
- 衍生生态已经出现：安全研究者 matteyeux、khanhduytran0 在 X 上做了带触控透传的 fork，社区还有 vphone-aio 一键脚本。

**社区怎么评价**:
- 正面: HN 406 分主帖，issue 区讨论质量高且维护者响应快；30 名 contributor，Top 2（Lakr233 123 / zqxwce 122 commits）双人主导但第二梯队有 4 人 20+ commit，不是纯单人项目。
- 负面: 装机门槛高、跨版本稳定性差。#435 `zsh: killed`、#355 无法进 recovery、#354 拿不到 kernel slide、#350 macOS 26.5.1 下 patchless 失效；#445 追问"能不能不关 SIP"——**必须关闭 SIP/AMFI** 是最大劝退点。功能上无摄像头、无基带，EXP 补丁下定位服务坏（#438）、越狱后设 passkey 失败（#439）。
- 健康度: 9,661 ⭐ / 59 subscribers（164:1）比值偏高，但 1,290 fork、22 open issues、累计 445+ issue 编号说明是真用户在提真问题，不是空心传播。MIT，2026-02-26 建仓，8-29 仍在推送。

**风险与争议**:
- **compliance**: 需关闭 SIP/AMFI 并运行未签名的 private entitlement 二进制；分发和使用苹果固件的法律状态模糊（Apple v. Corellium 是绕不开的先例背景）。
- **dependency**: 紧贴苹果私有 framework 与固件格式，macOS/iOS 一个小版本更新就可能让整条链路失效（#350 已是实例）。
- **stability**: 内核 panic、应用启动崩溃、跨 iOS 版本行为不一致，多个开放 issue 都是"某版本失效"。
- **privacy**: 无 Secure Enclave，登录真实 Apple ID 有风险，HN 上已有人指出 iCloud 等服务官方不支持。

**技术备注**: Swift，MIT。依赖 Apple Virtualization.framework（借道 Private Cloud Compute 研究 VM 的基础设施），仅 Apple Silicon。

### [pollen-robotics/microduck_rl](https://github.com/pollen-robotics/microduck_rl) — NEW ⭐ 810（+168）| Python | 信源：强

**它是什么**: 教一只机器鸭子走路的训练代码。Microduck 是 Hugging Face 旗下 Pollen Robotics 卖的 25 厘米、800 克、$399 的双足鸭子机器人；这个仓库让你在自己电脑的 GPU 上用仿真让虚拟鸭子反复练习走路、摔倒爬起、踢球、前滚翻，练好后把模型导出成 ONNX 刷进真机。

**解决什么问题**: "仿真里练好的动作能不能在真机上跑"（sim2real）一直是机器人领域的门槛，而各家的配方基本是私货。这个仓把完整配方公开了：BAM 执行器物理建模、域随机化、齿轮回差模拟、奖励函数设计经验（写在 AGENTS.md 里）。基于 mjlab（MuJoCo Warp），4096 个并行环境下 1–2 小时能训出可用步态，已注册 13 个任务；没有 GPU 的人可以加 `--hf-jobs` 跑 Hugging Face Jobs。

**谁在用、怎么用**（来自 Issues/HN/媒体）:
- 硬件适配与真机复现：外部 PR 全是真跑起来的人提的——#12 加 AMD ROCm 支持、#13 修 Windows 下 wandb 凭据路径（`~/_netrc`）、#2 修 DGX Spark/GB10 aarch64 的 torch CUDA 源。
- 任务扩展：#14 加跳跃任务、#15 校验 Blender 动作导出。
- 教学与入门摩擦：#6 用户找不到默认行走策略，维护者回复指向主仓 policies 目录。
- 定位是教育/科研的低成本双足 RL 平台，预订已排到 4–6 个月。

**社区怎么评价**:
- 正面: HN 主帖 774 分 / 247 评论（2026-08-27），TechCrunch、Axios、Engadget、heise 独立报道；138 fork 对 810 ⭐ 是很高的动手率。
- 负面: 媒体普遍质疑实用性——heise 直接问"它到底有什么用"，Axios 说别指望它干家务；ResetEra 讨论里评价"可爱但不实用、裸露线材该加固"；TechCrunch 提醒开源不等于装了第三方软件后隐私安全。Reddit 未检索到实质讨论帖，官方社区在 Discord。
- 健康度: 810 ⭐ / 3 subscribers（270:1），但这是官方产品的配套训练仓，主仓 microduck 有 3,248 ⭐ / 28 subscribers，单看这个比值会误判。5 位 contributor 但 apirrone 1,029 commits 占约 88%。Apache-2.0，8-30 仍在推送。

**风险与争议**:
- **bus_factor**: 单人主导（88% commits），外部贡献集中在平台适配层。
- **dependency**: 强绑定 mjlab + MuJoCo Warp + CUDA，没 GPU 就得依赖 HF Jobs。
- **stability**: README 自曝安装坑（ARM 机器上 uv 默认 30s 超时会中断 2GB CUDA 轮子下载），多个平台兼容 PR 未合。
- **privacy**: 带摄像头的家用机器人，媒体已就第三方软件的数据边界提出质疑。

**技术备注**: Python，Apache-2.0，PPO + mjlab（MuJoCo Warp），策略导出 ONNX。

### [handsomestWei/patent-disclosure-skill](https://github.com/handsomestWei/patent-disclosure-skill) — NEW ⭐ 5,711（+62）| Python | 信源：中

**它是什么**: 一个中文的 Claude Code / Cursor 技能包，把"我做了个项目，想申请专利"变成流水线：扫描你的设计文档和代码 → 挖出可申请的专利点 → 去国家知识产权局的公布公告站查新 → 生成带框图的交底书 Word。另外能把晦涩的公开专利翻成大白话笔记存进 Obsidian，还有审查意见答复（OA）草稿模式。

**解决什么问题**: 研发人员写不出交底书——专利点没人梳理、框图要手画、多轮改稿分不清哪版是定稿，最后往往交给代理人从头返工。作者把动机写在 README 里："做了多年核心研发，专利发明人那栏从没写过我的名字。"这是今天榜上少见的、问题描述比技术描述更清楚的项目。

**谁在用、怎么用**（来自 Issues/中文社区）:
- 企业研发年底冲专利指标：从代码库直接挖专利点，省掉"想不出来写什么"的阶段。
- 个人发明人自写交底给代理人过稿：产出的是可直接交付的 Word，不是提示词草稿。
- 读竞品专利建私有知识库：通俗解读 + Obsidian 归档。
- 差异点是查新走 CNIPA epub 爬虫（失败时降级到 WebSearch），同类工具多数只调 Google Patents。

**社区怎么评价**:
- 正面: 知乎、CSDN 的评测称"流程被 prompts 拆得很细，Agent 不会乱跑"；SkillHub、ClawHub 均已收录。作者对 issue 回复认真（#17、#10、#2 都有实质答复）。

- 健康度: 5,711 ⭐ / 16 subscribers（357:1）比值很高，但 700 fork（fork/star 12%）+ 中文社区多平台真实评测 + 8 月持续提交，说明落地是真的。30 次提交里 29 次是作者本人。HN、Reddit 零讨论——这是一个英文社区没有 footprint 的中文本地化工具，不等于空心。

**风险与争议**:
- **compliance**: 最重的一条。交底书由 AI 生成，存在公开不充分、技术参数编造的问题；查新降级到 WebSearch 时会漏检，可能造成新颖性误判。README 有免责声明，但复核责任全压在用户端。
- **privacy**: 未申请的核心技术方案送到云端模型和第三方 embedding 服务，在申请日前存在新颖性丧失隐患。
- **bus_factor**: 单人维护，外部贡献几乎为零。
- **dependency**: CNIPA 查新走爬虫，官网改版即失效。

**技术备注**: Python + Playwright，MIT。OA 向量检索需自配第三方 embedding（智谱 / DashScope / MiniMax / OpenAI）。

### [corsairdev/corsair](https://github.com/corsairdev/corsair) — NEW ⭐ 10,969（+126）| TypeScript | 信源：中

**它是什么**: 让你的产品一次性接上几百个第三方 SaaS（Slack、Gmail、Jira、Notion 等）的开源"万能插头"。一个 TypeScript 库加一个可自托管的服务，用一套语法调所有 API，还能帮你的终端用户各自完成 OAuth 授权。YC W25 项目，核心团队 2 人。

**解决什么问题**: 以前每接一个第三方 API 都要重写一遍鉴权、token 刷新、webhook 处理、错误重试的胶水代码，接 20 个就是 20 份。Corsair 把这层收敛成统一的 REST 层。它不只服务 MCP / agent 场景，也服务普通后端和多租户面板——凭证在服务内部解析，agent 只看到方法名和结果，不接触 token。

**谁在用、怎么用**（来自 Issues/npm）:
- npm 包 `corsair` 上月 19.7k 下载，说明有真实集成方。
- PR 区极其活跃但形态单一：#1301 brex、#1146 DocuSign、#764 Prisma，几乎全是插件 scaffold。
- 真实产品诉求停留在讨论阶段：#284 提限额控制、#288 提 human-in-the-loop 审批，均无结论。

**社区怎么评价**:
- 正面: 自托管形态解决了"token 落在闭源平台"的顾虑；661 个 integration 的目录规模在同类里靠前；8-30 仍在推送，Apache 2.0。
- 负面: 真实抱怨很少且无人回复——#261「OSS 页面登录报 invalid origin」开了两个月未修，#483「Hub GitHub 登录 404」。官方入口自己挂着，是比任何 ratio 都直接的健康度信号。
- 健康度: 10,969 ⭐ / 18 subscribers（609:1）；337 open items 实为 200 issue + 137 PR（已通过 GitHub search API 核实），200 个 issue 里约 37 个是 `[Integration] xxx` 认领贴、20 个是 docs，真正 bug 类只有个位数。贡献者高度集中：devjain32 749 + mukul7661 367 约占八成，第三名断崖降到 63。HN 零 story，Reddit 无讨论，X 上主要是官方号和 YC 合伙人站台。

**风险与争议**:
- **vanity**: star / fork / PR 的暴涨与官方悬赏直接相关。`corsair.dev/oss` 页面明写 "$30,000+ AI credits to earn"，规则是认领 integration issue、提 PR、合并后按 1 point = $1 计 AI credits（本条已直接访问官网核实）。这个位次读的是运营强度，不是采用度。
- **bus_factor**: 核心 2 人，外部贡献全是浅层插件。
- **stability**: 官方登录入口自身 404 / invalid origin 长期未修。
- **dependency**: 价值完全建立在 661 个第三方 API 的持续可用与鉴权兼容上，上游一改就得追。

## 如何理解今天的热度信号

今天榜单里出现了三种完全不同的"上榜原因"，混着读会得出错误结论：

- **发版驱动**：`checkstyle`（14.1.0，8-30）、`zod`（v4.5.4，8-29）、`ipatool`（v2.4.0，8-28）。这类项目单日 star 增量都在两位数（31 到 115），能进榜靠的是版本事件的可见度。用 star 增速衡量它们没有意义。
- **真实事件驱动**：`vphone-cli`（HN 406 分）、`microduck_rl`（HN 774 分 + 四家媒体独立报道）。这类项目的特征是 star 之外还有可核实的第三方讨论和动手证据（fork 率、外部硬件适配 PR）。
- **运营驱动**：`corsair` 的 $30k AI credits 悬赏是官网可查的事实。这类项目的 star、fork、PR 三个数字会同时膨胀，但 subscribers 和独立第三方讨论不会跟上——609:1 的比值加上 HN / Reddit 零讨论就是这个组合的典型形态。

另外提醒两个容易误判的比值口径：`awesome-mcp-servers` 的 3,551 open issues 是 awesome-list 的收录申请队列，不是技术债；`microduck_rl` 的 270:1 是因为它只是官方产品的配套训练仓，subscribers 集中在主仓。对这两类项目，单看 ratio 会得到相反的结论。

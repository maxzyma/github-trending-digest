## NEW 项目

### [kyutai-labs/pocket-tts](https://github.com/kyutai-labs/pocket-tts) — NEW ⭐ 6,210（+531）| Python | 信源：强

**它是什么**: 一个"能塞进口袋"的文本转语音（TTS）模型——小到能在普通 CPU 上跑，却能生成接近商业级质量的语音。出自法国非营利 AI 实验室 Kyutai（此前开源实时语音模型 Moshi 而知名）。

**解决什么问题**: 高质量 TTS（ElevenLabs、OpenAI 语音）通常要么闭源收费、要么依赖 GPU/云端。pocket-tts 把"好听的合成语音"这件事搬到本地 CPU，零推理成本、数据不出机，适合嵌入桌面、浏览器、移动端、智能家居等离线场景。

**谁在用、怎么用**（来自 Issues/HN）:
- 本地语音场景：Home Assistant 语音（Wyoming Docker）、ComfyUI 集成、有声书/EPUB 朗读器、游戏角色配音、浏览器（Safari WASM）与 iOS 端本地 TTS、OpenAI 兼容的实时语音克隆服务。
- 社区移植活跃：issue #118（62 评）为官方多语言扩展公告，社区参与度高；已出现 ONNX/Candle/MLX/WASM/纯 C 等多平台移植。
- 真实反馈：#115（14 评）指出韵律与音质"不如 Kokoro"；#2（11 评）请求编译加速；#30 求训练/微调代码。

**社区怎么评价**:
- 正面: HN 官方发布帖 635 分 / 158 评，后续多个社区移植帖同热；X 围绕"CPU 上跑出商业级质量、零成本、挑战 ElevenLabs/OpenAI"；Kyutai 因 Moshi 与开源 TTS 系列在社区享有良好声誉。
- 负面: 音质/韵律逊于 Kokoro，早期以英文单语言起步；Reddit 未检索到具体 r/LocalLLaMA 线程。
- 健康度: 6,210 ⭐ / 53 subscribers（≈117:1，官方实验室开源模型结构性偏高，非空心化）；forks 648、open issues 53；2026-01-07 创建约 6 个月，2026-06-23 仍在推送。

**风险与争议**:
- **stability**: 音质/韵律逊于 Kokoro，早期英文单语言起步，多语言仍在扩展。
- **compliance**: 语音克隆能力存在被滥用（伪造声音）的合规/伦理风险。
- **privacy**: 本地运行本身利于隐私，但语音克隆样本的采集与使用需注意授权边界。

**技术备注**: Python；CPU 可跑的小型 TTS 模型，基于 Mimi 神经编解码器；提供 OpenAI 兼容接口，社区已有 ONNX/Candle/MLX/WASM/C 多平台移植。

### [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search) — NEW ⭐ 11,121（+2,514）| TypeScript | 信源：中

**它是什么**: 一个建在 Claude Code 之上的"AI 求职助手"框架。你 fork 仓库、填好自己的资料，Claude 就能帮你评估职位匹配度、按岗位定制简历、写求职信、做面试准备。

**解决什么问题**: 求职时改简历、写 cover letter、研究公司、准备面试都是重复且耗时的活。ai-job-search 把这套流程包装成 Claude Code 可直接跑的命令，让 AI 按每个岗位定制材料，还带 ATS（简历筛选系统）关键词覆盖打分。

**谁在用、怎么用**（来自 Issues/PR）:
- fork 后填个人资料 → Claude 评估匹配度、定制 CV、写求职信、面试准备；亮点是 drafter-reviewer 双 agent（第二 agent 用全新上下文研究公司并批判草稿）、PDF 渲染校验循环（LaTeX 迭代到 CV 恰好 2 页）、防捏造的 truthfulness 校验。
- 社区贡献多为功能增补型 PR：#52（修复文档命令无对应文件的缺口）、#46（加 /followup 命令）、#58（/interview 面试准备）、#59（加 CI）、#60（TeX 安装文档）——建设性贡献为主，无大规模 bug 抱怨，但讨论量低。
- 求职门户 CLI 主要面向丹麦市场（Jobindex/Jobnet 等），LinkedIn 相关工具国别无关。

**社区怎么评价**:
- 正面: 3,710 forks（fork:star≈3:1）是"fork 填资料自用"框架的真实使用信号；4 个月新仓维护活跃。
- 负面: HN 仅一条 1 分 0 评的边缘帖，X/Reddit 无独立开发者讨论，口碑侧 grounding 弱。

**风险与争议**:

- **dependency**: 依赖 Claude Code + Anthropic API/订阅、Bun，以及丹麦本地招聘门户。
- **compliance**: 自动抓取招聘门户、自动投递可能触及各站 ToS。

**技术备注**: TypeScript / Bun；构建在 Claude Code 之上的命令与 skill 集合，含双 agent 评审、LaTeX 简历渲染校验、ATS 文本层解析与关键词打分。

### [AhmadIbrahiim/Website-downloader](https://github.com/AhmadIbrahiim/Website-downloader) — NEW ⭐ 4,046（+140）| HTML | 信源：中

**它是什么**: 一个整站源码下载器——输入一个网址，用 Node.js 把该网站的完整前端资源（HTML、CSS、JS、图片）打包成 ZIP 下载下来，用于离线查看、前端结构分析或静态备份。

**解决什么问题**: 想保存一个网站的完整前端、离线研究其页面结构，或做静态站备份时，手动扒资源很繁琐。这个项目把 wget 的整站抓取（转换链接、抓取页面依赖、限制目录）包装成一键下载 + ZIP 打包。

**谁在用、怎么用**（来自 Issues）:
- 场景：离线查看整站、前端结构分析、静态站备份；底层是 wget（`--convert-links`/`--page-requisites`/`--no-parent`）+ archiver 打包，通过 socket 回传 ZIP；已有 fork（codenpk/website-downloader）。
- 真实反馈以负面为主，集中在公开在线 Demo 长期宕机：#75「Website not working」、#69「Web is down (again)」、#87「Service has been suspended」、#60「404 on form submission」；#95 修复了 URL 框回车 404。

**社区怎么评价**:
- 正面: 989 forks（fork:star≈24%）说明有真实自托管/复制使用；核心代码可自托管仍可用。
- 负面: HN/X/Reddit 三处均无相关讨论；同类需求社区更常提 HTTrack、wget；托管 Demo 不稳定是主要痛点。
- 健康度: 4,046 ⭐ / 34 subscribers（≈119:1，工具类项目 watch 少属正常）；open issues 19、contributors 9；**创建于 2019-10-26，近 7 年老仓**，最近推送 2026-05-15。

**风险与争议**:
- **compliance**: 批量抓取任意网站源码涉及目标站 ToS、版权与 robots 边界，仅应用于自有或授权站点。
- **stability**: 公开 Demo 反复宕机/被暂停，非生产级。
- **vanity**: 老仓无外部社区 grounding，本轮上榜更像话题回潮而非真实采用增长。

**技术备注**: Node.js（仓库语言标记为 HTML）；底层封装 wget 整站抓取 + archiver 打包 + socket 回传，配简单前端表单。

## 如何理解今天的热度信号

今日"值得放心点开"与"需谨慎解读"的分野仍清晰：

- **端侧/本地 AI 是今日最扎实的真信号**：pocket-tts（Kyutai 官方、HN 635 分、多平台社区移植）、meetily（本地转写、持续高增量）grounding 厚实；这类项目高比值属官方模型/本地应用的结构性偏高，不能与短龄爆款一刀切。
- **skills 生态看供给方权威度**：dotnet/skills（微软官方）、agent-skills（Addy Osmani）属可放心评估的一端；清单类（awesome-claude-code）与合集类是注意力回流指标。
- **工具型/短龄项目要看 fork 与仓龄**：ai-job-search（159:1 但 fork:star≈3:1，真实自用信号强）、Website-downloader（近 7 年老仓话题回潮 + Demo 宕机）、claude-video（短龄单人 + 内容营销）都需结合 fork、issue 真实度、外部独立讨论组合判断。

结论不变：Trending 单日增量与 stars/subscribers 比值都只是"注意力"指标，判断"是否值得采用"要看 issue 真实度、外部独立讨论、仓龄与维护结构、以及 fork 使用侧信号的组合。

## 本日主线

**主线一：agent 工具链仍是榜单主体，但今天的排序被"额度"重新组织了一遍。** 19 席里有 11 席属于 agent/skill 生态：官方侧 openai/codex（第 2，117,394 ⭐，8-24 刚发 rust-v0.149.1）、anthropics/claude-plugins-community（↑8 至第 7）；运行时侧 NousResearch/hermes-agent（↑12 至第 6，235,958 ⭐）、apache/maka（↓2，3,021 ⭐）、openclaw/openclaw（RE，387,484 ⭐ 全榜星数第一）；供给侧 VoltAgent/awesome-agent-skills（↓6）、multica-ai/andrej-karpathy-skills（RE，206,693 ⭐）；应用侧 MadsLorentzen/ai-job-search（RE）、AgriciDaniel/claude-obsidian（NEW）。真正把第 1 名从 codex 手里拿走的，是 Alishahryar1/free-claude-code（↑7，49,221 ⭐，+891）——它解决的不是"agent 能力"而是"agent 用得起"。同一条线上，tashfeenahmed/freellmapi 首次上榜（第 15，19,893 ⭐），把 34 家厂商的免费层聚成一个 OpenAI 兼容 `/v1`。两个项目一头一尾，说明当前 Claude Code / Codex 这类 harness 的普及瓶颈已经从"好不好用"移到"按量计费扛不扛得住"。

**主线二：skill / plugin 供给侧正在从"清单"走向"官方目录"，最小的仓拿到了最高的名次增幅。** anthropics/claude-plugins-community 只有 1,450 ⭐（全榜最低，第二低的 apache/maka 是 3,021），却从第 15 升到第 7。它是 Anthropic 官方插件市场的**只读镜像**——`.claude-plugin/marketplace.json` 是机器可读的插件目录，第三方工具可以直接消费；但社区无法用 PR 修条目，唯一路径是提交表单后等审核，issue 区（#14 平台已显示 Published 却不进 marketplace.json、#1716 提交后状态数月零变化）反映的正是这套单向流程的摩擦。同日在榜的 VoltAgent/awesome-agent-skills（32,010 ⭐，收录 1,000+ skill）与 multica-ai/andrej-karpathy-skills（206,693 ⭐，但最后一次 push 停在 2026-04-20、已四个月未更新）代表旧的 awesome-list 形态。目录化是好事，但今天这三家同框也暴露了一个现实：**星数最高的那份是四个月没动的静态文件，星数最低的那份才是活的。**

**主线三：本地优先与自托管工具持续供货，且热度不依赖 AI 叙事。** AprilNEA/OpenLogi（↓3，16,016 ⭐，+1,097 全榜第三高日增，Rust）用 HID++ 直接改罗技外设的按键/DPI/SmartShift、不要账号不发遥测；basecamp/omarchy（↓10，30,392 ⭐，+1,056）四天前刚发 v4.0.0；dani-garcia/vaultwarden（↓2，66,147 ⭐，2018 年建仓、open issues 仅 85）是今天维护状态最稳的老项目，8-22 刚发 1.37.2。另一侧是商业 SaaS 的开源替代回流：makeplane/plane（RE，58,057 ⭐，8-23 发 v1.4.2）、PostHog/posthog（RE，39,046 ⭐，+83 全榜最低日增）。这两组共同点是"替掉一个装着账号体系的商业产品"，与 AI 赛道的传播逻辑完全不同。

**主线四：榜单解读提醒 — 今天两个 NEW 都需要结合社区 grounding 再判断。** claude-obsidian 与 freellmapi 的 stars/subscribers 分别是 208:1 和 218:1，都是四个月内的新仓，HN 与 Reddit 均无独立讨论，传播主要靠 X 上的 KOL 转发。比值本身不是判据（vaultwarden 214:1 是长期健康项目，成熟大仓比值天然偏高），但当"高比值 + 短仓龄 + 站外零讨论 + issue 集中在装不上"四项同时成立时，star 数不能读成使用规模。可操作读法：先看比值成因，再看 issue 里有没有真实工程讨论，最后看有没有独立于作者与官号的第三方跑过并写下结论。

### [AgriciDaniel/claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) — NEW ⭐ 12,070（+310）| Python | 信源：中偏弱

**它是什么**: 一套让 Claude Code 自动整理你 Obsidian 笔记库的模板。你把任何素材（网页、PDF、随手记）丢进指定目录，Claude 读完之后自动写摘要、建双向链接、归档到对应主题下，最终产出的是**你自己拥有的纯 Markdown 文件**，不是某个云服务里的数据库。作者把它称为"自组织的 AI 第二大脑"，实现思路参考 Karpathy 提出的 LLM Wiki 模式。

**解决什么问题**: 用 Obsidian 的人普遍有同一个毛病——素材进得快、整理跟不上，收藏夹变成坟场。以前的解法要么手动打标签建链接，要么换成 Notion AI 这类云端产品（数据不在自己手里）。这个项目的差异点是把整理动作交给本地跑的 Claude Code，输出仍然是可以离线打开、可以 git 管理的 Markdown。

**谁在用、怎么用**（来自 Issues）:
- 主流用法是把整个仓库 fork 成自己的 vault 模板，然后用 `/wiki`、`/save`、`/autoresearch` 三个斜杠命令驱动（#2、#11 都是围绕这几个命令的安装问题）。1,348 forks 占 star 的 11%，但 PR 里大量是 "personalize fork for XXX" 的个人分叉，不是协作。
- 用 Obsidian Web Clipper 剪藏网页后落到 `.raw/` 目录再让 Claude 消化（#5 反映 `.raw/` 是点开头的隐藏目录，Obsidian 默认不显示，导致剪藏内容看不见）。

**社区怎么评价**:
- 正面: 有社区成员主动提交修复 PR——#80 修 Windows 文件锁、#90 修 hook、#77 修 rerank 前缀，说明确实有人跑起来了。
- 负面: issue 高度集中在"装不上/跑不起来"。SessionStart 的 prompt-type hook 报错从 #7 / #29 / #40 / #42 一路重复到 #93，**跨数月至今 open**；#147 是 v2.0.0 在 Windows 上因 `os.O_DIRECTORY` 直接崩溃。上面那批社区 PR **全部 0 评论、未合并**。
- 健康度: 12,070 ⭐ / 58 subscribers = 208:1；open issues 133，但 issue 编号已排到 #161，报障速度远快于修复速度；contributors 实际只有 2 个（作者 231 commits + `claude` bot 12 commits）；最后一次 push 停在 2026-08-01，已 24 天无更新，v2.1.0（7-31）之后无动作。
- 外部讨论: HN 检索零命中；X 只搜到一条指向仓库的短链，无实质讨论；Reddit 的 r/ObsidianMD、r/ClaudeAI 均未见该项目，搜到的都是通用"Claude+Obsidian 第二大脑"教程。

**风险与争议**:
- **bus_factor**: 单人 + AI bot 维护，社区修复 PR 长期积压不合，核心 hook bug 跨数月无人处理。
- **stability**: SessionStart hook 在当前 Claude Code 上直接报错，Windows 端崩溃，安装成功率是当前最大障碍。
- **vanity**: 208:1 比值 + HN/X/Reddit 三处独立外部 grounding 全为空；作者自述身份为 "AI Marketing Systems Architect（SEO/ads）"，名下另有 claude-seo（15k ⭐）、claude-ads（8.4k ⭐）、claude-blog（1.8k ⭐）等一系列同款高星仓库，并有自营站点导流，传播路径高度营销化。
- **效果无证据**: 公开可见的使用证据几乎全部停留在安装阶段，找不到长期使用后的效果反馈。

**技术备注**: Python 为主，MIT 许可，2026-04-07 建仓。依赖 Claude Code 的 hooks / slash command 机制，`setup-vault.sh` 负责初始化 vault 结构；产出为纯 Markdown，无外部数据库。

### [tashfeenahmed/freellmapi](https://github.com/tashfeenahmed/freellmapi) — NEW ⭐ 19,893（+174）| TypeScript | 信源：中

**它是什么**: 一个自己在本机跑的 LLM 网关。它把 34 家厂商的**免费额度** key（Groq、Cerebras、SambaNova、Google、Mistral 等，共 635 个免费模型端点）聚合到一个 OpenAI 兼容的 `/v1` 地址后面，一家配额耗尽就自动切下一家。对上层应用来说，看到的只是一个普通的 OpenAI 接口。

**解决什么问题**: 想用 Claude Code、Codex、Aider 这类 agent 工具做实验，但按量计费的账单不可控；各家虽然都有免费层，但 key、限流、模型名各不相同，手动切换很麻烦。这个项目把切换逻辑做成路由 + failover，配上 `npx freellmapi setup-claude` 之类的一键接入命令。README 自我限定为**"仅供个人实验"**。

**谁在用、怎么用**（来自 Issues）:
- 有人真的在受限网络下当出站网关用：#974 / #975 请求增加 Cloudflare Worker "Fetch Relay" 通道（各 2 / 6 评论，PR 已提）。
- #960（5 评论）要求自定义分组 fallback 链——即按任务类型指定不同的降级顺序，属于长期使用者才会提的需求。
- #880 是接 Claude Desktop 时 `/v1/models` 有响应但返回 0 个可用模型，说明确有人在往桌面客户端上接。
- 部署形态有 Docker 镜像和 Electron 菜单栏版（监听 127.0.0.1:31415）。

**社区怎么评价**:
- 正面: issue 里有细节明确的功能需求和 bug 报告，不是空壳仓；提交非常活跃（8-24 仍在推 #1023）。
- 负面: #807 macOS 26 Tahoe 下 Desktop 版托盘与窗口不渲染（5 评论）；#943 指出 0.8.3 release 里 macOS 包名仍写着 0.8.1 且提示 "app is damaged"，发版流程有问题；#976 显示作者自己 CI 用的 Groq / Google key 过期，导致多个外部 PR 长期 UNSTABLE、外部贡献被卡。另有 #946 这类与技术无关的政治争吵。
- 健康度: 19,893 ⭐ / 91 subscribers = 218:1；forks 2,885（star:fork 约 6.9:1，fork 多但外部合入少）；open issues 58；2026-04-21 建仓，4 个月。贡献者高度集中：作者 437 commits，第二名 56，其余长尾，且提交多为作者本人的 UI / 路由微调。
- 外部讨论: HN 两条 story（5-22 得 2 分、8-15 得 4 分）**均 0 评论**，社区完全没接住；Reddit 的 r/LocalLLaMA、r/LLMDevs 未检索到讨论；X 是传播主战场，@Dinosn、@GithubProjects、@dr_cintas、@sairahul1 等账号连续转发，宣传口径里的 token 数从 800M → 1B → 1.3B → 4B → 7.4B **层层加码**，且 @sairahul1 宣称"无需信用卡、无需 API key"，与 README「自带各家免费层 key」直接矛盾。

**风险与争议**:
- **compliance**: 项目核心价值就是批量聚合各家免费层配额。README 只说 2026 年 5 月逐家 review 过 ToS（细节在 `docs/architecture.md`），并把责任推给用户——"你与上游提供商的关系由你接受的条款约束"。多数免费层条款禁止代理、共享或规避配额，实际使用大概率触发上游封号，而 README 未给出封号警告。
- **dependency**: 依赖 34 家第三方免费层随时可变的配额与接口；模型 catalog 还需从 `freellmapi.co` 拉取签名清单，引入外部单点。#976 说明连作者自己的 CI key 都会过期。
- **privacy**: key 声称用 AES-256-GCM 存 SQLite、按请求内存解密，catalog server 不接触 prompt——自托管前提下可信；但用户的 prompt 会被分发到 34 家免费层，免费层通常保留数据用于训练，README 未做提示。
- **stability**: 作者明确自述不用于生产；macOS 发版和 Claude Desktop 接入均有未修 bug。
- **vanity**: 218:1 比值、4 个月 20k star、HN 零评论、Reddit 零讨论、X 上宣传数字层层通胀——热度几乎全部来自 KOL 转发链，与可验证的使用规模不匹配。有真实用户，但数量级远低于 star 暗示的规模。

**技术备注**: TypeScript，MIT 许可，2026-04-21 建仓。OpenAI 兼容 `/v1`，智能路由 + 自动 failover，key 加密存 SQLite；提供 CLI（`npx freellmapi setup-claude`）、Docker 与 Electron 三种形态。

## 如何理解今天的热度信号

今天最值得校准的是**"额度类"项目的热度性质**。free-claude-code 登顶、freellmapi 首次上榜，两者的用户价值都建立在同一个前提上：上游厂商继续提供并容忍免费额度的聚合使用。这类项目的 star 曲线会比一般工具陡峭得多——它命中的是价格焦虑而不是能力缺口——但它的可持续性完全由第三方条款决定，属于结构性的 `compliance` + `dependency` 风险，与项目代码质量无关。判断这类项目时，"能不能用"和"能用多久"是两个问题。

其次是**比值不能单独当判据**。今天有四个项目的 stars/subscribers 超过 200:1：freellmapi 218:1、claude-obsidian 208:1、vaultwarden 214:1、ai-job-search 250:1。但四者成因完全不同——vaultwarden 是 8 年老仓的结构性偏高（open issues 只有 85，维护极稳）；ai-job-search 是 "fork it and own it" 的设计取向（11,930 forks，用户拿走就跑）；freellmapi 与 claude-obsidian 才是"高比值 + 短仓龄 + 站外零讨论 + issue 集中在装不上"四项同时成立的情况。比值只是提问的起点，不是结论。

第三是**日增与名次可以严重背离**。awesome-gpt-image-2 今天日增 +2,449 居全榜第一，名次却从第 2 掉到第 17；PostHog 日增仅 +83 却能回榜。Trending 的排序综合了增速、基数与时间窗口，单看任一维度都会误读。

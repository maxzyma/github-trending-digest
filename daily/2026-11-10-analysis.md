## 新上榜项目

### [garrytan/gbrain](https://github.com/garrytan/gbrain) — NEW ⭐ 32,184（+216）| TypeScript | 信源：中

**它是什么**: 一个给 AI Agent 用的"第二大脑"。你把会议记录、邮件、推文、通话等资料不断喂进去，它整理成人物、公司、事件页面，并标明每条信息的出处。你的 Agent（Claude Code、Codex、OpenClaw、Hermes 等）问问题时，它直接给出带引用的综合答案，而不是一串搜索结果。

**解决什么问题**: Agent 默认不记得上周聊过什么，每次会话都要重新交代背景。gbrain 让多个 Agent 共用一份可更正、可撤回的长期记忆，后台定时任务负责去重、补引用、找矛盾、为第二天准备待办。项目 MIT 开源，可自部署；gbrain.io 提供可选的付费托管。

**谁在用、怎么用**（来自 README/Issues/X/第三方评测）:
- 作者自用：Garry Tan 在 README 中称这是他 OpenClaw 和 Hermes 部署背后的生产记忆库，开会前用它查某人的往来记录和待办。
- 自托管个人知识库：README 给出"从零搭个人 Agent + 记忆库"的教程（OpenClaw + GBrain + Supabase，约 2 小时），以及 Notion、Obsidian 迁移的规划。
- 第三方评测：Vectorize 的评测认为它在个人单机场景下表现最好，可以用 git diff 查看 Agent 一夜学到了什么。没有找到公司或团队落地的独立案例。

**社区怎么评价**:
- 正面: Mem0 发过技术解析，Gamgee 称它是最完整的开源 Agent 记忆参考设计。
- 负面: ExplainX 指出它宣传的 LongMemEval 成绩来自作者团队自己的评测套件；Gamgee 提醒把它用作公司知识库会遇到权限治理问题。
- 健康度: 32,184 stars、4,769 forks、135 subscribers（约 238:1），798 个 open issue/PR，仓库 2026-04 创建，今天仍有推送。评论最多的 issue 是自动生成的夜间测试失败工单（#6841、#6049），外部用户反馈很少。提交集中在 garrytan（11,596 次），其次是 time-attack（1,278）和 capy-ai[bot]（625）。HN 官方帖（4-10）只有 9 分、2 条评论；X 上的讨论主要是作者本人的版本发布推文。

**风险与争议**:
- **vanity**: 星数和 subscribers、HN/Reddit 讨论不匹配，热度主要来自作者个人影响力，第三方采用证据弱。
- **bus_factor**: 绝大部分提交来自作者本人和机器人账号。
- **stability**: 版本迭代到 v0.60.x，夜间测试多次报红。
- **privacy**: 配置云端嵌入、重排、综合服务时，资料文本会发给对应服务商。
- **cost**: 7×24 摄入和夜间整理需要 8GB+ 内存的服务器和独立的 API 开销。

**技术备注**: TypeScript，MIT 许可；提供 Claude Code、Codex、ChatGPT、Claude Desktop、Perplexity 等客户端的 MCP 接入指南，存储可接 Supabase。

### [homeassistant-ai/ha-mcp](https://github.com/homeassistant-ai/ha-mcp) — NEW ⭐ 6,023（+31）| Python | 信源：中

**它是什么**: 一个让 AI 助手管理智能家居的连接器。装好后，你可以在 Claude、ChatGPT 或 Cursor 里用自然语言让 AI 新建、修改 Home Assistant 的自动化、脚本、场景和仪表盘，查看运行记录排错，也能整理实体、区域和备份。README 列出 87 个工具。

**解决什么问题**: Home Assistant 自带的 MCP Server 走语音助手 Assist 的通道，只能控制已经暴露给 Assist 的设备，适合"打开客厅灯"这类指令。写一条复杂自动化、查它为什么没触发，过去要自己读 YAML 和 trace。ha-mcp 让 AI 直接参与搭建和维护整套系统。它不是官方项目，组织简介写明是社区维护的"Unofficial Home Assistant AI Toolkit"。

**谁在用、怎么用**（来自 Issues/X）:
- 在 HA 里直接运行：#1527（27 条评论）推动改为在 Home Assistant 进程内运行，现已成为推荐安装方式。
- 查询家庭拓扑：#902（26 条评论）讨论让 AI 读出房间、设备和实体的关系。
- 远程连接 claude.ai：#1714（46 条评论）记录了远程 OAuth 在 claude.ai 上失败的排查。
- 教程传播：法国站 domo-blog.fr 和 KPeyanski 在 X 上发过教程与视频，主题是"用 AI 调试和写自动化"。

**社区怎么评价**:
- 正面: 功能需求主要由社区推动，issue 讨论活跃；当前评论最多的 open issue #2632 要求读写工具改用 HA Core 原生 API 和 schema。
- 负面: 连接问题集中，#2367 写入时出现 ClientDisconnect（79 条评论，已关闭）、#1721 websocket 断连、#1904 升级 v7.13.0 后无法启动。
- 健康度: 6,023 stars、294 forks、20 subscribers（约 300:1），24 个 open issue/PR，仓库 2025-09 创建。正式版 v9.1.2 于 11-08 发布，dev 构建今天仍在出。人类贡献者集中在 kingpanther13、julienld、Patch76、sergeykad 四人。HN 只有一篇 2 分帖子；Reddit 本次未能检索到，热度未知。

**风险与争议**:
- **权限范围**: 默认以管理员身份操作，可以改自动化、重启 HA、管理备份；#1990 报告门锁和安防面板的审批策略一度没有一致生效（已关闭）。项目提供只读模式、按工具开关、审批策略和编辑前自动备份，文件与 YAML 编辑默认关闭。
- **privacy**: 远程访问靠带密钥的 URL 作凭据，可选 ha_auth 或 OIDC 加固；家庭设备状态会经过所接的 AI 服务。
- **stability**: 传输层和版本升级回归较多。
- **dependency**: 要求 Home Assistant 2026.8 以上，大版本之间有破坏性变更。
- **bus_factor**: 核心维护集中在 2 到 4 人。

**技术备注**: Python，MCP 协议；支持 stdio、HTTP 和 HA 内运行三种方式，README 承认 stdio 传输存在已知问题（#1713）。

## 首次上榜项目

### [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell) — NEW ⭐ 10,881（+990）| Rust | 信源：强

**它是什么**: 给 AI agent 用的"安全隔离舱"。agent 在里面可以读写文件、装依赖、调用外部服务，但能碰哪些目录、能连哪些网址、能用哪把密钥，都由一份策略文件事先规定；越界的操作在系统内核层面就被拦下。策略修改前，还会用形式化方法检查新策略会不会意外开出危险权限。

**解决什么问题**: 以前让 agent 自主执行任务，要么把它放在一次性容器或虚拟机里（隔离粗、配置重），要么直接给本机权限（风险高，密钥容易泄露）。OpenShell 把"细粒度权限 + 密钥托管 + 策略审查"做成一个专门的运行时，让团队能在给 agent 更多自主权的同时保留可审计的边界。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 企业平台集成: Red Hat 在 X 上宣布将其集成进 Red Hat AI 平台并参与共建；NVIDIA 官方账号与 Jensen Huang 本人发文推广（X）。
- Kubernetes 部署: HN 上有 "OpenShell Kubernetes Operator"（2026-07-24，13 分）的社区帖子，说明已有人把它放进集群里跑。
- 多语言 SDK 与发行渠道: 热门 issue 集中在工程化，如 Snap 包在 Ubuntu VM 中的冒烟测试（#2869，18 条评论）、SDK 一致性测试 RFC（#3238）。

**社区怎么评价**:
- 正面: HN 上团队文章 "What we have learned at OpenShell applying formal methods to control AI agents"（9-15，40 分 / 11 条评论）是目前最有实质讨论的一帖；X 上有 All-In Podcast 的 David Sacks 等人评论"agent 安全是工程问题"。
- 负面: 9-29 有一篇质疑帖认为"隔离不等于安全"，但只有 2 分、无评论，尚未形成讨论；Reddit 未查到相关帖子。
- 健康度: 10,881 ⭐ / 60 subscribers（181:1）/ 1,436 forks / 493 open issues，Apache-2.0，2026-02 建仓，今天仍有推送；核心贡献者约 5 人（最高 337 次），不是单人项目。高比例主要来自 NVIDIA 官方矩阵的传播，issue、发版和企业集成都对得上。

**风险与争议**:
- **stability**: 刚进入 v0.1.x，open issue 接近 500，接口和策略格式仍可能变动。
- **dependency**: 核心隔离依赖 Linux 内核的 Landlock 能力，非 Linux 或老内核环境的覆盖需要单独确认。

**技术备注**: Rust 实现，声明式策略 + 内核级沙箱 + 凭据注入代理；提供多语言 SDK、Snap 包与 Kubernetes Operator。

### [t8y2/dbx](https://github.com/t8y2/dbx) — NEW ⭐ 22,429（+232）| Rust | 信源：中

**它是什么**: 一个很小（约 25 MB）的数据库管理工具，一个软件就能连 MySQL、PostgreSQL、Redis、MongoDB、DuckDB、达梦、OceanBase 等 100 多种数据库。有桌面版、网页版（Docker）和命令行版，还内置 AI 助手帮你写 SQL，并能作为 MCP 服务让 Claude Code、Cursor 等 AI 编程工具直接查库。

**解决什么问题**: 以前多数人要在 DBeaver（体积大）、Navicat / DataGrip（付费）和各数据库自带工具之间切换，国产数据库还常常缺好用的客户端。dbx 用一个轻量免费工具覆盖多种库，并把"让 AI 看懂表结构、生成并安全执行 SQL"做成内置能力。

**谁在用、怎么用**（来自 Issues/X/中文社区）:
- 政企与信创环境: #3222（14 条评论）请求适配统信 UOS 等国产系统和低版本 Linux，说明已有用户在信创环境里用。

- AI 编程接库: X 上有开发者推荐其"无 Electron、无订阅"的轻量定位和内置 AI 读 schema 生成 SQL 的能力；LINUX DO 论坛有用户称用它替掉了其他数据库软件。

**社区怎么评价**:
- 正面: 轻量、免费、覆盖面广，AI 与 MCP 是默认能力；几乎每天发版（最新 v0.6.28，9-29）。
- 负面: #7768（设置修改后无法生效，12 条评论）等稳定性问题；open issue 达 1,299，维护压力大。HN、Reddit 未查到针对本项目的讨论。

**风险与争议**:
- **vanity**: 227:1 的比例偏高，仓龄仅 5 个月，热度主要来自中文开发者圈和 X 转发，英文社区 grounding 弱。

**技术备注**: Rust 桌面应用，另有 Docker Web 版与 CLI；AI 助手可接 Claude / OpenAI / Ollama，AI 生成 SQL 执行前有安全检查；内置 MCP Server。

### [oblien/openship](https://github.com/oblien/openship) — NEW ⭐ 13,997（+437）| TypeScript | 信源：中

**它是什么**: 装在你自己服务器上的"一键部署平台"。代码推上去，它自动构建、上线、配域名和 HTTPS 证书，体验接近 Vercel，但机器和账单在你自己手里。可以用桌面 App、自托管服务端，或官方托管的 Openship Cloud。

**社区怎么评价**:
- 正面: dev.to 有独立评测认为自托管可减少对外部控制面的依赖，适合内网或敏感构建场景；发版密集（v0.8.0，9-27）。

**风险与争议**:

### [rakyll/hey](https://github.com/rakyll/hey) — NEW ⭐ 20,540（+34）| Go | 信源：中（知名老项目首入 tracker）

**它是什么**: 一个很小的命令行压测工具：给一个网址连续发大量请求，统计响应时间分布和成功率，用来快速看服务扛不扛得住。可以当作老牌 ApacheBench（`ab`）的替代品。

**解决什么问题**: 开发者想在发布前粗测接口性能时，不必搭建 JMeter、k6 这类完整压测平台，一条命令就能拿到延迟分位数和吞吐量。

**上榜归因**: 未找到对应的项目更新。最近一次推送与发版都是 2026-01-10 的 v0.1.5（距上一版 v0.1.4 已近 5 年），今日 +34 在 2 万基数上属于常规波动。

**社区怎么评价**: 2016 年建仓的成熟工具，20,540 ⭐ / 182 subscribers（113:1）/ 190 open issues，Apache-2.0，长期被当作 Go 生态里的标准小工具使用。本条按"知名老项目首入 tracker"处理，未做完整社区 grounding。

**风险与争议**:
- **bus_factor**: 维护节奏很慢，多年只有零星发版，新需求和 issue 响应有限。

**技术备注**: Go 单二进制，前身名为 boom，为避免与同名 Python 工具冲突改名为 hey；支持并发数、QPS 限速、HTTP/2 和自定义请求头。

**谁在用、怎么用**（来自 Issues/HN/X）:

**社区怎么评价**:

### [rommapp/romm](https://github.com/rommapp/romm) — NEW ⭐ 10,562（+410）| Python | 信源：强

**它是什么**: 一个自托管的复古游戏 ROM 管理器 + 播放器。你把自己收藏的 ROM 丢进去，它自动刮削封面/元数据、整理成漂亮的 Web 库，还能通过 EmulatorJS 直接在浏览器里开玩，支持多用户。

**解决什么问题**: 硬盘里堆着上千个杂乱 ROM 文件，没有封面、没有分类、也不能直接玩。romm 把它变成类似"自建的游戏流媒体库"，Docker 一键部署。

- 自托管玩家：Docker 部署管理个人 retro 收藏，浏览器内直玩；#1329 请求模拟服务器、#2050 平台级子文件夹、#2892 攻略支持——都是深度使用中的功能诉求。

**社区怎么评价**:
- 正面: HN 2025-06 Show HN 238 分/96 评；r/selfhosted 口碑正面，称赞 UI 精致、开发活跃。
- 负面: 需配置多个刮削 API key（IGDB/MobyGames/ScreenScraper）、文件夹结构要求严格。

**风险与争议**:
- **compliance**: ROM 分发涉版权，项目本身只做管理/播放，但用户导入内容的合法性属灰色地带。
- **dependency**: 强依赖第三方元数据源，刮削源失效会直接影响体验（#3505）。

**技术备注**: Python 后端 + Web 前端；Docker 部署，EmulatorJS 浏览器内运行，多用户认证。

## 如何理解今天的热度信号

今日"Claude Code 技能/skills 合集"这一细分里，短龄高比值样本密集（claude-skills 118:1、planning-with-files 233:1、CodexBar 346:1、caveman ↓11），但它们的 grounding 质量差异很大，不能一刀切：

- **有作者光环 + 真实 PR 佐证的**（CodexBar、gastown）：比值高源于知名作者高传播，forks/issue/PR 显示真实使用，非空心化。
- **靠 hype 叙事传播的**（planning-with-files 的"20 亿收购"、claude-skills 的作者自营销）：HN/Reddit 零独立讨论，热门 issue 以困惑为主，采用证据薄——这类才需要 vanity 谨慎。
- **成熟自托管应用**（romm 251:1、immich）：比值结构性偏高属正常，HN 数百分讨论 + 多年活跃维护，是扎实真信号。

结论不变：Trending 单日增量与 stars/subscribers 比值都只是"注意力"指标，判断"是否值得采用"要看 issue 真实度、外部独立讨论、仓龄与维护结构的组合。

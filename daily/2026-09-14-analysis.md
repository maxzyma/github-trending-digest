### [ever-co/ever-gauzy](https://github.com/ever-co/ever-gauzy) — NEW ⭐ 5,141（+191）| TypeScript | 信源：中

**它是什么**: 一套自己装在自己服务器上的公司后台管理系统。一个软件里同时装了客户管理（CRM）、人事（HRM）、招聘（ATS）、项目管理和进销存（ERP），还自带员工计时器和桌面端。定位是中小企业不想按人头买 SaaS、又想把数据留在自己机器上时的替代品。

**解决什么问题**: 以前一家小公司要拼四五个 SaaS——一个管客户、一个管工时、一个管招聘、一个开发票，数据互相不通，月费按人头叠加。Ever Gauzy 把这些做进同一个数据模型，可以只装桌面版试用（UI + API + SQLite 一体），也可以起完整 Docker Compose 栈（含 OpenSearch、MinIO、Redis、Cube、Zipkin 等 7 个以上服务），还提供 Pulumi 脚本部到 AWS EKS/ECS。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 一体化中小企业后台。主打员工工时与活动监控加时间表、发票与报价、销售管道、招聘流程，靠桌面计时器打通"谁做了多久"到"给客户开多少钱"。
- 场景 2: 接 AI agent。issue #10186 报告官方 MCP 镜像的 `tools/list` 调用失败——说明已经有人试图把它接进 agent 工作流。
- 场景 3: 长期踩坑用户。issue #1600（Seeds and Demos）2020 年开到现在还有 17 条讨论，基础演示数据的体验坑位一直没填上。

**社区怎么评价**:
- 正面: 功能覆盖确实广，官方维护者亲自回帖推进（如 #9343 图标库替换，17 条讨论）；发布节奏极快，v111.41.5 到 .10 全部发生在 9 月 13 日一天之内。
- 负面: 467 个 open issue，最老能追到 2019 年（#42、#63、#130 至今未关）；55 个 open PR 排队。
- 健康度: 5,141 ⭐ / 64 watchers = 80:1，对一个六年老项目属结构性正常，**不构成 vanity 判据**；但贡献者高度集中——rahul-rocket 9,010 commits、evereq 7,704、adkif 4,134，第四名骤降到 475，且三人都属 Ever Co. 官方，社区侧贡献稀薄。
- 外部: HN 无相关讨论（搜 gauzy 命中的全是 Gaudy / Gaussian 噪声）；X 上只有官方 @gauzyplatform 自宣和聚合号转发，未见独立开发者反馈；Reddit 的 r/selfhosted、r/opensource 均无使用贴。六年、5,141 ⭐ 却没有独立外部足迹，这个落差读者要自己折算。

**风险与争议**:
- **compliance**: README 上那个 "AGPL-3.0" 徽章只是三档许可里最低的一档。默认 Community Edition 走 AGPL-3.0——改了必须以同样 copyleft 开源，**通过网络提供服务也要放出全部源码**；想闭源必须买 Small Business（限年收入 ≤ $100 万的单一公司）或 Enterprise 授权。打算拿它做 SaaS 的人别只看徽章。
- **商标限制**: Ever® 与 Ever® Gauzy™ 是注册商标，未经书面许可不得使用，白标和二次分发受限。
- **privacy**: 本周的热门 issue 被 #10185~#10196 一批维护者自提的安全修复占满——租户越权、凭据泄露、权限缺失、SSRF、以明文 HTTP 传 Upwork 凭据。这是自查式集中修补，也意味着**历史版本存在成片的多租户与鉴权缺陷**，旧版不宜直接上生产。
- **bus_factor**: 前三名贡献者全是官方员工且占压倒性比例，项目实质由一家公司维护。
- **stability**: 完整栈组件超过 7 个服务，不是轻量自托管；一天多个 patch 的发版节奏对生产环境也意味着要频繁跟版。

**技术备注**: TypeScript（NestJS + Angular + Nx monorepo），AGPL-3.0 / 商业双轨，桌面端基于 Electron，数据库支持 SQLite 与 PostgreSQL。

### [alphaXiv/OpenResearch](https://github.com/alphaXiv/OpenResearch) — NEW ⭐ 2,103（+289）| Rust | 信源：中

**它是什么**: 一个给科研人员用的"实验调度台"。你已经在用 Claude Code 或 Codex 让 AI 帮你改代码跑实验了，但跑上十几组之后就会乱——哪个结果是哪版代码出来的、超参改了什么、能不能重跑一遍，全靠自己记。OpenResearch 把这件事管起来：每条研究方向开一个独立的 agent 会话，配一棵独立的 git worktree，每次实验存一份不可变快照，并用 git 原生结构记录"这个结果从哪个父实验分叉出来"。

**解决什么问题**: 它不做模型，也不替代 Claude Code——它把现成的编码 agent 当执行器，补上它们缺的那一块：**并行、可复现、有血缘的实验管理**。算力后端可以是本机、SSH 到工作站、Slurm、K8s、Ray、HF Jobs、Modal、Tinker，也可以用官方托管。`orx up` 起一个 `127.0.0.1:4791` 的本地面板，数据落 SQLite，代码和数据不出本机——这一点对有合规约束的实验室是实际卖点。还有个 `/reproduce-paper <论文 URL>` 命令直接跑复现。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 本地工作站跑通后想上超算。issue #303 的用户已经在自己机器上跑起来，追问能不能接 NSF ACCESS（卡在 Duo 二次认证）。
- 场景 2: 补调度后端。issue #316 提议加 `gflow` 单机调度；issue #317 是一位外部贡献者交付的 60 文件、+4,617/-1,571 行可靠性与可复现性大 PR——这是今天榜上少见的实质外部贡献。
- 场景 3: 论文复现与消融实验。官方主打场景是在自有 GPU 上并行跑一批消融，最后能说清每个数字的来路。

**社区怎么评价**:
- 正面: 发版接近日更（v0.2.1 于 9 月 12 日），累计 301 个 PR，issue 关闭率高（历史 17 个开过的 issue 已关 12 个）。
- 负面: 对上游 agent CLI 的集成很脆——issue #246 装了 OpenCode v2 之后每次对话报 500；#307 是 OpenCode 配置超过 64KiB 管道缓冲直接崩；#121 的本地 harness 检测忽略自定义 API 端点与鉴权；#244 在 Codex 自定义 provider 下无法切模型；#207 Windows 支持仍标 beta。
- 健康度: 2,103 ⭐ / 7 watchers = **300:1**，仓龄仅 3.2 个月，全历史只开过 17 个 issue。贡献者 sox8502(196) + rehaanahmad2013（联合创始人，65）+ myles332(63) 约占 97%。
- 外部: HN 无本项目讨论（母产品 alphaXiv 2024 年那条 549 分热帖与本仓无关，不能算作 grounding）；X 上是官方发布推加 Weights & Biases 的 Scott Condron 转介绍，属厂商生态互推；Reddit 含 r/MachineLearning 均无命中。

**风险与争议**:
- **vanity**: 300:1 的比值加上全史 17 个 issue、HN/Reddit 零讨论，热度主要由一家融过 $7M 的创业公司的发布节奏驱动，而不是社区自发。但 301 个 PR 与日更发版说明代码是真在做——判断应为"发布驱动的热度"，不是空壳刷星。
- **安全**: README 自述 `orx up --remote` 起的远端服务绑 loopback 但**没有应用层认证**，同一主机上的其他用户可以直接访问。共享 GPU 集群场景下这是实打实的越权风险。
- **dependency**: 强依赖 Claude Code / Codex / OpenCode 等外部 CLI，上游一改版就炸，issue #246 就是现成例子。
- **bus_factor**: 三人（含联创）占 97% 提交，社区维护几乎为零。
- **stability**: 三个月仓龄、v0.2.x、Windows 标 beta，多个 harness 集成崩溃的 issue 未清。
- **privacy**: 官方发布构建默认开启遥测（可 `orx telemetry off` 关掉）。

**技术备注**: Rust，MIT，CLI 名 `orx`，本地面板 `127.0.0.1:4791` + SQLite，另有桌面 App。

### [tonhowtf/omniget](https://github.com/tonhowtf/omniget) — NEW ⭐ 11,717（+507）| Rust | 信源：中

**它是什么**: 一个桌面下载器。核心是把 yt-dlp（命令行下载工具，支持 1,800 多个站点）包了一层图形界面，装好即用、不用配环境——yt-dlp 和 FFmpeg 它自己装。在此之上加了几个原生抓取器：Udemy、Hotmart、Kiwify、Rocketseat 的在线课程，以及 torrent、PDF/EPUB 阅读器、语音转写和闪卡功能。

**解决什么问题**: 主打的场景是"**我买的课程，在平台下架之前存到本地**"。在线课程平台经常下架内容或改订阅制，买过的人未必还能看；命令行工具能做这件事，但大多数买课的人不会用终端。omniget 把这段门槛去掉了。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 批量存课程。issue #286 报告课程只抓到第一页且不能续传；#185 报整门课漏抓——这类问题只有真的在跑几十节课的人才提得出来。
- 场景 2: Udemy 鉴权。issue #288、#334 是登录成功但拿不到鉴权令牌；#305 是 Hotmart 侧报错；#193 报 Courses 插件全平台"连接失败"。
- 场景 3: 通用站点下载与 Telegram 抓取。issue #289、#325 是 Telegram 插件崩溃（后者带 SIGSEGV）。

**社区怎么评价**:
- 正面: 发布节奏很密——6 周内 v0.8.2 到 v0.9.2 共 10 个版本，最近一次 9 月 11 日；1,025 forks 与 331 个 issue/PR 编号说明确有规模化使用。
- 负面: 投诉几乎全是功能性的，集中在课程抓取不完整、不可续传，以及 Linux 端画质卡死与插件加载失败（issue #265）。
- 健康度: 11,717 ⭐ / 44 watchers = 266:1，比值很高，但 forks、issue 密度和发版节奏都支持"真实使用"；贡献者极度集中——作者 2,635 commits，第二名 53。
- 外部: HN 两次提交合计 6 分 2 条评论，约等于无讨论；Reddit 搜不到原生讨论；X 无独立信号。搜索结果里反而有一批 `igect/omniget`、`cyberresearch/omniget` 之类**同名镜像仓**——要装二进制的人务必先确认上游地址。

**风险与争议**:
- **compliance**: 下载付费 Udemy / Hotmart 课程基本违反平台服务条款，即便你自己买过。README 的立场是只下登录会话能打开的内容、不绕过 DRM、遇到 DRM 课时跳过并报告；其自述的 AES-128-CBC HLS 解密属标准 HLS 加密而非 Widevine 级 DRM，说法自洽，但责任仍然切给用户。

## 如何理解今天的热度信号

今天有三个项目值得放在一起看，它们共同说明**"star 还在涨"和"项目还在动"是两件事**：

- `OpenMontage` 两周涨了 11,117 星，同期只有一条文档提交，实质合并停在 8 月 22 日。
- `pentagi` 今天排名跳升 8 位、单日 +590 星，最后一次提交在 8 月 6 日，最后一个 release 在 5 月 29 日。
- `Claude-Red` 拿到自身最高单日增量 +506，最后一次提交在 8 月 29 日。

这三个的共同点不是刷星，而是**扩散的时间常数比开发的时间常数长**——一次成功的发布或话题红利，能在代码静默之后继续推动几周的 star 增长。读者在评估"这个项目现在还值不值得投入"时，看 `pushed_at` 和最近一个 release 的日期，比看 star 曲线更有用。

反过来，今天也有热度与开发同步的例子：`gods-eye-view` 单日 +2,680 且当天就有三次实质提交，`VoiceStudio` 八天 +8,928 且 9 月 10 日刚发版，`colibri` 三天 +2,459 且 9 月 13 日刚发 v1.11.0。这三个的热度有当下的开发活动兜底。

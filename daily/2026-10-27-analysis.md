**主线二：设计技能成了同榜最大的一组。** Hallmark 连续 3 天在榜并升到榜首，Impeccable 10-26 发布 skill-v4.8.0 和 engine-v0.1.18，今天又加入 Huashu Design。三者针对同一个问题：Agent 生成的页面风格雷同、一眼能看出是 AI 做的。路线不同：Hallmark 用"反 AI 套路"规则约束 Agent 的设计选择；Impeccable 把设计语言做成技能加检测引擎，持续补检测规则；Huashu Design 面向中文用户，一句话产出网页原型、可编辑 PPTX、动画和信息图，10-17 发布的 3.0 版把风格库扩到 84 种，并加入本地设计偏好记录和设计体检。对产品和前端团队来说，这一组值得放在一起比较，看哪条路线适合自己的交付物。

**主线三：Agent 工作区出现第三条路线 —— 本地常驻的"AI 队友"。** 昨天同榜的 Cindy 和 ThinkRail 今天都还在。Cindy 是把 Claude Code、Codex 装进同一个客户端的多 Agent 产品，10-26 发布 v0.1.117-beta；ThinkRail 是 JetBrains 为 pi 编程 Agent 做的轻量 IDE，10-26 合入可在设置里指定 pi 配置目录和环境变量（#912）。新上榜的 OpenBot 走第三条路：在本机或 VPS 上长期运行多个 Agent，每个有独立工作区和任务队列，Agent 之间可以互发消息、分派任务。OpenBot 两个月发了 99 个版本，迭代很快，但使用 PolyForm 非商业许可，Agent 默认以完全访问权限运行，企业试用前需要先看许可和隔离方式。

**主线四：技能生态的老项目集体回榜，安全扫描同时回来。** ECC（上次在榜 10-18）、karpathy-skills（上次 10-11）和 Agent-Reach（上次 10-06）同日回榜，NVIDIA 的技能安全扫描器 SkillSpector 时隔四个多月再次上榜，这四个月 stars 从 6,413 涨到 22,249。技能包越来越多，SkillSpector 这类"安装前先扫一遍"的工具需求也在跟着涨。它 10-22 合入了多项检测边界改进（#841、#815、#819），10-23 发布 v2.13.1。

**主线五：榜单解读提醒 — 设计和工作区两组的热度要结合社区足迹看。** Hallmark 的 stars/subscribers 约 500:1、open issues 62；Huashu Design 约 266:1，open issues 只有 6 个；OpenBot 约 216:1，HN 只有一条 2 分帖。三者都有真实使用反馈，但站外独立讨论偏少，传播主要靠作者和 KOL。Postiz 是三年老项目，今天上榜的直接诱因更可能是托管服务的变动，不是新产品发布（见项目段）。

## NEW 首次上榜

### [nightly-labs/openbot](https://github.com/nightly-labs/openbot) — NEW ⭐ 1,515（+176）| TypeScript | 信源：中

**它是什么**: 一个桌面软件，让你在自己电脑上同时养几个长期在线的 AI 助手（可接 Codex、Claude、Grok）。每个助手有自己的文件夹和待办队列，可以操作浏览器、互相传文件、互相派活，像一个小团队一样协作。

**解决什么问题**: 以前要同时用几个编程 Agent，得开几个终端窗口手动来回贴上下文，Agent 之间也无法直接交接任务。OpenBot 把它们放在同一个常驻工作区里，用任务队列和 Agent 间消息把分工串起来，用户还能用已付费的 ChatGPT、Claude、Grok 订阅，不必另买 API key。

**谁在用、怎么用**（来自 Issues/X）:
- 场景 1: 在本机、VPS 或 Docker 上常驻多个 Agent 协作开发；有用户反馈协调者分派任务出错（#3041）、Cursor Agent 无法给其他 Agent 发消息（#3058），说明多 Agent 协作功能已有人实际使用。
- 场景 2: 社区补本地化和平台适配，如俄语界面（#1548）、Windows 开发运行脚本（#1215），也有人提 Apple Watch 伴侣应用需求（#2855）。
- 场景 3: X 上有葡语用户试用后评价"能用但有点臃肿"，自己 fork 去掉了登录。

**社区怎么评价**:
- 正面: 开发节奏极快，仓龄约 2.5 个月发了 99 个 release，最新 v0.51.1（10-26）；累计 issue 超过 1,000 个、未关闭约 160 个，处理速度快。
- 负面: 一轮对话在输出前失败会卡住整个 Agent 队列且重启不消失（#2214）；Codex 会话里 MCP 被强制禁用（#3149）；Codex 生图 404（#2970）。
- 健康度: stars/subscribers 约 216:1（1,515 / 7）；提交集中在 3 名核心成员，第一名 1,340 次；HN 只有一条 10-26 的 2 分帖，Reddit 未找到讨论。

**风险与争议**:
- **compliance**: 许可为 PolyForm Noncommercial 1.0.0，禁止商用，不属于 OSI 意义上的开源，与宣传中的"开源"口径有差距。
- **privacy**: README 写明 Agent 以 `danger-full-access` 运行，执行操作前不逐项审批，需要自行做机器隔离。
- **stability**: 官方标注 development preview，版本几乎每天更新，队列与协作功能有回归问题。
- **bus_factor**: 提交高度集中在少数核心成员。
- **命名混淆**: 与 Intel 的机器人项目 OpenBot 等同名，检索和选型时容易混淆。

**技术备注**: TypeScript 桌面应用，支持 macOS、Windows、Linux 与 Docker 部署，内置浏览器控制和远程桌面（Sunshine）；官网 openbot.run。

### [gitroomhq/postiz-app](https://github.com/gitroomhq/postiz-app) — NEW ⭐ 38,494（+188）| TypeScript | 信源：中

**它是什么**: 一个可以自己部署的社交媒体排期工具，相当于开源版的 Buffer 或 Hootsuite。把要发到 X、LinkedIn、Instagram 等平台的内容排好时间，到点自动发；现在也可以让 AI Agent 通过 MCP、CLI 或 API 直接帮你写和发。

**解决什么问题**: 运营多个社交账号的团队原本要么手动逐个平台发，要么付费订阅 SaaS 排期工具。Postiz 可以免费自托管，用 Docker 跑起来，并接入 n8n、Make 等自动化流程。

**谁在用、怎么用**（来自 Issues/G2/X）:
- 场景 1: 营销团队和独立开发者统一排期多平台发帖；G2 上 51 条评价、平均 4.8 分，称赞自托管和 API 集成。
- 场景 2: 让 AI Agent 自动发帖；10 月版本加入自托管 MCP connector，X 上有用户说"配合 agent 用得很好"。
- 场景 3: 接 Instagram 等渠道时报 "Could not add provider"（#918，61 条评论，一年多未关），说明大量用户在实际配置多平台账号。

**社区怎么评价**:
- 正面: 仓龄 3 年多，持续发版（v2.25.1 10-11、v2.25.2 10-23、v2.25.3 10-24），有付费用户和第三方产品嵌入。
- 负面: 每个平台都要自建 OAuth 应用，非技术用户上手门槛高；有用户要求支持自定义 OpenAI Base URL（#1074）；LinkedIn 评论 API 废弃迁移的 PR 长期未合（#1332）。
- 健康度: stars/subscribers 约 279:1（38,494 / 138），对三年老项目来说不足以单独说明问题；提交集中在作者 nevo-david。HN 有多个 Show HN，但互动最多的一条只有 42 分；Reddit 未找到具体帖子。

**风险与争议**:
- **dependency**: 完全依赖各社交平台的 API 和条款，Meta、LinkedIn、X 接口变动会直接导致发帖失败（#918、#1332）。
- **compliance**: AGPL-3.0，修改后对外提供服务需开源，商用集成前要评估。
- **privacy**: 作者在 X 上称托管版因上游云平台 Railway 的安全事件停机，随后 10-23、10-24 连发两版；事件细节与托管服务恢复情况本文未独立核实，使用托管版前应先确认。
- **bus_factor**: 提交集中在作者一人。
- **营销驱动**: 作者长期公开分享营收增长和营销打法，热度中有明显的运营成分。

**技术备注**: TypeScript（NestJS + Next.js），Docker 自托管，提供 Public API、MCP connector 与 CLI。

### [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design) — NEW ⭐ 26,855（+251）| HTML | 信源：中

**它是什么**: 一个装进 Claude Code、Codex、Cursor 等编程 Agent 里的"设计技能"。你用一句中文描述需求，它产出可以直接交付的网页原型、App 原型、可编辑的 PPT、动画或信息图，会先出 6 个候选再挑 3 个方向做完整稿。

**解决什么问题**: 不会设计的人让 AI 做页面或幻灯片，往往得到千篇一律的"AI 风"结果，PPT 还常常只能导出图片。这个技能提供 84 种带样张的风格库、可编辑 PPTX 导出，并记录你的外观偏好，越用越贴合个人口味。

**谁在用、怎么用**（来自 Issues/外部评测）:
- 场景 1: 课程和提案用的演示文稿；有教学场景实践（#49），用户要 PPT 版（#21）后现已支持可编辑 PPTX，3.0 修复了 PPTX 导出丢文字（#56）。
- 场景 2: 替代 Claude Design 做原型；第三方博客 Chase AI 做同题对比，称用该技能消耗约 1% 的 Claude Code 周额度，Claude Design 约 15%。
- 场景 3: 有社区做了韩文版衍生（#9），被多个技能目录和讯飞技能广场收录。

**社区怎么评价**:
- 正面: 3.0（10-17）改动实在：6 选 3 的候选流程、风格库扩到 84 种、新增本地品味记忆 `learn.py` 和设计体检 `design_lint.py`。许可自 2026-05-14 起改为 MIT，可商用。
- 负面: 有用户用其他 Agent 做不出演示效果，作者承认演示用的是最高档 Claude 模型且从多轮结果中挑选（#41）；`npx skills add` 安装失败（#48）；deck 页内方向键失灵（#23）。
- 健康度: stars/subscribers 约 266:1（26,855 / 101）；open issues 仅 6 个；提交几乎全部来自作者本人；fork 2,968，说明更多人在装用而非共建。HN、Reddit 未找到讨论，外部传播以作者本人和技能目录、博客转述为主。

**风险与争议**:
- **stability**: 效果高度依赖顶级模型和多轮挑选，换模型或换 Agent 后效果落差大（#41）。
- **bus_factor**: 几乎单人维护。
- **vanity**: 传播主要靠作者个人影响力，stars 增速与 issue 讨论量不匹配，属于轻度信号。
- **compliance**: 早期版本曾要求商用付费授权，部分聚合站仍展示旧条款；以仓库当前 MIT 许可为准。

**技术备注**: 以 HTML 为原生产物的 Agent 技能，附 Python 辅助脚本（偏好记录、设计检查、PPTX 导出），适配 Claude Code、Codex、Cursor 等。

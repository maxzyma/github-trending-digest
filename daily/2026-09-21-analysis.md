## NEW 项目

### [vercel-labs/json-render](https://github.com/vercel-labs/json-render) — NEW ⭐ 17,359（+291）| TypeScript | 信源：强

**它是什么**: Vercel Labs 出的"生成式 UI"框架。你先用 Zod 写一份**组件目录**（Card、Metric、Button…）和允许的动作清单，大模型只能输出引用这些组件的 JSON 树，框架再把这棵 JSON 树渲染成真实界面。已覆盖 React / Vue / Svelte / Solid / React Native / Next / Remotion / react-pdf / react-email / Ink / React Three Fiber。

**解决什么问题**: 让模型生成界面，此前常见做法是让它直接吐 React 代码——能跑，但没有任何护栏：模型可以引入你没有的组件、写出你不想要的交互，也很难做增量渲染。json-render 把可用组件收敛成一份显式白名单，模型的输出从"任意代码"降级为"受约束的数据"，因此可审、可校验，也能按 JSONL patch 逐行边生成边渲染。它和 Vercel AI SDK 不是替代关系：AI SDK 负责调模型和流式传输，json-render 是**架在它之上的渲染约束层**（官方有专门的 AI SDK 集成文档），不用 AI SDK 也能单独跑。

**谁在用、怎么用**（来自 Issues/HN/X）:
- text-to-dashboard：HN 讨论里有人用它做"自然语言生成仪表盘"，反馈是比裸用 structured outputs 稳定。
- 对话内嵌 UI 与 agent 界面输出：把 MCP / agent 的结果直接渲染成卡片、表单，而不是纯文本。
- 跨端复用同一份组件目录：同一个目录在 Web、React Native、PDF、邮件几端渲染。
- 安全方向开发者 @ethanolivertroy 已实际接入并反馈输出质量可用。

**社区怎么评价**:
- 正面: HN 首帖（1/24）77 分 23 评，有真实使用反馈；被 OpenUI、Daub 等项目拿来做对照基准；InfoQ、The New Stack、LogRocket 均有报道。
- 负面: **#258「How is anyone able to run this project?」** 是最热 issue——examples 依赖一个未声明的全局 `portless`，turbo 并发 20 撑不住 42 个任务，多人复现失败；**#297** 卡在 zod 4.4+ 无法升级；**#329** react 18 的 peer 范围过窄；**#9** 长期被追问 Vue 支持与 OpenUI 的基准对比。社区 PR 积压明显，Angular renderer **#244** 从 3 月挂到今天仍未处理。
- HN 上的主要质疑是"为什么不复用 OpenAPI / JSON Schema"和"与 Google A2UI 是否重叠"，讨论后的共识是：json-render 是应用内工具，A2UI 是跨信任边界的协议，两者定位不同。
- 健康度: 17,359 ⭐ / 59 watchers（约 294:1）/ 922 forks / 109 open issues；2026-01-14 建仓，仓龄 8 个月，9-18 仍在推进（v0.21.0 刚加 TanStack Start）。贡献者高度集中：ctate 179 commits，第二名仅 7 次。Apache-2.0。

**风险与争议**:
- **bus_factor**: 单人主导开发（179 : 7 的提交差距），社区 PR 长期无人合并，Angular renderer 挂了半年。
- **stability**: 仍是 0.x，examples 开箱跑不起来（#258），且对 zod / react 的版本约束偏紧（#297、#329）。
- **vanity**: 294:1 的 stars/watchers 比偏高，但这里主要是 Vercel 官方渠道放大所致——HN、媒体和第三方使用证据都存在，不是空心项目。

**技术备注**: TypeScript / Apache-2.0；核心是 Zod 定义的组件目录 + JSON 树渲染器 + JSONL patch 流式协议；多框架 renderer 以适配器形式提供。

## 如何理解今天的热度信号

今天这份榜单如果只看排名，容易读出三个错误结论，这里逐个拆开。

**排名第 1 不等于当天最热。** ECC 以 +826 排在榜首，security-audit-skill 以 +2,428 排在第 3，差了近三倍。GitHub Trending 的排序不是按当日 star 增量的单一排序，榜单收缩（15 → 13 项）也会把位置往上抬。看"哪个项目今天真的在涨"，应该直接看今日增量那一列。

**排名下滑不等于项目退步。** 今天 7 个已上榜项目全部下滑，但其中 higgsfield（+196 → +465）、OpenStock（+472 → +755）、agent-skills（+556 → +736）的日增其实在上升。周一榜单缩水时，相对排名的信息量比平时更低。

**高 stars/subscribers 比要分情况看。** 今天比值超过 190:1 的有 5 项：agent-native 404:1、json-render 294:1、cua 286:1、security-audit-skill 278:1、ECC 196:1、agent-skills 190:1。但它们的性质不同——json-render 和 security-audit-skill 有 HN 讨论、媒体报道、可读代码和第三方使用证据，高比值主要来自官方渠道的分发放大；agent-native 的 13 个 subscriber 配上"issue 里全是内部 PR"才是真正需要谨慎的组合；ECC 则是比值不算最高、但热度完全找不到对应事件的那一类。**比值本身不构成判断，要和 issue 形态、外部讨论、仓龄一起看。**

最后一点关于今天的两个新面孔：它们都不是被新发版推上来的。json-render 靠 Vercel 的持续分发，assignments 靠 9 月 22 日的开课日历。这不代表项目不好——json-render 的 grounding 在今天榜上属于最扎实的一档——但它提醒读者，Trending 位置反映的是"这一天有多少人在点开和 fork"，而这件事的成因可以完全与技术进展无关。

**主线三：Agent 成本层开始独立成赛道。** `workweave/router`（NEW，#19）是今天最值得盯的基础设施新项目：一个 Go 写的模型路由器，声称 <50ms 内把每个 prompt 分发到"够用的最便宜模型"，只换 base URL 就能给 Claude Code / Codex / Cursor 降本 40–70%。它在 6 月 26 日的 Show HN 拿到 216 分 / 113 条评论，且讨论质量很高——最尖锐的反驳是"换模型会打掉 prompt cache，路由省下的钱可能被缓存失效吃掉"，团队公开承认无状态路由确实更贵、只能靠 cache-aware 粘性缓解。这类"降本中间件"能不能站住，本质取决于 cache 经济学，而不是路由准确率。同组的 `Osmantic/ODS` 走的是另一条路：把整台 PC/Mac/Linux 变成本地 AI 服务器（Ollama + Open WebUI + n8n + ComfyUI 一键编排），主打不把数据送出去，但升级链路的破坏性 bug 相当密集。

**主线四：榜单解读提醒 — 今天四个非知名 NEW 项目的站外 grounding 全部偏弱。** OpenMAIC、ODS、user-scanner、workweave/router 四个 NEW 项目里，只有 workweave/router 有实质外部讨论（Show HN 113 评），另外三个在 HN 近乎零讨论、Reddit 完全无讨论。其中 ODS 的 GitHub 数据尤其需要拆开看：`open_issues_count` 显示 1,400，实际真 issue 只有 92 个，其余 1,308 是未合并 PR，且抽样最近 400 个 open PR 后发现作者高度集中在 4 个账号、标题格式高度雷同（`feat(x): expose … as JSON`），更像批量生成的 PR 灌注而非社区贡献。这不是说这些项目没价值——OpenMAIC 有清华真实课堂和 arXiv 论文背书、fork/star 达 19% 说明有人真在自部署——而是它们的热度曲线目前只能靠 GitHub 内部证据支撑，需要再观察一到两周才能判断是否转化为采用。

### [THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC) — NEW ⭐ 22,329（+907）| TypeScript | 信源：中

**解决什么问题**: 在此之前，用 AI 学一门新东西的方式是不停地和聊天框一问一答——你得自己知道该问什么，也没有别人替你问出你想不到的问题。OpenMAIC 把这个过程反过来：课程结构由 Plan Agent 先排好，讲解由 AI 教师主动推进，"你没想到要问的问题"由 AI 同学替你问出来。对自学者来说，差别是从"我来提问"变成"我来听课并随时插话"。

**社区怎么评价**:

### [bigskysoftware/htmx](https://github.com/bigskysoftware/htmx) — NEW ⭐ 49,126（+32）| JavaScript | 知名老项目首入 tracker

**它是什么**: 一个让你直接在 HTML 标签上写交互的库。想点按钮从服务器取一段内容替换到页面某处，用 htmx 就是在按钮上加几个属性（`hx-get`、`hx-target`）——不需要写 JavaScript、不需要构建工具、不需要前端框架。服务器返回 HTML 片段而不是 JSON，浏览器直接换上去。

**解决什么问题**: 现代前端的默认路径是"React/Vue + JSON API + 构建管线"，但很多应用其实只需要局部刷新。htmx 的主张是：如果 HTML 本身就能表达这些交互，那大部分单页应用的复杂度就是不必要的。对小团队和后端主导的项目来说，差别是能不能省掉整条前端工具链。

**为什么今天上榜**: 8 月 28 日发布 **v4.0.0** 主版本，两天后进入 trending。注意它今天只涨 32 ⭐——上榜靠的是主版本事件带来的短时关注度，不是 star 爆发。这和榜上单日四位数增长的 skill 仓是完全不同的信号类型。

**社区怎么评价**: 长期热议 issue 都是真实工程债而非 launch 期讨论——#1911 chunked transfer encoding 支持（47 条评论）、#3352 `hx-swap-oob` modifier（27 条）、#130 分页/元素数量限制（33 条）。681 open issues / 218 subscribers / 1,640 forks，2020 年 4 月建仓，六年活跃维护。

**风险与争议**:
- **迁移成本**: v4 是主版本，从 v2/v3 升级的破坏性变更需要按 release note 逐项核对；社区迁移反馈还需观察数周。

**技术备注**: 纯 JavaScript，无依赖，可 CDN 直引。零构建工具是它的核心卖点，也是它与主流前端生态的分界线。

**社区怎么评价**:

**技术备注**: Python，编排 Ollama / Open WebUI / n8n / ComfyUI 等既有组件，跨 NVIDIA / AMD / Apple Silicon。

### [workweave/router](https://github.com/workweave/router) — NEW ⭐ 2,761（+284）| Go | 信源：中

**它是什么**: 一个夹在你的编码 agent 和大模型之间的"调度员"。你把 Claude Code 或 Cursor 的 API 地址换成它，它会看每一条 prompt 有多难，然后把简单的发给便宜模型、把难的发给贵模型，整个决策在 50 毫秒内完成。官方说这样能省 40–70% 的推理成本，而你除了改一行配置什么都不用动。

**解决什么问题**: 用编码 agent 的实际成本结构里，大量请求是"补全一行、改个变量名、格式化"这类根本用不上顶配模型的活，但 agent 默认全部走同一个模型。此前要么手动切换模型、要么忍受账单。router 想把这个选择自动化掉。

**谁在用、怎么用**（来自 HN/Issues）:
- 场景 1: Claude Code / Codex / Cursor / opencode 换 base URL 直接降本，这是 Show HN 里被提及最多的用法。
- 场景 2: 自托管进 VPC，或用托管版 router.workweave.ai。前者是有合规要求的团队的选择。
- 场景 3: issue #526（nijave 提）请求 model alias 支持——这是目前少数几条真正来自外部用户的诉求。

**社区怎么评价**:
- 正面: 6 月 26 日 Show HN 拿到 216 分 / 113 条评论，是今天所有 NEW 项目里唯一有实质外部讨论的。开发投入也扎实：1,068 个 PR（83 open）、10 位贡献者、主力 steventohme 554 commits，昨天还在推送。这是有团队在推的产品仓，不是空壳。
- 负面: HN 上最尖锐的质疑是**换模型会打掉 prompt cache，路由省下的钱可能被缓存失效吃回去**——团队公开承认无状态路由确实更贵，只能靠 cache-aware 粘性缓解。其余质疑包括 scorer 只用自家代码库训练、奖励信号过简、以及路由剥夺了 agent 自身的模型感知与纠错回路。
- 健康度: 需要小心读数——`subscribers_count = 1`，比值 2761:1 看着极端，但这更可能是组织成员未订阅导致的字段异常，不宜当 vanity 证据。真正值得注意的是 issue 区几乎全是内部人自查条目：rohith500 一人开了 #454 #478 #487 #516 #535 #779 #780，内容是计费不设余额下限可被突发请求打成负数（#478）、缓存 TTL 计费错算少收 37.5%（#867）、admin API 泄露内部 Go 包名（#535）。外部用户反馈近乎为零。

**风险与争议**:
- **cost**: 40–70%（官方博客另有 80–85% 的说法）全部来自厂商自报，Robinhood/PostHog 案例没有独立验证；HN 上"cache 失效吃掉节省"的质疑团队已部分承认。
- **compliance**: Elastic License v2，不是 OSI 认可的开源许可，限制商业转售与提供托管服务。
- **privacy**: 托管模式需要把全部 provider key 和全量 prompt 交给第三方。
- **stability**: 计费与失败转移路径存在多条未修 bug（#478、#867），且多数 0–1 条评论、长期未关。
- **社区 grounding 不对称**: HN 有真实讨论，但 X 上可见传播多为聚合站 AI 生成稿（hyper.ai / baguaai），Reddit 无讨论。

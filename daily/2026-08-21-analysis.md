## 本日主线

**主线一：榜单地图 — agent 生态的重心正从"技能包"下移到"运行时与底座"。** 17 个项目里，技能包/插件规范层仍占 4 席（mattpocock/skills 22.7 万星、obra/superpowers 27.5 万星、cursor/plugins、caveman），但真正的新增量全在下面一层：`agent-substrate/substrate` 是 Google 开源的 Kubernetes 原生 agent 运行时（把上千个 agent 沙箱多路复用到少量预热 Pod，靠 gVisor 快照做亚秒级挂起/恢复），`volcengine/OpenViking` 是字节火山引擎的 agent 上下文数据库，`akitaonrails/ai-memory` 做跨 CLI 的长期记忆与交接，`Tencent/AI-Infra-Guard` 则专门扫 MCP server 和 Agent Skills 的供应链风险。四个项目分别对应"agent 在哪跑、记什么、怎么交接、怎么审"，而且出品方是 Google、字节、腾讯加一位独立开发者——这条线已经不是玩具阶段。对读者的判断是：如果你去年只在关注"写什么 skill"，今年要开始关注"skill 跑在什么东西上、谁来审它"。

**主线二：Modular/Mojo 三连事件 — 一次干净的事件驱动上榜。** `modular/modular` 首次进入本 tracker（rank 1，+268，累计 2.8 万星），触发点是清晰可查的三件事：2026-07-29 Qualcomm 完成对 Modular 的收购；08-11 发布 MAX 26.5 / **Mojo 1.0.0**，首次给出 API 稳定承诺；08-18 **Mojo 编译器与工具链全量开源**（此前 2024 年起只开源了 stdlib），当天 HN 346 分/77 评，ModCon 公告帖再拿 224 分/109 评，Mojo 1.0 本身 430 分/244 评。这类"版本 + 开源 + 收购"叠加的热度和刷出来的热度完全不同：三个独立事件都有官方博客、第三方媒体和大规模 HN 讨论对照。值得注意的取舍是编译器虽然 Apache-2.0（with LLVM Exceptions）开源了，但**暂不接受外部贡献**，官方目标是 2026 年底才开放——开源了代码，还没开源治理。

**主线三：本地优先桌面工具回流 — 两个"不联网、不要账号"的项目挤进前 12。** `AprilNEA/OpenLogi` 用 Rust 重写罗技外设配置（侧键、DPI、SmartShift 直接走 HID++ 协议，无账号无遥测），08-19 在 HN 拿到 1605 分/425 评论，是本周单帖最高；`mahlernim/google-timeline-visualizer` 把 Google 位置历史导出文件在本地渲染成年度旅行视频，不上传任何数据。两个项目都不新颖在技术上，而是精准踩在"厂商客户端越来越重、越来越要登录"的不满上。它们也共享同一个软肋：完全依赖被逆向的私有协议或第三方导出格式，上游一变就失效。

**主线四：榜单解读提醒 — 今天有三个高 stars/subscribers 比值，但成因完全不同。** OpenLogi 260:1、AI-Infra-Guard 125:1、agent-substrate 88:1，如果只看比值会得出三个"虚高"结论，但实测证据分岔明显：agent-substrate 的比值来自新建 org 无人订阅，它有 453 个已合并 PR、15+ 核心贡献者（含 Kubernetes 联合创始人 thockin）和 Solo.io 的第三方集成，社区活动量远超典型虚高项目；OpenLogi 有 HN 千分级讨论托底，但传播路径以多语种媒体扩散为主，独立开发者实测反馈偏少，且核心侧键映射在 macOS 上仍有未复现 bug；AI-Infra-Guard 是官号推广强于社区自然讨论，HN 近乎无讨论、Reddit 无原生帖，但有 2000 条 CVE 规则、benchmark、arXiv 报告和真实报错 issue，属于"推广强、grounding 薄"，不是空壳。**比值只是提问的起点，不是结论。**

## NEW 项目

### [modular/modular](https://github.com/modular/modular) — NEW ⭐ 27,985（+268）| Mojo | 信源：强

**它是什么**: 一套想替掉 CUDA 的 AI 计算底座，由两部分组成：Mojo 是一门语法像 Python、性能对标 C++/Rust 的新语言，专门用来写 GPU kernel 和高性能算子；MAX 是基于它的推理平台，让同一份 kernel 代码在 NVIDIA、AMD 等不同厂商的加速卡上都能跑。公司 2026-07-29 已被 Qualcomm 完成收购。

**解决什么问题**: 今天要把一个模型跑得快，实际是在给每家硬件各写一套底层代码——NVIDIA 走 CUDA、AMD 走 ROCm，两套栈的算子、调优、调试全不通用，换硬件等于重做。这不只是工程量问题，更是采购议价权问题：你越依赖 CUDA，越换不掉。Modular 的做法是在 Python 那层语法之下重建一条编译链（Mojo 编译到 MLIR），让你写一次 kernel、编译到多种后端；MAX 再把这层包成可部署的推理服务。它的价值主张对使用方很直接：绕开单一厂商锁定；反过来，公司自己现在归 Qualcomm 所有，锁定风险只是换了个方向。

**谁在用、怎么用**（来自官方案例/Issues/HN）:
- 场景 1: 推理服务商与 AI 产品公司用 MAX 做多硬件部署——官方案例包括 MiniMax、Hippocratic AI（医疗实时对话）、Inworld（语音合成）、Qwerky AI（一次写 Mamba kernel、多硬件跑）。
- 场景 2: 硬件与云侧接入——AMD MI300/325/355 已 GA，NVIDIA Blackwell/Hopper 支持，另有 TensorWave、AWS Marketplace 渠道。
- 场景 3: 语言本身仍在打地基。stdlib 提案讨论很活跃：#3988 String/Unicode 模型（15 评）、#5637 Codepoint、#5389 `String.is_like`、#5636 `Result` 类型——也就是说 1.0 冻结的只是一小部分 API。

**社区怎么评价**:
- 正面: "1.0 前把设计做完再开源"被认为有 intentionality；SIMD/GPU codegen 和 Python 风格语法受欢迎；HN 上有开发者明确表示"因为这周开源了才开始学"。
- 负面: 闭源期太长；早年"Python superset"的承诺 2025-08 已经官方改口，被反复提起；读懂编译器需要不少 MLIR 背景；对 Qualcomm 控制权的疑虑（HN 原话大意"别忘了它是我们的"）。
- 健康度: 27,985 stars / 3,001 forks / 269 watchers（约 104:1，大型成熟仓的结构性比值，不构成 vanity）；open issues 1,104、open PR 295；contributors 约 458+，头部作者分散（Ahajha 13、rachfop 8、JoeLoser 6），近一月 100+ commits，08-20 仍有提交。

**风险与争议**:
- **dependency**: 归 Qualcomm 所有，路线图受单一芯片厂商战略影响；虽是 Apache-2.0 with LLVM Exceptions，但编译器暂不接受外部 PR，治理未社区化。
- **stability**: 26.5 的破坏性变更多于往常（有 deprecated alias + fix-it 缓解）；`modular` 包将在 26.6 退役；async、pattern matching、type unions 均未进 1.0。
- **生态成熟度**: 语言核心类型（`Result`、String/Unicode 模型）仍在提案阶段；第三方评测指出 MoE 模型（Llama 4 Maverick、DeepSeek V3）未充分优化、缺 multi-LoRA，这类负载 vLLM 仍更优。

**技术备注**: Mojo（编译到 MLIR）+ Python 生态互操作；License 页面显示 NOASSERTION，实际为 Apache-2.0 with LLVM Exceptions；仓库 2023-04 创建，当前 tag `max/v26.5.0`。

### [AprilNEA/OpenLogi](https://github.com/AprilNEA/OpenLogi) — NEW ⭐ 11,940（+1,545）| Rust | 信源：强

**它是什么**: 罗技鼠标键盘配置软件的开源替代品。你买了 MX Master 这类高端外设，想给侧键换个功能、改 DPI 档位、关掉那个自动切换的滚轮（SmartShift），官方要你装 Logi Options+ 并注册账号、常驻后台。OpenLogi 直接用 Rust 跟设备说 HID++ 协议，配置写成一个能 diff 的 TOML 文件，不要账号、不发遥测。

**解决什么问题**: 外设配置这件事本来只需要往设备里写几个寄存器，但厂商客户端把它做成了要登录、要联网、要后台常驻的应用，且一次线上事故就能让所有人的按键映射失效——这正是本项目的触发点。此前开源侧只有 Linux 的 Solaar，macOS 和 Windows 用户没有选择。OpenLogi 把配置变成本地文本文件：可以进 git、可以在几台机器间同步、卸载软件也不丢配置。

**谁在用、怎么用**（来自 Issues/HN）:
- 场景 1: MX Master 系列侧键映射浏览器前进/后退，这是 Options+ 最常用场景——也正是目前最不稳的地方（见下）。
- 场景 2: 按应用切换 profile + DPI 档位 + SmartShift 开关；G 系列用户在 #459 要求支持 onboard profiles（0x8100）。
- 场景 3: 设备支持请求非常踊跃，说明有人真想拿它当主力：#163（MX Master 3 for Mac）、#521（MX Keys）；社区也自发交功能 PR，如 #467 拇指键长按重复。

**社区怎么评价**:
- 正面: HN 08-19 首页 **1605 分 / 425 评论**，普遍观点是"终于有 macOS/Windows 侧的开源替代"，且配置文件可 diff 这一点被反复点赞。
- 负面: HN 上的批评集中三点——① 官网文案明显是 LLM 生成的（中英文都一个味），代码注释也过量，被质疑真实工程质量；② README 自承 "not yet stable"，与官网的成品感矛盾，有人评"设备检测顶多 alpha"；③ 从 openlogi.org 拉设备图片，与"零遥测"的宣称有落差。多位用户反馈 M720、MX Anywhere 2S 完全检测不到（#87）。
- 健康度: 11,940 stars / 46 subscribers（约 260:1，偏高）；open issues 208（其中 84 个标 `type: bug`），已关闭 111，说明在真处理不是在堆积；contributors 53，但 AprilNEA 一人 651 commits、第二名 51；open PR 53 未合。2026-05-24 创建，3 个月发到 v0.7.3，8 月连发 7 个版本。

**风险与争议**:
- **stability**: 核心功能不稳。#23（21 条评论，标 `needs: repro`）MX Master 3S 侧键前进/后退不工作；#722 macOS 侧键手势捕获失败；#464 滚轮误触发。作者本人在 README 承认未稳定。
- **bus_factor**: 单人贡献约 92% commits，53 个 open PR 长期未合。
- **vanity**: 260:1 的 stars/subscribers 比，且传播以 Numerama、Korben、CaschysBlog、macitynet 等多语种媒体扩散为主，独立开发者实测反馈偏少（Numerama 实测结论是"有前景但很折腾"）。
- **dependency**: 逆向罗技私有 HID++ 协议，固件一变就可能失效。合规上有 Solaar 先例，没有直接法律争议。

**技术备注**: Rust + GPUI（Zed 的 UI 框架），Apache-2.0；配置为 TOML；覆盖 macOS / Windows / Linux。

### [agent-substrate/substrate](https://github.com/agent-substrate/substrate) — NEW ⭐ 1,409（+22）| Go | 信源：强

**它是什么**: Google 开源的一套"让成千上万个 AI agent 同时跑起来"的底层系统。它不是又一个 agent 框架，而是运行 agent 的地方：每个 agent 是一个叫 actor 的沙箱，多个 actor 复用少量已经预热好的 Kubernetes Pod，靠 gVisor / microVM 的内存快照实现亚秒级挂起和恢复——agent 没在干活时就冻结，来请求了再解冻，终端状态和文件系统都还在。README 自己写得很清楚：这不是 agent SDK，而是大规模跑 agent 的系统。

**解决什么问题**: 一个编码 agent 会话动辄占一个容器好几个小时，其中大部分时间在等人类回话。按传统方式一个会话一个 Pod，一千个用户就是一千个常驻容器，成本和冷启动都撑不住；而如果为了省钱把会话杀掉，agent 攒下的终端历史、文件改动、装好的依赖就全丢了。substrate 的答案是"高密度有状态"：把闲置 actor 冻成快照移出内存，Pod 复用给下一个请求，恢复时状态完整。配套的安全设计也值得注意——凭证在出口注入，agent 本身拿不到 API key。

**谁在用、怎么用**（来自 Issues/官方博客/第三方集成）:
- 场景 1: Solo.io 已把它做成 kagent 的可选 runtime，在上面跑沙箱化 agent（kagent.dev 有专门文档页）。
- 场景 2: google/ax 的分布式 agent runtime；以及高密度有状态编码环境——README 直接点名 Claude Code / Codex 这类需要保留终端和文件系统状态的场景。
- 场景 3: 沙箱化 MCP server 托管，把不可信的 MCP 工具关进 actor 里。
- 架构讨论很实心：#12 控制面持久化 RFC（18 评）、#119 Actor 状态机（23 评）、#484 非 HTTP 协议路由（Istio 侧的 keithmattix）、#368 解耦 CRD（Solo.io 的 EItanya）。

**社区怎么评价**:
- 正面: 有 RFC 文化，外部厂商（Solo.io、Istio 侧）直接进来讨论设计；Google Cloud 官方博客、The New Stack 都有专文。
- 负面: 稳定性坑不少。#1090 CPython actor 恢复后 accept 循环死掉、每次激活都失败；#1066 router 的 mTLS 客户端证书永不轮转，过期即全站路由中断；#1081 running actor 的请求吃掉 parking-lot 槽位；#1050/#1076/#1109 一批网络与并发 flaky 测试；#1009 连接泄漏。README 明写 early development、不适合生产、API 几乎肯定会变。
- 健康度: 1,409 stars / 252 forks / 16 subscribers（88:1，但成因是新建 org 没人订阅）；显示的 391 "open issues" 实际是 230 个真 issue + 161 个 open PR，另有 **453 个已合并 PR** 和 146 个已关闭 issue；contributors 15+ 核心（BenTheElder 83、juli4n 52、thockin 36——Kubernetes 联合创始人、dims 17），issue 全部由人类工程师撰写，无 bot 生成迹象。

**风险与争议**:
- **stability**: 官方自称非生产就绪；恢复失败（#1090）与证书不轮转（#1066）都是会直接打断服务的级别。
- **dependency**: 强绑 Kubernetes + gVisor/Kata；且是"Google 开源但非官方支持产品"，不在 Google VRP 范围内。
- **bus_factor**: 贡献集中在 Google/Kubernetes 少数核心成员，org 下只有这一个仓库。

> 关于 88:1 的 stars/subscribers 比：这里**不适合**打 `vanity`。高比值由新建 org 无人订阅导致，453 个已合并 PR 的活动量远超典型虚高项目——本日"高比值不等于空心化"的最佳反例，详见文末《如何理解今天的热度信号》。

**技术备注**: Go，Apache-2.0，2026-05-13 创建，当前仅 v0.0.0 tag；依赖 gVisor / Kata microVM 做快照；文档站 learn.agentsubstrate.dev。

### [mahlernim/google-timeline-visualizer](https://github.com/mahlernim/google-timeline-visualizer) — NEW ⭐ 1,615（+657）| Kotlin | 信源：中

**它是什么**: 把你手机里 Google 地图记录的位置历史，变成一段年度旅行回顾视频。你从 Google Timeline 导出一个 JSON 文件，选年份或具体日期，它在你自己的设备上渲染出方形、竖屏或横屏的 MP4，适合直接发社交媒体。文件不上传。

**解决什么问题**: Google 自己曾经有"年度回顾"，但位置历史在 2024 年后改成只存本地、导出格式也变了，官方那点可视化基本没了；而 Timeline 导出的 JSON 是一堆坐标和时间戳，普通人打开就懵。第三方的同类服务大多要你把位置数据上传到别人的服务器——位置历史恰恰是最不该上传的那类数据。这个项目的定位就是在这个空档里做本地渲染：Android 侧是 APK 在设备上跑，iPhone 侧走 Safari 网页版但同样不上传文件，无 Google 登录、无定位权限、无 analytics。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 年度旅行回顾发社交媒体，是最主流用法；也有人做单次几天的行程（比如日食旅行）短视频。
- 场景 2: 功能迭代基本由用户驱动——横竖屏导出预设 #41、自定义动画时长 #37、按交通方式过滤 #46 都是社区提的需求，作者跟进很快（#61 本地化崩溃当天修）。
- 场景 3: 隐私向用法：#66 + 外部 PR #69（Xerdiosa 提交）要求 "Safe Sharing Mode" 遮蔽家和公司位置，作者已出 prerelease 原型，并诚实声明遮蔽只降低精度、不保证匿名。

**社区怎么评价**:

## 如何理解今天的热度信号

今天最容易误读的是 stars/subscribers 比值。榜单上有三个高比值项目（OpenLogi 260:1、AI-Infra-Guard 125:1、agent-substrate 88:1），但把它们放在一起就能看出这个指标单独用不了：

- **agent-substrate 88:1，但不虚高**。453 个已合并 PR、15+ 核心贡献者、Kubernetes 联合创始人在提 RFC、Solo.io 做了第三方集成——比值高只是因为 org 是三个月前新建的，没人点 watch。
- **modular 104:1，也不虚高**。这是大型成熟仓的结构性比值：2.8 万星、458+ 贡献者的项目，watcher 数天然不会等比增长。
- **OpenLogi 260:1 和 AI-Infra-Guard 125:1 需要谨慎解读**，理由不是比值本身，而是比值 + 传播路径的组合：两者的外部声量都以媒体转载和官号推广为主，独立开发者的实测反馈明显少于星数暗示的量级；OpenLogi 有 HN 千分级讨论托底，但讨论里对"官网 LLM 生成文案 vs README 自承不稳定"的质疑同样集中。

可操作的读法是三步：先看**成因**（新 org / 成熟大仓 / 短龄 + 媒体扩散），再看**活动量**（已合并 PR、真实报错 issue、release 节奏），最后看**独立第三方**（有没有非作者、非官号的人真的跑过它并写下结论）。三项都弱才是需要打 `vanity` 的情况。

另一个今天格外明显的现象：**排名下降不等于降温**。MoneyPrinterTurbo（↓7）、OpenViking（↓11）、munder-difflin（↓7）三个项目排名都大跌，但日增全部高于昨天——原因是今天榜单从 13 项扩到 17 项且有 5 个 NEW、6 个 RE，位次被稀释。看趋势请看日增和累计，不要只看箭头。

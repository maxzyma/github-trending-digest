## 本日主线

**主线一：榜单地图 — 周末榜的上半场是 agent 工具层，下半场是老基础设施回流。** 17 个项目里有 6 个属于 agent harness / 技能包 / 插件规范这一层：`mattpocock/skills`（23.1 万星，+3,362 重回 rank 1）、`obra/superpowers`（27.7 万星）、`cursor/plugins`、`santifer/career-ops`、`affaan-m/ECC`、`ruvnet/ruflo`，几乎把前 13 位撑满。而 rank 12 往后突然换了年代：`TryGhost/Ghost`（2013 年建仓）、`protocolbuffers/protobuf`（2014）、`microsoft/onnxruntime`（2018）、`microsoft/TypeScript`（2014）四个长期项目同一天出现，当日增量都只有个位数到几十星（protobuf +4、onnxruntime +5、Ghost +32、TypeScript +65）。这是典型的周末榜结构：新项目投放减少，长期高基数仓靠正常流量就能挤上尾部。对读者的判断是——**今天前 10 看趋势，后 7 位不要当作"某个老项目突然火了"来读**。

**主线二：TypeScript 以 Go 项目的身份首次进入 tracker，是本日最容易被忽略的信号。** `microsoft/TypeScript` 在 Trending 上的语言标签写的是 **Go** 而不是 TypeScript——原生 Go 移植（tsgo / TypeScript 7 编译器）已经是主仓的主体代码。一个把"编译到 JavaScript"作为立身之本、被引用了十年的项目，主语言在 GitHub 的统计口径里换成了 Go，这本身就是过去一年前端工具链集体重写（esbuild、Rome/Biome、Oxc、Turbopack）的收束点。它今天只涨了 65 星，热度不重要；重要的是标签变了。

**主线三：Apache Maka 首次上榜 — agent workspace 开始进入基金会治理。** `apache/maka`（rank 14，2,559 星，+148）是一个 local-first 的 agent 工作台，Electron + React 桌面端 / TUI / eval 三个入口全部走同一个 Runtime Host，把模型消息、工具调用、工具结果、权限决策和终止事件写成 append-only 的执行记录。它值得注意的不是功能——这些功能 Claude Code、Cursor、Cline 都有——而是**它是目前极少数进入 Apache 孵化器的 agent 客户端**。README 用了整节篇幅声明"尚未做出任何 Apache release，现有产物都不是 ASF 发布物"，这种发布纪律在 agent 工具圈几乎没见过。与之对照，同榜的 `ECC`、`ruflo`、`superpowers` 全是个人或小团队仓库，治理靠作者自觉。

**主线四：OBLITERATUS 上榜，把"模型去审查"这条线摆到了明面上。** `elder-plinius/OBLITERATUS`（rank 16，8,011 星）是 abliteration 工具链——定位并移除大模型内部负责拒答的表征方向，不用重训练。它有真实的学术底座（Arditi et al. 2024 的 refusal direction、Gabliteration、grimjim 的 norm-preserving biprojection），HN 主帖 219 分 / 83 评，r/LocalLLaMA 有独立复现帖。但它同时是本榜合规风险最集中的项目：README 明确写"响应所有 prompt，无人为把关"，且默认开启遥测把运行数据回传成众包数据集。这条线读者要单独判断，不能按普通开源工具看待。

## NEW 项目

### [apache/maka](https://github.com/apache/maka) — NEW ⭐ 2,559（+148）| TypeScript | 信源：中

**它是什么**: 一个装在自己电脑上的 AI agent 工作台。你给它接一个模型（云端 API、本地模型或网关都行），它就能看你的项目文件、在沙箱里跑命令、帮你改代码；桌面端、终端命令行、批量评测三个入口共用同一个执行内核。项目正在 Apache 软件基金会孵化。

**解决什么问题**: 现在的 agent 客户端有两个反复出现的痛点。一是**记录丢失**：为了省上下文，工具输出被截断或滚出窗口后就真的没了，出问题回溯不到当时到底发生了什么；Maka 把模型消息、工具调用、工具结果、权限决策、终止原因全部写成只追加的日志，界面和下一次模型调用都只是这份记录的"视图"，压缩上下文不等于删历史。二是**同一套 agent 三个入口三种行为**：桌面、CLI、评测各跑各的，评测结果代表不了实际使用；Maka 强制三者都经过 Runtime Host，eval 只负责实验设计和打分。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 桌面端日常写代码与文件工作流。issue #2641（12 评）是从 Runtime Host 读取 usage 数据在桌面端展示，#2921（15 评）在重做 MCP editor 对话框和 inspector 的交互——说明真实用户已经在配 MCP server 并抱怨配置体验。
- 场景 2: 长会话可靠性。#2521（17 评，本仓评论最多）专门区分"用量超限"和"鉴权失败"两类错误——这是长时间连续跑 agent 才会踩到的坑，短试用碰不到。
- 场景 3: 批量评测。#3191（16 评）处理 eval 框架超时后残留进程未清理的问题，说明 eval 子系统确实被跑起来了，而不是摆设。
- 场景 4: IM 机器人接入仍是实验性。#2550（10 评）在做 bot 会话连续性，文档里明确标 experimental。

**社区怎么评价**:
- 正面: 执行记录 append-only、沙箱边界外的工具必须审批、崩溃后可恢复并续跑中断的 turn——这套"可审计执行"的设计在 agent 客户端里少见。ASF 孵化身份也给了企业侧一个可解释的引入理由。
- 负面: 目前只有 macOS Apple Silicon 桌面构建算早期公开版本，Intel Mac 和 Linux 完全不支持，Windows 是未签名预览版；README 明确不推荐任何预编译下载，要求从源码构建（需要 Node 22.19+、npm 11、ripgrep）——这道门槛会劝退大量想试用的人。
- 健康度: 2,559 stars / 309 forks / **12 watchers**（约 213:1）、open issues 262。watchers 极低要放在语境里看：仓库刚迁到 `apache/` org 不久，历史订阅者留在原 org 下，这个比值反映的是"搬家"，不是空壳。真正的活跃度证据在提交结构：头部贡献者 jackwener 1,793 次、Astro-Han 862 次、likun666661 261 次、M4n5ter 186 次，262 个 open issue 里评论数最高的几条全是具体工程 bug 而非 "star me" 类噪音。
- HN 口碑: **无讨论**。以 "Apache Maka" 检索 HN 无相关主帖——这是一个真实的空白，它的热度目前来自 GitHub 内部流量和中文社区，尚未经过英文技术社区的公开检验。

**风险与争议**:
- **stability**: 官方自述"数据格式、CLI 命令、实验能力仍可能变更"；桌面端仅 macOS arm64，Linux 未支持，Windows 未签名。
- **compliance**: 孵化中项目尚无任何经 IPMC 投票的正式 Apache release，现有二进制和 npm 包都不是 ASF 发布物，企业引入前要自己判断合规口径。
- **bus_factor**: 提交高度集中在头部两名贡献者（1,793 + 862，占绝对多数），ASF 孵化的目的之一就是稀释这种集中度，但目前尚未完成。
- **vanity**: watchers 仅 12、HN 零讨论，star 增长主要来自 Trending 曝光与中文渠道；不能仅凭 star 数判断采用度。

**技术备注**: TypeScript 单仓多包（npm workspace），桌面端 Electron + React，内置工具为 `Read`/`Write`/`Edit`/`Bash`/`Glob`/`Grep`，Grep 依赖 ripgrep；Computer Use 与 catalog skills 为可选且默认关闭。Apache-2.0。

### [elder-plinius/OBLITERATUS](https://github.com/elder-plinius/OBLITERATUS) — NEW ⭐ 8,011（+63）| Python | 信源：强

**它是什么**: 一个把开源大模型"拒答机制"摘掉的工具。它不重新训练模型，而是先探测模型内部哪些方向的激活值对应"我不能回答这个"，再在推理时把这些方向抹掉或偏转，让模型对所有 prompt 都作答，同时尽量保住语言能力。技术上这类方法叫 abliteration。

**解决什么问题**: 开源权重模型出厂时带了安全后训练，拒答判断是训练时定死的，部署方改不了。这在安全研究、红队评测和创作场景里是实际障碍——你没有"未对齐基线"就无法量化安全训练到底挡住了什么、误伤了什么。以往做 abliteration 要自己写激活提取和方向计算脚本，缺少可复现的对照。OBLITERATUS 把整条流水线工具化：从探测隐藏状态定位拒答方向，到多种提取策略（PCA、均值差、稀疏自编码器分解、白化 SVD），再到干预本身，每一步的中间产物（激活张量、方向向量、跨层对齐矩阵）都能取出来，还能在改动前先量化"顺从度 vs 连贯性"的取舍。一条命令即可跑完，也提供 HuggingFace Spaces 的 Gradio 界面和 Colab notebook，零代码可用。

**谁在用、怎么用**（来自 Issues/HN/Reddit）:
- 场景 1: 本地跑量化模型的玩家是主力用户。issue #15 请求原生支持 NVFP4 / ModelOpt checkpoint（点名 Qwen3.5-9B-NVFP4），#31 反映 NVIDIA Jetson AGX 不被原生支持——都是边缘/低显存部署诉求。
- 场景 2: 显存受限下的工程适配。#115 要求支持在 Accelerate offload 到 meta device 的权重上安全做"手术"，这是单卡跑不下大模型时的典型路径。
- 场景 3: 方法学对照。第三方文章《Ablation vs Heretic vs Obliteratus: one trick, three layers of tooling》把它与另外两个同类工具横向比较；r/LocalLLaMA 有"norm-preserving abliteration 在 Qwen3.6-35B-A3B 上做到 0% 拒答"的独立复现帖。
- 场景 4: 也有大量纯尝鲜用户。#22 "Chat not working"（6 评）是本仓评论最多的 issue，说明相当比例的访客卡在最基础的使用环节。

**社区怎么评价**:
- 正面: HN 主帖《A tool that removes censorship from open-weight LLMs》拿到 **219 分 / 83 评论**，是本日新项目里唯一有千人级英文社区讨论托底的；学术引用真实可查（Arditi et al. 2024、Turner et al. 2023、Rimsky et al. 2024、Gabliteration arXiv:2512.18901）；Spaces + Colab 双入口显著降低了门槛。
- 负面: HN 讨论里对"去审查即自由"的框架有明显分歧；README 的宣传语气（"co-authoring the science"、"precision liberation"）与其实际定位——一个成熟度尚早的研究工具——之间有落差；能力保全的代价缺少统一 benchmark。
- 健康度: 8,011 stars / 1,453 forks / 74 watchers（约 108:1）、open issues 仅 8。**fork:star 比高达 18%** 是这个仓最有信息量的指标：远高于典型工具仓，说明大量用户是真的 clone 下去改参数跑自己的模型，而不是点个星收藏——这与 vanity 型项目的行为特征相反。贡献者高度集中：jmagly 151 次、elder-plinius 21 次、StellaAthena 10 次，之后是个位数。

**风险与争议**:
- **compliance**: 移除安全对齐可能违反上游模型的使用条款（Llama、Qwen 等许可证多含使用限制），产出的模型再分发的法律边界不清晰；在部分司法辖区还涉及监管风险。
- **privacy**: 默认开启遥测，把运行数据作为"众包 benchmark 数据集"回传——README 把这一点写成卖点而非选项，使用前必须确认关闭方式和数据范围。
- **bus_factor**: 提交集中在 jmagly 一人（151 次，占绝对多数），项目署名者本人提交仅 21 次。
- **stability**: 硬件适配面窄（Jetson 不支持、NVFP4 未原生支持、Accelerate offload 场景会崩），最热 issue 是"聊天功能不工作"。

**技术备注**: Python，依赖 PyTorch / transformers / Accelerate，提供 CLI（`obliteratus obliterate <model> --method advanced`）、Python API、Gradio Spaces（ZeroGPU）与 Colab notebook；提取策略含 PCA、mean-difference、稀疏自编码器分解、whitened SVD。

## 如何理解今天的热度信号

今天最容易误读的是**榜尾四个老项目**。protobuf +4、onnxruntime +5、Ghost +32、TypeScript +65，如果只看"上了 Trending"这个事实，很容易写成"某某老项目重新火了"。实际成因是周末新项目投放减少、榜位出现空缺，而这些仓的日常自然流量本来就在几十星量级，足以填进尾部。**判断一个项目是否真的有事件，看当日增量相对它自身基数的比例，不看它是否在榜。**

第二个需要分层看的是 **watchers 比值**。今天有三个高比值：`career-ops` 262:1、`OpenLogi` 227:1、`maka` 213:1。三者成因不同：career-ops 是 star 增长远快于可验证使用证据，此前已多次记录；OpenLogi 有 HN 千分级讨论托底，比值高主要因为仓龄仅三个月、订阅行为滞后；maka 则是刚迁入 `apache/` org，历史订阅者留在旧 org，比值反映的是搬家。**同一个比值可以指向三种完全不同的事实，必须配合 fork:star、issue 内容质量和外部讨论一起读。**

反向的例子是 `OBLITERATUS`：它的 fork:star 高达 18%，远超普通工具仓，说明用户是真的拉下去跑；配合 HN 219 分主帖和 r/LocalLLaMA 独立复现帖，它的热度是有社区足迹支撑的。它需要谨慎对待的地方在合规和隐私，不在真实性。

### [cursor/plugins](https://github.com/cursor/plugins) — NEW ⭐ 2,814（+41）| TypeScript | 信源：中

**它是什么**: Cursor（那个基于 VS Code 改的 AI 编程编辑器）官方开的仓库，用来定义"插件"这个东西该长什么样，并把官方自己做的插件放进去当范例。可以理解成 Cursor 版的应用商店规格书 + 官方样板间：里面既有格式规范（`schemas/`、`.cursor-plugin/`），也有 `create-plugin` 这种脚手架，还有 14 个官方插件目录（`orchestrate` 编排、`pr-review-canvas` PR 评审、`cursor-team-kit` 团队工具包、`continual-learning`、`teaching` 等）。

**解决什么问题**: 在这之前，想给 AI 编辑器加能力，各家路子都不一样——Claude Code 走 skills、别的走 MCP server、还有的靠自定义 prompt 文件，写一份能力要针对每个客户端重做一遍，而且第三方能力怎么被编辑器发现、怎么声明权限、怎么版本化，都没有公开答案。这个仓库把 Cursor 一侧的答案写成文件：按规范打包，提 PR 进目录，就能被官方分发。对插件作者的意义是有了明确的提交口径；对团队的意义是能照着官方插件的结构自建内部插件。

**谁在用、怎么用**（来自 Issues/PR/HN）:
- 第三方 MCP 插件通过 PR 进目录是主要用法：8-13 合入 Profound 的第三方 MCP 插件（#213），同日 revert 掉 AgentMail（#212）——说明目录是**有人工审核门槛**的，不是照单全收。
- open issues 里绝大多数是插件投稿：#157 Atlaso Memory、#160 Yolfi payments（2 条评论）、#140 agent-vent、#145 Unforgit。33 个 open issues 中有 20 个是 PR，实际问题反馈很少。
- 官方自用：#173 请求让 `/orchestrate` 的模型目录支持环境变量覆盖，是团队/企业场景的典型诉求。
- HN 侧：2026-02-19 有一条 `Extend Cursor with Plugins`（指向 cursor.com/blog/marketplace，2 分 0 评论），此外只有零散的 Show HN 提到"给 Cursor 写插件"（如 `Context Plugins`，8 分 6 评论）。**插件市场本身在 HN 没有形成讨论**，热度主要沿 Cursor 官方渠道传播。

**社区怎么评价**:
- 正面: 官方规范落到公开仓库、有脚手架、有 14 个可抄的官方实现，第三方提交路径明确；`agent-compatibility` 目录还处理跨 agent 兼容问题。
- 负面: 讨论几乎不存在——热门 issue 最多 2 条评论，多数 0 评论；Reddit 上找不到关于插件市场的实质讨论串（搜索结果基本被同名的 RPG Maker / WordPress 光标插件淹没）。
- 健康度: 2,814 stars / 12 subscribers = **234:1**，比值很高，但这是厂商官方仓库、建仓才 7 个月（2026-01-23），大部分用户是通过 Cursor 客户端消费而不是 watch 仓库，这个比值不构成 vanity 判断。贡献者 11 人且高度集中在 Cursor 员工（poteto 74、ericzakariasson 52、SamSokolin 23、cursoragent 15），社区贡献目前只发生在"提交插件"层面，规范本身是单方定义的。今日 +41 stars 是全榜最低，靠的是绝对存量而非增速。

**风险与争议**:
- **compliance**: 仓库**没有 LICENSE 文件**（`license=none`）。一个明确邀请第三方提交插件、并内含 `third_party/` 目录的规范仓库不声明许可证，第三方能否 fork、改写、在其他 agent 上复用官方插件代码，法律上是空白。
- **dependency**: 规范由 Cursor 单方定义、随客户端版本演进，没有跨厂商治理机制；按它写的插件锁死在 Cursor 客户端上。
- **bus_factor**: 前 5 贡献者全是厂商成员，规范演进不受社区约束；`agent-compatibility` 目录能否长期维护取决于厂商意愿。

**技术备注**: TypeScript，5.4MB，无 topics。目录即规格：`schemas/` 定义插件清单格式，`create-plugin` 是脚手架，`cursor-sdk` 是插件 SDK，`third_party/` 存放外部插件。8-13 把 X 插件从 API key 改成 OAuth 用户登录 + write scope，是权限模型在收紧的信号。

## 如何理解今天的热度信号

今天有两类需要分开看的"高热度"：

**第一类是项目侧真的在动**：ragflow（一天修三个"界面撒谎"类缺陷）、spec-kit（同日发版 + 三条目录变更）、macro（日更 + 日发版）、semantica（工程卫生批次）、holaOS（MCP 代理砍掉 69% 冷启动底噪）、rustdesk（拆插件框架）、ToolJet（beta/LTS 双轨发版）。这几项的 star 增长有对应的代码事件可解释。

**第二类是存量声誉被流量顶上来**：holehe（停更近 2 年）、spiderfoot（停更近 3 年）、modly（21 天无提交却升 7 位）、awesome-deepseek-agent（停更 2 个月、100+ PR 积压）。这四项今天合计 +1,621 stars，找不到任何项目侧事件。**Trending 排的是 star 增速，不是维护状态**，两者今天分歧特别大。

还有一个独立的观察维度：**主动投放**。diagram-design（8-14）和 holaOS（8-12）都在 README 加了 Trendshift 徽章，这是把榜单流量当增长渠道用的常规动作。它本身不说明项目质量好坏，但意味着 star 曲线里有一部分是运营结果，判断时应当把它和 forks、subscribers、issue 活跃度、外部讨论一起看。

最后是 stars/subscribers 比值的用法提醒：今天比值最高的几个是 ego-lite（335:1）、diagram-design（240:1）、cursor/plugins（234:1）、ToolJet（199:1）。其中 cursor/plugins 是厂商官方仓库（用户通过客户端消费，不 watch 仓库）、ToolJet 是 2021 年建仓的成熟大仓（forks、贡献者、HN 历史讨论全部对得上），**这两个的高比值不构成 vanity 判断**。真正需要结合其他信号看的是 ego-lite 和 diagram-design 这类"仓龄短 + 比值高 + 外部有机讨论薄"的组合。

### [google-labs-code/stitch-skills](https://github.com/google-labs-code/stitch-skills) — NEW ⭐ 7,078（+340）| TypeScript | 信源：中

**它是什么**: Google Labs 出品的 Agent Skills 技能库，配合 Stitch（Gemini 驱动的 UI 设计工具）的 MCP server，让 Claude Code / Cursor / Gemini CLI 等编码 agent 能直接调用 Stitch 生成界面设计并转成代码（React / React Native / shadcn 等）。注意：属 Google Labs 实验项目，非 Google 官方支持产品。

**解决什么问题**: 以前"设计 UI"和"写前端代码"是两个割裂步骤，设计稿要人工翻译成组件代码。stitch-skills 把设计生成挂进编码 agent 的技能体系，让 agent 在一次对话里完成"生成设计 → 对齐设计语言 → 出代码"。

**谁在用、怎么用**（来自 Issues/社区）:
- 亮点技能 `stitch-loop`（baton 机制驱动 agent 自主连续建站）与 `design-md`（用 `DESIGN.md` 作设计语言 source of truth 对齐生成结果）。
- 唯一有讨论的热点是 #63 请求扩展兼容更多 agent（Opencode integration），说明用户主要把它当可安装插件消费。

**社区怎么评价**:
- 正面: fork 944（相对 star 比例高），说明大量人真在把它当模板/插件安装使用。
- 负面: Issues 讨论稀薄，缺乏沉淀下来的实际使用案例。
- 健康度: stars/subscribers ≈ 50:1（大厂官方仓健康区间）；open issues 仅 21；10 contributors 但高度集中（单人 JLXIA 占绝对主力提交）；仓龄约半年，仍在维护。

**风险与争议**:
- **dependency**: 强依赖 Stitch MCP server + Stitch 云服务，脱离即不可用。
- **bus_factor**: 单人主导贡献，contributor 高度集中。
- **vanity**: 传播主要靠 Google 官方 @stitchbygoogle 的 X 推广，独立社区（HN/Reddit）grounding 几乎为零；但比值健康、fork 多、有真实插件消费属性，不构成典型空心化。

**技术备注**: TypeScript；核心是 MCP server + 一组可安装 skill；依赖 Gemini/Stitch 后端。

### [DayuanJiang/next-ai-draw-io](https://github.com/DayuanJiang/next-ai-draw-io) — NEW ⭐ 33,302（+81）| TypeScript | 信源：中

**它是什么**: 一个用自然语言对话来生成和修改 draw.io 流程图/架构图的 Web 应用——你用自然语言描述需求，AI 直接操作 draw.io 的 XML 出图，也能上传已有图让 AI 复刻改进。

**解决什么问题**: 画架构图/流程图通常要手动拖拽，费时且难保持一致。这个项目让"说清楚要什么"就能得到可编辑的 draw.io 图，再人工在画布上微调、让 AI 精修。

**谁在用、怎么用**（来自 Issues）:
- 绘制云架构图（内置原生 AWS/GCP/Azure 图标）、AI 生成基础架构后人工微调再精修、截图复刻已有图。
- 真实功能请求佐证使用：#513（补全主题面板）、#711（self-hosted 精简聊天面板）、#579（autosave 同步）、#560（迁 pnpm）。
- 已支持 OpenAI/Anthropic/Bedrock/Ollama 及 Claude Sonnet 4.5、GPT-5.1、Gemini 3 Pro 等多模型。

**社区怎么评价**:
- 正面: fork 3,603（fork/star ≈ 10.8%，相当健康），大量人克隆自部署；issue 均为建设性功能请求，无大规模崩溃投诉。
- 负面: 英文社区几乎无声——HN 仅 1 条 Show HN（2 分 2 评论），X/Reddit 无讨论；中文侧有传播（阮一峰 weekly #8386 自荐、HelloGitHub 收录）。
- 健康度: stars/subscribers ≈ 179:1，数值上很高，但应用型工具仓的用户是去用/自部署而非 watch 源码，不能仅凭此判 vanity；单人 DayuanJiang 提交 497 次（人类第二仅 29）。

**风险与争议**:
- **bus_factor**: 单点维护，人类贡献者高度集中。
- **dependency**: 依赖各家 LLM API 与 draw.io。
- **vanity**: star 增长与英文社区足迹（HN/X/Reddit 近乎为零）明显不匹配，热度主要靠 GitHub 榜单 + 中文渠道；但 fork 比例和 issue 质量表明有真实用户基础，更准确的描述是"传播热度强、英文社区 grounding 弱、单人维护"，而非典型空心化。

**技术备注**: TypeScript / Next.js；核心是把 LLM 输出映射到 draw.io XML。

### [malisper/pgrust](https://github.com/malisper/pgrust) — NEW ⭐ 2,089（+774）| Rust | 信源：强

**它是什么**: 一个用 Rust 从零重写的 PostgreSQL，磁盘格式兼容 Postgres 18.3（可直接从现有数据目录启动）。作者 Michael Malis（前 Heap CEO）主要靠 AI 编码代理（自述 8 个并行 Codex 账号、约 45 万行代码）生成，目标是让 Postgres 内部更易改造——去掉 VACUUM、内置连接池、换用线程/连接模型。

**解决什么问题**: Postgres 的 C 代码库改造门槛高（进程模型、VACUUM、扩展协议等）。作者想验证"能否用 Rust + AI 代理重写一个磁盘兼容的 Postgres"，从而更自由地做内部架构实验。目前定位是实验/演示，非替代品。

**谁在用、怎么用**（来自 Issues/HN）:
- 目前无真实业务使用——只有浏览器 demo（pgrust.com），作者明确说非 production-ready、无发布日期。
- 社区讨论集中在质疑与压测：#24「Is this a serious project or just AI slop?」（9 评论）直接质疑严肃性；#12「Rewrite in Zig」（12 评论）多为玩梗。

**社区怎么评价**:
- 正面: HN 主贴 805 分 / 717 评论，话题度极高；技术命题（磁盘兼容重写、去 VACUUM）本身有意思。
- 负面: 实测 #31 pgbench 初始化慢约 11x、TPS 低约 9x；#30 负载测试 OOMKilled；#22/#14 扩展查询协议函数缺失（hash fn、xml_recv）——与 README 宣称"50% 更快 / 分析型 300x"形成明显落差。OrioleDB 的 Ben Dicken 评价"还没达到我的标准"。
- 健康度: 2,089 stars / 17 subscribers（约 123:1，极度失衡）；open issues 17；单人主导、目前不接受 PR；仓龄约 3 个月；AGPLv3。

**风险与争议**:
- **vanity**: stars 暴涨 vs subscribers 17，讨论以质疑和玩梗为主，热度远超真实采用。
- **stability**: 基准慢于原版、OOM、协议函数缺失，与性能宣称落差大，非 production grade。
- **bus_factor**: 单人主导、不接受 PR、贡献者极度集中。
- **compliance**: AI/c2rust 转换产物 + AGPLv3 许可，法律定性与"drop-in 替代"预期存疑（X 上已有关于 c2rust 转换产物 AGPL 合法性的争议）。

**技术备注**: Rust；磁盘格式对齐 Postgres 18.3；大量代码由 AI 代理生成，是"AI 大规模生成系统级软件"的代表性讨论样本。

## 如何理解今天的热度信号

今天的可信度结构比较清晰，读者可分三档理解：

1. **稳态基础设施档（可放心）**：C++ 基础库、terraform/ansible、.NET、Web 框架群、fprime。它们 stars/subscribers 比结构性偏高是正常的，属"老项目回归"而非炒作，不需要额外 grounding。
2. **大厂官方 agent 供给档（中等 grounding）**：stitch-skills、openai/plugins、claude-cookbooks。传播多由官方渠道驱动，独立社区讨论偏薄，但有真实消费（fork/安装）属性，判断时看 fork 与 issue 质量而非只看 star。
3. **短龄高失衡档（需谨慎）**：pgrust（AI 生成、性能宣称与实测落差、HN 质疑为主）与 next-ai-draw-io（英文社区足迹弱、单人维护）。star 数不足以证明采用，需结合 issue、HN/Reddit/X 与 subscribers 综合判断。

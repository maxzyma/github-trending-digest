### [InfinityLoop1308/PipePipe](https://github.com/InfinityLoop1308/PipePipe) — NEW ⭐ 6,600（+242）| Shell | 信源：中

**它是什么**: 一个 Android 上的第三方视频客户端，可以不装 Google 服务、不登录账号、不看广告地看 YouTube，也支持 BiliBili、NicoNico 等站点。它从知名开源客户端 NewPipe 分叉而来，加了更多"好用"的功能。

**解决什么问题**: 官方 YouTube App 需要 Google 服务，后台播放和下载要付费会员，还有广告和 Shorts 推送。PipePipe 把后台播放、下载视频和整个播放列表、自动跳过赞助片段（SponsorBlock）、显示点踩数（Return YouTube Dislike）、屏蔽 Shorts、睡眠定时这些功能做成免费开源的一体化 App。

**谁在用、怎么用**（来自 Issues/HN）:
- 无 Google 服务的 Android 用户：HN 讨论（9-25，492 分 / 273 评论）中多位用户称已日用数月到近一年，主要用来后台听、下载和跳过赞助片段。
- 自建 DNS 拦截广告的用户：#2757（20 条评论）说明拦截 `googleapis.com` 会导致播放失败，这类用户同时在用 Pi-hole 等工具。
- 长时间后台播放场景：#2576 后台播放随机中断（EAI_NODATA）、#2462 长时间暂停后无法继续，说明它被当作"音乐 / 播客播放器"使用。

**社区怎么评价**:
- 正面: HN 上最常见的评价是"YouTube 一改作者就及时修"，功能比 NewPipe 更全；F-Droid 有上架，AlternativeTo 有收录。
- 负面: 热门 issue 集中在播放稳定性（#2757、#2576、#1505 拖动卡顿、#2462）；HN 也有人反映在 CGNAT 网络下被 YouTube 封锁，NewPipe 与 PipePipe 同时失效。
- 健康度: 6,600 stars / 53 subscribers（125:1），153 个 open issues，GPL-3.0；仓库建于 2022-05，9-24 刚发 v5.4.0。作者 100 次提交，其余贡献者 1–3 次。X 与 Reddit 未检索到独立讨论。

**风险与争议**:
- **compliance**: 绕开官方客户端与广告的第三方客户端，存在违反 YouTube 服务条款的风险。
- **stability**: 与 YouTube 的反爬机制持续对抗，播放类故障会随平台变更反复出现。
- **bus_factor**: 开发几乎全部由一位作者承担。

**技术备注**: Android App，GPL-3.0；GitHub 语言统计显示 Shell，实际主体为 Android 客户端代码，解析层延续 NewPipe 的提取器思路；9-23 发 v5.4.0-beta2、9-24 发正式版。

### [vercel-labs/scriptc](https://github.com/vercel-labs/scriptc) — NEW ⭐ 5,423（+102）| TypeScript | 信源：中

**它是什么**: 一个把 TypeScript 代码直接编译成原生可执行程序的编译器。写法还是 TypeScript，产物却像 C 写出来的小程序：不需要装 Node，体积很小，启动极快。

**解决什么问题**: 以前想发一个"单文件、小体积、秒启动"的命令行工具，要么换 C / Rust / Go 重写，要么用 Bun / Deno 的 compile 把整个运行时打包进去（产物上百 MB）。scriptc 走第三条路：用官方 TS 编译器做类型检查，再生成 C、LLVM IR、目标文件、原生程序或 WASI 模块。媒体报道 CLI 产物约 178KB、冷启动约 2ms，Node 需要 35–60ms。

**谁在用、怎么用**（来自 Issues/HN）:
- 写小型命令行工具：HN 帖（7-26，287 分 / 156 评论）中有人认为它适合"用 TS 写服务端、发成单个小二进制"；Simon Willison 也公开试用。
- 移植现有项目：有人拿本地项目整体跑覆盖测试，报出数百个错误；#35、#262 都是内部编译错误（SC9001 ICE）。
- 与原生代码互操作：#123 反映 FFI 不支持回调，#362 反映 `fs.writeSync/readSync` 只支持部分用法；社区 PR 在补 GCC 工具链（#249）、tsconfig paths（#42）、Dockerfile（#237）。

**社区怎么评价**:
- 正面: 思路清晰，能静态编译的部分直接编，用了 npm 包或 `any` 的代码加 `--dynamic` 后交给内嵌的 quickjs-ng（约 620KB）执行，其余在编译期拒绝并附改写提示。InfoQ、DEV 等媒体跟进报道。
- 负面: HN 实测吞吐比 Node 24 慢约 7.5 倍；也有人批评它是"5 天 vibecoded 出来的，几个月后就会停更"；#139 指出整数范围推断会让 NaN 进入 i64/u64。
- 健康度: 5,423 stars / 19 subscribers（285:1），55 个 open（多为 PR），仓库 7-22 创建、今天仍有提交，Apache-2.0。ctate 734 次提交，第二名 13 次。X 与 Reddit 未检索到独立讨论。

**风险与争议**:
- **stability**: README 自称实验性，现有 npm 生态大多编不过，连 TS 编译器本身也编不过。
- **bus_factor**: 几乎由一人维护；HN 上有人拿 Vercel 实验项目发布后很快停更的先例作对比。
- **vanity**: 比例偏高、代码大量由 AI 生成，但 HN 讨论与实测是真实的，属于"关注度领先于可用性"，不应直接判为虚高。

**技术备注**: TypeScript 实现；内存管理用引用计数而非 GC，字符串用 UTF-8 存储，与标准 JS 语义有差异；同类方案有 Porffor、AssemblyScript、PerryTS 与 Bun compile。

### [mvschwarz/openrig](https://github.com/mvschwarz/openrig) — NEW ⭐ 1,018（+114）| TypeScript | 信源：中

**它是什么**: 一个让 Claude Code、Codex 等多个编程 agent 组成"小团队"一起干活的调度工具。你用一个配置文件写好"谁当组长、谁负责什么"，一条命令把整组 agent 拉起来。

**解决什么问题**: 同时开几个编程 agent 时，人要自己开多个终端、手动转发任务、盯着每个窗口。OpenRig 把每个 agent 放进一个 tmux 会话，由后台 daemon 统一管理，组长 agent 通过 `rig send` 和任务队列给专家 agent 派活，另有 TUI 看板查看进度；多个 rig 还能组成拓扑。

**谁在用、怎么用**（来自 Issues/HN）:
- 混合运行 Claude Code 与 Codex：#86（Claude 2.1.283 检测失败）、#79（Codex 0.153 提示符变化）、#69（Codex ≥0.157 共享 app-server）都来自真实混跑环境。
- 长时间无人值守运行：#49 恢复时跳过 spawn、#47 Slack 投递失败、#64 同目录下 Claude 会话互相覆盖，都是跑久了才会遇到的问题。
- 接入更多 agent：外部 PR 在补 Oh My Pi（#35）、Muse / OpenCode（#19、#32）适配和 Linux 测试（#83）。

**社区怎么评价**:
- 正面: 最近 100 条里有 43 个 issue，大多是外部用户提的具体运维问题，说明确有人在真实环境使用。
- 负面: 强依赖上游 CLI 细节，Claude / Codex 一升级就可能断；#48 反映自动发送会把操作者没打完的输入提交出去；#88 没有 Windows 支持；#55 有人质疑"新项目就进维护模式"，作者澄清停更的只是旧 Web UI。
- 健康度: 1,018 stars / 7 subscribers（145:1），51 个 open（含 PR），仓库 4-01 创建、今天仍有提交，Apache-2.0。作者 1,485 次提交，其他人各 1 次。HN 三次 Show HN 均为个位数分数；X 与 Reddit 未检索到讨论。

**风险与争议**:
- **bus_factor**: 代码几乎全部出自一人。
- **privacy**: 安装与运行会写入 `~/.claude.json` 的信任设置、项目级 Claude 本地配置（默认 `acceptEdits` 与 hooks）和 `~/.codex/config.toml` 的信任项；README 注明 YOLO 模式默认关闭，但仍需在接受前逐项确认。
- **dependency**: 依赖 Claude Code / Codex 终端界面的版本细节，已多次被上游升级打断。
- **stability**: agent 之间共享同一主机的网络与文件系统，没有隔离；作者假设运行在操作者自己控制的机器上。

**技术备注**: TypeScript，`npm i -g @openrig/cli` 安装；依赖 Node 20/22/24、tmux，并要求 Codex 已登录；与 A2A 协议不兼容，用自有的轻量连接机制。

### [willfaust/Madeira](https://github.com/willfaust/Madeira) — NEW ⭐ 829（+83）| C | 信源：中

**它是什么**: 一个在没越狱的 iPhone / iPad 上运行 Windows 电脑游戏的研究项目。它把 Windows 兼容层、x86 指令翻译器和图形转换层三样东西塞进一个 iOS App 里。

**解决什么问题**: iPhone 芯片性能已经不弱，但 Windows 游戏是 x86 程序、依赖 Windows 系统和 DirectX，iOS 上原本完全跑不了。Madeira 用 Wine（ARM64EC）处理 Windows 系统调用，FEX 把 x86-64 指令翻译成 ARM64，DXMT 把 D3D11 转成 Apple 的 Metal，整套链路跑在单个进程里（wineserver 以线程形式运行）。

**谁在用、怎么用**（来自 Issues/X）:
- 想自己装来玩的玩家：#1（how to run）、#2（The .ipa?）、#3 / #24（要求 CI 构建）、#13（构建指南）集中反映"没有安装包、不会编译"。
- 外部开发者扩展能力：#16、#22、#29 补手柄支持，#10 做 iPad 沉浸模式，#7 加固 JIT 断连；贡献者 125hz 提交了一批 PR（#26–#39），覆盖 WoW64、D3D9、原生 D3D12、Steam 与新前端。
- 硬件扩展诉求：#6 请求支持 M 系列芯片 iPad。

**社区怎么评价**:
- 正面: 技术链路有新意，外部贡献者自发投入；Notebookcheck、KOCPC 等媒体做了报道。
- 负面: README 写明目前可玩的只有 Thumper 和 ULTRAKILL，其他游戏帧率低；9-11 一条"Cyberpunk 2077 跑在 iPhone 上"的热帖被 X 社区注释纠正，视频其实来自作者朋友的另一个项目。官方账号称 RDR2 在 iPhone 18 Pro 上能到 30+ FPS，但未找到独立复测。
- 健康度: 829 stars / 12 subscribers（69:1），152 forks（不少 fork 在自行发布安装包），25 个 open，GPL-3.0；仓库 3-07 创建，最后一次推送 9-25。作者 204 次提交。HN 仅一条 1 分投稿，Reddit 未检索到讨论。

**风险与争议**:
- **dependency**: 需要借助 StikDebug 挂调试器开启 JIT，免费 Apple ID 签名 7 天过期需每周重签；Apple 政策一变就可能失效，也不可能上架 App Store。
- **compliance**: Wine fork 按 LGPL-2.1 §3 改为 GPL-3，fork 中有大量 AI 辅助代码，而 FEX 上游不接受 AI 生成的贡献；用户自带游戏文件的侧载场景有盗版灰区。
- **vanity**: 对外传播的游戏效果与 README 状态差距明显，已有被社区纠正的误传。
- **bus_factor**: 核心代码几乎由作者一人完成。
- **stability**: 作者自称 "research project, not a product"，不提供官方安装包。

**技术备注**: C 为主；开发机为 A15（iPhone 13 Pro）；图形链路 D3D11 → Metal（DXMT），PR 中在试验原生 D3D12 运行时。

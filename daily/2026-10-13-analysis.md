### [microsoft/BitNet](https://github.com/microsoft/BitNet) — NEW ⭐ 40,932（+97）| C++ | 信源：中

**它是什么**: 微软研究院开源的推理程序 bitnet.cpp，专门运行"1.58 位"大模型。普通模型的每个参数用 16 位数字存储，这类模型每个参数只取 -1、0、1 三个值，体积和内存占用小得多，可以在普通电脑的 CPU 上运行，不需要显卡。

**解决什么问题**: 在没有显卡的笔记本、边缘设备上跑大模型，通常只能用压缩后精度下降的模型，或者干脆跑不动。BitNet 的思路是模型从训练时就按三值参数设计，再配一套专用的 CPU 计算内核，让小内存设备也能本地推理。代价是只能运行专门训练的 BitNet 模型，不能直接拿现有的普通模型来用。

**谁在用、怎么用**（来自 Issues/HN）:
- 边缘设备实验：HN 9-28 的"ESP32S3 cluster running 1.58-bit (BitNet) Language model"拿到 150 分、30 条评论，有人把 BitNet 模型拆到一组 ESP32 微控制器上运行。
- 社区补齐服务端能力：#638 提交显卡上的批量解码计算内核，#642 修复 2.4B 模型批处理和多轮对话崩溃，#644 补 Windows 下 MSVC 编译支持；#206 用户追问何时提供服务端版本，21 条评论，至今未关闭。
- 用途从对话扩到检索和语音：7 月仓库发布了 0.6B 和 270M 两个 1 位 embedding 模型的转换指南，README 新增 VibeASR.cpp 语音识别的消息。

**社区怎么评价**:
- 正面: HN 讨论扎实，3-11 的"BitNet: Inference framework for 1-bit LLMs"拿到 370 分、167 条评论，2024-10 首发时也有 173 分。思路被认为是 CPU 端推理的一条可行路线。
- 负面: 推理精度和构建问题集中。#588 报告前馈层误用 SiLU 而不是 ReLU²，所有 CPU 后端困惑度 99.8 对参考值 17.1，7 月提出至今未关闭；#639 报告 2B-4T 模型困惑度约为参考实现的 6 倍（已关闭）；#641 是 Apple Silicon 上的构建失败。
- 健康度: 星数与 subscribers 比约 110:1，对微软官方的成熟研究仓属于结构性偏高，不足以说明热度失真。339 个 open issue 和 PR，主仓最后一次 push 在 7-27，此后社区 PR 无人合并。X 上只找到 @MSFTResearch 的官方发布帖，Reddit 未检索到相关讨论。

**风险与争议**:
- **bus_factor**: 主仓 7-27 之后没有合并任何代码，10 月新开的多个社区 PR 都在排队，维护者响应缺位。
- **stability**: #588 的激活函数问题影响所有 CPU 后端的输出质量，构建失败的报告也多，不宜直接用于生产。
- **dependency**: 需要专用推理引擎和专门训练的模型，Ollama 和主线 llama.cpp 不能直接加载，旗舰对话模型仍是 2025-04 发布的 2B 参数规模。

**技术备注**: C++ 实现，基于 llama.cpp 改造，模型以 GGUF 格式分发，提供 x86 与 ARM 的 CPU 内核和 GPU 内核；MIT 许可证；2024-08 建仓，不走 GitHub 正式发版。今天回榜没有找到明确的触发事件。

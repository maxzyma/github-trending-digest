**主线一：榜单地图 — 今天是"老面孔回流日"，16 项里 6 项是重新上榜，AI agent 仍占半壁但不再独占。** 今日 16 项可分五组：① **agent 编排与管理**（6 项，最大盘）——paperclipai/paperclip（NEW，第 5，76,654 ⭐，把一组 coding agent 编成带 org chart、预算和审批的"AI 公司"）、PrimeIntellect-ai/prime-agent（↓5，但 +2,642 仍是全榜单日增量第一）、msitarzewski/agency-agents（↑1，141,977 ⭐）、addyosmani/agent-skills（↑2）、pingdotgg/t3code（↓2）、danielmiessler/LifeOS（NEW，第 9，把同样的 harness 思路装到个人生活侧）；② **AI 基础设施与检索**——semantica-agi/semantica（RE，图原生上下文层）、vitali87/code-graph-rag（↓11）、firecrawl/firecrawl（RE，165,256 ⭐ 的抓取/上下文 API）；③ **垂类模型与应用**——google-deepmind/weathernext（↓7）、TauricResearch/TradingAgents（RE）、Comfy-Org/ComfyUI（↓5）；④ **数据采集**——NanmiCoder/MediaCrawler（RE，中文社媒爬虫）；⑤ **非 AI 系统项目**——LadybirdBrowser/ladybird（RE，独立浏览器引擎）、ruvnet/RuView（RE，WiFi 信号做空间感知）、opa334/Dopamine（NEW，iOS 越狱）。结构性看点是：昨天榜单的前两名（prime-agent、code-graph-rag）今天分别掉到 6 和 13，而昨天不在榜的 6 个项目集体回归——这是典型的"无单一大事件"日，榜单回到长尾轮动。

**主线二：agent 的竞争重心从"技能包"移到了"管理层"。** paperclip 是今天最值得点开的 NEW：它不是又一个 coding agent，而是 agent 之上的一层——用 Node+React 自托管面板把 Claude Code / Codex / Cursor / OpenClaw 组织成有组织架构、预算上限、审批流和 heartbeat 定时唤醒的"公司"。同一天上榜的 danielmiessler/LifeOS 是它在个人侧的镜像：TELOS 目标文件 + skills + hooks + 记忆检索，做 Claude Code 之上的常驻个人上下文层。两者加上仍在榜的 agency-agents（预置角色团队）、agent-skills（技能包），构成一条清晰的分层：**模型 → harness → 技能 → 组织与预算**。过去一年 Trending 上的 agent 项目主要在争"给模型喂什么"，今天两个 NEW 都在争"一群 agent 由谁调度、花多少钱、谁批准"。对读者的实际意义：如果你在评估把 agent 接入团队工作流，paperclip 的 org chart / budget / approval 三件套是目前开源侧最完整的参考实现，即便你不打算直接用它。

**主线三：非 AI 项目靠明确事件重回榜单，Dopamine 的上榜有硬新闻支撑。** opa334/Dopamine 是今天唯一有确切事件驱动的 NEW：2026-08-07 发布 3.0，首次公开支持 iOS 26.0–26.0.1（A12/A13），是 iOS 26 发布 326 天后的第一个越狱；随后 08-07 的 3.0.1、08-09 的 3.0.2 与 3.0.4 连续修回归，MacRumors、iClarified 跟进后热度外溢到 Trending。同组的 LadybirdBrowser/ladybird（65,301 ⭐，从零自研浏览器引擎）和 ruvnet/RuView（89,441 ⭐，用商用 WiFi 信号做存在感知与体征监测）也在同一天回流。这组项目提供了一个对照：它们的热度可以追溯到具体的版本、具体的技术能力和具体的媒体报道，判断成本远低于 agent 板块的新项目。

**主线四：榜单解读提醒 — 今天有三个 ratio 异常项目，成因完全不同，不能用同一句话打发。** ① paperclipai/paperclip：76,654 ⭐ / 380 subscribers ≈ **202:1**，HN 四次提交（03-06、03-07、05-12、07-26）全部 1–5 分 0 评论，Reddit 定向搜索只见 SEO 评测博客，传播主战场在 X（Greg Isenberg、The Neuron 等 KOL 密集推广，作者匿名）——这是**传播强于技术验证**的典型形态。② danielmiessler/LifeOS：18,046 ⭐ / 210 subscribers ≈ 86:1，HN/X/Reddit 三个外部社区均无独立讨论，增长高度依赖作者自有受众（fabric 项目 + Unsupervised Learning newsletter + Discord）；但 fork/star 达 13%，且 issue 区是逐行代码审计级别的高质量反馈（见下文），说明**存在真实用户群，不是纯空心**。③ opa334/Dopamine：forks 6,200 **多于** stars 6,085，看起来最异常，实际是仓库自带 build-and-upload workflow，用户 fork 后自建自签 IPA——抽查最新 10 个 fork 全为零提交、pushed 时间与上游 HEAD 一致，属**消费行为假象**而非刷量。同一个"比值异常"，三种成因，只有第一个需要真正谨慎解读。

## NEW 项目

### [paperclipai/paperclip](https://github.com/paperclipai/paperclip) — NEW ⭐ 76,654（+198）| TypeScript | 信源：中

**它是什么**: 一个自己装在服务器上的网页面板，用来"雇佣和管理一群 AI 员工"。你在里面画组织架构图——谁是 CTO、谁是工程师、谁向谁汇报，给每个岗位设预算上限和审批规则，然后由 Claude Code、Codex、Cursor 或 OpenClaw 这类真实的编码 agent 去顶岗干活。系统有个 heartbeat 机制会定时唤醒这些 agent 推进各自的目标，不需要人一直坐在旁边发指令。

**解决什么问题**: 现在跑多个 AI agent 的人普遍面对三件事：不知道它们各自在干什么、不知道花了多少钱、不知道哪一步该由人拍板。以前的做法是自己写脚本串起来，或者开一堆终端窗口人肉盯。paperclip 把这三件事变成产品功能——组织结构决定谁能调用谁，预算决定什么时候强制停，审批节点决定哪些动作必须人点头。

**谁在用、怎么用**（来自 Issues/X）:
- 场景 1: 自托管长跑。#2583 是社区贡献的自托管升级脚本，带 quiesce/drain 流程——说明有人真的把它当常驻服务在运维，而不是本地玩玩。
- 场景 2: 可观测性接入。#9672 引入 OpenTelemetry 埋点，需求来自要把 agent 运行纳入现有监控体系的用户。
- 场景 3: 独立使用反馈（X）：Harshil Mathur 的评价是"失败原因和人类公司一样——缺规划与对齐"，这是少见的非 KOL 视角实感。

**社区怎么评价**:
- 正面: 迭代密集，近 30 天 commit ≥100，release 节奏一度是每周一版（v2026.609/618/627/707/720/722）；100+ 贡献者、5,224 个已关闭 PR，社区参与是真实的。
- 负面: 运行可靠性是最集中的抱怨。#4060 记录了一次 40+ 小时的 outage（checkout UUID 校验问题）；#6373 / #6376 是全仓最热的两个 issue（85 / 61 条评论），内容是运行日志里泄露 runtime secret、需要 redact；#4356 指出 pause 开关在 heartbeat 入队处不生效——安全阀失灵；#10556 报告热重启会丢内嵌 Postgres 数据。
- 健康度: 76,654 ⭐ / 380 subscribers ≈ 202:1，比值很高。"5,092 open issues"需要拆开看：真 issue 约 2,087，open PR 达 3,006——积压 PR 占六成，review 严重堵塞。贡献者高度集中，`cryppadotta` 一人 2,405 commits，第二名 336。7/22 之后近三周没有新 release。仓库 2026-03-02 创建，仅 5 个月，MIT。

**风险与争议**:
- **privacy**: 运行日志泄露 runtime secret（#6373 / #6376），而这个系统天然持有大量 API key 与仓库凭据。
- **stability**: 40+ 小时故障（#4060）、pause 开关不生效（#4356）、热重启丢数据库（#10556），距离 production grade 还有距离。
- **cost**: heartbeat 是 24/7 定时唤醒模型，社区反馈普遍需要 Claude Max（$200/月）级别订阅才跑得动。
- **bus_factor**: 单人 2,405 commits 对第二名 336，且 3,006 个 open PR 说明 review 瓶颈就卡在核心维护者身上。
- **vanity**: 202:1 比值 + HN 四次提交全部 1–5 分 0 评论 + Reddit 无原生主题帖 + X 侧 KOL 密集推广，传播强度明显超过独立技术验证。

**技术备注**: TypeScript / Node + React，自托管，内嵌 Postgres，MIT。适配层支持 Claude Code、Codex、Cursor、OpenClaw 等多种 agent 后端（仓库有 `adapter-plugin.md` 定义插件契约）。官网 paperclip.ing 目前未见付费层，暂无 open-core 锁定证据。

### [danielmiessler/LifeOS](https://github.com/danielmiessler/LifeOS) — NEW ⭐ 18,046（+315）| TypeScript | 信源：中

**它是什么**: 装在 Claude Code 之上的一层"个人操作系统"。你先写一份叫 TELOS 的文件描述自己的目标、身份和问题清单，系统再用一组 skills、hooks 和记忆检索把这些上下文常驻到每次对话里，配一个叫 Pulse 的面板显示当前状态。作者把它的定位描述为"爬山法"：不断把你从 Current State 推向 Ideal State。

**解决什么问题**: 用 AI 助手的人反复遇到同一件事——每开一个新会话都要重新解释自己是谁、在做什么、在乎什么。LifeOS 的做法是把这些写进结构化文件并自动注入，让 AI 在研究、写作、安全任务里共享同一份个人上下文。

**谁在用、怎么用**（来自 Issues/Discussions）:
- 场景 1: 深度个人定制。#1580 里一位用户为自己从 v6 升到 v7 写了个 CoreUpgrade skill，因为他积累了 **77 处个人定制**——这是相当强的实际使用证据，作者回复"engineering is excellent"。
- 场景 2: 版本升级实测。greg-bandy 在同一线程给出 6.0.5→7.1.1 的实地升级数据。
- 场景 3: 安装即用。一句 prompt 或 `curl | bash` 装好，之后作为研究/写作/安全任务的统一上下文入口。

**社区怎么评价**:
- 正面: issue 区质量意外地高，是逐行代码审计而非灌水；作者回复详尽且认领问题。近 100 次 commit 集中在 2026-04-30 ~ 08-07，日均约 1 次，维护活跃；48 个 PR 已合并。
- 负面: 集中在"承诺的能力实际没生效"。#1712 指 SessionStart 的动态上下文恒为空——读三个源但没有任何地方写入；#1665 指项目级安装的 `--config-root` 在约 60 个文件里静默回落到 `~/.claude`；#1790 指出随包发布的 8 条 `.env` 保护规则在默认 `auto` 模式下根本不触发提示，`.env` 仍可被 10 个已 allow 的 Bash 动作读到；#1791 指数据外泄规则没有可判定的边界；#1795 指已应用的 proposal 没有回收出口，常驻文件膨胀到吃掉 29% 上下文。外部博客的实测评价是"安装后一片绿灯，但系统根本不认识我"（identity 文件 12 处占位符未填、dashboard 仍叫 Sample User）。
- 健康度: 18,046 ⭐ / 210 subscribers ≈ 86:1，偏高但未破 100:1；fork/star 达 13%（2,370 forks），对个人工具而言异常高，说明大量人真的 clone 下来改配置自用。累计 issue 仅 62、open 44。贡献者极度集中：danielmiessler 657 commits，第二名 4 commits。v7.28.3（2026-08-01），MIT。

**风险与争议**:
- **privacy**: 面向"全部个人生活数据"的系统，但默认权限配置与 `.env` 保护实际失效（#1790 / #1791）——承诺的防护和实际行为对不上。
- **bus_factor**: 约 94% 的提交出自作者一人。
- **stability**: 版本跳变剧烈（v6 → v7 → v7.28），升级会破坏用户定制，#1580 附带了 skills 被清空的实例。
- **供应链暴露**: 安装方式是 `curl | bash` 或"让 AI 读网页自行安装"，攻击面大。
- **vanity**: 18K stars 与 HN / Reddit / X 三个外部社区零有机讨论之间落差明显，增长高度依赖作者自有受众（fabric 35K ⭐ + newsletter + Discord）。但 fork 比与 issue 深度证明存在真实用户群，不宜按纯空心处理。

**技术备注**: TypeScript，MIT，v7.28.3。运行在 Claude Code 之上，依赖其 skills / hooks / SessionStart 机制；配套有 ourlifeos.ai 站点与 YouTube walkthrough。

### [opa334/Dopamine](https://github.com/opa334/Dopamine) — NEW ⭐ 6,085（+111）| C | 信源：强

**它是什么**: iPhone 越狱工具。它利用 iOS 内核漏洞解除系统的安装限制，让用户能装苹果商店之外的软件和系统级插件（tweak）。"semi-untethered"意思是手机重启后越狱状态会失效，需要重新打开 App 激活一次。

**解决什么问题**: iOS 默认不允许用户修改系统行为或安装未经苹果审核的软件。越狱之后，用户可以装自定义插件改系统 UI 和功能、侧载应用；安全研究者则用它做 iOS 内核研究和设备取证——没有越狱，很多研究根本无法在真机上开展。

**谁在用、怎么用**（来自 Releases/Issues/媒体）:
- 场景 1: iOS 26 首破。3.0 于 2026-08-07 发布，首次公开支持 iOS 26.0–26.0.1（A12/A13 设备），是 iOS 26 正式发布 **326 天后**的第一个越狱，MacRumors、iClarified、redmondpie 均有报道。
- 场景 2: 老版本全覆盖。3.0 整合了 alfiecg24 的 Titan PPL/SPTM bypass 打通 16.5.1–17.3.1 全设备，staturnzz / TheRealClarity 的 momentarius 覆盖 16.6–18.7.1。
- 场景 3: 自建自签。仓库自带 `main.yml` 的 build-and-upload workflow，普通用户 fork 后用 CI 产出自己的 IPA——这也是 forks 反超 stars 的直接原因。

**社区怎么评价**:
- 正面: iOS 26 首破本身是硬成就；#786 的讨论中用户反馈新的 ClearSword exploit 比原 DarkSword 更稳。
- 负面: 3.0 的回归相当集中——#906 删除 BaseBin 失败导致文件系统损坏（9 条评论）、#913 Files app 与文件选择器损坏、#921 A17 Pro 在 17.1.1 随机重启、#923 systemhook.dylib 导致 App Store 应用崩溃、#922 DarkSword 在 17.3.1 失败。作者在 08-07 / 08-09 连发 3.0.1、3.0.2、3.0.4 修复。老问题 #533（tweak 注入触发 watchdog）、#123（A14 亮度）长期未解。
- 健康度: 近 10 天 97 次 commit，作者本人高频响应，维护活跃。84 个 open issue 中大量是"支持某版本吗"类询问（README 明示此类 issue 直接删除）。forks 6,200 > stars 6,085 的异常已解释为 CI 自建行为——抽查最新 10 个 fork 全部零提交、pushed 时间与上游 HEAD 完全一致。HN 上两条"iOS 26 Gets First Jailbreak"帖仅 6–7 分、1 条评论，讨论极弱；作者不用 X，发布公告在 Mastodon（infosec.exchange/@opa334）；MacRumors 论坛出现"现在还有人越狱吗"的冷淡回应——这个生态的整体关注度已远不如从前。

**风险与争议**:
- **compliance**: 越狱违反 Apple 服务条款，会导致设备失去保修。
- **security**: 依赖内核漏洞利用，越狱本身会降级系统防护层级，扩大攻击面。
- **stability**: 3.0 发布后两天内连发三个修复版，仍有文件系统损坏（#906）与随机重启（#921）报告。
- **bus_factor**: opa334 主导全部维护，核心 exploit 依赖少数几位外部贡献者（alfiecg24、staturnzz、TheRealClarity）。

**技术备注**: C / Objective-C，MIT，仓库 2023-01-31 创建。3.0 版本组合了多套 exploit 链（ClearSword / DarkSword / Titan PPL-SPTM bypass / momentarius）覆盖 iOS 15 至 26.0.1。

## 如何理解今天的热度信号

今天最值得记住的一条方法：**stars / subscribers 或 forks / stars 的异常值只是提问的起点，不是结论**。今日三个比值异常项目给出了三种不同答案——paperclip 的 202:1 配上四次 HN 零评论与 KOL 驱动传播，指向传播强度超过技术验证；LifeOS 的 86:1 配上 13% 的 fork 率和逐行审计级的 issue，指向作者受众驱动但用户真实；Dopamine 的 forks > stars 看似最离谱，实为 CI 自建 IPA 的消费行为，与刷量无关。判定顺序应当是：先看 fork 里有没有真提交、issue 里有没有具体到行号的反馈、外部社区有没有独立于作者的讨论，再回头解释比值。

第二条：**排名下滑不等于降温**。prime-agent 今日 +2,642、code-graph-rag 今日 +682，都比昨天高，但分别掉了 5 位和 11 位——因为今天有 6 个老项目回流挤占名次。在"无单一大事件"的日子里，Trending 排名反映的是当天竞争强度，绝对增量才是项目自身的热度曲线。

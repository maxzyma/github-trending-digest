### [mjmirza/app-store-compliance](https://github.com/mjmirza/app-store-compliance) — NEW ⭐ 1,879（+377）| Shell | 信源：弱

**它是什么**: 一份 App Store 和 Google Play 的「被拒原因手册」，外加一个提审前自查脚本。手册整理了 117 种常见拒审情形和修法，还跟踪 95 个监管截止日（欧盟 AI 法案、DSA、COPPA、各地年龄验证法规等）。脚本扫描你的 Xcode 或 Android 工程，给每一项标出 `BLOCKED`、`CLEAR` 或 `NOT CHECKED`。

**解决什么问题**: 应用被商店拒审，常见原因是隐私清单没填全、数据安全声明和实际行为对不上、漏了某个新规的截止日。这些规则分散在苹果、谷歌和各国监管机构的文档里，独立开发者通常要等被拒一次才知道。这个项目把规则收进一个仓库，并通过 `install.sh` 把检查装成 Claude Code、Codex、Gemini CLI、Cursor、Copilot 等 13 个编码工具的提交前钩子和技能，让 AI 写完代码后先过一遍检查。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 有人在 Windows 上跑了它的脚本并报了三个缺陷。#2330 指出截止日数据库按系统默认编码读取，Windows 上会崩溃，或者不报任何问题就放行；#2332 是 `check-docs.py` 误报 `install.sh` 无法解析；#2333 是 `release-audit.py` 写死了 `python3`，在 Windows 上什么都没审计。报告人自己提了修复 PR #2334。
- 没有找到独立用户描述真实提审过程的记录。

**社区怎么评价**:
- 正面: issue 区没有看到「用它通过了审核」这类反馈。
- 负面: 上面三个 Windows 缺陷，其中「静默放行」对一个检查工具来说影响最大。
- 健康度: 1,879 星、126 forks、5 subscribers，比值约 376:1。提交 81 次，80 次来自作者本人。最近 100 条 issue 和 PR 里 96 条是 PR，其中绝大多数由作者自己提交。热门的 open issue 多是作者自建的监管截止日跟踪条目。HN 无讨论；X 和 Reddit 的站内搜索没有返回相关结果，这两处的检索不完整。

**风险与争议**:
- **compliance**: 许可证是自定义的 OpenRoots Agent License 2.3，不是 OSI 认可的开源许可证。个人、非营利组织、学校、政府以及年营收不超过 2,000 万美元的公司免费使用；超过的部分按 0.5% 收费，每年封顶 25 万美元；用于 AI 训练需要另外授权。
- **bus_factor**: 内容和代码几乎由一人维护，法规更新的及时性取决于这一个人。
- **vanity**: 星数增长快，subscribers、外部 issue 和社区讨论都很少，README 里直接请求 star、fork 和 follow。
- **内容时效**: 作者在 #659 里记录了一批还没用一手来源复核的条目。把它当检查清单用可以，提审前仍需对照苹果和谷歌的官方政策。

**技术备注**: Shell 加 Python 脚本，数据是 `data/` 下的 JSON，文档在 `docs/`。2026-06-06 建仓。

### [Tracer-Cloud/opensre](https://github.com/Tracer-Cloud/opensre) — NEW ⭐ 13,157（+38）| Python | 信源：中

**它是什么**: 一个帮你查「CI 为什么挂了」的命令行 Agent。CI 只告诉你构建失败，它去读失败那次运行的日志，逐个验证可能的原因，然后推一个修复给你审，并把结论发到 Slack、PagerDuty 或 Telegram。你也可以直接问它，例如 `opensre ask "why is checkout-api slow?"`。

**解决什么问题**: 流水线失败后，工程师要在 CI 日志、监控面板、Kubernetes 事件和最近的提交之间来回翻。opensre 把这些数据源接到一个 Agent 上，README 称支持 60 多种工具，包括 Grafana、Datadog、Kubernetes、AWS、GitHub、GitLab 和 Jenkins；模型可以用 Anthropic、OpenAI、Bedrock 或本地的 Ollama。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 在远程 Linux 机器上通过 ssh 和 tmux 试装。#6719（6 条评论）反映安装器会自行打开浏览器，登录回调指向 localhost，远程环境走不通，用户要求改成设备码登录，已有外部贡献者提 PR #6727 跟进。
- 场景 2: 贡献者接入新的数据源和模型，例如 OpenObserve（PR #7051）和 Azure OpenAI（PR #3631）。
- 没有找到用它排查生产事故的公开案例。

**社区怎么评价**:
- 正面: 维护者响应快，仓库累计合并 3,000 多个 PR，每天自动发版。
- 负面: 一位用户在 11-12 集中报了一批缺陷，包括 MCP 工具列表分页时丢工具（#7044）。
- 健康度: 13,157 星、1,905 forks、65 subscribers，比值约 202:1。open issue 和 PR 合计 12 个。贡献集中在头部四人，最多的一位 1,100 次提交。HN 上相关的 3 个帖子分别是 2 分、1 分、1 分；X 上以官方账号 @open_sre 和 Python 榜单聚合号的转发为主；Reddit 没能查成，不能当作无讨论。

**风险与争议**:
- **dependency**: README 首句写「自托管，用你自己的模型」，但快速开始要求先登录账号，首次启动激活的是托管模型。想完全离线自托管，需要走容器部署并自己配置 `LLM_PROVIDER`。
- **privacy**: 产品分析和 Sentry 遥测默认开启，需要设置 `OPENSRE_NO_TELEMETRY=1` 关闭。CI 日志和监控数据会发给你选的模型供应商。
- **stability**: README 标注 Public Alpha，API 和集成仍可能变化。
- **vanity**: 星数和独立用户反馈不匹配。讨论最多的 #2074 有 89 条评论，绝大多数出自同一位贡献者；已关闭的 #344 是公司招募维护者并提供每月 300 到 500 美元赞助的帖子。仓库里的活跃度有一部分由公司组织。

**技术备注**: Python，Apache-2.0，2026-01-13 建仓。部署有三种：OpenSRE Cloud 托管网关、AWS EC2、自托管容器（Railway、ECS、Vercel）。

### [XiaoYouChR/Ghost-Downloader-3](https://github.com/XiaoYouChR/Ghost-Downloader-3) — NEW ⭐ 12,793（+341）| Python | 信源：中

**它是什么**: 一个跨平台的桌面下载器，想用一个软件接住各种下载任务。普通的 HTTP 文件、磁力链接和 BT 种子、FTP、网页视频用的 M3U8 和 MPEG-DASH、eD2k，它都能下；还能解析 YouTube 和 Bilibili 的视频，并给 GitHub 和 HuggingFace 的下载走镜像加速。

**解决什么问题**: 以前下大文件用 IDM，下种子用另一个客户端，抓网页视频再装一个命令行工具。Ghost Downloader 把这几类引擎整合到一个界面里，另外提供浏览器扩展嗅探下载链接、兼容 aria2 的 RPC 接口和 `ghd` 命令行，覆盖 Windows、macOS、Linux 和 Android。

**谁在用、怎么用**（来自 Issues/中文社区）:
- 场景 1: 替代 IDM 下载大文件，包括 HuggingFace 上的模型。#717 是用户下载大文件几分钟后报异常的记录。

**社区怎么评价**:

**风险与争议**:
- **bus_factor**: 作者一人提交 1,631 次，第二名贡献者 27 次。最新的发布说明写着「因为学业，更新会变少」。

**技术备注**: Python 加 Qt 界面。README 提示 Qt 6.6 及以上需要 CPU 支持 AVX 指令集。插件机制已经可用，公开的插件 API 还在路线图上。今天上榜没有找到明确的触发事件。

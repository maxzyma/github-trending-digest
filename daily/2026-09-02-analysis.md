### [Gitlawb/openclaude](https://github.com/Gitlawb/openclaude) — NEW ⭐ 31,349（+80）| TypeScript | 信源：中

**它是什么**: 一个跑在终端里的 AI 编程助手命令行工具。它复刻了 Claude Code 那一整套交互——读写文件、跑 bash、grep 搜代码、调 MCP、slash 命令、流式输出——但把背后的模型换成了你自己选的：OpenAI 兼容 API、Gemini、GitHub Models、Codex OAuth，或者本机跑的 Ollama。一句话概括它的卖点：同样的用法，不绑定某一家模型厂商。

**解决什么问题**: 在它之前，想用 Claude Code 那套终端 agent 工作流，就得接受它绑定的模型和计费方式；想换成公司内部模型、免费额度模型或本地离线模型，只能另找工具重学一套交互。openclaude 把交互层和模型层拆开：配置目录另起炉灶（`~/.openclaude`，不读 `~/.claude`），`npm i -g @gitlawb/openclaude` 装完就能指向任意后端。issue #1540 里有人直接接了 NVIDIA nemotron 的免费模型，#514 在问怎么接 Kimi 的套餐——这两个诉求在原版里都没有答案。

**谁在用、怎么用**（来自 Issues/HN）:
- 接免费或低价模型省成本：#1540（NVIDIA nemotron）、#514（Kimi 套餐）是最典型的动机。
- 接本地模型做离线开发：#486 报告 Ollama 后端读不了文件，说明确实有人在本机模型上跑完整工作流。
- 中文开发者在用：#915 是中文报错 issue，说明用户群不限于英文社区。

**社区怎么评价**:
- 正面: PR 讨论有实质技术评审（#2095、#1614 各有 20+ 条评论），并且已经跟进 Opus 5 / Sonnet 5（#2181），今天仍有提交。

- 健康度: 31,349 ⭐ 对 221 subscribers（142:1）偏高；但 8,951 fork 占 star 的 28.6% 异常之高，且能查到 openclaude-android、OpenClaude-Portable 等一批二次派生仓——这个 fork 率反映的是"被大量抄走改造"，配合 issue 区真实的报错，说明它不是空壳。贡献集中在三人（223 / 155 / 123 次提交）。
- HN: 有讨论但极弱。原帖标题是 "Forked the leaked Claude Code source and made it work with ANY LLM"，只拿到 3 分 1 条评论。
- X / Reddit: 均无独立讨论，X 上只有项目自宣。

**风险与争议**:
- **compliance**: 衍生自泄露的专有源码，README 自己写明部分版权仍属 Anthropic；License API 返回 `NOASSERTION`，与 README 上的 MIT 徽章不一致。商用与 ToS 风险是实在的，不是理论担忧。
- **stability**: TUI 卡死、键盘无响应、认证重试风暴等高评论量 issue 集中在主路径上。
- **bus_factor**: 前三名贡献者占据绝大部分提交。
- **vanity**: 142:1 的 stars/subscribers 比、Trendshift 徽章加五个合作方 logo 墙，运营痕迹明显；但 fork 量和真实报错说明存在实际使用，热度不是凭空的。

**技术备注**: TypeScript，npm 全局包 `@gitlawb/openclaude`，配置目录 `~/.openclaude`。仓库创建于 2026-04-01，今日仍在推送。

### [averygan/reclip](https://github.com/averygan/reclip) — NEW ⭐ 7,697（+56）| JavaScript / HTML | 信源：中

**它是什么**: 一个自己部署在家里服务器或 NAS 上的"视频下载网页版"。打开网页，粘贴 YouTube、TikTok、Instagram、X 的链接，选 MP4 还是 MP3，点一下就下载，可以一次粘贴多条链接并自动去重。整个后端约 150 行 Python + Flask，前端是单个原生 HTML 文件，没有构建步骤。

**解决什么问题**: 下载引擎其实就是命令行工具 yt-dlp。它解决的不是"能不能下"，而是"每次都要敲一长串命令行参数"——给 yt-dlp 套了个自己人能点的网页壳。README 明说支持的站点完全等同 yt-dlp。需要说清的是：这个定位与已有的 MeTube 高度重叠，它的差异只在"极简、代码可读、零框架"，而不在能力；如果你想要订阅、归档、媒体库这类功能，它没有，Tube Archivist 那类项目才是对的方向。

**谁在用、怎么用**（来自 Issues/PR）:
- 家庭服务器与 NAS 自部署：#48 有人补了 docker-compose 并加固 Dockerfile，是典型的 selfhost 场景。
- 批量存播放列表：#27 / #9 要求 YouTube 播放列表批量下载，#28 已经合入。
- 音轨与格式细节：#47 希望合并 mp4 时优先选 m4a 音轨，#20 要 GIF 导出。这些都是真在用的人才会提的需求。

**社区怎么评价**:
- 正面: 代码短、能读懂、装起来只要 Flask 和 yt-dlp 两个依赖，这是它被 fork 的主要原因（1,318 fork 占 star 的 17%，符合"clone 下来自己用"的工具型特征）。
- 负面: 安装门槛是最热的抱怨（#4 "能不能出个安装教程"，6 条评论，全仓最热）；更要紧的是 YouTube 反爬导致主流场景常态失效——#51、#8 报 "Access denied by the platform"，#7 指出不配 cookies 就被拦。
- 健康度: 7,697 ⭐ 对 43 subscribers（179:1）明显偏高。最后一次 push 是 2026-07-09，已近两个月无提交；未合并 PR 最早可追到 4 月（#29、#33、#36），最新的 #61 也挂了一个多月。贡献者 averygan 12 次提交，第二名 4 次——bus factor 实际为 1。
- HN / X / Reddit: HN 只有一条 2026-05-07 的提交（2 分 0 评论），X 与 Reddit 均无相关讨论，r/selfhosted 和 r/DataHoarder 都搜不到。外部足迹几乎只有 Cloudron 论坛一帖，以及二手聚合站转载。

**风险与争议**:
- **未修复的注入类 PR**: PR #58 明确指出未净化的 URL 可以做 yt-dlp 参数注入（RCE 类），#59 提出补 CSRF、API key 鉴权和限流——两个 PR 都开着没合，且仓库两个月无更新。**不要把它暴露到公网**，Cloudron 论坛也有人在问实例是不是默认无登录保护。
- **bus_factor**: 单人维护、两个月停更、PR 积压最早到 4 月。
- **stability**: 最主流的 YouTube 场景常态失效，需要自备 cookies。
- **dependency**: 全部能力来自 yt-dlp 上游，自身无独立护城河，上游一变就跟着断。
- **compliance**: 视频下载天然涉及平台 ToS 与版权，README 只有一句免责声明。

**技术备注**: Python + Flask 后端（约 150 行），单文件原生 HTML/CSS/JS 前端，依赖 Flask + yt-dlp + ffmpeg，无构建步骤。

## 如何理解今天的热度信号

今天需要读者格外注意的不是"某个项目热度虚高"，而是**两个新面孔各自带着一个会影响能否直接使用的前提条件**：

- `openclaude` 的问题在来源与授权。它确实有真实用户和真实报错，142:1 的比值不足以判它空心；但它衍生自泄露的专有源码，License 状态为 `NOASSERTION` 而 README 挂 MIT 徽章。评估它的时候，第一个问题应该是"能不能合规地用"，而不是"好不好用"。
- `reclip` 的问题在安全与维护状态。两个指出参数注入（RCE 类）与缺失鉴权的 PR 挂着没合，仓库两个月没动。它作为本机自用的小工具是成立的，作为暴露到公网的服务不成立。

另一类需要校准的是**位次与热度不同步**。OpenMAIC 名次从 #1 掉到 #3，但单日增量反而创了它上榜以来的新高；`scientific-agent-skills` 只跌 6 位，增量却直接腰斩。位次由同榜其他项目的相对表现决定，判断一个项目自身的热度走向，看单日增量比看位次可靠。

最后，`awesome-design-md` 这类清单型项目的停更值得单独说一句：它没有代码需要维护，价值全在条目的新鲜度上，所以"一个月无提交"对它的影响比对一个代码库更直接。看到清单类项目回榜时，先确认最后更新时间。

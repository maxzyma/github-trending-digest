## 本日主线

**主线一：Agent Skill 赛道换挡 — 从"收录清单"变成"能干活的单点 skill"。** 今天 16 个项目里有 7 个直接属于 skill / plugin 生态：`tt-a1i/archify`（#1）、`ConardLi/garden-skills`（#12）、`K-Dense-AI/scientific-agent-skills`（#14）、`VoltAgent/awesome-agent-skills`（#16）、`anthropics/claude-plugins-official`（#3）、`anthropics/claude-plugins-community`（#11），加上 `freestylefly/awesome-gpt-image-2`（#2，README 明确写"并提炼出 Skills"）。真正的变化不在数量，而在榜首位置的性质：过去几个月霸榜的是 `awesome-*` 收录清单，今天的第一名 archify 是**一个只做一件事的功能型 skill**——把自然语言描述的系统结构渲染成自包含 HTML 架构图。它 4 个多月前建仓，今天 +1,035 星到 18,088，仓内带 typed JSON IR、schema 校验、renderer 与 `run-tests.mjs` 测试脚本，说明这一层已经从"帮我找 skill"进化到"skill 本身就是可交付产品"。这也是 `npx skills add <owner>/<repo>` 这套安装约定开始产生复利的直接证据：archify 和 garden-skills 的 README 都以它为首选安装路径，跨 Claude Code / Cursor / Codex / OpenCode 通吃。

**主线二：Anthropic 官方目录与社区目录同日在榜，方向相反。** `claude-plugins-official` 从昨天 #15 拉到 #3（34,372 星，+308），`claude-plugins-community` 从 #2 掉到 #11（2,214 星，+538）。两者一起在榜比单独任一个更有信息量：官方仓 **1,020 个 open issue**，对一个"经 Anthropic 审核的高质量插件目录"来说，这个积压量说明提交量远超审核吞吐；社区仓则明确自述是 read-only mirror，投稿走 `clau.de/plugin-directory-submission`。也就是说插件分发正在向"中心化审核 + 镜像展示"收口，而瓶颈已经出现在审核端。对做 skill / plugin 分发的人，这里的可读信号是：能否进官方目录、多久能进，会比 star 数更决定实际装机量。

**主线三：本地优先的个人 AI 工具仍是稳定基本盘。** `tinyhumansai/openhuman`（Rust，38,240，+525）、`AgriciDaniel/claude-obsidian`（13,467，+810，排名持平 #6）、`MadsLorentzen/ai-job-search`（36,524，+1,300）、`basecamp/omarchy`（Shell，32,049，+1,024，↑2）四个项目连续多日在榜，共同点是"跑在你自己机器上、数据归你"：本地记忆库、纯 Markdown 知识图谱、本机跑的求职流水线、自成一套的 Linux 桌面。`ai-job-search` 的 12,423 forks 对 36,524 stars（1:2.9）在榜单里属于异常高的 fork 比，但它 README 直接写"Fork it and own it"——fork 是设计意图而非刷量，这类反常比值需要看项目定位再判断。

**主线四：榜单解读提醒 — 今天有一批短龄高星项目需要结合社区足迹判断。** 最典型的是 `DietrichGebert/ponytail`（#10，112,659 星，+1,598）：2026 年 6 月 12 日建仓，两个半月冲到 11 万星，但只有 281 个 subscriber（ratio 401:1），最后一次 push 是 8 月 7 日——已停更 20 天，star 却仍在四位数增长。`archify`（208:1）和 `garden-skills`（192:1，最后 push 停在 7 月 12 日）的 ratio 同样偏高。这些数字本身不构成"项目不好"的结论，但它提示 star 增长的主要驱动是传播而非日常使用，判断时要另找 issue 质量、外部讨论和维护节奏这三类证据。

### [tt-a1i/archify](https://github.com/tt-a1i/archify) — NEW ⭐ 18,088（+1,035）| HTML | 信源：中

**它是什么**: 一个装进 AI 编程助手里的"画架构图"插件。你用一段中文或英文描述你的系统（比如"用户请求先过 CDN，再进 API 网关，然后分流到三个微服务"），或者直接把一个仓库指给它，它输出一张能直接在浏览器打开的技术图——单个 HTML 文件，带明暗主题切换、动效，可以导出 PNG / SVG / WebM 和 1200×630 的社交分享图。支持五类图：架构、工作流、时序、数据流、生命周期。

**解决什么问题**: 以前要出一张能给人看的架构图，路径无非三条：手画（Figma / draw.io，慢，改一次重排一次）、写 Mermaid（快，但样式丑、导出难看、复杂图会糊）、或者截图别人的图凑。archify 的取法是"把描述当输入、把校验过的 HTML 当输出"——中间有一层 typed JSON IR 和确定性检查（仓内 `schemas/` + `scripts/run-tests.mjs`），所以同一段描述重跑结果稳定，不是每次让模型自由发挥一张。它还能接受粘贴进来的 Mermaid 代码（flowchart / sequenceDiagram / stateDiagram），按 archify 的排版风格重新布局一遍，等于给 Mermaid 做了个美化后端。另有 delta 模式，比较两张已校验的快照，输出 Before / Delta / After 三联。

**谁在用、怎么用**（来自 Issues/X/仓内源码）:
- 场景 1：跨 agent 分发。issue #87（5 条评论）在加 Claude、Grok、Codex、Pi 四家的 plugin marketplace 入口，说明使用者不是单一 Claude Code 用户群，而是要求同一个 skill 在多个 agent 里都能装。
- 场景 2：真在画大图并撞到布局边界。issue #126 报告 workflow 图相邻列的边长不均匀，导致"同样的规格，换一对列来量就一会儿过一会儿不过"；issue #111 报告 viewer 底部导航条压住图内容。这两条都是有人真在用它出正式图、且图足够复杂才会遇到的问题。
- 场景 3：图类型在被使用者往外扩。issue #115 提议加第六种 `erd`（实体关系 / 数据模型图），典型的"我拿它画数据库设计但缺这一类"。
- 场景 4：仓内 `benchmarks/`、`experiments/`、`integrations/`、`examples/` 四个目录并存，加上 `check-release-identity.mjs` 这种发布身份校验脚本，是按"要被别人长期依赖"来组织的，不是 demo 仓。

**社区怎么评价**:
- 正面: 外部 skill 目录站（OpenAgentSkill、Claude Skills Hub）已收录并给了独立介绍页；X 上有开发者转发（如 @wolfdeng 的 GitHub 链接推）；有 5 名以上外部贡献者提交（sunsunsun-java 10 次、YunyueLi 4 次、NgoQuocViet2001 3 次、ShiroKSH 2 次），其中 #75 是外部提交的构图修复。
- 负面: 已知能力边界被作者明确划出去了——自动解析 Mermaid、通用自动布局、托管分享、所见即所得编辑都不在当前 scope，想要"改图"的用户会失望。issue #126 / #111 说明复杂图的布局和 viewer UI 还在打磨期。
- 健康度: 18,088 stars / 87 subscribers = 208:1，明显偏高；29 个 open issue 相对 1.8 万星偏少。但另一侧证据是正的：143 次提交集中在作者 tt-a1i 手上（bus factor 高），今天仍有 push（`pushed_at` 2026-08-27），issue 里是具体技术问题而非"star 了很棒"，MIT 许可。HN 上搜 "archify" 只匹配到 2012 年一家同名归档创业公司，与本项目无关——**这个 skill 本身在 HN 无讨论**。Reddit 本次不可检索（爬虫被站点拒绝），不作为证据。

**风险与争议**:
- **vanity**: stars/subscribers 208:1 且 HN 零讨论，18,088 星里有多少来自"看到漂亮示例图就 star"值得打折看待；trendshift 一类榜单站的收录会进一步放大传播。
- **bus_factor**: 143 次提交中作者一人占绝大多数，第二名贡献者仅 10 次；作者停手项目就停。
- **stability**: 复杂图布局仍有已确认缺陷（#126 边长不均导致校验结果随取样列变化、#111 UI 遮挡），出正式交付图前需要人工复核。
- **能力边界易误读**: 官方明确不做 Mermaid 自动解析、通用自动布局与可视化编辑，宣传语"从自然语言到技术图"容易让人以为是 draw.io 替代品。

**技术备注**: 主语言标为 HTML（产物是自包含 HTML），工具链是 Node/ESM（`.mjs` 脚本、`package.json`）。核心链路：自然语言或 Mermaid → typed JSON IR（`schemas/`）→ 确定性校验 → renderer 出 HTML + PNG/SVG/WebM/分享卡。安装 `npx skills add tt-a1i/archify -g`，兼容 Claude Code / Cursor / Codex CLI / OpenCode。MIT。仓内有 `archify.zip` 打包产物与 `build-zip.sh`，走的是"可离线安装"路线。

### [ConardLi/garden-skills](https://github.com/ConardLi/garden-skills) — NEW ⭐ 10,947（+113）| CSS | 信源：弱

**它是什么**: 中文开发者 ConardLi 的个人 skill 合集，5 个 skill 打包一起发：网页设计（`web-design-engineer`）、讲解式视频演示（`web-video-presentation`）、图像生成（`gpt-image-2`）、知识库检索（`kb-retriever`）、文章排版（`beautiful-article`）。不是收录别人 skill 的清单，是作者自己写的、自己在用的那一套。

**解决什么问题**: 主线是"让 AI 产出能直接给人看的东西"。`web-design-engineer` 管的是页面、仪表盘、原型、幻灯片、动画、UI 稿、数据可视化这类浏览器里渲染的视觉产物，并且明确声明不管后端、CLI 和非视觉编码。`beautiful-article` 不只是"生成一个网页"，而是一条编辑流水线：素材 → 提纲 → 双次确认 → 生成 → 终审。`kb-retriever` 解决的是知识库检索的成本问题——它在每一层目录读 `data_structure.md`，只挑最相关的子目录往下递归，避免一次把整棵树喂进上下文。

**谁在用、怎么用**（来自 Issues/仓内源码）:
- 场景 1：有人在做多语言适配。issue #24 提出给 `web-video-presentation` 的 TTS 加一层发音抽象，处理非中文 token——说明有使用者在用它做中英混排的讲解视频。
- 场景 2：有人在往里接自己的服务。issue #31 给 `gpt-image-2` 加可选的 Atlas Cloud provider，issue #22 加 Xquik 社交数据工作流——外部使用者在把它当可扩展底座而不是成品。
- 场景 3：分发路径两条并行。`npx skills add ConardLi/garden-skills`（可 `-s` 单装、`--global` 全局），以及 Claude Code 插件市场 `/plugin marketplace add ConardLi/garden-skills`——`.claude-plugin/marketplace.json` 里按 presentation / web-design / knowledge-base / image-generation 分了四个插件包。
- 场景 4：给 CI 和生产环境准备了钉版本的路径——按 tag 的 `tree/` URL 装指定 commit，每次正式发布还出带 SHA-256 校验的不可变 zip 到 GitHub Releases，适合 CI、Dockerfile 和离线安装。

**社区怎么评价**:
- 正面: 分发工程做得比多数个人 skill 仓扎实（多语言 README：英/中/日，CONTRIBUTING 三语，版本钉法 + 校验和发布）；已被 Claude Skills Hub 收录；有外部贡献者（eltociear 4 次提交）。
- 负面: HN 搜 "garden-skills" 命中数 **0**；X / Reddit 本次未取到有效独立讨论（Reddit 爬虫被拒，不计入证据）。issue 讨论极冷——列出的 5 个热门 issue 评论数是 0 / 1 / 1 / 1 / 0，也就是说"最热"的 issue 也只有一条回复。
- 健康度: 10,947 stars / 57 subscribers = 192:1；只有 16 个 open issue；118 次提交集中在作者一人，第二"贡献者"是 github-actions 机器人（20 次）。最关键的一条：**最后一次 push 是 2026-07-12，已停更约 6 周**，而 star 今天还在 +113。

**风险与争议**:
- **vanity**: 一万多星 / 57 subscriber / HN 零讨论 / issue 最热一条回复，热度与实际使用足迹落差明显；作者本人的中文技术影响力是主要传播来源。
- **bus_factor**: 118 次提交几乎全是作者，第二位是 CI 机器人；这是典型的个人作品集仓结构。
- **stability**: 停更 6 周，而 `gpt-image-2`、TTS 这类 skill 依赖的上游模型和服务迭代很快，长期不更新会静默失效。
- **dependency**: `gpt-image-2` 依赖第三方图像生成 API（issue #31 正在加 Atlas Cloud 作为可选 provider），上游定价或可用性变化会直接影响可用性。

**技术备注**: 语言标为 CSS（产物以前端视觉件为主），SKILL.md 约定，装到项目 `.claude/skills/` 或 `~/.skills`。5 个 skill 各自独立，可单装。MIT。仓内有 `dist/`、`website/`、`demo/` 与发布脚本，走的是"个人合集也按产品发版"的路子。

## 如何理解今天的热度信号

今天有三组数字容易被误读，分开说：

**stars/subscribers ratio 要分档看。** 今天的 ratio 分布：marin 85:1（最健康）、omarchy 192:1、garden-skills 192:1、archify 208:1、claude-obsidian 217:1、browser-use 241:1、ai-job-search 259:1、gpt-image-2 279:1、ponytail 401:1。但 browser-use 的 241:1 和 ponytail 的 401:1 意义完全不同——前者是 11 万星的两年老仓，超大成熟仓 ratio 结构性偏高属正常；后者是两个半月的新仓，同一个指标在这里才指向传播驱动。**ratio 单独不能定性，必须和仓龄、issue 质量、push 节奏一起看。**

**open issue 多不等于项目烂，少不等于项目干净。** omarchy 1,724 个 issue 是因为它是 Linux 发行版（硬件、驱动、包管理天然膨胀）；claude-plugins-official 1,020 个是因为审核吞吐跟不上提交；marin 570 个是活跃研究项目的正常形态。反过来，scientific-agent-skills 3.4 万星只有 10 个 open issue、garden-skills 1 万星只有 16 个且最热 issue 仅 1 条回复——**issue 太冷才是更需要警惕的信号**，它说明 star 的人和用的人不是同一批。

**"最后 push 时间"是今天最有区分度的一条。** 全榜有三个项目在 star 高速增长的同时已经停更：ponytail（停 20 天，仍 +1,598）、garden-skills（停 6 周，仍 +113）、ai-engineering-from-scratch（停 4 天，仍 +838）。star 是滞后指标，push 是即时指标，两者背离时以后者为准。

**外部讨论缺席本身是信号，但要说清缺席的原因。** archify 和 garden-skills 在 HN 上都是零命中（archify 的搜索命中全是 2012 年一家同名归档创业公司，与本项目无关）。本次 Reddit 检索被站点拒绝爬虫、未取到数据——这是**采集失败，不是"无讨论"**，不作为任何判断的依据。所以今天两个 NEW 中文/个人项目的信源强度分别定为「中」（archify：有多名外部贡献者提交 + 具体技术 issue + 独立目录站收录 + X 有转发）和「弱」（garden-skills：仅 GitHub 侧，且 issue 极冷）。

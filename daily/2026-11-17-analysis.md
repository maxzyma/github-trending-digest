### [getarcaneapp/arcane](https://github.com/getarcaneapp/arcane) — NEW ⭐ 8,775（+46）| Go | 信源：中

**它是什么**: 一个网页版的 Docker 管理面板。装在自己的服务器或 NAS 上以后，打开浏览器就能看到容器、镜像、网络和数据卷，用 Docker Compose 文件启停一整组服务，镜像有新版本时会提示更新。它还能通过 Agent 管理多台机器，盯住一个 git 仓库自动部署（GitOps），并用 Trivy 扫描镜像漏洞。

**解决什么问题**: 自托管用户以前多用 Portainer 管 Docker，但 Portainer 的部分功能要付费；Dockge 只管 Compose，功能较少。Arcane 不分版本、没有付费功能，许可证是 BSD-3-Clause，自带更新提示，不再需要另装 watchtower。

**谁在用、怎么用**（来自 Issues/X）:
- 家庭实验室和 NAS: 在群晖、Unraid、LXC 上集中管理 Compose 栈，SynoForum 有群晖部署帖，IT-Connect.fr 写了法语教程。
- 多台 VPS 统一管理: 通过 Agent 连接多台主机；v3 发布后有用户报告 Agent 返回 403（#4821）。
- 功能由社区推动: GitOps（#24，34 条评论）和 Swarm 支持（#591，42 条评论）都是用户提议后落地的。

**社区怎么评价**:
- 正面: X 上 DBTech 做过直播测评，A DevOps Girl 对比 Portainer 后评价它"迭代快、用起来顺"，但多环境扩展仍是 Portainer 更强。维护者响应快，累计约 1,473 个 issue，open 只剩 10 个。
- 负面: 内存占用偏高（#503、#639）；v1.12.0 曾破坏 Compose include（#1405）；CPU 限制报错（#1727，49 条评论）。v3 发布后又出现 API 响应不压缩（#4819）、webhook 不触发重新部署（#4825）等问题。
- 健康度: 8,775 星，subscribers 16，比值约 548:1。项目从 ofkm/arcane 迁来，比值和 1,400 多个 issue 的社区足迹不相符，单凭比值不宜判断热度虚高。2025-04-19 建仓，kmendell 一人约 3,000 次提交，另有约 1,200 次来自 dependabot 和项目机器人，外部贡献者最多 48 次。HN 只有两帖、都没有评论，Reddit 只找到官网转引的 r/selfhosted 评价。

**风险与争议**:
- **安全**: 2026-05 到 11 月发布了 10 多条安全公告，其中至少 5 条是 High 级，涉及主机任意文件读取、OIDC 账号接管和路径穿越（11-14）。面板持有 Docker socket，相当于拿着主机 root 权限，需要及时升级。
- **stability**: v3 移除了旧协议和配置，刚发布就出现一批回归，升级前要读 release notes。
- **bus_factor**: 核心开发集中在 kmendell 一人。

**技术备注**: Go 后端，BSD-3-Clause。支持 Docker、Podman 和 Swarm，内置 Trivy 扫描。今天排 #5 但日增只有 +46，推断与 11-14 的 v3.0.0 发布有关。

**它是什么**: 「江山时序」是一张在浏览器里打开的中国历史地图，界面做成宣纸风格。拖动时间轴，可以看到从战国（前 403 年）到现代的疆域变化，共 18 个时期、198 张疆域快照。点一座古城，能看到它历代叫什么名字、归哪一级政区管辖；地图上还能一步步回放张骞、玄奘、苏轼等人的行迹，并配上相关诗词。在线地址是 deanchen.me/jiangshan-map。

**解决什么问题**: 以前想知道"唐代的某个州在今天哪里"，要翻《中国历史地图集》或查 CHGIS 这类学术数据库，普通读者很难用上。江山时序把疆域、地名沿革和人物行迹放在同一张可交互的地图上，读史书、读诗词时可以直接对照；开发者可以导出 GeoJSON，用 MCP 接口或 Agent Skill 让 AI 渲染历史地图。

- 边界核查: #267 有用户逐条核对唐代安东都护府、外东北和西域的 GeoJSON 边界，至今未关闭。

**社区怎么评价**:

**风险与争议**:
- **compliance**: 郡县一级的边界来自 CHGIS，这批数据只许学术、非商业使用，不得再分发，和仓库的 GPL-3.0 许可冲突。作者已在导出脚本中默认排除这一层，但网站仍在展示，fork 的人容易忽略。

**它是什么**: Google Cloud AI Research 团队发布的论文配套代码，用 5 个 AI 智能体合作写学术论文。你提供想法笔记、实验日志和会议的 LaTeX 模板，它依次写大纲、画统计图和概念图、检索并核对参考文献、分节写正文，最后模拟审稿人提意见并反复修改，输出一份能直接编译的 LaTeX 论文。

**解决什么问题**: 研究者做完实验后，把零散的记录整理成符合会议格式的论文要花大量时间，文献综述还容易出现引用编造。PaperOrchestra 把这个过程拆给多个智能体，用 Semantic Scholar 的接口核实每条引用确实存在。论文（arXiv 2604.05018，已收录 COLM 2026）的人工评测显示，它明显好于单个智能体和 AI Scientist-v2，但仍不如人写的原文。

**谁在用、怎么用**（来自 Issues/X）:

- 研究基线: 主要用于整理实验记录成初稿、生成相关工作综述，或作为"自动写论文"研究的对照基线；没有找到真实投稿使用的案例。

**社区怎么评价**:
- 正面: 有正式论文和评测，引用核实机制针对的是 AI 写作最常见的引用编造问题。

**风险与争议**:
- **compliance**: 涉及学术诚信，作者在论文伦理声明中要求使用者自行核查全部结果；投稿前需要确认目标会议对 AI 写作的披露要求。

**技术备注**: Python，Apache-2.0。论文实验用 Gemini-3.1-Pro 写作、Gemini-3-Flash 加 Google Search 检索文献，运行需要 Semantic Scholar API key。论文 v1 与 Google Research 页面上的文献综述胜率数字不一致，引用时注意版本。

### [kajisho5/ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill) — NEW ⭐ 6,831（+367）| Python | 信源：中

**它是什么**: 给 Claude Code、Cursor、Codex 这类编程 Agent 用的本地视频剪辑工具箱。它把 FFmpeg 的常用操作做成 42 个工具，覆盖剪切、删静音、加字幕、裁成 9:16 竖屏、调响度和按平台导出。你用自然语言告诉 Agent 怎么剪，Agent 按"先探测素材、再编辑、最后自检"的流程调用这些工具，全程在本机运行，不需要云服务或 API key。

**解决什么问题**: 直接让 Agent 拼 FFmpeg 命令很容易出错，参数一长就难以检查结果。ffmpeg-skill 给每个工具定义了机器可读的输入输出契约，Agent 不用自己拼命令，剪完还能自动检查输出是否符合要求。它同时提供 MCP server，可以接入支持 MCP 的其他工具。

**谁在用、怎么用**（来自 Issues/npm）:
- 口播短视频: 删除静音和"嗯、啊"等填充词，自动转写加字幕，按平台的响度和体积要求导出。
- 转写效果对比: #318 有用户在两台 Mac、六组语音素材上对比 Parakeet 和 whisper.cpp 的转写质量。
- 团队实测: AutoClaw 团队做了真实任务测试并反馈（#240）；#406 请求做 Codex 插件，已实现。
- 安装量: npm 近 30 天下载约 3.5 万次，是目前最有力的使用证据。

**社区怎么评价**:
- 正面: 设计思路清楚，README 写明不经过 shell、不接受外部传入的原始 FFmpeg 参数，会覆盖文件的工具都做了标注。
- 负面: ffprobe 失败时曾经删除输入文件（#111，已修复）；Windows 日文区域设置下非 ASCII 路径出错（#234）；字幕位置错误（#436）。
- 健康度: 6,831 星、603 个 fork，subscribers 12，比值约 568:1。2026-09-03 建仓，约 75 天发布了 217 个 npm 版本。作者 322 次提交，另有大量 GitHub Actions 和 claude[bot] 提交，外部贡献者每人 1 到 2 次。issue 区约 131 个由作者自己开，外部用户提交的约 27 个。HN 和 Reddit 没有讨论，X 上只有转述 Trendshift 的推荐帖。

**风险与争议**:
- **vanity**: 比值很高，开发者社区讨论几乎为零；但 npm 下载量说明有真实安装，热度需要结合使用数据判断。
- **stability**: 75 天 217 个版本，接口变化频繁，2.0 已有破坏性变更；曾出现删除输入文件的严重缺陷。
- **bus_factor**: 单人维护，大量开发由 AI 辅助完成。

**技术备注**: Python 标准库实现，MIT 许可，通过 npm 分发。项目不打包 FFmpeg，GPL/LGPL 义务取决于用户自己安装的 FFmpeg；只有 LGPL 构建、没有 libx264 时会自动改用 VideoToolbox 编码。

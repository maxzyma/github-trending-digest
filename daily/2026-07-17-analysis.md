## NEW 项目详析

### [apache/ossie](https://github.com/apache/ossie) — NEW ⭐ 915（+60）| Python | 信源：中

**它是什么**: 一套让不同数据平台"对同一个指标说同一种话"的开放规范。今天你在 BI 工具里定义的"月活跃用户"，到了 AI 助手、数据仓库、报表工具里往往各算各的口径；Ossie 想用一份厂商中立的 JSON/YAML 规范，把指标、维度、关系这些"语义元数据"标准化，作为跨平台的单一事实源。

**解决什么问题**: 没有它之前，每个平台自带一套语义层，跨工具迁移和对账要人工翻译口径；有了统一规范，语义定义可以在 dbt、Snowflake、Databricks、Salesforce 之间以标准格式交换，减少"同名不同义"。

**谁在用、怎么用**（来自 Issues/官方博客）:
- 厂商共建转换器: #152 讨论 Databricks Unity Catalog Metric View 转换器，#93 讨论 Spark 转换器，反映真实厂商在贡献 spec 与适配层。
- spec 设计辩论: #113（datatype 字段、重构 is_time，11 评论）、#84（field datatype，9 评论），核心难点是 metrics 语言与时间/窗口逻辑仍在定型。

**社区怎么评价**:
- 正面: 前身 Open Semantic Interchange（Snowflake 发起），2026-06 进入 Apache 孵化器；联盟从 17 家扩至 50+，含 Snowflake、Dremio、Salesforce、Databricks、dbt Labs、GoodData 等，非单一厂商控制。
- 负面: HN/X/Reddit 几乎零独立讨论，传播以 Snowflake/dbt/Dremio 官方博客为主；规范仍 v0.1，核心语义未定型。
- 健康度: 915 star / 38 subscribers（约 24:1，对早期规范项目正常）、open issues 57、forks 135；贡献者多元但实际由 Snowflake+Dremio+dbt 三家主导。

**风险与争议**:
- **vanity**: 社区足迹薄——独立开发者讨论近乎为零，热度靠大厂官方渠道推动。
- **stability**: v0.1 规范，metrics 语言、时间/窗口表达仍在设计，落地实现有限。
- **dependency**: 虽入 ASF，核心开发与治理影响力集中在少数大厂。

**技术备注**: Python，Apache-2.0；参考实现含 Ossie→dbt MetricFlow、Apache Polaris、Snowflake Semantic Model 转换器；治理走 ASF 邮件列表 + 投票。

### [PrismML-Eng/Bonsai-demo](https://github.com/PrismML-Eng/Bonsai-demo) — NEW ⭐ 1,525（+196）| Shell | 信源：强

**它是什么**: PrismML 官方发布的"把大模型塞进手机/笔记本"的本地推理 demo。它把 Qwen3.6-27B 这样的 27B 参数模型压到 1-bit（约 3.9GB，能在 iPhone 上跑）或 ternary/1.58-bit（约 5.9GB，能在笔记本跑），并附带在 Mac(Metal)/Linux/Windows(CUDA/Vulkan/ROCm)/CPU 上的下载与运行脚本。仓库语言标成 Shell，只是因为它本质是围绕 llama.cpp/MLX 的 setup/下载脚本包装器。

**解决什么问题**: 27B 级模型通常要几十 GB 显存、跑在服务器上；极端量化后，多模态（视觉 + 工具调用 + 256k 长上下文）能力可以下沉到消费级设备，本地、离线、低成本地跑，主打"能力/体积比"。

**谁在用、怎么用**（来自 Issues/HN/Reddit）:
- 多硬件实测适配: #71 ROCm Strix Halo、#51 Strix Halo TheRock、#52 RTX A2000 benchmark，是真实用户在不同硬件跑起来后回贡 PR。
- 上手门槛痛点: #4（7 评论）报 Intel x86 Mac 编译问题；社区反映 LM Studio / stock llama.cpp / Ollama 尚不支持 1-bit 权重，普通用户难直接用。

**社区怎么评价**:
- 正面: HN 讨论罕见地强——"Bonsai 27B runs on a phone"694 分/249 评论、"1-Bit Image"464 分、Show HN 430 分、Ternary 225 分；star 增长与讨论高度匹配，非空心化。
- 负面: r/LocalLLaMA 实测——通用聊天/邮件/简单数学不错，但事实性问题会幻觉、复杂代码/JSON 吃力；benchmark 多为自报。
- 健康度: 1,525 star / 29 subscribers（约 52:1，脚本 demo 仓属正常偏高）、forks 153、open issues 16；核心提交集中在 khosravipasha（49 次）；组织另有 Bonsai-Image-Demo（499⭐）。

**风险与争议**:
- **dependency**: 27B 模型需 HuggingFace token 且部分 repos 私有；依赖上游 llama.cpp 合并进度（Q2_0 Vulkan 仍在 review）。
- **stability**: 主流推理引擎尚不支持 1-bit，普通用户上手门槛高。
- **transparency**: 训练/压缩管线未开源（仅白皮书），benchmark 以自报为主。

**技术备注**: Shell（脚本包装器），底层 llama.cpp/MLX，Apache-2.0；组织 fork 了 mlx/llama.cpp/sglang 做适配。

### [ibelick/ui-skills](https://github.com/ibelick/ui-skills) — NEW ⭐ 4,292（+178）| TypeScript | 信源：中偏弱

**它是什么**: 一个给 AI 编码助手挂"UI 质量约束"的技能目录 + 路由层。作者是知名设计师 ibelick（motion-primitives、prompt-kit 作者）。它想解决 AI 生成 UI"平庸、千篇一律"的问题：`npx ui-skills start` 后，agent 会按需加载若干 skill 来打磨界面。

**解决什么问题**: AI 直接生成的前端往往间距混乱、层级不清、无障碍缺失；ui-skills 把"去 slop、修排版、补 ARIA/键盘/对比度、修动画性能"等设计工程经验打包成可复用 skill，让 Claude Code/Cursor/Codex 生成更规范的 UI。

**谁在用、怎么用**（来自 Issues）:
- 内置 6 个 skill: baseline-ui（去 slop、修间距/排版，面向 Tailwind）、fixing-accessibility（WCAG）、fixing-metadata、fixing-motion-performance、improve-ui、ui-skills-root（路由，最多选 3 个）。
- 生态投稿为主: #36 UIZZE、#23 unslop、#21 product-ui-design、#20 Compose Expert 等多为第三方想把自己的 skill 加进 registry；#22"给 skills 加评分"仅 1 条评论。

**社区怎么评价**:
- 正面: 已能吸引第三方 skill 贡献，跨 Claude Code/Cursor/Codex 复用；被 Snyk 文章与多个 skill marketplace 收录。
- 负面: issue 区几乎无独立用户的使用体验/bug 反馈，讨论深度弱；HN 仅 1 条 story（5 分 0 评论），Reddit 无讨论。
- 健康度: 4,292 star / 12 subscribers（约 358:1，极度失衡）、open issues 9、forks 183；贡献者高度集中（ibelick 一人 156 提交）。

**风险与争议**:
- **vanity**: star 与 subscribers、HN、issue 实质讨论、Reddit 全面不匹配，热度由作者个人声誉 + skills 生态热点驱动，缺独立采用证据。
- **bus_factor**: 单人主导（156/其余各 1-2 提交），维护高度依赖作者。

**技术备注**: TypeScript，半年龄（2026-01 建），配 ui-skills.com 站点，兼容 Claude Code/Cursor/Codex。

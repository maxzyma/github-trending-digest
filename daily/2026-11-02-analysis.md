### [cjpais/Handy](https://github.com/cjpais/Handy) — NEW ⭐ 36,606（+339）| Rust | 信源：强

**它是什么**: 一个免费、完全离线的语音转文字应用。按住快捷键说话，松开后识别出的文字自动粘贴进当前输入框，可以选用 Whisper、Parakeet 等本地语音模型。

**解决什么问题**: 同类听写工具如 Wispr Flow、Superwhisper 多为付费，且常把录音传到云端。Handy 在本机完成识别，不花钱也不上传录音；作者最初是因为手指受伤、打字困难才开始做这个项目。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 场景 1: 给 ChatGPT 或编程 Agent 口述提示词、写邮件和文档。X 上 flaviocopes 评价 Handy 配 Parakeet v2 "又快又准"；日本用户 matsuu 发现用 Whisper Turbo 时会自动去掉"あー""えー"这类语气词。
- 场景 2: Linux 桌面使用。评论较多的问题集中在这里：Ubuntu 22.04 快捷键失效（#102，45 条评论），GNOME/Wayland 下粘贴丢首字（#429，42 条）。
- 场景 3: 粘贴链路。评论最多的 #502（90 条）报告粘贴出的是剪贴板原内容而不是识别结果。

**社区怎么评价**:
- 正面: HN 两次上首页，2025-09 帖 237 分 98 条评论，2026-01 帖 247 分 110 条评论；X 上有英、日、法语用户的自发分享；AlternativeTo 把它列为听写工具替代品第一。
- 负面: 竞品 Spokenly 的评测提到停止说话后要等 2 到 5 秒、没有移动端（评测方立场可能不中立）。Reddit 未找到讨论。
- 健康度: 100 个关注者，星数与关注者之比约 366:1，对一个 21 个月、HN 讨论充分的项目不宜单凭比值判断；open issue 约 92 个、open PR 119 个；作者 590 次提交，第二名 22 次。最新版本 v0.9.8（10-03），今天上榜没有对应的新版本或明确事件。

**风险与争议**:
- **bus_factor**: 作者一人主导，119 个 PR 积压。
- **stability**: 仍是 0.x 版本，Linux/Wayland 适配和粘贴链路的问题反复出现。

**技术备注**: Rust（Tauri 桌面框架），MIT 许可。支持 macOS、Windows、Linux。

### [beenuar/AiSOC](https://github.com/beenuar/AiSOC) — NEW ⭐ 6,261（+446）| Python | 信源：中

**它是什么**: 一套可以自己部署的"AI 安全值班室"。它把各类安全告警汇总归并，让 AI 代理先做研判、对照 MITRE ATT&CK 攻击框架调查，把每一步提示和工具调用记进可回放的"决策账本"；隔离主机、封禁账号这类处置动作必须由人批准。

**解决什么问题**: 安全团队每天面对大量告警，人工逐条研判成本高；商业 SOC 平台贵且不透明。AiSOC 想让团队用自己的模型（可用 Ollama、vLLM 完全离线运行）做可审计的 AI 研判，事后能复盘 AI 每一步为什么这么判断。

**谁在用、怎么用**（来自 Issues/外部介绍）:
- 场景 1: 接入外部告警源。外部用户报告 GitHub 检测规则匹配不上规范化后的事件（#1545，已关闭）；作者开帖征集用户想要的数据源连接器（#356）。

- 未找到具名的生产部署案例。

**社区怎么评价**:
- 正面: 工程量扎实，98 个 issue 中 95 个已关闭，1,467 个 PR 中合并 1,174 个；6 个月发了 41 个版本，最新 v20.4.0。README 公开写明各模型评测结果"未实测"，没有拿自报数据包装效果。

**风险与争议**:
- **bus_factor**: 开发几乎由作者一人完成，第二名贡献者在最近 100 次提交中只有 8 次。
- **stability**: README 自己把 AI 研判和决策账本标为 Beta；半年发到 v20，大版本迭代快，已有 Helm chart 跨大版本升级出问题的记录（#1440）。

**技术备注**: Python，MIT 许可。自托管部署，支持本地模型离线运行，附带 MCP server。

### [FlashML-org/FreeToken](https://github.com/FlashML-org/FreeToken) — NEW ⭐ 15,440（+242）| Python | 信源：强

**它是什么**: 一个在普通游戏显卡上跑超大 AI 模型的推理引擎。它针对 MoE（混合专家）模型，把放不进显存的部分放到内存里调度，让 8GB、12GB 显卡也能跑几十 GB 甚至上百 GB 的模型。

**解决什么问题**: 以前在本地跑大模型，要么买大显存显卡，要么用 llama.cpp、Ollama 接受较慢的速度。FreeToken 想在消费级 N 卡上跑得更快，并通过兼容 OpenAI 和 Anthropic 的接口，直接接给 Claude Code、Codex 等编程 Agent 当本地模型。

**谁在用、怎么用**（来自 Issues/HN/X/Reddit）:
- 场景 1: 在 8GB 到 16GB 显卡上跑 Qwen 3.6 35B 等模型。X 上有独立用户报告 RTX 4080 16GB 约 60 到 90 tok/s；r/LocalLLaMA 有用户用 RTX 3060 12GB 加 64GB 内存跑 85GB 的 DeepSeek-V4-Flash，约 3 tok/s（转述自 Trendshift 汇总，原帖未打开）。
- 场景 2: 换硬件。呼声最高的是 AMD 显卡（#60，22 条评论）、Intel 显卡（#74，21 条）和 Apple Silicon（#9，17 条），社区已提交 ROCm RDNA4 移植（#82）。
- 场景 3: 桌面版加载模型。#782、#784、#847 报告加载 NVFP4 权重失败，#798 报告高 KV 配置下崩溃。

**社区怎么评价**:
- 正面: 有论文和真实引擎代码（约 6.7MB Python、近 1MB CUDA、1.3MB C/C++）；HN 的 Show HN 帖 41 分；fork 约 1,550，issue 和 PR 都活跃。
- 负面: RTX 4060 8GB 上 v0.2.0 比 v0.1.3 变慢（#822）；官方称 8GB 显卡跑 35B 模型可达 39.3 tok/s、比 Ollama 快 2 到 4 倍，有用户反驳 llama.cpp 在 RTX 5060 8GB 上已能跑 34.9 tok/s（转述自搜索摘要）。
- 健康度: 98 个关注者，星数与关注者之比约 158:1；仓库创建于 2026-07-20；主作者 140 次提交，第二名 9 次。

**风险与争议**:
- **bus_factor**: 维护集中在一位作者，FlashML-org 实际是个人账号。
- **stability**: 新版本有性能回退，部分权重加载失败。
- **dependency**: 目前只支持 NVIDIA 显卡。
- **测速争议**: 官方测速与 llama.cpp 的对比口径存疑，选型前用自己的硬件实测。

**技术备注**: Python + CUDA + C/C++，Apache-2.0 许可。提供 OpenAI 与 Anthropic 兼容 API 和桌面版。

## NEW 项目

### [jingyaogong/minimind](https://github.com/jingyaogong/minimind) — NEW ⭐ 56,187（+495）| Python | 信源：中

**它是什么**: 一套"自己动手造一个能说话的小模型"的完整教程加代码。不是让你调用别人的大模型，而是从最原始的一步开始——把中文语料切成 token、随机初始化一个 64M 参数（约 GPT-3 的 1/2700）的网络、在自己的显卡上训练它，直到它能接着你的话往下写。作者的口号是"大道至简"：README 首行写的是「仅用 3 块钱成本与 2 小时训练时间」。

**解决什么问题**: 大模型训练对绝大多数人是黑箱——论文看得懂，但从没见过完整的一条链路。现有的开源大模型仓库要么只放推理代码，要么训练脚本依赖上百 G 数据和集群。minimind 把整条链路缩到个人 GPU 能跑完的规模，并且把每一步都摊开写成可读的裸 PyTorch：数据清洗、预训练（Pretrain）、监督微调（SFT）、LoRA、RLHF（DPO）、RLAIF（PPO / GRPO / CISPO）、Tool Use、Agentic RL、自适应思考、模型蒸馏，以及 MoE 结构。学完之后你不是"会用大模型"，是"知道大模型是怎么长出来的"。

**谁在用、怎么用**（来自 Issues/HN）:
- 个人复现与训练记录：#26「不是 Issue，一点个人训练 minimind 的记录」拿到 29 条评论，是全仓评论最多的帖子——issue 区被当成了学习者的共同笔记本，这是教学仓独有的使用形态。
- 能力边界探索：#620「如何让模型学会 100 内的加减法？」20 条评论，讨论的是在 64M 规模下用什么数据配比和训练策略才能让模型学会最基本的算术，属于典型的教学场景延伸实验。
- 二次教程创作：#73「学习代码的时候写了一个教程，希望可以帮到其他同学」9 条评论——读者读完之后再写教程给下一批人，形成了自增强的学习链。
- 工程改进：#599（把 LoRA 权重合并进模型做推理）、#214（加交互式 notebook）说明也有人把它当作可改造的训练脚手架，而不只是读物。
- 生态外延：作者还开源了视觉模态 MiniMind-V、多模态 MiniMind-O、扩散语言模型 MiniMind-dLM 和线性模型 MiniMind-Linear，形成系列。

**社区怎么评价**:
- 正面: 56,187 ⭐ / 7,326 fork（7.7:1）——对一个教学仓来说 fork 率高是好信号，说明人们真的把代码拉下来跑而不只是收藏。issue 区讨论质量高，最热的帖子是学习笔记而非报错。Apache-2.0，2026-08-31 仍在推送，仓库活了两年多。
- 负面: HN 上只有一条 2026-03-24 的帖子（"MiniMind: End-to-end GPT-style LLM training pipeline in pure PyTorch"），3 分 1 评论，基本没有讨论——它的传播完全在中文技术圈内部（README 主语言是中文，英文版是翻译件）。英文世界的开发者对它几乎无感知。
- 健康度: 56,187 ⭐ / 256 subscribers（220:1）比值偏高，但对"读完就走"的教学类仓库这是结构性的，不能直接按 vanity 判。真正的隐忧在贡献者结构：jingyaogong 191 commits，第二名 6 commits，作者一人占约 93%。

**风险与争议**:
- **bus_factor**: 单一作者贡献占比约 93%，且同时维护 MiniMind-V / -O / -dLM / -Linear 五个衍生仓，注意力分散风险明显。
- **vanity**: 220:1 的 stars/subscribers 与 HN 3 分的外部足迹落差大；这里的热度主要来自中文社区的教学口碑传播，把它当成"被广泛采用的训练框架"会误读——它是教材，不是生产工具。
- **stability**: 训练结果对数据配比和超参极敏感（#620 讨论的加减法能力就是实例），"2 小时训出可用模型"是最理想路径下的数字，复现体验差异大。
- **cost**: README 的「3 块钱成本」以最小配置计；跑到 MoE、RLHF、多模态衍生分支时的实际显卡与时间开销远高于此。

**技术备注**: Python + 裸 PyTorch，Apache-2.0，2024-07-27 建仓。模型权重挂在 Hugging Face collection，配套 GitHub Pages 文档站。

## 如何理解今天的热度信号

今天 16 项里有 6 项的 stars/subscribers 超过 200:1（`reverse-skill` 329:1、`open-seo` 336:1、`patent-disclosure-skill` 348:1、`minimind` 220:1、`ECC` 195:1、`archify` 295:1），但这个比值本身不构成判断——`minimind` 的高比值来自"读完就走"的教学属性，`archify` 的高比值来自 skill 包被复制而非被 watch，两者性质完全不同。今天真正值得警惕的只有一个结构性异常：`Wand-Enhancer` 的 **fork 多于 star 2.5 倍**。fork 与 star 是两种不同的动作成本，正常项目 star 远多于 fork；反过来时，通常说明用户是被引导去"复制仓库"的，而不是自发关注。

对照组在 `checkstyle`：9,423 ⭐ / 221 subscribers（43:1）、764 open issue、13 年仓龄、当天有推送。这是"被真实使用的工程工具"应有的样子——关注比低、issue 多、维护连续。读今天任何一个高 ratio 项目时，都可以拿它做尺子。

另外提醒一点：今天只有 1 个 NEW，且这个 NEW 是两年前的老仓。当 Trending 的新增供给断档时，位次更多反映的是"哪些老项目还有余温"，而不是"什么正在发生"。这类日子适合回头补课，不适合据此判断技术方向的转折。

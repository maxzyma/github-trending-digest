## 新上榜项目

### [ag-ui-protocol/ag-ui](https://github.com/ag-ui-protocol/ag-ui) — NEW ⭐ 17,389（+9）| TypeScript | 信源：强

**它是什么**: 一份让 AI Agent 和网页、App 界面对话的公共约定，叫 Agent-User Interaction Protocol。Agent 在后台思考、调用工具、改数据时，界面需要实时知道"它说到哪了、在调什么工具、状态变成了什么"。AG-UI 把这些事件定成统一格式，再提供 TypeScript、Python 等 SDK，前端照着接一次，就能换用不同框架写的 Agent。

**解决什么问题**: 以前每个 Agent 框架都有自己的流式输出格式，产品团队把 LangGraph、CrewAI 或自研 Agent 接进前端时，要为每一种各写一层转换，换框架就得重写。AG-UI 让后端框架和前端组件各自对接协议，两边可以分开替换。

**谁在用、怎么用**（来自 Issues/HN/X/厂商文档）:
- 产品内 AI 助手: 合同管理 SaaS fynk 用 LangGraph + AG-UI + CopilotKit 重写了站内助手，删掉约 1.1 万行自研代码，并向上游贡献了 Vue 版本（[fynk 博客](https://fynk.com/en/blog/fynk-assistant-copilotkit-vue/)）。
- 大厂框架接入: 官方集成页列出 Microsoft Agent Framework、Google ADK、AWS Strands 与 Bedrock AgentCore、AG2，生态侧还有 LangGraph、Mastra、Pydantic AI、LlamaIndex 等；ClaudeDevs 账号发过把 Claude Managed Agents 接入 AG-UI 的示例。
- 移动端与更多语言: #510（21 条评论）请求 React Native 客户端，#494 请求 Swift SDK，#231 请求支持 MCP 的 elicitation（Agent 中途向用户追问）。

**社区怎么评价**:
- 正面: Show HN 发布帖 36 分、5 条评论；一位 Google 工程师在 HN 评论里认为它适合 UI 和 Agent 都自己掌控的场景。2026-09-30 发布 1.0。
- 负面: HN 上有人指出协议虽开放，CopilotKit 本身仍是付费服务；#733 报告用户主动停止时出现 ECONNRESET，#868 报告 Edge 浏览器里不流式输出；Google 开发者论坛有人反映 ADK 部署到 Vertex Agent Engine 后需要额外适配。
- 健康度: stars/subscribers 约 181:1，但这是协议仓，开发者主要通过 npm/PyPI 包消费，比值不能单独说明问题。1,667 个 fork；open 593 项，其中 PR 280 个，积压明显。11-12、11-13 连续发布。下载量"每周 250 万"是 CopilotKit 自报数字，未独立核实。

**风险与争议**:
- **dependency**: 一篇生产实践文章指出，断线重连和事件回放属于 CopilotKit 商业层功能，不是协议本身的保证；选型时要分清协议能力和厂商运行时能力。
- **bus_factor**: 前五名贡献者都在 CopilotKit 团队；#2256 指出社区维护的 Rust SDK 没有 code owner，PR 推不动。
- **stability**: 中止流程、个别浏览器的流式输出和云平台部署仍有兼容问题（#733、#868）。

**技术备注**: TypeScript 为主，附 Python、Kotlin 等多语言 SDK，MIT，2025-05-07 建仓。基于事件流（SSE / WebSocket 等传输均可），与 MCP（Agent 调工具）、A2A（Agent 之间通信）分工不同，AG-UI 管的是 Agent 和用户界面之间这一段。

### [Tencent/LoopForge](https://github.com/Tencent/LoopForge) — NEW ⭐ 931（+33）| Go | 信源：中

**它是什么**: 腾讯开源的一个"编码 Agent 调度台"，可以部署在自己的服务器上。你在聊天框里提需求，它开一个 Docker 沙箱、拉取代码仓库，再把活分派给 Claude Code、Codex、CodeBuddy、OpenCode、Cursor CLI 等编码工具，最后提交 PR。也可以把"需求澄清、设计、编码、评审、测试"画成一条固定流水线，中间插入人工审批，谁签字谁放行。

**解决什么问题**: 团队直接用编码 Agent 时，每个人的用法各不相同，也很难保证每次都跑过编译、单测和代码评审。LoopForge 把这些步骤做成可复用的 SOP，节点不达标就打回重做，交付量和调用成本也能按需求统计。它还有一个本地版（`npx loopforge-cli install claude`），把内置流程装进个人的编码助手。

**谁在用、怎么用**（来自 Issues/中文技术媒体）:
- 团队交付流水线: 官方发稿称腾讯内部已有 20 多个业务使用、单月交付 200 多个需求（自述数字，未独立核实，见 [InfoQ](https://www.infoq.cn/news/QGaIWSgd9uwx2WGw0yFv)、[OSCHINA](https://www.oschina.net/news/503437)）。
- 自建代码托管: 外部贡献者提交了支持自建 GitLab 的 PR #155、接入 Qoder 执行器的 PR #403 和工具安全加固 PR #835。
- 早期试用踩坑: #461、#475 报告 DeepSeek 默认模型报错和 Docker 一键安装失败（#475 已关闭）；#600 报告定时任务每次运行泄漏约 73 MB 磁盘（已关闭）。

**社区怎么评价**:
- 正面: 研发很活跃，v0.3.6、v0.3.8、v0.3.9-rc.1 在 11-11 到 11-13 三天内连发；已有外部贡献者提交执行器和平台适配。
- 负面: #717 报告 SOP 成功后清理工作区，会连带删掉未提交的改动；#660 报告对话中 CLI 连续异常退出。
- 健康度: 931 星、216 个 fork，subscribers 只有 8，比值约 116:1；2026-07-28 建仓，约 324 个提交，前几位贡献者看起来都是项目团队成员。HN、X、Reddit 均未找到相关讨论。

**风险与争议**:
- **stability**: 版本还在 0.3.x，几乎每天发版；#717 涉及未提交代码丢失，使用前先确认工作区清理策略。
- **vanity**: 约两周内 star 增长约 20 倍，外部声量目前只有官方发稿，独立用户反馈还少。
- **dependency**: 需要同时兼容十种编码 CLI 的版本变化，任何一家改接口都可能影响流水线。
- **compliance**: README 写 MIT，GitHub API 识别的许可证为 NOASSERTION，正式使用前看一眼 LICENSE 原文。

**技术备注**: Go 后端，Docker 沙箱执行，2026-07-28 建仓。支持聊天和 SOP 两种模式，SOP 节点类型包括 Agent、脚本、人工审批和子 SOP。

### [martin-olivier/airgorah](https://github.com/martin-olivier/airgorah) — NEW ⭐ 5,898（+270）| Rust | 信源：弱

知名老项目首入 tracker。

2022 年建仓的 Linux 图形界面 WiFi 安全审计工具，MIT 许可，作者一人维护（58 次提交，其余主要是 dependabot）。按 README 的说法，它用图形界面完成抓取周边 WiFi 流量、发现接入热点的设备、发送断开认证（deauth）帧、抓取握手包和 PMKID、破解热点密码等操作，常被渗透测试入门者当作命令行工具之外的选择。最新版本是 09-26 的 v0.9.0。Issues 里最多的是网卡兼容问题：#197（Intel AX201 第二次启动后扫不到网络）、#120 和 #129（5GHz 或虚拟机环境不可用），#68 讨论能否脱离 systemd 运行（18 条评论）。README 明确写着，对不属于自己的网络发起攻击在几乎所有国家都违法；只在自有或已获书面授权的网络上使用。

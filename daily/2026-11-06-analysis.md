## 新上榜项目

### [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser) — NEW ⭐ 45,931（+150）| Rust | 信源：中

**它是什么**: 一个给 AI 编程助手用的"遥控浏览器"。助手通过几条命令打开网页、看页面上有哪些按钮和输入框、点击、填写、截图，再把结果读回来继续判断。发命令和读结果的都是 Agent，人不需要盯着窗口。

**解决什么问题**: 以前让编程助手操作网页，常见做法是接 Playwright 脚本或 Chrome DevTools MCP，模型要读大量 DOM 或截图，token 消耗大，元素定位也容易出错。agent-browser 把页面压成一份带编号的可交互元素清单，模型用 `@e1` 这类引用下指令；安装方式是一个命令行程序加一份 Skill 说明，不需要单独配置 MCP 服务。

**谁在用、怎么用**（来自 Issues/X）:
- 场景 1: 让 Claude Code、Codex、Cursor、opencode 等编程助手在改完前端后自己打开页面做 QA 和回归检查；X 上有开发者（Jason Zhou、Ryan Carson）在 1 月发布后发了实测推荐。
- 场景 2: 连接用户已经在运行的 Chrome，复用登录态做表单填写和页面数据抓取；这种用法下窗口会抢前台焦点，用户在 #1247 请求后台模式（9 条评论，仍开放）。
- 场景 3: 前端性能调试，有用户用它检查懒加载是否生效；也有用户反馈它看控制台和接口请求不如 DevTools MCP 方便。

**社区怎么评价**:
- 正面: 多位用户称它比 Chrome DevTools MCP 省 token、响应快，元素引用让模型更少点错（用户自述，未见公开测量方法）。发版密集，10-29 至 11-03 连发 v0.41.0、v0.41.1、v0.41.2，Firefox 支持在 PR 中（#2206）。
- 负面: Windows 问题集中，二进制没有代码签名被 Defender 隔离（#382）；命令没有单步超时，会话卡住后快照、读取会一直挂起（#1713）。
- 健康度: stars/subscribers 约 455:1（45,931 / 101），偏高，但 X 上有多语种独立实测，不足以判为热度失真；3,150 forks；489 个 open issues 中约 323 个是待合并 PR，积压明显；提交高度集中在 ctate（411 次），第二名 76 次。HN 上 1 月有两条帖子，均无评论；Reddit 未找到讨论。

**风险与争议**:
- **stability**: Windows 兼容性问题多（签名、启动、管理员 shell），会话卡死无超时回收（#1713），版本更新快，命令行接口可能继续变化。
- **bus_factor**: 主要提交来自一人，约 323 个 PR 待处理。
- **dependency**: 底层依赖 Chrome DevTools Protocol，浏览器侧变化会直接影响可用性；Firefox 支持尚未合并。

**技术备注**: Rust 编写的 CLI，后台常驻 daemon 管理浏览器会话；通过 CDP 控制 Chromium；Apache-2.0 许可；2026-01-11 创建。

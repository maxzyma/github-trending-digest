### [strands-agents/harness-sdk](https://github.com/strands-agents/harness-sdk) — NEW ⭐ 7,937（+115）| Python | 信源：强

**它是什么**: AWS 出品的 agent 开发工具包，原名 Strands Agents SDK。开发者用它写 AI agent：定义模型、工具和任务，SDK 负责让模型循环地思考、调用工具、拿结果再继续，直到把事做完。这次改名后，同一个仓里同时放 Python 和 TypeScript 两套实现，并配了一个命令行工具 harness-cli。

**解决什么问题**: 没有这类 SDK 时，团队要自己写"模型 → 工具调用 → 结果回填 → 再调用"的循环、上下文压缩、会话存储和接入云服务的胶水代码。Strands 的思路是让模型自己驱动流程，开发者只声明工具和目标，代码量比 LangGraph 这类显式编排图少很多。9-23 发布的 "Strands harness" 在此之上再包一层，主打"一个 import 即用"和官方宣称的 token 成本下降约 28%。

**谁在用、怎么用**（来自 Issues/HN/X/AWS 博客）:
- AWS 内部产品：据 AWS 公开材料，Amazon Q Developer、AWS Glue、VPC Reachability Analyzer、Kiro 在生产中使用 Strands。
- 多语言与生态接入：#156（要 TypeScript SDK，121 个反应，已完成）、#616（要 Go SDK，94 个反应）、#1181（要 skills 支持，56 个反应），说明已有不少团队在上面搭东西。
- 生产化细节：#2020 在多租户场景下要求 SessionManager 支持只读模式，#476 要求能自己控制工具调用的线程池，都是已经上线的用户才会提的问题。

**社区怎么评价**:
- 正面: HN "Strands Harness" 帖（134 分 / 92 评论）里有人肯定事件驱动的设计好扩展；DEV、Medium 上的对比文认为它在大多数简单场景下比 LangGraph 省事。
- 负面: HN 上有人质疑 Terminal-Bench 2.1 已接近饱和、拿它当证据说服力不足，也有人对"省 30% token"不感兴趣；对比文认为复杂工作流的控制力不如 LangGraph。Issue 侧 #1671 反映 Bedrock Guardrail 会误判工具结果。
- 健康度: 7,937 ⭐ / 53 subscribers（约 150:1），1,209 forks，贡献者超过 100 人。810 个 open 中 issue 526 个、PR 284 个，带 bug 标签的 open issue 128 个。9-22 同日发布 Python v1.57.0 与 TypeScript v1.19.0，更新频繁。仓库建于 2025-05，不是短龄项目。

**风险与争议**:
- **vanity**: 本轮热度主要由 AWS 官方与合作 KOL 推动，benchmark 与成本对比数字目前没有独立复现；程度偏轻，项目本身有真实用户与生产案例。
- **dependency**: Guardrail、Bedrock 相关 issue 集中，外界普遍认为它偏向 AWS 生态，离开 AWS 使用的体验需要自己验证。
- **stability**: 改名与新 harness 同时发布，定位仍在变；issue 与 PR 积压较多。

**技术备注**: Python + TypeScript 双实现，Apache-2.0。模型驱动的 agent loop，支持 MCP 工具与多家模型供应商。旧仓 `sdk-python` 已重定向到本仓。

### [harry7557558/spirula-studio](https://github.com/harry7557558/spirula-studio) — NEW ⭐ 785（+69）| C++ | 信源：中

**它是什么**: 一个把视频变成 3D 场景的桌面工具。你用手机、360 相机或无人机绕着一个物体或空间拍一段视频，它先算出每帧的相机位置，再训练出一个"3D 高斯泼溅"（3D Gaussian Splatting，一种用大量半透明小椭球表示场景的技术）模型，最后还能转成普通的 3D 网格。

**解决什么问题**: 主流 3DGS 训练工具大多只支持 NVIDIA 的 CUDA，AMD、Intel 和苹果显卡用户基本被挡在门外，而且从视频到可用模型要串好几个独立工具。spirula-studio 用 Vulkan 做跨厂商后端（也保留 CUDA），并把"视频 → 相机位姿 → 3DGS → 网格"放进一条流水线。

**谁在用、怎么用**（来自 Issues/X）:
- 360 全景扫描：#77 用户反馈 360 相机素材对齐不准（平均误差 0.83px 但结果仍错位），作者当天发布 v2026.9.24 改进序列数据集处理。
- 非 NVIDIA 显卡用户本地训练：#23（6900XT）、#75（5700XT、RX 6600）、#18（Strix Halo）都是 AMD 用户在跑，说明跨厂商确实是它吸引人的点。
- 外部评价：X 上日本用户 @DuckbillStudio 称赞浮点噪点少、从 SfM 到 3DGS 一条流水线，能直接导入 Osmo360 的 OSV 文件；radiancefields.com 为它做了平台收录页。

**社区怎么评价**:
- 正面: 作者响应快，#48 给用户单独打调试版；9 月发了 5 个版本，v2026.9.20 下载 1,243 次、v2026.9.13 下载 757 次，有真实下载量。
- 负面: AMD 在 Vulkan 下崩溃是最集中的问题（#23、#75、#18），恰好打在"跨厂商"这一卖点上；另有 #48 Windows 蒙版阶段闪退、#73 生成网格报错。
- 健康度: 785 ⭐ / 21 subscribers（约 37:1），57 forks，30 open issues。harry7557558 提交 896 次，第二名仅 7 次。仓库建于 2024-05，原名 spirulae-splat。HN、Reddit 无讨论。

**风险与争议**:
- **bus_factor**: 几乎是单人项目，提交集中度超过 99%。
- **stability**: 跨厂商是核心卖点，但 AMD Vulkan 路径在多款显卡上反复崩溃或卡死。
- **compliance**: GPL-3.0，商用产品集成需要注意传染性条款。

**技术备注**: C++，Vulkan / CUDA 双后端，GPL-3.0。覆盖 SfM 位姿估计、3DGS 训练与网格导出，按日期打版本号（v2026.9.x）。

### [TNT-Likely/PanWatch](https://github.com/TNT-Likely/PanWatch) — NEW ⭐ 1,609（+95）| Python | 信源：中

**它是什么**: "盯盘侠"，一个装在自己电脑或服务器上的 AI 盯盘助手。它盯着你持有或关注的 A 股、港股、美股，价格异动时提醒你，并调用多个 AI agent 协作给出分析意见，再把结果推到 Telegram、飞书、钉钉或微信。

**解决什么问题**: 散户盯盘要么一直开着行情软件，要么依赖券商 App 的简单提醒，拿不到综合分析。PanWatch 把实时监控、持仓管理和 AI 分析（集成了 TradingAgents 多 agent 投资决策框架）放在一个自托管服务里，数据留在本机，推送走你常用的 IM。

**谁在用、怎么用**（来自 Issues/中文社区）:
- 日常盯盘：#7 用户要求显示个股当日盈亏（8 条评论，提问者说"今天用了"），#91 要支持 ETF，#5、#121 希望登录证券账号同步持仓。
- 自行部署与二次开发：304 个 fork，外部 PR #126 接入东方财富 / 同花顺行情，#128 改进前端。
- 中文社区传播：linux.do 有一条非作者发的推荐帖（2026-01-29）；另有官方 Telegram 群。

**社区怎么评价**:
- 正面: 需求具体、贴近真实使用；一个月内发了 5 个版本（0.12.0 → 0.14.0），维护积极。
- 负面: #4 飞书能测试推送但分析完不推；#1 配 DeepSeek 实际请求打到智谱、请求头缺 Authorization；#36 DeepSeek V4 thinking 模式报 400；#28 同账号两台机器同时登录会卡死（已关闭）；早期有 #17 沪深市场判断错误。
- 健康度: 1,609 ⭐ / 18 subscribers（约 89:1），fork/star 约 19%，偏高，说明不少人真的拉下去部署。63 open（issue + PR），TNT-Likely 提交 222 次、第二名 3 次。HN、X、Reddit 无讨论，传播基本在中文圈。

**风险与争议**:
- **compliance**: 输出 AI 买卖分析，存在被当作投资建议使用的风险；行情依赖东财、同花顺、yfinance 等非官方接口，有服务条款风险。
- **dependency**: 上游行情接口不稳定（PR #119 处理 yfinance 429 限流），LLM 供应商适配也常出问题（#1、#36）。
- **bus_factor**: 几乎是单人维护。
- **privacy**: 持仓数据虽留在本机，但会发送给用户配置的 LLM 服务。

**技术备注**: Python，自托管，SQLite 存储（PR #45 涉及 database is locked 问题），MIT。支持多家 LLM 与多种 IM 推送渠道。

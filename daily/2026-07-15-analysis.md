## 本日主线

**主线一：视频剪辑「CapCut 替代」赛道两仓同框，OpenCut 单日暴涨领跑。** OpenCut（rank4，↓3，今日 +4,276，累计 69,268）在昨日首入后继续放量，是今日全榜单日 star 增量最高的项目；同赛道的新面孔 Clypra（NEW，rank11，Tauri+React 桌面剪辑）同日首入，主打「无水印无订阅的 CapCut 替代」。两者定位重合——本地桌面、多轨时间线、FFmpeg 导出——但成熟度差距明显：OpenCut 有近 7,000 fork、社区体量大，Clypra 仓龄不足 3 个月、核心拖拽功能仍在报 bug（#128）。这条赛道值得关注「Web/桌面剪辑开源化」的读者，但选型上 OpenCut 明显更稳。

**主线二：Claude Code / agent skills 生态继续霸榜，「技能包 + 防护 + 知识图谱」多形态并进。** 今日与 AI coding agent 直接相关的仓占近半：mattpocock/skills（RE，rank2，170,355 stars，Matt Pocock 的 `.claude` 技能集）回归高位；graphify（↓7，rank14，把任意代码/文档目录转成可查询知识图谱的 coding-agent skill）单日 +1,851；hallmark（↓1，anti-AI-slop 设计 skill）；destructive_command_guard（RE，rank3，拦截 agent 执行危险 git/shell 命令的 Rust 守卫）。从「写技能」到「防 agent 误删」到「喂知识图谱」，Claude Code 周边工具正在形成完整配套，是本周最稳的技术真信号。

**主线三：榜单解读提醒 — 部分短龄项目 stars 与社区足迹不匹配，需结合 grounding 判断。** 今日有两个高失衡样本：grok2api（NEW，逆向 Grok 的多账号 API 网关，subscribers 仅 13、fork:star≈1:3，HN/X/Reddit 全无讨论，且逆向代理存在明确 ToS 合规风险）与 Clypra（stars/watchers≈265:1，传播主要靠 X KOL 与 YouTube 安利，HN/Reddit 零讨论）。此外 awesome-llm-apps、exercises-dataset、maths-cs-ai-compendium 属「收藏/学习型」仓，star 反映收藏意愿而非采用，其高 ratio 对该类仓属正常，不宜单独判定虚高。

## 首次上榜项目（NEW）

### [AIEraDev/Clypra](https://github.com/AIEraDev/Clypra) — NEW ⭐ 2,648（+85）| TypeScript | 信源：中偏弱

**它是什么**: 一个用 Tauri + React + TypeScript 写的桌面视频剪辑器，定位「免费的 CapCut 替代品」——把付费剪辑软件的常用能力（多轨时间线、剪切、导出）做成本地原生、无水印、无订阅的开源工具。

**解决什么问题**: CapCut 等主流剪辑工具要么收费、加水印，要么把功能锁在订阅里。Clypra 想让用户在本地就能完成多轨剪辑、波形/缩略图预览、导出 MP4/MOV，不依赖云端账号，靠 Tauri 拿到接近原生的性能与更小的安装体积。

**谁在用、怎么用**（来自 Issues/评测）:
- 场景 1: 本地无水印剪辑导出，卖点是替代 CapCut 的付费功能（YouTube 测评 "Free CapCut Alternative? I Tested Clypra"）。
- 场景 2: 真实使用仍卡在门槛——多个 issue 是「装不上/跑不起来」：#128 媒体无法拖入时间线（核心功能坏）、#81 macOS Universal DMG 在 Intel Mac 跑不起、#76/#63 缺 FFmpeg 与 `.env.example`。

**社区怎么评价**:
- 正面: X 上有西语 KOL 安利（"Olvídate de pagar por CapCut"），Peerlist/Pinokio 收录，属「发现型」传播。
- 负面: Issue 区以基础可用性 bug 为主，缺真实「跑通交付」的工作流证据；#129 是作者自发的营销式 feedback 帖。
- 健康度: 2,648 stars / 仅 10 watchers（≈265:1），open issues 15，贡献者仅 2 人（作者占 942 提交），仓龄不足 3 个月。

**风险与争议**:
- **vanity**: 265:1 stars/watchers，HN/Reddit 零讨论，传播主要靠 X KOL 与 YouTube 安利。
- **stability**: 核心拖拽功能报坏、跨平台构建缺陷，仍是 early alpha。
- **bus_factor**: 2 人团队、单核心作者高度集中。

**技术备注**: Tauri（Rust 壳）+ React + TypeScript，FFmpeg 做媒体处理，跨平台桌面分发（macOS DMG 有 Intel/Universal 兼容问题）。

### [chenyme/grok2api](https://github.com/chenyme/grok2api) — NEW ⭐ 5,870（+186）| Go | 信源：中

**它是什么**: 一个面向 Grok（Grok Web / Grok Build / Grok Console）的多账号 API 网关。它把逆向得到的 Grok 网页会话，用多个账号的 SSO Token 组成「号池」，再以 OpenAI/Anthropic 兼容的 API 形式统一对外暴露。

**解决什么问题**: xAI 的 Grok 没有便宜或免费的官方 API 出口。grok2api 让用户用自己的多个 Grok 账号自建一个中转层，以低成本/免费方式调用 Grok（含文生图、视频、并发负载均衡），并伪装成标准 OpenAI 接口接入现有工具链。

**谁在用、怎么用**（来自 Issues）:
- 场景 1: 自部署号池运维——反馈几乎全是「怎么把号池跑得更稳、更隐蔽、支持多代理」：#589 每账号单独设代理、#633 Grok Console 无法设代理、#600 希望 chat 接口支持画图。
- 场景 2: 绕过风控——#632 请求超时、#620 Grok-4.5 联网搜索调用失败、#634 凭证被误标失效但实际可用，依赖 FlareSolverr/WARP 绕 Cloudflare 风控。

**社区怎么评价**:
- 正面: 中文自部署小圈子活跃，有 jiujiu532 等二开分支主打「零成本 console 模型」。
- 负面: 反馈全是风控/凭证类故障，官方接口随时可能失效。
- 健康度: 5,870 stars / subscribers 仅 13（≈452:1），fork 1,928（fork:star≈1:3，典型「一键部署白嫖」结构），open issues 10，仓龄约 9 个月，仍活跃（未 archived）。

**风险与争议**:
- **compliance**: 逆向代理 Grok/xAI 明确违反 xAI ToS，项目自带「仅供学习研究」免责声明。
- **dependency**: 依赖 xAI 未公开接口 + Cloudflare 风控绕过（x-statsig-id、FlareSolverr），官方一变即失效。
- **vanity**: fork:star 1:3 + subs 13 是「免费用 Grok」需求驱动的号池工具特征，热度非技术采用；HN/X/Reddit 全无独立讨论。
- **bus_factor**: 单作者项目，几乎无人跟进维护。

**技术备注**: Go 编写，OpenAI/Anthropic 兼容接口，多账号 Token 池 + 负载均衡，配合 WARP/FlareSolverr 做反封部署。

### [HenryNdubuaku/maths-cs-ai-compendium](https://github.com/HenryNdubuaku/maths-cs-ai-compendium) — NEW ⭐ 5,277（+112）| TypeScript | 信源：中

**它是什么**: 一份面向「想进顶级 AI Lab」的数学/CS/AI 学习合集，作者把从线性代数到量子 ML、从 SIMD/CUDA/Triton 底层到面试 roadmap 的内容做成 intuition-first（先建直觉）的教材，并附带一个 MCP server 可当 Claude Code/Cursor 的知识库调用。

**解决什么问题**: 准备 DeepMind/OpenAI/Nvidia 这类研究岗面试的人，通常要在零散论文、课程和刷题资料间自己拼路线。这份 compendium 想给出一条「直觉优先」的系统化学习+面试路径，并能被 AI coding agent 直接检索。

**谁在用、怎么用**（来自 Issues/HN）:
- 场景 1: ML 工程师/研究员当面试与自学教材，HN Show HN 拿到 88 分 / 26 评论，卖点是「7 年经验、朋友靠它进 DeepMind/OpenAI、intuition-first」。
- 场景 2: 接 MCP server 当 Claude Code/Cursor 的领域知识库；#7 反馈文件名含冒号导致 Windows 无法 clone（真实可用性）、#13 修复复杂度记号排版。

**社区怎么评价**:
- 正面: HN 有中等有机讨论（88 分），是真实学习资源而非空壳。
- 负面: 热度也引来 spam issue（#14 折扣引流、#12/#11 营销性收录）；内容质量与「能进大厂」效果缺第三方独立佐证。
- 健康度: 5,277 stars / subscribers 63（≈84:1，对教材型仓属正常），open issues 7，仓龄约 5 个月，作者一人 68 提交、bus_factor 高。

**风险与争议**:
- **content-only**: 本质是单作者教材内容仓而非软件，star 反映收藏意愿而非采用。
- **author self-promotion**: LinkedIn + Show HN 强宣发，「朋友进大厂/作者进 YC」叙事无第三方验证。
- **bus_factor**: 单作者主导，贡献高度集中。

**技术备注**: TypeScript 承载站点，内容为数学/CS/AI 教材，附 MCP server 供 AI coding agent 检索。

## 如何理解今天的热度信号

- **收藏型仓的高 ratio 不等于虚高**: awesome-llm-apps、exercises-dataset、maths-cs-ai-compendium 是学习/数据集类仓，star 表达的是「收藏/复用意愿」，subscribers 偏低是结构性正常，不应按 100:1 阈值单独判虚高。
- **真正需要谨慎的是短龄 + 全渠道无 grounding + 合规风险**: grok2api（452:1、逆向 ToS 风险、HN/X/Reddit 零讨论）与 Clypra（265:1、核心功能报坏、传播靠 KOL）属于「传播热度强、社区 grounding 弱」的样本，选型或引用前应结合 issue 与外部讨论核实。
- **今日最稳的真信号是 Claude Code skills 生态配套化**: skills（技能集）+ hallmark（质量护栏）+ graphify（知识图谱）+ dcg（命令护栏）同日成簇，反映 agent 周边工具正从单点走向完整配套。

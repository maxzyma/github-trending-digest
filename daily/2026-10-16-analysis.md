### [lightseekorg/tokenspeed](https://github.com/lightseekorg/tokenspeed) — NEW ⭐ 2,551（+30）| Python | 信源：中

**它是什么**: 一个把大模型部署成在线服务的推理引擎，和 vLLM、SGLang、TensorRT-LLM 是同一类软件。公司在自己的 GPU 集群上跑开源大模型时，用它接收请求、排队调度、管理显存里的对话缓存，再把生成结果流式返回。项目口号是"性能做到 TensorRT-LLM 的水平，易用性做到 vLLM 的水平"，背后是非营利组织 LightSeek Foundation。

**解决什么问题**: 编程 Agent 的请求往往上下文很长、轮次很多，同一段代码库要反复读，通用推理引擎在这种负载下的缓存命中和调度效率不够好。TokenSpeed 把调度和 KV 缓存管理写成 C++ 状态机，算子做成可插拔的独立层，同时适配 NVIDIA 和 AMD 的数据中心 GPU，目标是在同样的硬件上服务更多并发 Agent 会话。

**谁在用、怎么用**（来自 Issues/README/X）:
- 新模型首日部署：README 列出 Kimi K3、Qwen3.8 Flash Next、GLM 5.3 Flash 在发布当天即可用 TokenSpeed 部署；AMD 官方技术博客发表了 Kimi K3 在 MI355X 上用 TokenSpeed 推理的案例。
- 训练中在线更新权重：#1373 和 #1479 都围绕在训练过程中把新权重推给推理引擎的接口，这是强化学习训练接入推理引擎的常见用法。
- 硬件厂商与平台适配：外部 PR 包括 #1770 为 DeepSeek-V4 优化 MoE、#2084 优化 AMD gfx1250，#1747 是允许在仓库外接入自定义模型和算子的设计提案。

**社区怎么评价**:
- 正面: README 记录 2026-08 加入 PyTorch 生态，PyTorch 博客发过两篇技术文章；发布时 NVIDIA AI、Together AI、vLLM 官方账号在 X 上发帖支持。贡献者分布较分散，除机器人账号外，前几名贡献者提交数在 87 到 174 次之间。
- 负面: HN 发布帖 2 分、0 评论，Reddit 的 r/LocalLLaMA 没有相关讨论，缺少独立第三方的性能复测。X 上有评论指出 AMD 那组对比只和 AMD 自家引擎比，16 并发时对方反超，更适合读作调优案例。
- 健康度: subscribers 16，星数与 subscribers 比约 159:1；forks 342；open issue 8 个、open PR 约 100 个，参与以 PR 为主。2026-05-06 建仓，MIT 许可，最新版本 10-06 的 v0.1.1。

**风险与争议**:
- **stability**: 仍在预览期、只发 nightly 包；#1373（仍未关闭）显示通过 NCCL 更新权重时接口返回成功、实际没有传输，#1479 中两个更新权重的接口会直接拖垮调度器。
- **dependency**: 性能优势集中在 GB300、B200、MI355X 等数据中心 GPU，个人和消费级显卡用户收益有限。
- **基准自测**: 580 TPS、单用户 685 tokens/s、与 TensorRT-LLM 的对比曲线均由项目方或合作厂商发布，尚无独立复测。

**技术备注**: Python 执行层加 C++ 调度器，提供兼容 OpenAI 的接口；重点优化 MLA 注意力和 MoE，支持 FP4/MXFP4；覆盖 NVIDIA Hopper、Blackwell 和 AMD ROCm。

### [xerj-org/xerj](https://github.com/xerj-org/xerj) — NEW ⭐ 5,890（+715）| Rust | 信源：中

**它是什么**: 一个装在本机的搜索引擎。执行 `xerj autoindex <目录>`，它会自动识别代码、文档、日志、PDF、SQLite、CSV 并建立索引，代码按函数、类等符号切分。建好后可以像查 Elasticsearch 一样查，也可以通过 MCP 让 Claude Code、Cursor 这类编程 Agent 直接调用。

**解决什么问题**: 编程 Agent 找代码时常用 grep，命中后把整个文件读进上下文，既费 token 又容易让模型分心。XERJ 只返回相关片段。它主推的用法叫"参考编程"：先把同类开源项目克隆下来建索引，让 Agent 照着别人已有的实现写代码，而不是从头推导。

**谁在用、怎么用**（来自 Issues/HN/X）:
- 代码库检索与参考编程：README 的自测案例是 8 个任务、16 轮，解题数相同时输出 token 比 grep 少 2.7 倍；作者也写明，对模型已经熟悉的热门库，效果中性甚至变差。
- Agent 记忆评测：#1138 是社区贡献的 Agent 记忆评测方案。
- 大规模建索引：#1183 记录在全新构建时 297 个线程全部死锁，#1250 是多个索引同时写入时在 16 GB 内存上限附近反复触发熔断，说明已有人用它处理较大的语料。

**社区怎么评价**:
- 正面: 单个 Rust 二进制、不依赖 JVM，兼容 Elasticsearch 接口，现有客户端可以直接用；有外部贡献者在修性能问题（#1394、#1396、#1400）。
- 负面: 热门 issue 大多由作者账号自己提交。#500 发现符号索引返回整个类或方法体，字节量反而是 grep 的 32 到 48 倍，与主打卖点相冲突，现已关闭。HN 只有 1 个帖子（3 分、1 评论），Reddit 无讨论，X 上传播以作者 10-13 的 Corpus Hub 发布帖为主，未见独立评测。
- 健康度: subscribers 17，星数与 subscribers 比约 346:1；forks 318，open issue 和 PR 46 个。2026-06-30 建仓，Apache-2.0 许可。提交高度集中，xerj-org 账号约 2,657 次，第二名约 130 次。README 把提交一份使用报告 PR 作为加入社区的方式，PR 和贡献者数量会因此偏高。

**风险与争议**:
- **vanity**: 星数与 subscribers 比约 346:1，外部讨论稀少，传播主要来自作者账号。
- **stability**: 仍是 1.0.0 候选版，近期 issue 里有死锁（#1183）、内存耗尽崩溃（#1122）和 bool 查询打分错误（#361）。
- **bus_factor**: 绝大多数提交来自一个 2026-06 新注册的账号。
- **宣传口径**: 仓库简介写"比 grep 少 40 倍 token"，README 自测为 2.7 倍，两处不一致。
- **默认安全**: 快速上手使用的 `--insecure` 模式不开 TLS、不鉴权，暴露到局域网前需要自行加固。

**技术备注**: Rust 单二进制，tree-sitter 做语法感知的代码切分，实现 Elasticsearch 的索引、批量写入、搜索和聚合接口；`xerj mcp` 提供 MCP stdio 服务，`xerj init` 可一键接入 Claude Code 或 Cursor。

### [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV) — NEW ⭐ 18,212（+978）| TypeScript | 信源：中

**它是什么**: 一个可以自己部署的影视聚合网站。它本身不存任何视频，而是接入用户填写的第三方影视采集站接口，把多个来源的搜索结果合并展示，提供换源测速、在线播放、缓存和下载单集，也能播放 IPTV 直播列表和 TVBox 订阅。首页推荐取自豆瓣、Bangumi 等榜单。

**解决什么问题**: 想免费追剧的用户原本要在多个带广告的影视站之间来回找片源。LibreTV 用一条 Docker 命令就能在 NAS 或云服务器上搭一个带访问密码的私人站点，统一搜索和播放。

**谁在用、怎么用**（来自 Issues/中文社区/X）:
- 家庭 NAS 或 VPS 自建追剧站：知乎有多篇部署教程，飞牛 NAS 论坛也有讨论，但部分教程的端口和部署方式已过时。
- 功能需求推动迭代：评论最多的历史 issue 多是功能请求，如 #176 首页影视界面（26 条评论）、#182 豆瓣推荐（24 条）、#349 TVBox 接口（21 条），大多已实现。
- 片源可用性是最常见的问题：#64 无法获取资源（22 条评论）、#221 新版本搜索结果变少想回滚（20 条），#922 用 HTTP 访问时密码正确却无法登录，README 已专门提示生产环境要走 HTTPS。

**社区怎么评价**:
- 正面: 部署门槛低，访问需密码，有防内网探测（SSRF）保护和失效源自动停用；10 月初仍在密集迭代，10-02 一天发了两个小版本。
- 负面: X 上的传播主要是 2025-04 的两条推荐帖，有用户回复抱怨加载慢；中文社区有人称已改用同类项目 MoonTV，也有人提醒部分片源涉及成人内容。HN 和 Reddit 无讨论。
- 健康度: subscribers 11，星数与 subscribers 比约 1,650:1；forks 28,785，比星数还多，主要是用户 fork 后一键部署。open issue 5 个。2025-04-06 建仓，AGPL-3.0 许可。提交集中，bestZwei 约 374 次，其后是机器人账号。

**风险与争议**:
- **compliance**: 内容全部来自来源不明的第三方采集站，播放的多为未经授权的影视资源；README 免责声明称项目"不存储、不制作任何视频内容"，合法性由数据源负责，部署者仍需自行承担所在地区的版权风险。
- **dependency**: 采集源经常失效或变更，功能可用性取决于用户能找到的源。
- **bus_factor**: 核心开发集中在一名维护者。

**技术备注**: Next.js 15 + TypeScript + Tailwind，播放器为 ArtPlayer + hls.js；提供 amd64 和 arm64 双架构 Docker 镜像。

## 本日主线

**主线一：榜单地图 — 今天最大的一盘是"本地跑 AI"，不是 agent 框架。** 今日 17 项可分五组：① **本地与端侧 AI 运行**（5 项，最大盘）——unslothai/unsloth（NEW，第 6，71,101 ⭐，8-11 发布 Unsloth Desktop，从微调库变成本地训练+推理桌面应用）、cactus-compute/needle（↑13，第 4，5,002 ⭐，14MB 端侧函数调用模型，全榜升幅第一）、altic-dev/FluidVoice（RE，第 5，9,897 ⭐，macOS 端上听写）、Lightricks/LTX-2（=，第 15，8,939 ⭐，音视频生成）、lightningpixel/modly（NEW，第 16，5,476 ⭐，本机 GPU 出图转 3D）；② **agent 能力包与 skills**（4 项）——cathrynlavery/diagram-design（=，守住第 1，14,897 ⭐，+4,475 比昨天的 +2,855 还高）、anthropics/skills（RE，第 3，169,089 ⭐）、kepano/obsidian-skills（RE，第 12，45,853 ⭐，时隔 129 天回归）、msitarzewski/agency-agents（↓9，第 14）；③ **agent 工作台与流量层**（3 项）——macro-inc/macro（↓5，2,643 ⭐）、holaboss-ai/holaOS（NEW，第 11，6,664 ⭐）、NVIDIA-NeMo/Switchyard（↑1，1,251 ⭐）；④ **OSINT**（2 项）——megadose/holehe（NEW，第 8）、smicallef/spiderfoot（↑4，第 9）；⑤ **成熟基建与工具**（3 项）——semantica-agi/semantica（↑1，第 2）、infiniflow/ragflow（↓8，第 17）、3b1b/manim（RE，第 13）。和昨天对比，变化很清楚：昨天的重心是"给 agent 补一项交付能力"（画图、做 PPT），今天重心整体下移到**模型和推理在哪台机器上跑**。

**主线二：Unsloth 把自己从"库"改成了"应用"，这是今天最实的事件。** unslothai/unsloth（71,101 ⭐，2023-11 建仓，本 tracker 首次收录）在 8-11 发布 `v0.1.701-beta「Introducing Unsloth Desktop」`，8-13 已跟到 v0.1.702-beta，最近提交（8-14 凌晨）全是桌面端琐事——`Settings > Debugging` 里读日志、Kaggle 大 overlay 保存、拒绝导出装不下的 GGUF。仓库描述也换了口径：从微调加速库改成 "Local UI to run and train LLMs and diffusion models"，明确覆盖 MLX、扩散图像/视频、音频和 GGUF，并支持把 Claude Code、Codex 接到本地模型。对读者的意义是：过去两年"本地跑模型"分成两个互不重叠的人群——LM Studio / Ollama 那批只做推理，Unsloth 那批只做微调；这次是第一次有人把训练和运行收进同一个窗口。外部评价定调为"LM Studio 在本地 AI 桌面赛道有了正经对手"。但反馈也一致地卡在同一处：安装过程会不打招呼地拉 Python 和一堆依赖，Windows / Mac / AMD 三边都有装不上的报告，一位 AMD 用户称只有单个 Qwen 模型能跑通。**判断：赛道信号很强，具体版本还在 beta，值得跟但别急着当生产工具。**

**主线三：端侧的另一端——needle 单日升 13 位，是全榜最大位移。** cactus-compute/needle（5,002 ⭐，+769）昨天以第 17 名首次上榜，今天冲到第 4。它是 14MB / 45M 参数 / 2-bit 量化模型，只把自然语言转函数调用，目标是手表、智能家居、树莓派这类 28MB 内存的设备。昨天记录的 HN 硬缺陷仍未修（「HN」「potato」「我宿醉了」都能触发 `lock_door`），但作者侧在持续推进：8-13 深夜连续提交了 finetuning 文档、Apple 兼容性和 confidence 处理改进。把它和 Unsloth Desktop 放一起看，今天这条线的完整形状是：**大模型往本地桌面走，小模型往设备里钻，中间那段云端推理被两头挤。**

**主线四：两个实质停更的 OSINT 工具同框上榜，是流量现象不是项目事件。** megadose/holehe（NEW，第 8，12,461 ⭐）最后一次提交是 **2024-09-10**，近两年零代码变动；smicallef/spiderfoot（↑4，第 9，20,690 ⭐）默认分支最后提交是 **2023-11-05**、最后 release v4.0 停在 2022-04。两个都没有版本事件、没有 CVE、没有知名 fork，却在同一天同框——更合理的解释是外部 OSINT 教程/榜单类内容集中导流，而不是社区回暖。holehe 的 issue 区更能说明问题：热门 issue 前四位（#269 / #262 / #270 / #271，均 2026-05~07）全是西语非技术用户在求"帮我找回被盗的 Hotmail / 脸书账号"，技术讨论已经被求助帖挤掉。**读者视角的判断：这两个仓可以当 OSINT 方法的教材读，但不要当在维护的工具装。**

**主线五：agent skills 这条线没退，但在分层。** 今天 4 个 skills 相关仓的状态各不相同：diagram-design 守住第 1 且日增反而放大到 +4,475（不过它昨天被记为 HN / X / Reddit 三处均无有机讨论，今天的提交也主要是改名和加 Trendshift 徽章）；anthropics/skills（169,089 ⭐）作为官方仓两天后回归，最近提交是持续更新 `claude-api` skill；kepano/obsidian-skills 时隔 **129 天**回归，但它最后一次提交停在 2026-06-08，属于长尾基线被顶上榜；agency-agents 掉 9 位到第 14，最后提交 2026-08-06。分层的形状是：**官方仓和有具体交付物的包在往上走，人格化 agent 合集和长期没更新的 skills 目录在往下滑。**

### [unslothai/unsloth](https://github.com/unslothai/unsloth) — NEW ⭐ 71,101（+328）| Python | 信源：强

> 知名老项目首入 tracker（2023-11 建仓，71K ⭐）。本条侧重本次上榜的直接事件——Unsloth Desktop 发布。

**它是什么**: 一个让你在自己电脑上跑和训练 AI 模型的桌面应用。以前 Unsloth 是给会写 Python 的人用的微调加速库，你得配 CUDA 版本、装依赖、抄 notebook；8-11 之后它多了一个装完就能用的窗口，模型下载、对话、微调、导出都在里面。

**解决什么问题**: 过去"在本机跑模型"和"在本机训模型"是两拨互不相干的工具——LM Studio / Ollama 只管跑，Unsloth / Axolotl 只管训，中间要靠人手工搬运。Unsloth Desktop 把两件事收进同一个应用，还顺带覆盖了 MLX、扩散图像/视频、音频和 GGUF，并能把 Claude Code、Codex 指向本地模型端点。

**谁在用、怎么用**（来自 Issues/HN/媒体评测）:
- 场景 1: 把本机当成 coding agent 的模型后端——Unsloth 暴露 OpenAI 兼容端点，Codex 可以作为自定义 provider 接入，敏感代码不出本机。
- 场景 2: 无 Python 环境的用户做本地微调——评测明确写它的价值是"抹掉安装摩擦"，底下仍是原有的 Unsloth Studio 与 Core。
- 场景 3: 大模型量化分发的既有场景延续，如 Kimi K3 的 1.56TB→594GB 压缩（HN 2026-07-29）。

**社区怎么评价**:
- 正面: 被普遍读作对 LM Studio 的正面竞争——"不只是下载模型然后聊天"。发布节奏很快，8-11 到 8-13 两个 beta，8-14 凌晨仍在提交桌面端细节。
- 负面: 反馈高度集中在安装环节——安装会不询问就拉取 Python 和大量依赖；Windows / Mac / AMD 三边均有失败报告；一位 AMD 用户称 ROCm 双卡下只有单个 Qwen 模型跑通。另有用户报告难以挂接已有项目或连上本地模型。
- 健康度: 71,101 ⭐ / 369 subscribers（193:1，成熟大仓的 watch 习惯本就低，此处不作 vanity 判据）；6,407 forks、1,140 open issues 说明是真在被大规模使用的仓。HN 侧本次发布两帖分别 15 分 / 10 分，明显低于历史高点（Unsloth Studio 388 分、Dynamic 2.0 GGUFs 237 分）——桌面化这一步在 HN 的关注度不如前几次模型侧成果。

**风险与争议**:
- **stability**: 版本号仍是 `v0.1.70x-beta`，安装失败类反馈横跨三个平台，AMD/ROCm 支持明显不成熟。
- **dependency**: 桌面壳之下仍是 Python 环境、运行时、本地 API 和训练任务，评测指出这决定了它的实际支持成本没有界面看起来那么低。
- **cost**: 本地训练的门槛在硬件不在软件，桌面化降低的是配置摩擦，不是显存要求。

**技术备注**: Python 为主，桌面端为 Unsloth Studio 的原生封装；覆盖 MLX / GGUF / 扩散模型 / 音频；提供 OpenAI 兼容本地端点。2026 年此前已加入 PyTorch 生态（2026-05）、宣布 AMD 支持（2026-07）。

### [megadose/holehe](https://github.com/megadose/holehe) — NEW ⭐ 12,461（+195）| Python | 信源：中

**它是什么**: 给一个邮箱地址，它自动跑到 120 多个网站上"假装点忘记密码"，从各站响应的细微差别反推这个邮箱在哪些平台注册过，有些站还能带出被打码的备用邮箱或手机尾号。全程不给目标发邮件、不惊动本人。

**解决什么问题**: 以前要确认某个邮箱的社交足迹，只能一个站一个站手工试重置密码，几十个平台要试一下午。holehe 把这件事压成一条命令，是渗透测试前做资产盘点、反欺诈尽调时的标准起手式。

**谁在用、怎么用**（来自 Issues/外部教程）:
- 场景 1: 渗透测试前的邮箱资产盘点与攻击面梳理，通常和 spiderfoot 这类工具配套用。
- 场景 2: 已被大量非技术用户当"找回被盗账号"的工具用——issue #269 / #262 / #270 / #271（2026-05~07）全是西语用户在求助找回 Hotmail、Facebook 账号，技术讨论已被求助帖挤占。
- 场景 3: 二手封装消费为主：Apify 上的 actor 封装累计 4,279+ 次运行，另有 `holehe.online`、`holeheosint.com` 等在线套壳站。

**社区怎么评价**:
- 正面: 作为邮箱 OSINT 的入门标准工具被 2026 年多篇 Kali 教程和视频反复引用，长尾流量稳定。
- 负面: #232「docker method does not work」（12 条评论）、#174「rate limited」长期未解；各平台改掉密码重置端点后模块大面积失效，假阴性多。2026-02 已有 "RIP Holehe: user-scanner is the new king" 这类唱衰文。
- 健康度: 12,461 ⭐ / 259 subscribers（48:1，六年老仓的正常区间，不构成 vanity 判据）；1,672 forks、95 open issues；**最后一次提交 2024-09-10，近两年零代码变动，未归档但实质失修**。贡献者极度集中：megadose 357 次提交，第二名仅 14 次。
- HN: 零相关讨论（搜索命中全是 HomeHero / Holodeck 噪声）。Reddit 未取到可确认帖子，不作为证据。

**风险与争议**:
- **bus_factor**: 单人 357/14 的提交分布，且作者已两年未推送代码。
- **stability**: 依赖第三方站点未变更的重置端点，端点一改模块即失效，假阴性无告警。
- **compliance**: 利用密码重置端点探测他人账号存在与否，多数平台 ToS 明确禁止。
- **privacy**: issue 区已出现明显的"查他人账号"请求，工具正被非技术人群当人肉搜索用。
- **dependency**: 能力完全外挂在 120+ 第三方站点的行为差异上，本身无兜底。

**技术备注**: Python，GPL-3.0，CLI + 库两种用法，异步并发请求；未归档但无维护。

### [holaboss-ai/holaOS](https://github.com/holaboss-ai/holaOS) — NEW ⭐ 6,664（+241）| TypeScript | 信源：中

**它是什么**: 一个"给 AI 助手用的电脑桌面"。你不用在几个 AI 工具之间来回复制粘贴——它把 Claude Code、Codex 和自带 agent 装进同一个本地工作台，共用一份记忆、一批工具和同一批文件。主打卖点是"不失忆"：关掉应用、换个 agent，上周那个项目的上下文还在（记忆以本地纯文本文件存，人可读可改）。

**解决什么问题**: 现在每个 coding agent 各有各的会话历史、各自的工具配置，跨天跨周的任务一换工具就得重新交代背景。holaOS 想做的是把上下文从 agent 里抽出来放到工作台层，agent 变成可替换的执行器。附带 100+ 集成、MCP 支持和应用市场，模型可以用自带的也可以 BYOK。

**谁在用、怎么用**（来自 Issues/X）:
- 场景 1: 跨天、跨周的长周期任务——agent 记住项目状态后继续推进，而不是每次从零对话。
- 场景 2: 需要登录态的网页操作——复用本机浏览器真实会话执行，而不是走 API wrapper（这是 X 上少数偏实质的评价点，来自 @ai_for_success）。

**社区怎么评价**:

- 负面: 全部集中在可用性 bug 而非架构质疑——#468 项目 composer 无法附加文件、#462 Docker 镜像 COPY 了不存在的 `package-lock.json` 导致构建直接失败、#156 Artifacts 显示延迟、#146 marketplace 模板经网关报 "Service not found"、#140 Google OAuth 问题。
- 健康度: 6,664 ⭐ / 171 subscribers（39:1，对新仓属正常区间，不是极端值）；602 forks，**但 open issues 只有 8 个**，相对 6.6K stars 明显偏薄。贡献者 3 人，前两名占 78% 提交，且都是官方团队。Discussions 仅 1 条。

**风险与争议**:
- **vanity**: 6.6K stars 对应 HN 零讨论、Reddit 零讨论、X 以营销话术为主、issue 仅 8 条，传播路径和技术验证之间存在明显落差。

- **bus_factor**: 3 名贡献者且全为官方团队，开源仓是商业产品 Holaboss Desktop 的环境层，持续性取决于商业方。

**技术备注**: TypeScript，目前仅 macOS（Win/Linux 开发中），本地纯文本记忆存储，MCP 支持，100+ 集成，内置模型或 BYOK。

### [lightningpixel/modly](https://github.com/lightningpixel/modly) — NEW ⭐ 5,476（+118）| TypeScript | 信源：中

**它是什么**: 一个桌面应用，把一张照片拖进去就生成能用的 3D 模型，全程在自己电脑的显卡上跑，图片不上传。导出支持 GLB / OBJ / STL / PLY，其中 STL 可以直接丢进 3D 打印切片软件。

**解决什么问题**: 图生 3D 的模型这两年不缺，缺的是"装完就能用"——过去要自己配环境、拼 pipeline、处理网格。modly 把安装、节点式工作流（Image → Generate Mesh → Add to Scene）、网格平滑与减面打包成一个应用，另外给 agent 留了一个零依赖的 CLI。

**谁在用、怎么用**（来自 Issues/媒体）:

- 场景 2: 游戏和美术的快速占位资产生成。
- 场景 3: 素材涉密或有商用限制、不便上云时的本地生成；#111 中 mkinney 实测 v0.4.1 的 arm64 dmg 报告"安装顺利、成功生成模型"。

**社区怎么评价**:

## 如何理解今天的热度信号

今天有三类需要分开看的"高热度"，不能用同一把尺子量：

**第一类：有明确产品事件驱动。** unsloth（Desktop 8-11 发布）、LTX-2（v1.2.0 8-11）、Switchyard（v0.2.0 8-10）、macro（日更发版）属于这一类。热度对应真实的代码和版本变化，判断重点应放在"这个版本能不能用"，而不是"热度真不真"。unsloth 的答案是 beta 且三平台安装均有问题，Switchyard 的答案是 README 自己写着不要上生产。

**第二类：长尾基线被外部流量顶上榜。** holehe（最后提交 2024-09）、spiderfoot（最后提交 2023-11）、obsidian-skills（最后提交 2026-06-08）三个仓今天的共同点是：star 在涨，代码没动。这类项目的 stars/subscribers 比反而正常（holehe 48:1、spiderfoot 46:1），因为老仓的 watch 是历年积累的——**对它们该问的不是"热度真不真"，而是"还有没有人维护"**，而三个的答案都是否定或接近否定。

**第三类：传播强于 grounding。** diagram-design（244:1，HN/X/Reddit 三处无有机讨论，今日提交是改名和加徽章）、holaOS（6.6K stars 但仅 8 个 open issue、HN 与 Reddit 零讨论、X 讨论以雷同 KOL 话术为主）、modly（116:1，HN 2 分，官方 X 号 123 关注，已出现多个同描述镜像仓）属于这一类。三者都有真实可用的产品内核——modly 有实测装成功的报告，holaOS 有外部功能 PR——但热度的量级和社区留下的痕迹不匹配，**适合观望和试用，不适合据此判断采用规模**。

另外提醒一个反向误读：unsloth 的 193:1 和 needle 的 147:1 数值上都不低，但前者有 6,407 forks / 1,140 open issues，后者有两次 HN 爆款（776 分、526 分）和 Home Assistant 论坛的真实使用记录——**比值只是提问的起点，不是结论**。

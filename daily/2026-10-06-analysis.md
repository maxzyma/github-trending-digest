### [boykopovar/AnyPS5](https://github.com/boykopovar/AnyPS5) — NEW ⭐ 4,987（+997）| C++ | 信源：中

**它是什么**: 一个把 PS5 游戏"搬"到电脑上运行的工具。它不是模拟器，而是把 PS5 的游戏程序直接改写成 Windows 或 Linux 能运行的程序，再自己补上一套 PS5 系统功能和显卡着色器的翻译。

**解决什么问题**: PS5 和 PC 都是 x86-64 架构，CPU 指令本身大体相通，真正的障碍是系统库和显卡接口。传统模拟器要在运行时逐条模拟，开销大；`AnyPS5` 的思路是提前完成转换（重链接 + 重写运行时 + 着色器转 SPIR-V），理论上性能损耗更低。项目定位是互操作、研究和游戏保存。

**谁在用、怎么用**（来自 Issues/PR/X）:
- 逐个游戏推进兼容：`Demon's Souls`（#5）、`Deathloop`（#407）、`The Last of Us`（#338、#518）都有专门的 issue 或 PR，目前仍处于启动或加载阶段；#153 让一款游戏进入剧情加载。
- 底层问题排查：GPU 显存管理讨论（#290，18 条评论）、Windows 上 TLS 指令不支持导致崩溃（#217）、Linux 上自带 `libc.prx` 的游戏无法加载（#476）。
- 新手上手困难：有人拿到"Invalid ELF magic number"（#173，可能是未解密文件），有人直接问怎么用（#342）。

**社区怎么评价**:
- 正面: PR 社区很活跃，累计约 746 个 PR；X 上有开发者指出它是"重链接 + 重写运行时"而非反编译，技术路线清楚。
- 负面: X 上的传播以游戏媒体和 KOL 转述为主，夹带"GTA 6 能早上 PC"之类的预期；有人质疑是否借用了 shadPS4 / KytyPS5 的代码（#393）。HN 有 3 条转帖（1–3 分），均无评论；Reddit 未搜到讨论。
- 健康度: 4,987 ⭐ / 82 subscribers（约 61:1）/ 371 forks / 119 open（以 PR 为主，累计 issue 仅 34 个）。8-03 建仓，10-06 仍有推送。作者约 727 次提交，第二名约 455 次，共 30 多位贡献者。

**风险与争议**:
- **compliance**: README 声明不含密钥、固件或专有库，需用户自备合法二进制；但运行需要已解密的 PS5 游戏文件，取得方式通常绕不开破解主机（推断），存在被权利方要求下架的可能。
- **stability**: 能稳定运行的只有一款 2D 游戏，商业大作仍在崩溃或加载阶段；遇到未实现的情况直接抛异常退出。
- **vanity**: 程度中等。外界预期明显领先于实际能力，热度主要来自 X 上的媒体转述，HN、Reddit 几乎没有技术讨论。
- **bus_factor**: 前两位贡献者占大部分提交，但已有多人参与，集中度中等。

**技术备注**: C++，GPL-2.0；着色器转 SPIR-V；支持 SDL 手柄映射，键鼠通过 `anyps5-input.ini` 配置；作者表示至少一款商业游戏完全稳定后才发正式版。

### [M-Abozaid/esp32-c3-adblock](https://github.com/M-Abozaid/esp32-c3-adblock) — NEW ⭐ 1,370（+196）| C++ | 信源：中

**它是什么**: 一块约 2 美元的小芯片做成的家庭广告拦截器。插上电、设成家里网络的 DNS，它就会把广告和跟踪域名的请求挡掉，效果类似常见的 Pi-hole，但不需要树莓派。

**解决什么问题**: Pi-hole 需要一台常开的小电脑，挂了全家上网都受影响。这个项目在只有约 400 KB 内存、没有额外 PSRAM 的 ESP32-C3 上实现拦截：把 53.7 万个域名转成 40 位哈希、排序后存进 flash，查询时二分查找，内存只占约 50 KB。作者自己把它当作 Pi-hole 宕机时的备用 DNS。

**谁在用、怎么用**（来自 Issues/HN）:
- 性能优化：#3 提出减少 flash 读取，作者合并 PR #2 后实测拦截查询从约 115 提升到约 165 QPS。
- 长时间运行稳定性：#10 报告运行 1–2 小时后停止解析，社区成员定位到 UDP socket 超时后收发错位，已修复。
- 安全加固：#12 指出管理页原先没有密码、可被改黑名单地址，#11 补上鉴权；同一 issue 还报告路由器断开后设备卡在配置模式，已修。
- 规则兼容：有人希望支持 AdGuard 规则语法（#8），也有刷写失败的报告（#4）。

**社区怎么评价**:
- 正面: HN 上 Tom's Hardware 的报道（7-19，94 分）讨论集中在实现思路，最热的问题是"为什么不用 Bloom filter"，README 已把它列为下一步；另有 fork 加上了 Bloom filter。
- 负面: 也有人认为瓶颈在 WiFi 延迟而非 flash 读取；X 上以搬运转发为主，未找到独立使用反馈；Reddit 无讨论。
- 健康度: 1,370 ⭐ / 12 subscribers（约 114:1）/ 121 forks / 9 open。6-19 建仓，10-04 仍有推送。4 位贡献者，作者 26 次提交，其余三人合计 6 次。

**风险与争议**:
- **stability**: 长时间运行后停止解析（#10）刚修复不久；不含 DHCP，只适合做 DNS。
- **security**: 管理页鉴权是后补的（#11、#12），固件自动升级尚无签名方案。
- **bus_factor**: 几乎由作者一人维护。
- **误拦取舍**: 40 位哈希会让极少数无关域名被误判，按 53.7 万 / 2^40 估算，单次查询误判概率约为百万分之 0.5；完整名单需占用单 app 分区，代价是失去无线固件升级，保留 OTA 时最多约 25 万域名。
- **vanity**: 程度较轻，热度主要来自 Tom's Hardware、XDA 报道和 X 转发。

**技术备注**: C++，MIT；FNV-1a 40 位哈希；UDP DNS 拦截 + Web 管理页；默认名单约 14 万域名。

### [anthropics/skills](https://github.com/anthropics/skills) — NEW ⭐ 168,158（+485）| Python | 信源：中（官方仓，未做外部 grounding）

**它是什么**: Anthropic 官方维护的 Agent Skills 公共仓库——存放"技能"这种东西本身的官方样例和参考实现。所谓 skill，就是给 AI agent 的一份写在 markdown 里的操作手册（SKILL.md + 配套脚本、参考资料），agent 需要做某类任务时按需加载它，而不是把所有知识都塞进上下文。

**解决什么问题**: 在 skill 这套规范出来之前，让 agent 掌握一套特定工作流的做法是写超长 prompt 或做定制封装，既费上下文也不可复用、不可分发。官方仓给出的是"一个技能应该长什么样"的权威参照，以及一批可直接取用的官方技能。

**谁在用、怎么用**: 本 tracker 此前多次记录过这条线——2026-07-03 的分析中提到 Agent Skills 规范已从本仓迁出、由中立组织 agentskills 托管并纳入 Linux Foundation 旗下 Agentic AI Foundation 治理，被 OpenAI Codex、Gemini CLI、Cursor、Copilot 采用；本仓则继续承担官方技能内容池的角色。今天是它第一次以榜单条目形式被收录。

**社区怎么评价**:
- 健康度: 168,158 ⭐ / 1,104 subscribers（≈152:1，超大仓的结构性高比值，不单独作为 vanity 依据）；20,034 forks（fork:star ≈ 0.12，对内容型仓库属正常复用形态）；1,075 open issues；最近推送 2026-08-07。
- 观察点: issue 存量超过 1,000 是这条线上最值得跟的指标——内容型官方仓的 issue 多为技能提交与格式讨论，消化速度直接影响生态贡献体验。

**风险与争议**:
- **依赖治理迁移**: 规范主体已迁至中立组织，本仓与规范仓的职责边界需要读者自行区分，不要把官方样例池当成规范本身。

**技术备注**: 主语言 Python（技能配套脚本），内容主体是 markdown。

### [nvm-sh/nvm](https://github.com/nvm-sh/nvm) — NEW ⭐ 94,493（+22）| Shell | 信源：中（知名老项目首入 tracker）

**它是什么**: 在一台机器上装多个 Node.js 版本、并随时切换的命令行工具。一个 POSIX 兼容的 bash 脚本，`nvm install 24`、`nvm use 22` 就能换版本。

**解决什么问题**: 不同项目需要不同 Node 版本，系统级安装只能有一个。nvm 让版本切换变成 per-shell 的事情。

**社区怎么评价**:
- 健康度: 94,493 ⭐ / 1,082 subscribers（≈87:1）；10,354 forks；394 open issues；建仓 2010-04，是今日榜单里仓龄最长的项目；v0.40.6 发布于 2026-07-15，最近推送 2026-07-24。
- 观察点: 今日 +22 是全榜最低日增，纯基线上榜。

**风险与争议**:
- **dependency**: 十五年维护、发布持续，属基础设施级工具；使用侧的主要摩擦点是它通过 shell 启动脚本注入 PATH，与 shell 配置耦合，换 shell 或换机时需重新配置。

**技术备注**: Shell（bash/zsh 兼容）；同类替代品有 fnm、volta、asdf 等，选型时可对比启动开销。

### [3b1b/manim](https://github.com/3b1b/manim) — NEW ⭐ 90,203（+197）| Python | 信源：中（知名老项目首入 tracker）

**它是什么**: 3Blue1Brown 频道作者写的数学动画引擎——用 Python 代码描述"这个公式怎么变形、这条曲线怎么画出来"，渲染成讲解视频里那种精确的数学动画。

**解决什么问题**: 讲清楚数学概念常常需要精确受控的动画，通用视频软件做不到公式级的对齐和演化。manim 把动画变成可版本管理的代码。

**社区怎么评价**:
- 健康度: 90,203 ⭐ / 946 subscribers（≈95:1）；7,484 forks；487 open issues；建仓 2015-03；最近推送 2026-08-11，但**最新 release 仍停在 v1.7.2（2024-12-13）**。
- 观察点: 本仓是作者个人向的实现；社区维护的分支 ManimCommunity/manim 发布节奏更规律，做长期项目的读者应先确认自己要用哪一支。

**风险与争议**:
- **bus_factor**: 本仓围绕单一作者的创作需求演进，release 已近 20 个月未更新，API 变动不保证向后兼容。
- **分支选择**: 社区版与作者版并存，教程和示例互不完全通用，容易踩混用的坑。

**技术备注**: Python；渲染依赖 ffmpeg 与 LaTeX 环境。

## 如何理解今天的热度信号

今天有两个容易读错的地方：

**第一，`NEW` 今天不等于"新项目"。** 本 tracker 的 NEW 标记含义是"首次进入本 tracker 的收录范围"，而今天 6 个 NEW 全部是建仓 7–16 年的经典仓或官方仓。它们的日增量（+22 到 +485）远低于榜单头部的 agent 项目（+748 到 +1,138）。把 NEW 读成"今天冒出来的新东西"会完全读反今天的榜单。

**第二，超大成熟仓的 stars/subscribers 比值不能单独当作 vanity 依据。** transformers 133:1、project-based-learning 80:1、anthropics/skills 152:1——这些比值在数值上和短龄冲榜项目接近，但它们的 fork:star 比、issue 消化、发布节奏和仓龄都给出了完全不同的答案。今天真正需要结合社区 grounding 谨慎解读的，是仓龄 5 个月内、open issues 已达 3,500–5,000 的 orca 和 paperclip，以及停更 6–9 天但仍高位在榜的 agency-agents 和 OpenMontage。

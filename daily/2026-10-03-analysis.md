## 首次上榜项目

### [pablostanley/yoinks](https://github.com/pablostanley/yoinks) — NEW ⭐ 3,520（+623）| TypeScript | 信源：中

**它是什么**: 一个在终端里下载网络视频的小工具。打开后粘贴链接，从列表里选清晰度或只要 MP3 音频，回车就开始下载，界面是全屏的终端菜单而不是一串命令参数。

**解决什么问题**: 想从 YouTube、X、Instagram、TikTok 等站点存视频，常见做法是用广告很多的在线下载站，或者学会 yt-dlp 的格式参数。`yoinks` 在 yt-dlp 外面包了一层选单，选格式时直接显示预估文件大小，首次运行会自动下载 yt-dlp 程序，本机没有 ffmpeg 时也用内置版本，用户只需要 Node 18+，执行 `npx yoinks` 即可。

**谁在用、怎么用**（来自 Issues/X/评测）:
- 不熟悉 yt-dlp 的个人用户：几篇独立博客与 Substack 评测都把它当作"免记参数的 yt-dlp"推荐，重点提到选格式时能看到文件大小。
- 二次开发：社区有人 fork 出带 Web 界面的版本，也有人加了 gallery-dl 以支持下载图片。
- 实际故障：#8（YouTube 下载报 "Requested format is not available"，4 条评论，仍未解决）、#29（输入框无法粘贴链接）。

**社区怎么评价**:
- 正面: 交互对新手友好，安装成本低；作者是知名设计师，界面完成度在同类终端工具里较高。
- 负面: X 上的讨论以作者 7-16 发布帖和营销类账号转发为主，独立技术反馈很少；有外部 PR 指出它靠匹配 yt-dlp 的输出文字判断下载状态，写法脆弱（#30）。
- 健康度: 3,520 ⭐ / 25 subscribers（141:1）/ 310 forks / 22 open issues（含多个外部 PR）。单一作者 29 次提交，仓库 7-16 创建、7-17 后再无提交，#23、#27、#28、#30、#31 等外部 PR 无人处理。HN、Reddit 均未找到讨论。

**风险与争议**:
- **compliance**: 下载 YouTube、Instagram 等平台内容通常受平台服务条款和版权约束，工具本身不处理授权问题。
- **dependency**: 下载能力完全来自 yt-dlp，且内置的 yt-dlp 还不会自动更新（在 roadmap 上），平台改版后容易出现 #8 这类失效。
- **bus_factor**: 单一作者，7-17 后停更，外部 PR 积压。
- **vanity**: 热度主要来自作者个人影响力，issues、HN、Reddit 足迹与 3,500 星不匹配；建仓两个半月后首次进入本 tracker，今天 +623 也没有对应的版本或提交。
- **同名仿冒**: GitHub 上出现多个同名仓库，其中有的引导下载 Windows 可执行文件，安装时应认准 `pablostanley/yoinks` 或 npm 包 `yoinks`。

**技术备注**: TypeScript + Ink 实现终端界面，npm 分发（`npm i -g yoinks`）；yt-dlp 二进制下载到 `~/.yoinks/bin`，已安装则复用本机版本；MIT 许可。命令行参数、播放列表等功能仍在 roadmap。

### [Effect-TS/effect](https://github.com/Effect-TS/effect) — NEW ⭐ 16,559（+80）| TypeScript | 信源：中（知名老项目首入 tracker）

**它是什么**: 一个 TypeScript 应用开发框架，把错误处理、并发、重试、资源管理、依赖注入等写服务端程序时反复要处理的事情，统一成一套类型安全的写法。

**解决什么问题**: 普通 TypeScript 代码里，"这个函数会抛什么错""失败后要不要重试""连接用完有没有关"大多靠约定和注释。Effect 把这些写进类型，编译器能检查遗漏，适合对可靠性要求高的后端与工具链项目。

**上榜归因**: 10-01 发布 `effect@4.0.0` 正式版及 `@effect/vitest@4.0.0` 等配套包；10-02 继续合入 NodeSocket 读端清理、连接池空闲回收和 HashRing 分片稳定性修复（#8678、#8679、#8675）。

**社区怎么评价**: 2019 年建仓，16,559 ⭐ / 40 subscribers（414:1）/ 803 forks / 302 open issues，MIT，今天仍有推送。比例偏高是成熟依赖库的常见结构：多数使用者通过 npm 安装而不 watch 仓库。本条按"知名老项目首入 tracker"处理，未做完整社区 grounding。

**风险与争议**:
- **stability**: 大版本升级通常伴随 API 调整，从 3.x 迁移到 4.0 需要按官方迁移说明逐项核对，刚发布的正式版仍在密集修复。

**技术备注**: monorepo，核心包 `effect` 加平台、测试、SQL 等扩展包分别发布到 npm。

### [getsentry/sentry](https://github.com/getsentry/sentry) — NEW ⭐ 45,038（+16）| Python | 信源：中（知名老项目首入 tracker）

**它是什么**: 应用错误追踪与性能监控平台。程序出错或变慢时，Sentry 收集堆栈、请求和用户环境信息，帮团队定位是哪次发布、哪行代码出了问题。可以用官方云服务，也可以自行部署。

**解决什么问题**: 线上故障如果只靠用户反馈和日志检索，定位很慢。Sentry 把同类错误自动归并、关联到发布版本和提交，并给出影响人数，帮团队排出修复优先级。

**上榜归因**: 未找到明确诱因。今日 +16，最新月度版本是 9-15 的 26.9.0；近期提交集中在自动修复（autofix）触发统计和任务重试策略（#126254、#126403）。

**社区怎么评价**: 2010 年建仓，45,038 ⭐ / 668 subscribers（67:1）/ 4,892 forks / 2,273 open issues，今天仍有推送。本条按"知名老项目首入 tracker"处理，未做完整社区 grounding。

**风险与争议**:
- **compliance**: GitHub 未识别出标准开源许可证（NOASSERTION），Sentry 采用自有的源码可用许可，商业托管等用途需先读许可条款。

**技术备注**: Python（Django）后端 + TypeScript 前端，自托管通过官方 `self-hosted` 仓库的 Docker Compose 部署。
